# 每天五条一分钟视频的成本测算

日期：2026-09-21。用户计划：每天 5 条、每条 1 分钟，按每月 30 天计，共 150 条 / 150 分钟。

[打开可调参数 HTML](数字人口播成本测算.html)。这是口播环节的情景预算，不是已核账单或完整生产报价。

## 1. API 与租云 GPU

按用户给出的 API 60 元/输出分钟：每月 `150 × 60 = 9,000 元`。若采用阿里 720P 的公开参考价 54 元/分钟，则名义费用为 8,100 元/月。均未计优惠、计费取整、失败重做及其他环节。

现有算力云是自部署模型，不是自购硬件。用户提供 GPU 价格为 1.58 元/开机小时，该租金已包含硬件使用与电力；不能另外再加显卡折旧。

- 每天开机 2 小时预算：`2 × 30 × 1.58 = 94.80 元/月`，150 条全部合格且该窗口够用时，GPU 部分平均 `94.80 ÷ 150 = 0.632 元/条`。
- 每天开机 24 小时：`24 × 30 × 1.58 = 1,137.60 元/月`，同条件每条 7.584 元。
- 因此是否批量生产、及时关闭实例对账单影响很大。退出 SSH 或结束推理不等于实例停止计费。

## 2. 两小时是不是够用

当前只有短片基准，不是 60 秒实测，以下做线性预算情景：

- 单图 M1：9.36 秒输出对应 99 秒整个进程，推算 60 秒输出约 634.62 秒（10.58 分钟）；一天 5 条约 52.88 分钟。另预留 15 分钟/天给额外操作，则约 67.88 分钟/天，每月 33.94 小时。
- 动作母版缓存 M3：9.36 秒音轨对应 22.840906 秒缓存调用，推算 60 秒约 146.42 秒（2.44 分钟）。不包括模型启动/母版准备，母版成本及循环接缝尚待验收；原样片有末帧遗漏问题。

“每天 2 小时”留了缓冲，但不保证长片、所有模型占用、传输或重做都能塞进窗口。生成器通过测试不等于影片合格。

单图情景如果合格率只有 80%，需约 187.5 次尝试/月，处理加假设额外时间约 40.55 小时；如果降到 50%，需约 300 次尝试，约 60.38 小时，会超出 60 小时预算。付费 API 同样可能发生输出成功收费但质量不合格的重做。

M1 活跃时费线性估算约 0.27853 元/成片分钟；M3 约 0.06426 元。这不是实际完整成片成本，两项流程不同，也不是一个误差区间。

## 3. 自己买机器怎么算

只作算例：整机 10,000 元，36 个月摊销，残值 0；开机整机平均 400W，电价 0.8 元/kWh。这些不是采购报价，也没有证明一万元机器与当前云实例同等性能。

- 月折旧：`10000 ÷ 36 = 277.78 元`。
- 按每天 2 小时开机，月电费：`0.4 × 60 × 0.8 = 19.20 元`。
- 合计：约 `296.98 元/月`，每条约 1.98 元；未计维修和人工维护。
- 一万元硬件要先付现金，月折旧只是摊销口径，不是每月付款。

在这些假设下，自购与租云同开机时长的费用平衡点是：

```text
277.78 ÷ (1.58 − 0.4 × 0.8) ≈ 220.46 小时/月
≈ 每天 7.35 小时（按 30 天）
```

这是假定同样硬件吞吐、持续使用满摊销期的经济比较，不是采购后的现金回本月数。已有机器应另外区分增量现金费用、损耗与机会成本。

## 4. 不能漏掉的项与建议

总成本应包括 GPU/API、首次部署、TTS、内容生成、字幕、母版、素材、磁盘、流量、人工质检、维护、失败重做及等待时间。如果其他模型也在同一 GPU 跑，计入其占机时间；另租机器则另计租金。

动作母版可复用，创建费用按批准的实际复用量摊销；每套衣服/背景可能需新母版。若每一期先调用整段 API 再用 MuseTalk 重驱动，就仍然承担整段 API 费用。

**当前建议：先用租云 GPU 按需批量生产，暂不为本需求购买专用机器。** 先验证真正的 60 秒长片是否有合格的自然动作、身份、声音与口型，再用连续多条试验记录合格率、总开机时间和人工耗时。之后比较每分钟合格成片总成本。
