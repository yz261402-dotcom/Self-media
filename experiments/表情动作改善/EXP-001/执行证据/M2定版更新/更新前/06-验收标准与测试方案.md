## 1. 验收对象与不可替代的证据

验收对象是能够持续生产同一位写实虚拟主播内容的系统。固定真人外观的 Base Avatar 与 Outfit、Background 在资产身份和业务接口上解耦；换装、换背景不能重新随机换人。视觉实现可以采用参考图约束的完整画面生成，不要求把三张图片机械拼接。音色必须固定且版本可追溯。

V1 完整链路为：选题与角度 → 证据检索 → 有来源的口播稿 → 历史主题/观点/文本三层去重 → 内容硬门禁 → 固定音色 TTS → 真实唇形、表情、头动的口播视频 → 后处理、完整字幕与封面 → AI 标识检查 → 发布就绪包及审计记录。

以下是不可被综合评分覆盖的硬拒绝条件：

- 生产链路使用 T2V，或用 SVG/CSS 人形、卡通主播、静图加音频、RMS 能量驱动的形变嘴、贴片嘴冒充真实数字人口播。
- 主播身份漂移、擅自换声音、存在未解决的事实矛盾、关键事实无证据、重复内容未处理、Mock 结果混入生产。
- 最终视频规格不符合 9:16、1080×1920、MP4、H.264、AAC、30 fps CFR；最终音频综合响度不在 -14 LUFS ±1 内，或 true peak 高于 -1.5 dBTP。
- 字幕漏句、错序、时间轴与最终成片不对应；必需的 AI 标识缺失或被后处理覆盖。
- 未授权费用、提交结果未知时盲目重提、把草稿包或人工回填伪记为官方发布成功。

除上述已明确的产品规格外，本文的样本规模、时延、相似度、同步误差、保留期和费用上限均为**建议工程基线，未经本项目实测标定，也不是平台保证**。执行前须冻结 `acceptance_profile` 版本、测量工具和阈值；不得看到失败结果后临时降低门槛。商业许可待确认的检测模型不得直接成为生产门禁，选型和例外处理见[技术选型](02-技术选型对比.md)。

## 2. 三层验收与结论规则

验收层级与 [PRD](01-产品需求文档.md) 里程碑按以下关系对应，二者不能混用：

- **L0 = G0→G1 期间的 Mock 开发验证**：G0 是文档/开发基线，L0 验证契约与编排，不算真实能力。
- **G1 是 L1 的真实核心能力子集**：身份/声音定版、六个变体与真实短口播样片证明路线可行，不能据此宣称完整 L1。
- **完整 L1 = G2**：真实 RAG 生产、媒体门禁、发布就绪包、排期/人工回填功能及恢复/备份均通过；按 PRD 要求，实际人工投稿演练须另获具体发布授权后执行并单列证据。
- **L2 = G3 条件验收**：获得适用官方权限及发布授权后，独立验证官方真实发布；实际执行模式决定能否宣称自动发布。

若真实就绪包已经通过，但尚未获准执行 PRD 所要求的人工投稿演练，记录“L1 生产与就绪包部分通过；G2 人工演练待授权”，不得暗中发帖，也不宣称完整 G2。该情形不阻止继续开发和其他验收。

### L0：Mock 结构与契约

验证请求/响应契约、状态转换、数据持久化、错误传播、费用拦截和故障恢复。使用全新隔离目录、空数据库、全新实现的显式 Mock Provider 和新建合成夹具，禁止访问真实计费服务或发布接口。所有模拟数据须标明来源，不从失败 Demo 导入或改造。

L0 产物必须携带运行模式与来源标记，界面和报告显示“Mock / 结构测试”。即使有可播放 MP4，L0 也不能证明写实形象、音色、事实正确、真实口型或官方发布。L0 通过不等于 L1 通过。

### L1：真实生产全链路与发布就绪包

使用获准的真实 Provider、冻结的 Base Avatar/VoiceAsset、真实内容与证据、真实媒体处理链，完成全部 V1 必需用例。输出可人工发布的完整就绪包，并保留从选题到每项产物的证据链。

L1 的成功语义是“真实生产验收通过、就绪包已生成”。它不表示作品已经出现在抖音。人工上传后的记录只可标记为人工确认来源，不升级为 L2。

### L2：官方真实发布

前置条件是已核验的主体/应用资格、目标账号授权、适用权限和该权限允许的实际发布方式。按当时官方能力完成真实上传、发布与状态核验，记录官方作品标识、可核验状态和回执。仅有路由存在、HTTP 200、上传成功、SDK 拉起、草稿包、Webhook 2xx 或人工回填均不算 L2。

L2 不属于本轮 V1 完成条件。未取得权限时标记“阻塞：官方权限”，不能标记“通过”，也不能以此否定已通过的 L1。若官方能力要求用户确认，必须如实验收为“官方渠道人工确认发布”；只有权限与规范确实允许、并验证了无人值守提交，才能宣称“真实自动发布”。

### 结果记录

每个验收 ID 记录 `PASS / FAIL / BLOCKED / NOT_RUN`、层级、样本 ID、输入/输出哈希、执行版本、实测值、阈值版本、证据路径、评审人和时间。`NOT_RUN`、`BLOCKED` 不折算成通过率；硬门禁失败不能被均分抵消。阶段状态字段以[契约](04-接口契约与数据字典.md)为准，验收报告额外保存证据层级和来源。

## 3. 全新项目的验收起点

本规范从用户“整个项目从零重做”的决定出发。新工程计划使用 `production/src/avatar_studio/`，运行数据计划存放于 `production/runtime/`；这些是待实施目录约定，不表示工程、数据库或资产已经创建。当前全部验收用例均为 `NOT_RUN`，没有新系统的实现、真实样片或通过回执可以继承。

失败 Demo 不作为正例、反例、技术设计依据或质量金标；其源码、模块、测试、数据库、头像、声音、历史样本、图片、视频、日志和旧验收报告均不复制、不导入、不链接、不读取。不通过修改包名、包装接口或复制形变代码将其纳入新工程。独立选型的通用依赖须从受信来源重新取得并记录版本和许可。

所有模块都必须全新交付，并用本文规定的证据单独验收：

1. **身份与变体**：从新建写实 Base Avatar、服装、背景和权属记录开始，建立身份基准及变体批准流程，通过 AC-AV。
2. **内容与证据**：从空内容库、空证据库、空查重索引开始，实现来源检索、逐断言核验、主题/观点/文本三层去重，通过 AC-CT。
3. **固定声音与真实口播**：新建 VoiceAsset，接入真实 TTS 和音频驱动口播，保存实际服务与媒体证据，通过 AC-TTS、AC-TH；生产路径不得接入 T2V。
4. **媒体与交付**：全新实现后处理、完整字幕、封面、AI 标识和发布就绪包，通过 AC-MEDIA、AC-PUB 的 V1 用例。V1 提供发布辅助；G3 才在取得适用权限和具体发布授权后验收官方发布。
5. **工作台与运行支撑**：全新实现任务状态、成本账本、异步对账、幂等、调度、可观测性、备份恢复和工作台，通过 AC-OPS、AC-NFR。
6. **测试与证据体系**：全新编写合同测试、故障夹具和模拟 Provider；全部身份、声音、稿件、媒体、数据库与样本清单在新项目中建立。静图、错音、错时、形变嘴等负例由新项目测试工具基于本次获准输入独立构造，保留制作过程和来源，不使用失败项目的素材或代码。

本文提到的“历史库”“历史样本”和“已有合格结果”均只指新系统从空库启动后自行形成的数据。新系统已经通过相应验收的资产和样本，可在授权、版本和证据仍适用时复用；这不允许导入失败 Demo 的任何历史资产。测试夹具与真实生产数据始终隔离，Mock 或人工构造负例不能作为真实生产成功的证据。

新工程的自包含交付须通过 AC-OPS-10：临时环境只提供新工程、明确获准的配置与独立依赖，从空数据库创建身份、声音和任务；无法访问 Demo 时仍能完成所验收层级的链路。L0 只证明结构与隔离，L1 另须真实 Provider、真实媒体和全部质量门禁证据。

## 4. 样本、阈值与证据保留

### 4.1 建议最低样本集

下列正例、负例、人工金标和测试夹具全部为新项目新建，记录样本 ID、来源、创建方式、输入哈希和所属 L0/L1 层级。数据库从空库建立；去重所需历史内容在新项目测试空间单独新建，不能导入失败项目的历史库或样本。

- `AV-POS`：1 个冻结 Base Avatar，包含 1 张正面定妆照（hero）及至少 4 张经审核的参考图；另验至少 2 套服装 × 3 类背景的 6 个变体，含正面、轻侧转、不同表情/光照但仍符合栏目构图的样本。每个生产允许的变体均须验收，未测变体不能因同一 seed 自动进入白名单。
- `AV-NEG`：不同人物、刻意改变年龄/发型/五官的变体、卡通图、几何人形、模糊/遮挡人脸各至少 1 个。失败样本不进入主播资产库。
- `CT`：至少 50 对人工标注去重样本，覆盖原文复制、同义改写、同题同观点、同题新角度、异题同模板和不相关内容；校准集与保留测试集分开，禁止同一文本变体跨两集泄漏。另有不少于 12 个断言用例，覆盖支持、矛盾、无证据、部分支持、过期来源、来源不可访问和引用偷换。
- `TTS`：至少 10 段跨长度/情绪/语速的真实语音，包括中文、数字、日期、缩写及“RAG”“向量”“检索增强”等术语。固定基准句；正式连续运行再积累 30 条音色分布。首次验收不得把尚未积累的 30 条写成已达成。
- `TH`：至少 3 条不同稿件的真实全链路成片，覆盖不少于 2 套服装、2 个背景，至少 1 条完整 RAG 主题，3 条不同稿件同时覆盖固定音色一致性验收；另有 10–15 秒多音素短片。口型用词覆盖双唇闭合 /b,p,m/、唇齿 /f/、张口 /a/、展唇 /i/、圆唇 /u/、自然停顿和不同语速，例如“妈妈买白面包，爸爸泡杯白茶；阿姨翻开图谱，一起复盘方法”。
- `TH-NEG`：使用新编写的测试工具，从新系统本轮获准输入或已验收样本制作静图加同音频、能量形变嘴、音轨交换、音轨整体前后偏移 400 ms、音量包络相近但音素不同的错配音轨、嘴部矩形贴片、冻结片段和异常抖动。负例可离线构造；不得复制失败项目的形变代码、音频或视频，禁止为凑负例重复调用付费生成。
- `MEDIA/PUB/OPS`：裁剪+片头+分段拼接的时间轴样本，缺文件/哈希错误/漏标识样本，两套错误码与空作品 ID 回执，进程崩溃/超时/重复回调/时区边界样本。

真实样本按第 7 节分批授权新建；建议样本数不是批量付费授权。仅允许复用新系统自身已通过相应验收、且权属、参数、哈希和原始证据完整的真实样本，并说明时间、授权与版本适用性。失败 Demo 的头像、声音、媒体、历史样本和完成记录不得导入或充当质量金标。

### 4.2 建议测量基线

- 身份与音色相似度使用已批准可商用的模型，按同人/异人、同音色/异音色样本独立标定；记录模型/权重/预处理版本。未经本项目标定的数值不得作为已验证阈值，也不得用平均哈希代替身份识别。
- 去重的主题、观点、文本分开校准，分别报告误报/漏报与命中片段；建议保留集召回率和准确率均至少 90%，样本偏少时同时报告原始计数。逐字复制、已标注事实矛盾、Mock 污染等硬负例必须全部拒绝。
- 音画整体时长差建议不超过 250 ms；唇形对齐抽检的绝对偏移建议中位数不超过 120 ms、P95 不超过 200 ms。测量方法、窗口和不确定性一起报告；人工不得感到持续抢拍/拖拍。RMS 相关性只作辅助诊断，不能证明音素同步。
- 活跃口播段的连续完全静止超过 1 秒建议报警并复核；有意静默/停顿不机械判废。运动大小按脸部尺寸归一化，禁止直接跨分辨率复用像素阈值。
- 字幕建议单行不超过 14 个汉字等宽单位、最多 2 行、1080×1920 下底部保留 320 px；英文和长术语按实测文字宽度换行，不得截断。字幕对齐建议 P95 误差不超过 200 ms，专有词和可见口播正文不得漏字、重复或错序。
- 人工视觉与听感评审采用 1–5 分量表，建议自然度、清晰度各项至少 4 分；2 位评审独立检查，分歧进入复核。脸变了、嘴型不符、声音变了、正文事实错误属于硬失败，不能取平均通过。

### 4.3 证据与保留规则

每次运行使用新目录，例如 `production/runtime/acceptance/<run_id>/`，按 `l0/`、`l1/`、`l2/` 隔离；本轮不创建这些运行目录。保留只增不覆盖的样本清单、授权记录、冻结参数、代码版本、输入哈希、脱敏请求/响应、Provider task ID、查询时间线、成本账本、原始媒体、最终媒体、完整字幕、ffprobe/响度报告、关键帧、人工评语和逐 ID 结论。

普通原始大媒体按 PRD 建议保留 30 天、最终成片/清单至少 180 天，稿件历史与审核记录持续保存，资产/授权/发布回执长期保存。被纳入验收样本的原始媒体及其他验收证据至少保留 90 天；同一文件同时适用多个策略时取更长周期，因此验收原片不在第 30 天清除，验收最终成片/清单仍至少 180 天。金标与版本证据在该版本使用期内保留；存在争议或失败调查时保留到关闭，所有在用依赖均禁止清理。云端临时输入使用最小权限短期地址，建议 TTL 不超过 24 小时，任务完成即清理并记录清理结果。故障对账需要延长时明确记录原因和期限。临时云端文件清理不等于删除本地受控验收证据。

公开报告仅含脱敏摘要，禁止包含密钥、访问令牌、完整签名 URL 或敏感账号信息。脱敏后的原始响应与原始媒体应能通过哈希对应；不可为脱敏重写成功/失败业务字段。样本修订生成新版本并保留旧结论，禁止替换失败样本后沿用旧运行 ID。

## 5. 按能力分组的 Given / When / Then 用例

本文共定义 51 个独立用例，全部待实现后执行，当前结论均为 NOT_RUN。
AC-OPS-10 验证从空环境独立运行；各用例样本和历史数据均受第 3、4 节的新建与来源规则约束。

### 5.1 Base Avatar 与身份：AC-AV

#### AC-AV-01 固定资产与版本复用（L0 + L1）

- **Given**：在新项目中新建并审批的写实 Base Avatar，含 1 张正面定妆照与至少 4 张审核参考图，具有资产 ID、版本、来源/权属记录、原图哈希和身份基准。
- **When**：创建多条任务、重启服务或更换非身份生产参数。
- **Then**：均引用同一冻结身份资产，不自动重生人脸；显式换人必须产生新版本并重新验收。缺图、哈希不符、来源不清均阻止生产。证据：资产清单和任务引用链。

#### AC-AV-02 换装换背景多样本身份一致（L1）

- **Given**：`AV-POS` 的 6 个变体及冻结基准，Outfit/Background 各有独立 ID/版本。
- **When**：分别只换服装、只换背景、同时换二者，并生成获准的口播样本。
- **Then**：所有变体仍为同一人，脸型、五官、年龄感、肤色、发型身份特征稳定，颈部/发丝/光照自然；变体图及成片首中末、分段边界和最大转头帧均通过已标定检测与人工对照。证据：变体矩阵、分项结果、关键帧，不以固定 seed 代替。

#### AC-AV-03 身份与画风负例必须拦截（L0 + L1）

- **Given**：`AV-NEG`，以及冒用正常资产 ID 但更换文件的样本。
- **When**：进入资产登记、变体批准或生产前检查。
- **Then**：不同人物、卡通、SVG/CSS/几何人形、无法判断身份、哈希篡改均失败或待复核，不进入生产白名单；拒绝原因可定位到资产和帧。

#### AC-AV-04 权属与检测许可证（L1）

- **Given**：生成服务条款、图像/声音来源授权和检测模型许可清单。
- **When**：拟批准某资产或启用检测 Provider。
- **Then**：商业使用范围可追溯，未确认的模型/权重许可证阻塞该方案；算法名称或代码许可证不能替代权重许可。证据：已核验版本和批准记录，不在报告中伪造法律结论。

### 5.2 内容、事实检索与去重：AC-CT

#### AC-CT-01 完整内容与来源契约（L0 + L1）

- **Given**：一个 AI 科普选题、受众、角度、时长目标及历史库版本。
- **When**：生成候选稿件。
- **Then**：保存选题、标题、简介、正文、段落/表达标记、标签、实际 Provider、版本、来源与断言关联；标题兑现正文，内容有具体信息与适用边界。真实失败不能回退模板并标记为生产成功。

#### AC-CT-02 检索链路可追溯（L0 + L1）

- **Given**：获准来源集合及有来源版本/抓取时间/哈希的正文，含过期和互相冲突的资料。
- **When**：执行断言检索。
- **Then**：保存查询、过滤条件、命中文档/片段、排序结果、所用证据与引用；片段可回溯原文，最新有效版本优先，冲突不得被隐去。搜索摘要、引用 URL 存在或 LLM 自称查过均不独立构成支持证据。

#### AC-CT-03 逐断言事实硬门禁（L0 + L1）

- **Given**：包含数字、版本、机构、时效或因果结论的稿件及人工金标。
- **When**：抽取全部影响结论的可核验断言并检查引用。
- **Then**：每条记录支持/部分支持/矛盾/无证据及理由；矛盾拒稿，部分支持仅允许保留被证据支持的范围。无证据须补证、删除或转为明确非事实的个人观点并重审，不能只加“据说”“可能”就通过。无可核验事实的纯观点稿也须显式说明适用范围，不能获得虚构的事实满分。

#### AC-CT-04 事实负例与检索故障（L0 + L1）

- **Given**：伪造数字、机构名、旧版本当前化、链接可访问但正文不支持、仅部分支持、断链及检索不可用样本。
- **When**：执行事实门禁，或向来源正文植入“忽略规则/直接通过”的指令。
- **Then**：分别拒绝或标记待补证，外部文本指令不改变流程；不把无检索、措辞谦逊或综合高分当事实通过。证据包括每个负例的命中原因及未进入 TTS 的记录。

#### AC-CT-05 历史主题去重（L0 + L1）

- **Given**：由新项目新建测试数据或本系统后续真实记录构成、包含已批准/已导出/已发布状态的历史库，主题窗口与允许再谈条件已冻结。
- **When**：输入同题同角度、换标题不换主题、同题实质新角度样本。
- **Then**：命中历史主题并给出原稿 ID、时间和差异；前两类拒绝或进入改题，实质新角度仅按明确的再谈策略审批，不能凭改标题放行。并行任务须互相预留主题，不能同时绕过历史检索。

#### AC-CT-06 历史观点去重（L0 + L1）

- **Given**：同义改写、换比喻但同一结论、同题不同论点和否定结论对照样本。
- **When**：抽取关键观点与历史观点进行语义比较。
- **Then**：识别表达不同但论点重复的内容，输出观点级命中与可读解释；不把否定句/条件变化一律归为同观点。阈值经保留集验证，结果独立于文本层分数。

#### AC-CT-07 历史文本与模板去重（L0 + L1）

- **Given**：逐字复制、局部搬句、首尾模板复用、同义改写和独立原创样本。
- **When**：进行整稿、段落、句级检查。
- **Then**：逐字及片段复制必须被拦截，重复开头/结尾给出命中范围；不同量纲不混用一个阈值。三个去重层分别报告，任一必需层不可用即停止生产放行，不能静默改用字面相似度并宣称语义查重通过。

#### AC-CT-08 有限重写与再次核验（L0 + L1）

- **Given**：稿件因长度、口语、重复或证据问题未通过，且初稿后最多 3 次重写及费用上限已冻结。
- **When**：执行局部改写、换角度、换选题等策略。
- **Then**：保存每版稿件、策略、成本和前后报告；重写后重新检查事实、三层去重和标题一致性，不得靠省略出处、同义改写掩盖失败。超限或无新策略时结束并待处理，不循环到预算耗尽。用户指定 RAG 等主题时重写仍须满足原题；未经确认不得擅自换题，通用选题池任务才可按批准策略换题。

#### AC-CT-09 历史入库与版本隔离（L0 + L1）

- **Given**：Mock 稿件、失败稿件、已批准稿件和已导出稿件共存。
- **When**：下一任务检索历史，或稿件改版、模型/索引升级。
- **Then**：Mock 历史不混入真实内容库；真实已用主题/观点/文本按状态可追溯，失败断言亦可防止复活。向量对应正文哈希及模型版本，索引失败或版本不兼容显式阻塞，不返回“无重复”的假结果。

#### AC-CT-10 质量分数与人工相关性（L1）

- **Given**：冻结的 30–50 篇分层稿件、至少 3 位盲评者及清晰量表。
- **When**：比较自动质量分与人工对“能理解、有收获、适合口播”的评分。
- **Then**：报告相关性、评审一致性与分布；未达冻结基线时分数仅作预警，不承担自动放行。事实、重复、授权等硬门禁始终独立，不能通过修改权重覆盖。

### 5.3 固定音色与语音：AC-TTS

#### AC-TTS-01 音色资产冻结（L0 + L1）

- **Given**：在新项目中新建并批准的 VoiceAsset、参考音频哈希、Provider/model/voice ID、参数和权属记录。
- **When**：连续生成 3 条不同稿件，另用 10 段详细样本覆盖长度、语速、情绪，并重启服务。
- **Then**：每段实际使用的音色资产与版本一致，变化只在获准表达范围内；逐段声纹检测与盲听支持同一主播。固定 seed 只记为参数，不单独算音色一致证据。

#### AC-TTS-02 发音、表达与完整性（L1）

- **Given**：含多音字、数字、英文缩写、AI 术语、停顿/重音/语速/情绪标记的金标稿。
- **When**：确定性编译表达标记并真实合成。
- **Then**：标记不被读出，关键术语正确、语句不漏读重读、停顿自然、情绪不致人格漂移；不支持的控制能力在调用前报告，不假装已生效。保存编译输入、输出参数、音频和人工逐项听检记录。

#### AC-TTS-03 固定音色失败不得静默替换（L0 + L1）

- **Given**：主音色不存在、被删除、限流、单句失败或返回空音频。
- **When**：生产任务继续到语音阶段。
- **Then**：显式阻塞/失败并保留已完成片段；不得自动换备用声音、混入 Mock 或拼接其他人音色。获准切换 Provider 仍须证明同一音色资产，生成新记录并重验；PoC 不自动发起替代计费调用。

#### AC-TTS-04 字词时间戳与对齐回退（L0 + L1）

- **Given**：分别有原生字词时间戳、无时间戳、错误时间戳的真实音频结果。
- **When**：构建字幕时序。
- **Then**：原生时间戳必须校验；不可用时走可验证的强制对齐/ASR 并与冻结稿件校正，记录对齐来源。只有平均分配时长或未验证逐句时长时不得宣称字词对齐已完成；失败则阻塞就绪包。

### 5.4 真实数字人口播：AC-TH

#### AC-TH-01 真实视频级 Provider（L0 + L1）

- **Given**：已批准人物图/视频与 TTS 音频，Provider 能力和费用授权满足任务。
- **When**：提交音频驱动口播任务并查询、下载。
- **Then**：保留实际 Provider、模型、输入哈希、外部任务 ID、状态时间线和原始视频；无 T2V 调用、无程序形变冒充真实口播。只有权重路径或类名为真实服务不算推理证据；L0 测结构，L1 必须有可核验真实任务结果。

#### AC-TH-02 多音素唇形同步（L1）

- **Given**：多音素短片与对应音频/文字金标。
- **When**：按正常速度观看全片，并逐帧/慢放抽查闭唇、唇齿、展唇、圆唇、停顿与语速转换。
- **Then**：口型与音素和时间对应，无持续错位、牙齿漂移、嘴部矩形遮罩或周期性同一嘴型；报告对齐误差、失败帧与人工结论。嘴动了、像素变了、RMS 高相关都不能单独通过。

#### AC-TH-03 错配音频与伪口播负例（L0 + L1）

- **Given**：`TH-NEG`，特别是音量包络相近但音素不同的错配音轨，以及前后偏移 400 ms 的音轨。
- **When**：用同一验收检测和盲评流程处理正负样本。
- **Then**：静图、形变嘴、音素不符和明显偏移必须拒绝，不因音量相关或分辨率正确而通过。保留每个正负样本的原始分数与结论，证明门禁确实能区分。

#### AC-TH-04 表情、头动与真人构图（L1）

- **Given**：自然解释、提问、强调、停顿的真实口播段落。
- **When**：评审整片及首中末/极值姿态关键帧。
- **Then**：眨眼、眉眼和头部动作自然，具有真实三维姿态/非刚性面部变化；不能仅以整张图平移、缩放或局部贴图满足。人物具有合理颈肩/身体构图，无裁到下巴的悬浮头像、僵直长段、抽搐和边缘穿帮。

#### AC-TH-05 分段约束与接续（L0 + L1，采用分段 Provider 时必测）

- **Given**：服务时长上限已由新项目接入时的当前能力证据确认，稿件需分段；围绕所选 Provider 的实际时长上限新建边界前后样本。
- **When**：按语义/停顿切段、逐段驱动并拼接。
- **Then**：提交前拒绝超限片段，每段身份/音色一致，边界不漏字重字、断音、跳脸或重复帧，字幕和音频偏移统一；记录所有子任务和汇总成本。未采用该路线可记有理由的“不适用”，不能代表该 Provider 已验收。

#### AC-TH-06 异步失败与下载校验（L0 + L1）

- **Given**：任务失败/超时、返回未知状态、结果 URL 过期、下载中断或媒体哈希损坏。
- **When**：恢复或继续任务。
- **Then**：按原外部任务 ID 查询并验证文件完整性，区分运行中、远端失败和本地未知；不会把空文件、HTML 错误页或过期链接当视频，也不会静默落回形变嘴。不能确定是否提交成功时遵循 AC-OPS-02。

### 5.5 媒体、字幕和 AI 标识：AC-MEDIA

#### AC-MEDIA-01 最终编码规格（L0 + L1）

- **Given**：包括片头片尾、字幕、AI 标识的最终交付视频。
- **When**：对最终文件执行 ffprobe、完整解码和时间戳检查。
- **Then**：MP4、9:16、1080×1920、H.264、AAC、30 fps CFR，建议 yuv420p、AAC-LC/48 kHz、faststart；逐帧时间戳支持 CFR，而非仅比较标称/平均帧率。无缺流、损坏、异常旋转或非方形像素失真。原始分辨率与放大处理记录透明，不能把放大当原生细节提升。

#### AC-MEDIA-02 最终响度与音画完整（L1）

- **Given**：后处理和片头片尾拼接全部完成的最终文件。
- **When**：运行两遍响度标准化并独立测量最终 AAC 音轨，同时检查裁剪与同步。
- **Then**：综合响度 -14 LUFS ±1、true peak ≤ -1.5 dBTP；保存测量日志，不以滤镜配置替代实测。无削波、音节截断、不明静音；有声正文完整保留，时长和同步满足冻结基线。

#### AC-MEDIA-03 黑帧、静止、清晰度与水印（L1）

- **Given**：真实成片及黑帧、冻结、模糊、矩形嘴和非预期服务商水印负例。
- **When**：完整解码、自动检测并人工抽查全部告警片段。
- **Then**：正文无异常黑帧/冻结/嘴部贴片，脸部可辨清楚；非预期水印不进入就绪包，处理方式为获得合适授权或服务档位，不删除/遮盖应保留的法定 AI 标识或来源标识。建议阈值和误报均记录。

#### AC-MEDIA-04 完整字幕时间轴（L0 + L1）

- **Given**：冻结正文、TTS 时间戳/对齐结果及裁剪、片头片尾、分段拼接编辑表。
- **When**：生成烧录字幕和可导出字幕文件。
- **Then**：同一编辑时间轴驱动最终视频与字幕；所有有声正文不漏句、不重叠错序，起止时间在最终视频范围内，末句不截断。给出正文覆盖比对、时间单调性检查和同步抽检；字幕不能仍停留在 TTS 原始时间轴。

#### AC-MEDIA-05 字幕与封面可读性（L1）

- **Given**：长术语、数字、中文/英文混排和较亮/较暗背景样本。
- **When**：以竖屏手机尺寸叠加平台常见 UI 安全区预览。
- **Then**：字幕不截断、不遮嘴或关键人物区域，重点词高亮不改变内容，封面有有效画面且标题与稿件一致；字号/换行/安全区满足冻结参数，输出封面 1080×1920。平台 UI 布局以执行时复核记录为准。

#### AC-MEDIA-06 显式与隐式 AI 标识正反对照（L0 + L1）

- **Given**：完整标识样本，以及仅末尾闪现、被裁掉、元数据缺失、manifest 声称有但文件没有的负例。
- **When**：最终封装后逐段检测可见标识、读取实际元数据并核对 manifest。
- **Then**：首帧起至末帧均有清晰可见的项目要求 AI 生成标识；元数据与 manifest 一致且符合已冻结的适用规则；所有缺失/冲突样本被拦截。自定义 comment 字段只能证明写入过信息，不能独立宣称已满足标准化隐式标识规范；未知规范格式须先关闭待核验项。

### 5.6 发布就绪包与官方发布：AC-PUB

#### AC-PUB-01 完整发布就绪包（L0 + L1）

- **Given**：全部内容、身份、音色、媒体和标识硬门禁通过的任务。
- **When**：导出就绪包。
- **Then**：包内含最终视频、封面、标题/简介/标签、完整字幕文件、AI 声明说明、manifest、质量报告与证据索引；manifest 记录相对路径、SHA-256、媒体规格/时长、版本、实际 Provider 与运行模式、资产/音色引用、事实/去重报告、标识及成本摘要。逐文件可校验、可离线阅读，不依赖失效的临时 URL。

#### AC-PUB-02 发布状态不夸大（L0 + L1）

- **Given**：导出成功、Webhook 2xx、用户人工上传后回填链接三种情况。
- **When**：更新系统状态和界面文案。
- **Then**：分别记录包就绪、交接已受理、人工确认来源；没有官方核验回执不能变成官方已发布。人工回填只写 `reported_published`，保留操作者/时间/链接和 `manual` 证据来源，不计入 L2 自动发布成功率。

#### AC-PUB-03 包完整性与门禁不可绕过（L0 + L1）

- **Given**：缺封面、字幕漏句、媒体哈希被改、AI 标识缺失、内容门禁失败或含 Mock 的包。
- **When**：导出、排期或准备发布。
- **Then**：失败并明确指出缺项，不能因为存在 MP4 或 `ready_to_upload` 字段就放行；修改视频/文案/字幕后必须使旧验收签名失效并重新检查受影响环节。

#### AC-PUB-04 官方权限与能力探测（L0 + L2）

- **Given**：已脱敏记录的目标账号、应用、权限、有效期及官方允许的发布方式。
- **When**：计划或触发真实发布。
- **Then**：实际权限覆盖目标操作；无权限、过期或不适用时阻塞且不循环提交。未取得权限的 L0 只验证错误契约；SDK/H5 仅拉起编辑器不等于已发布。

#### AC-PUB-05 双错误码与真实失败（L0 + L2）

- **Given**：HTTP 错误、顶层/嵌套 `error_code`、`err_no`、无作品 ID、业务拒绝和合法成功响应夹具。
- **When**：适配器解析上传/创建/查询结果。
- **Then**：仅识别到合法业务成功并取得必要标识才进入下一状态；权限、配额、审核拒绝不误报成功、不盲重试，原始脱敏响应可追溯。真实环境至少保存一次合法成功和可安全验证的权限/参数失败；不得为测故障制造违规发布。

#### AC-PUB-06 官方发布与结果核验（L2）

- **Given**：真实权限可用、内容已获发布授权、包仍通过校验、平台 AI 声明可设置。
- **When**：通过获准官方通道完成上传、必要人工确认或获准自动创建，再查询作品状态。
- **Then**：记录官方作品 ID、目标账号一致性、提交/审核/发布状态、发布时间、可核验 URL 和回执；等待审核不算已发布，作品被拒或不可核验不得通过。报告明确实际模式，导出包和人工回填不可代替本用例。

#### AC-PUB-07 平台 AI 声明对照（L0 + L2）

- **Given**：文件层显式/隐式标识完整，平台侧有声明要求；另有未设置声明的负例。
- **When**：进入官方发布确认并核对平台实际结果。
- **Then**：声明操作/字段与真实作品状态可核验，负例在提交前被阻止；文件中的 AI 元数据不能替代平台声明。入口、字段与规范按执行时官方证据确认，不将平台入口、字段或规范格式永久写死。

### 5.7 费用、异步、恢复与调度：AC-OPS

#### AC-OPS-01 费用授权与原子预算预留（L0 + L1）

- **Given**：单次、单任务、当日、当月和本轮 PoC 总上限，含各 Provider、计费单位、税费/存储/传输等已知费用。
- **When**：提交前估算并有多个任务同时竞争剩余额度。
- **Then**：先原子预留预算，超限/价格未知/授权缺失即不提交；实际费用回写并对账。失败和取消不能在未确认账单前释放可能已发生的成本。估算不是账单，未知实际费用保留为待对账。

#### AC-OPS-02 一次提交与未知结果处理（L0 + L1）

- **Given**：同一幂等键的任务在请求发送后连接断开或进程崩溃，不知远端是否受理。
- **When**：重启、用户再次点击或网络恢复。
- **Then**：先按已有任务 ID/幂等键/Provider 查询能力对账；查询确认前不再次计费提交。不能核实时进入人工处理。PoC 每个获准样本最多一次实际提交，不自动切 Provider、不自动重抽；只读查询/下载重试与提交重试分开计数。

#### AC-OPS-03 异步超时与有限轮询（L0 + L1）

- **Given**：远端长时间运行、限流、暂时网络故障和业务永久失败。
- **When**：按冻结轮询间隔/最大等待时间执行，建议起始间隔 10–15 秒、总等待 30 分钟。
- **Then**：退避和总时限有效，业务拒绝不重试；本地超时记为待对账而不推断远端取消/免费。任务可通过原 ID 恢复查询，费用预留与审计记录不丢失。

#### AC-OPS-04 分阶段重启恢复（L0 + L1）

- **Given**：在提交前、受理后未记账、下载中、媒体处理后未提交状态、包写入中分别中断。
- **When**：恢复同一逻辑任务。
- **Then**：只执行未确认完成的安全阶段，不重复计费/发布；通过输入版本与产物哈希检查有效性，损坏/半写文件不得因“存在”跳过。状态、错误与费用记录可重建，无混用旧稿新音频。

#### AC-OPS-05 业务幂等与并发（L0 + L1；发布部分 L2）

- **Given**：相同身份/音频/Provider/参数哈希请求、重复点击、重复回调与并行调度。
- **When**：同时执行多次。
- **Then**：同一有效任务最多一个外部生成提交和一个允许的发布动作，新系统自身已有且通过相应验收的合格结果可复用；参数或输入变化产生新任务版本。重复/乱序回调不能倒退终态，幂等键与 Provider task ID 入库可查。

#### AC-OPS-06 时区、到期和错过执行（L0 + L1；真实发布另按 L2）

- **Given**：明确 `Asia/Shanghai` 时区、UTC 持久化时刻、本机改为其他时区，包含跨日和暂停恢复的排期。
- **When**：触发计划、服务重启、重复 tick，或切到不支持相同 cron 语义的调度后端。
- **Then**：在正确本地时刻执行一次，不提前消费未来队列；错过任务默认提示逾期、不集中补发、不自动改期；经明确批准的其他处理策略必须冻结并留痕。调度后端能力不足须拒绝配置，不静默忽略日期/星期/秒。V1 排期只推进生产/就绪包及人工待办，不能无权限自动发布。

#### AC-OPS-07 Provider 模式隔离与依赖失效（L0 + L1）

- **Given**：内容、检索、TTS、口播任一阶段为 Mock，或真实 Provider 未配置/不可用。
- **When**：请求生产输出或查看任务结果。
- **Then**：Mock 只能留在测试空间，实际来源逐阶段可查；缺依赖、能力不足或降级建议对用户可见。只有用户明确批准、同等级且重新通过相关验收的替代方案可进入生产，绝不静默降级。

#### AC-OPS-08 存储访问与证据安全（L0 + L1）

- **Given**：云 Provider 需读取人物图与音频，任务含临时签名 URL。
- **When**：上传、生成、完成/失败与日志导出。
- **Then**：只上传必要文件，访问期限覆盖任务但有上限，过期/拒绝访问明确报错；日志不泄露签名/令牌，清理可验证；清理不破坏受控本地证据。来源文件和旧验收目录不被覆盖。

#### AC-OPS-09 端到端可观测性（L0 + L1 + L2）

- **Given**：一个任务经历生成、质检、人工处理或失败。
- **When**：从用户结果追查任一阶段。
- **Then**：能定位 run/job/stage、实际 Provider、输入输出、状态、重试类型、费用、耗时和对应验收 ID；错误不能只显示“done”。L0/L1/L2 结果分别汇总，不能把产物存在率写成生产成功率。

#### AC-OPS-10 全新项目隔离验收（L0 + L1）

- **Given**：临时环境只提供新工程 `production/src/avatar_studio/`、配套新建测试与启动文件、获准配置及从受信来源独立安装的依赖；`production/runtime/` 为新的空运行区，数据库为空，失败 Demo 的目录、包和数据均不可访问。真实服务授权、输入来源与费用范围分别登记。
- **When**：从零初始化 schema，新建身份、声音和任务，执行内容检索/生成、质检、TTS、音频驱动口播、媒体处理与发布就绪包全链路，并记录导入依赖、文件访问、资产来源、任务事件和产物清单。L0 使用全新 Mock 与合成夹具；L1 在获准范围内另行使用真实 Provider 和新建真实资产执行。
- **Then**：启动和链路执行均无 Demo 路径、包、数据库或数据读取，不依赖复制的旧代码、素材、缓存、日志或隐式搜索路径；身份/声音/任务可追溯至新系统创建记录，产物落在新运行区。L0 报告明确“模拟结构与隔离验证”，不能声称生成了合格真实视频；L1 只有同时具备真实生成证据并通过相应质量用例才通过。保存环境依赖清单、空库初始化记录、来源清单、访问审计和逐层结果，任何越界依赖均失败。

### 5.8 工作台与非功能验收：AC-NFR

#### AC-NFR-01 工作台性能与关键交互（L0 + L1）

- **Given**：记录了 CPU、内存、磁盘和服务版本的本机环境，1 个运行任务和 10 个同时查询客户端。
- **When**：采集至少 100 次任务创建/状态查询，并走选题、审核、预览、下载包、改期、回填流程。
- **Then**：创建 P95≤2 秒、查询 P95≤1 秒；报告实际值和失败数；真实生成耗时另计。键盘可完成核心操作，错误与预算阻断可见，API 不返回密钥。

#### AC-NFR-02 备份与隔离恢复（L0 + L1）

- **Given**：含历史稿件、审核证据、进行中作业、费用预留和发布包的数据库及媒体清单。
- **When**：建立一致性备份，并在全新隔离目录恢复和重新启动。
- **Then**：任务、摘要、审批、历史查重、媒体引用和预算均可追溯；未知外部受理继续核对而非重提；原目录不覆盖，缺失文件明确阻断；保留恢复报告。

#### AC-NFR-03 保留期与依赖保护（L0 + L1）

- **Given**：超过配置保留期的媒体、仍被运行任务/未知作业引用的媒体、长期身份与发布回执。
- **When**：先运行清理预览，再执行批准范围内的清理。
- **Then**：只删除到期且无依赖的副本；运行中/未知状态、争议、受控验收证据和在用人物资产不被误删；清理可审计。验收证据至少 90 天的专项规则优先于普通原始媒体 30 天默认值。

#### AC-NFR-04 试运营质量与反指标（L1）

- **Given**：已获得明确额度并完成 20 次真实生产任务，任务集事先登记。
- **When**：统计合格就绪包、失败、主动取消、费用和人工干预。
- **Then**：至少 18 次在预算内形成合格包；全部失败计入分母，主动取消单列；Mock、重复投稿、已知错误断言漏放和身份异常漏放目标为 0。样本未完成只报告实际数量，不将首次样片推算成达标。

## 6. “RAG 检索增强生成”真实端到端验收脚本

本节是 AC-CT/AC-TTS/AC-TH/AC-MEDIA/AC-PUB/AC-OPS 的联合用例。建议目标时长 60–75 秒，具体字数由真实语速决定，不为了达到字数补空话。**本轮没有执行此脚本。**

1. **冻结输入**：选择“RAG 为什么还可能答错”这一角度，固定新项目已新建并通过相应验收的主播/服装/背景/音色版本、目标时长、Provider、预算与新系统历史库快照。记录对应授权号，创建新的 L1 运行目录。
2. **取得证据**：使用经批准的 RAG 原始论文、维护者官方说明或权威技术文档；保存本次查询、来源版本、获取时间、可复核正文和片段哈希。不能用“搜到 RAG 链接”代替有效检索。
3. **建立断言清单**：至少覆盖“检索为生成提供外部上下文”“检索结果可能缺失、过期或不相关”“RAG 不保证回答必然正确”。每条均要由实际证据支持；如证据不足，先调整稿件而不预设其已通过。
4. **加入事实负对照**：把“RAG 可以彻底消除所有幻觉”及一个虚构提升百分比送入同一门禁，预期拒绝；保留拒绝报告。正例中不得偷换为相同错误断言的弱措辞版本。
5. **生成并保存内容**：输出标题、简介、正文、分段、标签与表达标记，说明检索和生成各自作用、一个具体例子及适用边界。对最终正文逐断言核验，不只检查初稿。
6. **执行三层去重**：在新项目测试空间新建历史集，含一篇同题同角度、一篇同义改写及一篇同题不同角度，并保留来源与标注。输出主题、观点、文本三个独立结果；重复候选须变更实际内容并重新验收，不能改标题了事。
7. **真实 TTS**：使用冻结音色，核对“RAG”、数字和术语读音；保存完整音频、参数、实际 Provider、字词时间戳或真实对齐结果。中途换音色或 Mock 即失败。
8. **真实口播**：以批准人物资产和该音频驱动口播，保存提交/查询/下载证据及原片。全片检查身份、唇形、表情、头动；另用多音素短片和错配音频负例验证门禁有效。
9. **处理与字幕**：执行裁剪、规格统一、字幕/封面、两遍响度及最终封装；编辑时间轴统一映射。用最终文件核对分辨率、CFR、编码、响度、true peak、完整正文及字幕同步。
10. **核验标识**：逐段观看首帧至末帧可见 AI 标识，读取真实文件隐式标识并与 manifest 对照；包中给出平台 AI 声明的待操作事项。
11. **导出并校验包**：生成 AC-PUB-01 的全部文件，校验哈希与跨文件引用。系统只记录发布就绪，不发起本轮未授权的官方发布。
12. **回查与签收**：从最终包可反查每个断言来源、三个查重报告、资产/音色、外部任务、费用及失败负例；人工完整观看和盲听后签收。任一步缺证据即记失败或未执行，不能只凭 `produce` 命令退出成功签收。

通过结论应写为：“运行 `<run_id>` 完成 RAG 主题的 L1 真实生产与发布就绪包验收；L2 未执行/受权限阻塞。”只有独立执行 AC-PUB-04～07 后，才能追加相应官方发布结论。

## 7. 真实服务 PoC 的费用授权与一次提交纪律

本规范**不构成付费授权**。默认新增付费调用额度为 0；免费额度也须纳入账号、样本和调用范围确认，不能假设失败重提不会扣费。下列金额仅为可提交给用户审批的建议封顶值，以接入时实际价格重新估算：

- 身份/变体 PoC：建议总额不超过 ¥20，最多 6 个明确变体，每个变体一次提交；不足以覆盖实际价格则缩减样本或重新申请，不自动超支。
- 固定音色 PoC：建议总额不超过 ¥10，限定音色创建和逐段试听样本清单；音色创建次数与合成次数分别列出，每个样本一次提交。
- 真实多音素口播 PoC：建议单 Provider、1 条 10–15 秒、总额不超过 ¥30，含所需 TTS/存储费用；不得收到低质结果后自行重复抽取。
- RAG 真实端到端 PoC：建议 1 条 60–75 秒、全链路总额不超过 ¥120；口播只提交一次，LLM/检索/TTS 的调用清单和各子上限预先明确。
- L1 多样本验收：在上述 PoC 证明路线可行后单独授权，建议 3 条真实成片合计不超过 ¥360；仅新系统自身已验收的合格样本可按第 4 节复用。此上限不与其他批次自动合并，金额不足不降低验收门槛。

每次只申请下一批具体可审阅的调用，不能一次授权无限重试。轮询/下载可以在既定上限内有限重试；任何新增计费 submit、切换 Provider、改变稿件再次合成、补足样本均需在已明确授权清单之内，否则重新批准。系统的故障恢复策略不得覆盖此项 PoC 纪律。
