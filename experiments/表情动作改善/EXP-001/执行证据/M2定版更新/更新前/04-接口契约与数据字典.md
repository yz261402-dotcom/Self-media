## 1. 公共约定

- API 前缀 `/api/v1`；JSON 使用 `snake_case`、UTF-8。业务 ID 为服务端生成的不透明字符串，不能拼接为磁盘路径。
- 所有时间使用含时区 RFC 3339，存储统一 UTC；排期额外保留 IANA 时区，默认 `Asia/Shanghai`。时长与时间轴统一为非负整数毫秒，区间采用 `[start_ms, end_ms)`。
- 金额使用人民币分整数 `*_fen`，不使用浮点货币；提交前估价向上取整。其他币种必须先经版本化汇率折算，不能直接相加。
- `schema_version` 从新系统第 `1` 版开始；只承诺本系统后续版本按明确契约升级，版本号相同不代表兼容任何外部或旧项目 schema。请求未知字段拒绝，响应允许客户端忽略新增字段。
- 文本先统一换行为 LF、Unicode NFC，再计算 SHA-256。字符位置为规范化文本的 Unicode 码点偏移，不是 UTF-8 字节数或 UTF-16 长度。
- `sha256` 为文件原始字节的 64 位小写十六进制摘要。`asset_id` 是稳定引用；签名 URL 是短期传输凭据，不是资产 ID，不写进业务事件或日志。
- `mode` 值为 `mock | integration | production`，由运行环境决定，请求不能越级切换。每个任务、资产、Provider 任务和发布包均携带该值。
- 成功响应必须包含经校验的业务结果；HTTP 200、空错误码、`success=true` 均不能单独证明成功。普通写接口返回 200/201，异步受理返回 202；冲突 409、校验失败 422、能力不支持 422、权限失败 403。

### 1.1 全新资产来源约束与零兼容保证

- 项目暂定名为 `avatar_studio`；实际语言、目录与包结构待工程栈选型，当前不据此创建生产包。新 schema 初始化空数据库，配置及 `AVATAR_STUDIO_` 凭据引用由新项目建立；启动不搜索旧配置、路径或数据库，不提供旧包别名、旧字段映射、旧数据导入或旧任务恢复接口。
- Base Avatar、参考图、服装/背景素材、声音设计/注册结果、基准音频、成片及证据均须有新项目的来源链。允许本项目新生成或为本项目独立取得授权的新材料；禁止读取旧数据库、导入旧头像/声音 ID/音频/视频/审批结果，即使补写新 ID 或复制文件也不改变来源。
- 根资产须绑定新建 SourceRecord 和可核验摘要；派生资产须保留 `parent_asset_ids` 并可追溯全部根资产。创建身份/声音、提交任务、登记派生媒体和生成发布包时均校验来源；来源缺失或属于排除范围返回 `ASSET_SOURCE_FORBIDDEN`，人工审批不能豁免。
- `VoiceAsset` 从本项目首次声音创建/注册及基准验证建立。跨供应商注册使用的参考音频同样必须来自上述合法新来源；不接受只提供未经本项目建立来源证据的 `remote_voice_id`。
- Mock 由新写的确定性契约模拟器生成固定响应与带模拟标记的测试素材；离线负例和测试夹具全部独立新建。身份、声音、语义和视频质量阈值依据新标定集产生，不接受历史夹具或经验阈值直接放行。几何嘴型实现不作为 Mock、预览或负例生成器。
- 仅允许新系统内部有来源证据的 `integration` 资产经显式审批新登记为生产资产；保持原始记录与模式追溯，不能直接改 `mode`。模拟资产及其后代不得进入生产。

## 2. 权威枚举与状态规则

### 2.1 PipelineStage：处理到哪一步

按正常顺序：`topic | script | content_review | avatar_variant | tts | talking_head | postprocess | video_review | publish_package`。

- `topic`：确定选题与来源；`script`：结构化口播稿与表达标记；`content_review`：内容门禁。
- `avatar_variant`：选择或创建已批准的服装/背景变体；`tts`：声音、发音和时间戳。
- `talking_head`：真实图像加音频驱动；`postprocess`：裁剪、规格统一、字幕、封面和标识。
- `video_review`：成片技术检测与人工观感检查；`publish_package`：冻结发布材料与 manifest。

资产首次创建属于前置资产流程，不冒充某期视频已经完成。`stage` 只指当前/最后处理阶段，不能填 `running`、`failed` 或 `published`。

### 2.2 TaskState：本期生产任务处于什么状态

`queued | running | waiting_provider | waiting_review | retry_wait | succeeded | failed | cancelled | blocked`。

合法主路径：`queued → running → waiting_provider/running → waiting_review/running → succeeded`。

- Provider 外部任务未结束用 `waiting_provider`，不是持续占用工作线程；等待质检人工处理用 `waiting_review`。
- 明确可重试的临时错误：`running/waiting_provider → retry_wait → queued`；记录 `next_run_at` 与剩余次数。
- 预算、许可证、权限、能力缺失或外部提交结果不明用 `blocked`。条件解决后经可审计的 resume 回到 `queued`，不能自动清除阻断原因。
- 不可恢复错误或重试耗尽用 `failed`。生产成功只表示所有生产门禁及发布包完成，`succeeded` 不表示抖音已发布。
- `cancelled` 只表示停止推进；已提交云任务必须继续核对、下载必要证据并结算，不能因此宣称未计费。
- `succeeded/failed/cancelled` 是本次执行终态；再次生产创建新执行 ID 并引用 `previous_task_id`，不得修改旧证据。

`StageExecution.state` 复用 TaskState；整体 TaskState 是当前阶段的投影。阶段 `succeeded` 必须有输出摘要、门禁结果和提交时间，不以文件存在替代。

### 2.3 PublishState：独立的发布状态

`pending | ready | awaiting_human | reported_published | scheduled | submitting | submitted | published | rejected | failed | blocked | unknown | cancelled`。

- V1：`pending → ready → awaiting_human → reported_published`。`ready` 表示材料齐全；人工报告保存作品 URL、操作者、时间及证据，显示“人工报告已发布”。未收到报告可长期保持 `awaiting_human`，不使生产任务失败。
- V2：能力和授权实证通过后，`ready → scheduled/submitting → submitted → published/rejected`。`scheduled` 必须有有效排期授权和 Adapter 的定时能力；V1 到点只提醒，不进入 `scheduled`。
- `submitted` 表示官方受理且有远端 ID；只有明确的官方状态响应或验签回调能转 `published`，保存该响应证据。人工回填不能直接执行此转换。
- 提交超时、连接断开或无法确认副作用时进入 `unknown`；先查远端和既有回执，禁止自动重新创建作品。核对后可转 `submitted/published/rejected`；确认未受理后才允许新的提交尝试。
- `reported_published` 若以后取得对应作品的官方证明，可转 `published`，同时保留原人工报告。无官方查询能力不强行核验成功。
- `blocked` 表示缺授权/能力/标识/有效材料；`failed` 为已明确失败且无不明副作用；`rejected` 为平台审核拒绝；`cancelled` 只取消尚未执行的计划，不等于删除远端作品。

发布与生产失败互不覆盖。例如生产 `succeeded`、发布 `awaiting_human` 是合法 G2 结果。

### 2.4 其他小枚举

- `ApprovalState`：`pending | approved | rejected | revoked`。批准总是绑定对象版本与内容摘要。
- `CheckOutcome`：`pass | fail | review | not_run`。`not_run` 不能按通过计。
- `ProviderJobState`：`prepared | submitting | queued | running | succeeded | failed | cancelled | unknown`。
- `ClaimVerdict`：`supported | refuted | unverified`，不把“未发现问题”当作 `supported`。
- `EvidenceOrigin`：`automatic | human | provider`；人工结论和机器结果分开保存。

## 3. 核心实体

以下为技术中立的逻辑实体；具体数据库、表布局、文档字段与索引由存储选型结果决定。除不可变内容外，实体均有 `id`、`created_at`、`updated_at`、用于乐观锁的 `version`；更新使用期望版本。

### 3.1 身份与声音资产

**AvatarIdentity**

- `id`、`name`：固定主播；“真人 Base Avatar”指写实成年虚拟人物，不表示采用真实自然人的肖像。
- `hero_asset_id`、`reference_asset_ids`、`identity_prompt`、`identity_digest`：冻结的主参考图、参考集、身份锚定描述及摘要。脸型、五官、发型、肤色、年龄与性别不随单期配置改变。
- `source_record_id`：生成来源、模型版本、提示词/seed、使用权证据。seed 仅用于复盘，不能证明身份一致。
- `approval_state`、`approval_id`：首次人工确认。批准后不可覆盖 hero 文件；换身份创建新 identity，旧期视频继续引用旧资产。

**AvatarVariant**

- `identity_id`、`image_asset_id`、`outfit`、`background`：服装与背景选择，只描述本次可变部分。
- `reference_digest`、`provider_run_id`、`generation_spec_digest`：能追溯到冻结身份和生成参数。
- `identity_report_id`、`approval_state`、`approval_id`：须先过身份门禁再可生产。无许可清晰的人脸模型时，以人工对照审批代替自动打分；不得填写虚构相似度。

**VoiceAsset**

- `provider`、`model`、`region`、`remote_voice_id`：完整音色作用域；四者作为组合解释，不能仅凭字符串 ID 复用。
- `reference_audio_asset_id`、`synthesis_profile`、`profile_digest`：冻结试听音频和基础参数；不支持 seed 的服务不得写“已固定 seed”。
- `source_record_id`、`approval_state`、`approval_id`：声音设计或授权来源、盲听/基准句评审。声音更换创建新版本。
- 新模型/供应商必须创建独立 VoiceAsset 并重新验收；Qwen Voice Design 输出 ID 能否供某 CosyVoice 型号使用是待实证能力，默认不允许。允许用有权使用的参考音频重新建音色，但不承诺完全相同。

**SourceRecord** 只保留 `source_type`（本项目生成 / 为本项目新取得授权 / 本项目独立测试素材）、`provider/model/version`（适用时）、`provider_run_id`（真实生成或注册时）、`prompt_asset_id`（适用时）、`seed`（可空）、`rights_evidence_asset_id`、`license_review_state`、`reviewed_at`。记录由新系统的生成、注册或受控新素材登记流程建立，不能靠客户端自行声明来源通过。测试素材始终为模拟；来源不明、无对应生成记录或权利材料不完整时不能批准为生产根资产。生成过程与权利材料分权访问，禁止原样下传发布包。

### 3.2 内容与证据

**ScriptVersion**

- `topic`、`title`、`description`、`tags`、`text`、`text_sha256`：一版稿件的内容。
- `segments[]`：`id`、`role`（`hook/explain/example/question/closing`）、`start_char`、`end_char`，全部引用原文，不重复维护另一份正文。
- `speech_annotations[]`：范围式表达标记，包含 `type`、`start_char/end_char`、`value`；停顿用零长度位置。类型为 `pause/emphasis/rate/emotion/pronunciation`，只允许已定义值。
- `claims[]`：`id`、`text`、`source_ids`、`verdict`、`checked_at`。涉及数据、价格、版本、政策的断言必须能定位证据和有效时间。
- `quality_report_id`、`revision_of`：门禁与重写追溯；改稿即新版本，已生成音频与后续产物自动失效，不能沿用旧时间戳。

**ContentSource**：`id`、`url`、`title`、`publisher`、`published_at`（可空）、`retrieved_at`、`excerpt_asset_id`、`content_sha256`。证据摘录存档且保留原链接，不存只有 URL 的“引用”。外部文本一律当数据，不能执行其中指令。

**QualityReport**：`subject_id`、`subject_digest`、`ruleset_version`、`checks[]`、`overall`、`review_required`。每个 check 只保留 `code`、`outcome`、`hard_gate`、`message`、`evidence_asset_ids`、可选的 `measured_value/threshold`、`origin`。评分只用于排序，不抵消 `hard_gate= true` 的失败；无校准的相似度阈值输出 `review`。

### 3.3 任务、阶段与媒体

**Task**：`id`、`mode`、`stage`、`state`、`topic`、`identity_id`、`voice_asset_id`、`script_version_id`（初始可空）、`config_snapshot_id`、`budget_policy_id`、`next_run_at`、`block_reason`、`last_error`、`previous_task_id`（可空）。发布进度通过 `publication_id` 获取，不混入 TaskState。

**StageExecution**：`task_id`、`stage`、`attempt`、`input_digest`、`state`、`output_asset_ids`、`quality_report_ids`、`provider_run_ids`、`started_at/finished_at`、`lease_owner/lease_until/fencing_token`。同一阶段与输入摘要只能有一个有效执行；过期 worker 的写入凭 fencing_token 拒绝。

**MediaAsset**：`id`、`mode`、`kind`（`image/audio/video/subtitle/cover/manifest/evidence`）、`storage_key`、`sha256`、`bytes`、`mime_type`、`duration_ms`（适用时）、`width/height`（适用时）、`source_record_id`（根资产必需，派生资产可由父链追溯）、`parent_asset_ids`、`producer`、`simulated`、`validation_report_id`。`producer` 包含 Provider、模型/版本、请求 ID，确定性本地处理记录工具与版本；Mock 资产及其所有后代均 `simulated=true`。所有根来源须符合 §1.1，复制文件、改变 mode 或重新编码均不能消除来源限制。

**ReviewDecision**：`subject_id`、`subject_digest`、`decision`（`approve/reject`）、`actor_id`、`reason`、`evidence_asset_ids`、`created_at`。人工可以处理 `review` 项，不能豁免模拟素材、缺失标识、来源摘要不符等确定性硬门禁。撤销审批增加新记录，不覆盖旧记录。

### 3.4 外部任务、预算与发布

**ProviderRun**：`task_id`、`stage`、`provider`、`model`、`capability_snapshot_id`、`request_digest`、`idempotency_key`、`state`、`remote_job_id`（未取得时可空）、`request_trace_id`、`poll_after`、`deadline_at`、`result_asset_ids`、`cost_reservation_id`、`last_error`。未知远端任务仍保留占用/预算，不因 worker 重启创建替代计费任务。

**BudgetPolicy**：`provider_model_allowlist`、`per_task_limit_fen`、`daily_limit_fen`、`monthly_limit_fen`、`max_billable_submissions`、`allow_failover`、`valid_until`、`authorization_evidence_id`。默认额度与可计费次数均为 0；不得将 0 解释为无限制。

**CostReservation**：`task_id`、`provider_run_id`、`budget_policy_id`、`reserved_fen`、`actual_fen`（未知时为空）、`state`（`reserved/settled/released/disputed`）、`price_snapshot_id`、`billing_evidence_id`。`actual_fen=0` 只用于确认零费用，不能表示未知。预算按已花费加未结算预留校验，日界使用配置时区；重试和备用供应商也占预算。

**PublishPackage**：`task_id`、`mode`、`video_asset_id`、`cover_asset_id`、`subtitle_asset_id`、`title`、`description`、`tags`、`ai_label`、`manifest_asset_id`、`package_digest`、`quality_report_ids`、`review_decision_ids`。任何文案/成片/封面修改都生成新 package，旧审批不继承。

**Publication**：`package_id`、`account_binding_id`（V1 可空）、`adapter`、`state`、`idempotency_key`、`scheduled_at`（可空）、`authorization_id`（V2 必需）、`remote_item_id`、`official_evidence_asset_id`、`manual_report`（`url/actor_id/reported_at/ai_declaration_confirmed/evidence_asset_ids`）、`last_error`。`reported_published` 可以有 URL 但无 official evidence；`published` 必须有官方证据。

**PublicationPlan**：`publication_id`、`planned_at`、`timezone`、`state`（`pending/due/overdue/completed/cancelled`）、`completed_at`。V1 的计划表示人工投稿提醒，不改变 PublishState 为 scheduled；已上线应用到点置 due，休眠错过置 overdue，禁止集中自动补发。生产排产用独立 `ProductionSchedule` 保存规则、下一次触发和 `schedule_id + planned_fire_at` 唯一键。

## 4. Provider 契约

### 4.1 能力声明必须先于调用

`capabilities()` 返回 `provider`、`model`、`verified_at`、`evidence_id`、`supported_modes`、`operations`、`constraints`。每个 capability 的状态为 `unverified/supported/unsupported`；只有 `supported` 可被生产调度采用。能力证据绑定账号、地域、模型版本，有过期时间；服务升级后重新验证。

- 图像：是否支持参考图输入、最大参考数、允许分辨率。
- TTS：可用 VoiceAsset 作用域、字/词级时间戳、可用表达控制、音频格式和最大文本长度。
- TalkingHead：必须是 `image_audio_to_video`（或经批准的视频加音频驱动），包括输入时长/尺寸限制、输出分辨率、并发、查询/取消、服务端幂等及按客户请求 ID 查询能力。
- 发布：`prepare_package`、`official_submit`、`official_status`、`scheduled_submit`、`ai_declaration`、`requires_human_confirm`。存在接口地址不等于任何能力为 `supported`。

不支持必需参数时返回 `CAPABILITY_UNSUPPORTED`；禁止静默忽略情绪、改音色、降级为形变嘴巴或调用 T2V。允许的近似表达必须在编译结果明确列出并经该音色的能力配置批准。

### 4.2 异步媒体 Provider

以下是接口签名约定，不是可直接运行的 SDK：

```text
estimate(request, price_snapshot) -> CostEstimate
submit(request, idempotency_key) -> ProviderReceipt
poll(remote_job_id) -> ProviderStatus
lookup(client_request_id) -> ProviderStatus | Unresolvable
download(result_locator, destination) -> MediaAsset
cancel(remote_job_id) -> CancellationReceipt
```

`request` 只引用已批准的 `person_asset_id`（AvatarVariant）、`audio_asset_id`、`output_spec` 和 Provider 参数。Provider 适配器从对象存储获取短期 URL；业务层不提供任意下载地址。

`submit` 前先事务持久化 ProviderRun、幂等键及预算预留，再执行外部调用。`ProviderReceipt` 含远端任务 ID、接受时间、请求追踪 ID。`poll` 一次查询后立即返回，不在 API 或 DB 事务中长轮询；用 `poll_after` 重新排队。

无 remote ID 的提交超时：置 `unknown`，按服务端幂等/lookup 能力核对；能力缺失则人工核账，不能换供应商重发。已持有 ID 的超时：继续查询同一 ID。`download` 可按同一结果重复下载，临时文件完整校验后原子发布为 MediaAsset。

示例是 **mock 契约数据**，请求 ID 不对应真实付费任务：

```json
{
  "schema_version": 1,
  "provider_run_id": "pr_mock_001",
  "mode": "mock",
  "provider": "mock_talking_head",
  "model": "contract_v1",
  "idempotency_key": "mock:talking_head:task_001:input_001",
  "state": "running",
  "remote_job_id": "mock_remote_001",
  "request_trace_id": "trace_mock_001",
  "poll_after": "2026-09-21T03:00:15Z",
  "deadline_at": "2026-09-21T03:30:00Z",
  "cost_reservation_id": "cost_mock_001",
  "result_asset_ids": [],
  "last_error": null
}
```

### 4.3 音频、表达与字幕时间轴

`TTSResult`：`audio_asset_id`、`voice_asset_id`、`script_version_id`、`spoken_text_mapping`、`timing_source`（`provider/forced_alignment/asr_alignment/mock`）、`words[]`。word 含 `start_char/end_char/start_ms/end_ms`，时间均相对于对应的 **实际音频文件起点**。分句合成必须先加分句在整段音频中的偏移再汇总；字级能力需在具体模型和音色上验证。

表达编译器不得改变字幕原文。发音替换将原文范围映射到朗读字符串，例如 `RAG` 与供应商所需读法；合成后时间戳必须映回原文范围。标记范围越界、未知标记、剥离标记后正文变化均拒绝。句长均分只能用于 mock，生产不得以按字数均摊伪装时间戳；无原生时间戳时用 ASR/强制对齐并核对术语，无法可靠对齐则待审。

`EditTimeline`：`source_audio_asset_id`、`source_video_asset_id`、`provider_lead_ms`、`clips[]`、`final_duration_ms`。`provider_lead_ms` 是原始口播视频相对输入音频多出的前导时长，必须测量/核对，不能默认靠改字幕掩盖口型偏移。

每个 clip 含 `source_start_ms`、`source_end_ms`、`target_start_ms`；source 指原始口播视频时间轴。V1 只允许速度 1 倍和非重叠顺序剪辑。音频某时刻先映射为 `source_video_ms = audio_ms + provider_lead_ms`，再映射为 `final_ms = target_start_ms + source_video_ms - source_start_ms`。字幕区间先与 clip 求交，跨剪点则拆分；被删除区间不能产生负时间戳。片头/片尾占目标时间轴，未对应口播的区间不显示原文字幕。

```json
{
  "schema_version": 1,
  "source_audio_asset_id": "audio_001",
  "source_video_asset_id": "raw_video_001",
  "provider_lead_ms": 0,
  "clips": [
    {"source_start_ms": 400, "source_end_ms": 11800, "target_start_ms": 1000}
  ],
  "final_duration_ms": 12900,
  "example_word": {"text": "你好", "audio_start_ms": 500, "audio_end_ms": 900, "final_start_ms": 1100, "final_end_ms": 1500}
}
```

此例裁去前 400 ms 和尾部，加入 1000 ms 片头与 500 ms 片尾。若云端因时长限制分段，另存每段输入音频范围与输出剪辑映射；不得简单 concat 重叠的音频，必须验证无重复字、漏字和段间口型跳变。默认按句无重叠切分，确需上下文重叠时先裁掉重复区再生成映射。

### 4.4 发布 Adapter

```text
capabilities(account_binding) -> PublishCapabilities
prepare(package_id) -> Publication
record_manual_report(publication_id, report) -> Publication
submit(publication_id, authorization_id, idempotency_key) -> Publication
status(publication_id) -> Publication
```

- `ManualPackageAdapter.prepare` 产出 `ready`，交付后 `awaiting_human`。`record_manual_report` 只写 `reported_published`。其 `submit`、官方查询/定时能力必须返回不支持，不能用本地包路径充当作品 ID。
- `MockPublishAdapter` 只接受 mock 资产，输出模拟回执；真实运行无法注册该 Adapter。
- `OfficialPublishAdapter` 为 V2：需账号 OAuth/所需 scope、主体/场景资格、实际接口测试、有效用户授权及 AI 声明能力。当前只约定接口，不宣称可自动发布。
- 平台响应按具体路由族校验 `error_code/err_no` 及嵌套结构，并要求预期 `video_id/item_id` 或明确状态；未知格式归为契约错误。授权错误不无限刷新重试；刷新一次仍失败即阻断。
- 同一环境、目标账号、平台、`video_sha256` 设重复作品保护键；同一请求另有幂等键。修改标题、日期或请求键不能绕过视频重复保护。需要重发必须显式创建有理由的新发布意图并核对旧结果。

## 5. 应用 API 最小集

以下接口仅是开发契约。所有写接口须验证操作者；高风险发布/预算操作另核对授权范围。客户端不得传入本地任意路径、明文 key 或未经登记的外部媒体 URL。

- `GET /api/v1/capabilities`：返回已验证能力与阻断原因，不返回凭据。
- `POST /api/v1/avatar-identities`、`GET /api/v1/avatar-identities/{id}`：建立候选身份/读冻结资产；没有覆盖已批准 hero 的接口。
- `POST /api/v1/avatar-identities/{id}/variants`：提交服装/背景变体生成任务。
- `POST /api/v1/voice-assets`、`GET /api/v1/voice-assets/{id}`：登记作用域明确的候选音色与证据；生产音色需审批。
- `POST /api/v1/tasks`：提交选题、资产 ID、已授权预算策略；返回 `task_id/state/stage`。
- `GET /api/v1/tasks/{id}`、`GET /api/v1/tasks/{id}/events?after_seq=...`：状态与增量事件。
- `POST /api/v1/tasks/{id}/cancel`、`POST /api/v1/tasks/{id}/resume`：停止推进/解决阻断后恢复；不得清除未知外部副作用。
- `POST /api/v1/tasks/{id}/script-revisions`：保存修订稿，创建新的执行输入并失效下游缓存。
- `POST /api/v1/reviews`：对精确对象摘要提交 approve/reject；过期摘要返回 409。
- `GET /api/v1/publish-packages/{id}`、`GET /api/v1/publish-packages/{id}/download`：查看、下载经验证的发布材料。
- `POST /api/v1/publications`：由包生成发布辅助记录；V1 仅 ManualPackageAdapter。
- `POST /api/v1/publications/{id}/plan`、`PATCH /api/v1/publications/{id}/plan`：V1 设置/改期/取消人工投稿提醒，返回 PublicationPlan；不调用平台。
- `POST /api/v1/publications/{id}/manual-report`：记录作品 URL、操作者和证据，写 `reported_published`。
- V2 才启用 `POST /api/v1/publications/{id}/submit`、`POST /api/v1/publications/{id}/schedule`、`GET /api/v1/publications/{id}/status`。
- `POST /api/v1/provider-callbacks/{provider}`：默认关闭；只在提供商具备验签能力并完成防重放验证后开放，原始请求体校验签名，不能复用普通登录接口放行。

所有创建/提交/人工回填接口接受 `Idempotency-Key`。同 key 同规范化请求返回原结果；同 key 不同请求返回 409。重放不得生成新预算预留或远端请求。

创建任务示例（预算策略须提前存在，示例不授予消费权限）：

```json
{
  "topic": "RAG 如何补充模型回答所需的信息",
  "identity_id": "avatar_001",
  "voice_asset_id": "voice_001_v1",
  "outfit": "news_suit",
  "background": "studio",
  "budget_policy_id": "budget_approved_001",
  "target_duration_ms": 65000
}
```

统一错误体：

```json
{
  "error": {
    "code": "PROVIDER_SUBMISSION_UNKNOWN",
    "message": "云端是否已接受任务尚未确认，已暂停重复提交。",
    "retryable": false,
```

## 6. 事件与发布包

事件与业务状态在同一事务提交，事件为追加记录。每个聚合的 `seq` 单调递增，消费者按 `event_id` 去重；outbox 投递是至少一次，不能承诺跨外部服务 exactly-once。

事件名：`task.created`、`stage.started`、`provider.submission_unknown`、`provider.completed`、`quality.review_required`、`review.decided`、`stage.completed`、`package.ready`、`publication.manual_reported`、`publication.submitted`、`publication.confirmed`、`cost.settled`、`task.blocked`。

```json
{
  "schema_version": 1,
  "event_id": "evt_001",
  "aggregate_type": "task",
  "aggregate_id": "task_001",
  "seq": 7,
  "type": "quality.review_required",
  "occurred_at": "2026-09-21T03:15:00Z",
  "trace_id": "trace_001",
  "payload": {
    "stage": "avatar_variant",
    "state": "waiting_review",
    "subject_id": "variant_001",
    "quality_report_id": "qr_001",
    "reason_code": "LICENSE_REVIEW_REQUIRED"
  }
}
```

发布包目录至少包含 `video.mp4`、`cover.jpg`、`subtitles.srt`、`title.txt`、`description.txt`、`tags.txt`、`ai_label.txt`、`manifest.json`。字幕同时烧录成片并提供文本文件；包不是“已发布证明”。

包内另附可离线阅读的 `quality-summary.json` 和脱敏 `evidence-index.json`，提供必要质量/事实/查重结论与费用摘要，敏感原始证据仍在受控库中；不能仅给出无法离线解释的内部 ID。

manifest 必需字段：`schema_version/package_id/task_id/mode/simulated`、每个交付文件的路径/摘要/大小、成片规格、实际 Provider 与身份/音色版本、事实/去重报告和费用摘要、AI 显式/隐式标识检查结果、平台声明待办、`quality_report_ids`、`review_decision_ids`、`created_at`。仅包含相对文件名，不包含密钥、对象存储签名 URL、内部文件绝对路径或上游完整提示词。以确定性清单计算 package_digest，manifest 中不包含自身摘要；清单摘要存 DB，避免循环自哈希。

AI 隐式标识的具体字段与封装方式由上线前确认的规范版本决定；任意 `comment=AI-generated` 不能单独算规范通过。标准未核对时对应 check 为 `review/not_run`，不得宣称合规已经验收。

## 7. 契约验证清单

- 枚举、JSON Schema、字符偏移、时间戳、金额和状态转移拒绝非法值；每个样例需可解析。
- 空环境只使用新工程即可初始化；无旧包导入、旧库访问、旧配置探测或兼容入口。用独立新建的无来源/来源不符样本验证拒绝规则，不读取旧素材制作夹具。
- 身份、VoiceAsset、根媒体及派生媒体必须追溯新 SourceRecord；测试素材复制、改 mode、转码或伪填新 ID 后仍被拒绝进入生产。阈值须关联新标定集和规则版本。
- G0 是文档基线；Mock 跑通只计 G0→G1 期间的开发检查。真人身份与声音定版、真实图像驱动样片另计 G1，稳定生产与发布包计 G2，官方授权自动发布另计 G3。
- 同幂等键重放、并发提交、过期 lease 写入、worker 重启、下载半文件、URL 到期、提交丢响应、重复回调均有故障用例。
- 测试音色跨作用域误用被拒绝、未批准变体被拒绝、模拟素材在 production 被拒绝、人工回填只得到 `reported_published`。
- 裁剪/片头/分段/发音替换之后，字幕时间戳单调且落在成片范围，字幕原文与批准稿一致；不能用放宽时长阈值掩盖时间轴错误。
- 发布未知结果阻止重复创建；业务错误和缺失远端 ID 不能成功；上传成功与官方发布确认分别建证据。

详细验收场景见同目录验收文档；本文是它们的数据与状态依据。
