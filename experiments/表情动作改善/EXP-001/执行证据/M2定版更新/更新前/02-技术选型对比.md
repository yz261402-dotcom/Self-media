### 1.2 不可替代的目标

- 固定人物的脸型、五官、发型、发色、肤色、年龄感和性别呈现；只允许按版本选择服装、背景及受控表情、姿态。不能通过新生成人脸来冒充换装成功。
- 首次可通过文生图创建全 AI 人物；后续服装、背景变化必须保持已批准的 Base Avatar 身份，具体编辑方法按 §4 对比决定。**文生图不等于文生视频；所有 T2V 路线禁止进入本项目视频管线。**
- 真实固定音色音频必须先形成可核验资产，数字人服务读取这段音频。禁止几何嘴部形变、RMS 拉伸、静图加配音、循环静态片段冒充真实数字人口播。
- 默认时长 60—75 秒，可配置；90 秒用于预算和边界验证。1—3 条/天是设计产能；当前仅有一个短片任务耗时，尚无生产全链路时延、成功率或持续吞吐证据。
- 首期范围已按用户选择确定：V1 交付真实生产全链路与发布就绪包（G2）；取得官方权限后的自动定时发布作为后续 G3 单独验收。保留全自动最终目标，不把人工发布包冒充自动发布，也不再将首期范围列为待确认。

### 1.3 G0—G3 验收阶段不能混用

| 层级 | 能证明什么 | 不能证明什么 |
|---|---|---|

| **G1 真实人物与声音样片** | 冻结人物和声音资产、真实音频驱动样片及许可/质量证据 | 持久恢复、完整内容生产与发布包、真实自动发布 |
| **G2 V1 真实生产与发布就绪包** | 真实图像/TTS/数字人链路及质检通过，得到可追溯成片、字幕、封面、文案、AI 标识与 manifest；可经人工发布并留证 | 全自动定时发布；人工点发布或扫码确认的成功仍仅属于 G2 |

## 2. 总体路线候选

| 路线 | 可能收益，尚待验证 | 主要代价/缺口 | 对比时须回答的问题 |
|---|---|---|---|
| 云 API 生成 + 自有编排与质检 | 图像编辑、固定音色 TTS、音频驱动数字人各自适配；保有原始资产、账单与质量证据 | 多供应商契约、长期异步任务、身份及声音回归、外部费用与权限管理需要自行实现 | 能否保持人物/声音并取得完整证据；质量、总成本与故障恢复是否达标 |
| 一体化数字人 SaaS/企业服务 | 如 HeyGen、国内企业数字人平台，可能减少形象和渲染集成工作 | 自定义全 AI 形象、外部音频、资产导出、API 价格、商用授权和发布权限须核验；网页套餐不等于 API 套餐 | 在相同输入下能否满足人物/声音固定、证据导出和总成本要求 |
| 本地/自托管开源生成 | 控制部署、版本和资产；可能减少持续 API 支出 | 目标设备上的质量、时延、显存和依赖许可均缺完整验证；有算力、电费、维护、权重授权成本 | 真实设备上能否通过同样的质量、稳定性与商用许可门槛 |

三种路线等位列出，允许逐环节组合；首轮两家云口播候选不意味着已选全项目云端架构。所有路线都不能绕开发布资质。数字人供应商提供视频，不等于它有权代发抖音。本文不填入未经测试的质量排名或出片分钟数。

## 3. 基础技术栈候选与待测指标

从空工程建设是已确认边界；语言、框架、数据库、任务执行方式、前端和存储均未选定。以下候选不按优先级排序，也不因列在前面而成为默认值。先定义同一能力测试，再记录各候选结果，最后决定工程结构、包名、依赖及部署方式；本轮不创建生产工程。

| 模块 | 等位候选 | 共同待测指标 |
|---|---|---|
| API 与契约 | Python + FastAPI/Pydantic；Python + Django；Node.js + 对应校验框架 | 同一请求集的严格校验、错误模型、鉴权、媒体工具调用、依赖兼容、启动资源与部署维护成本 |
| 主状态数据库 | SQLite WAL；PostgreSQL | 并发任务与预算原子性、唯一约束、锁等待、崩溃恢复、备份恢复、目标机器部署成本 |
| 向量存储与检索 | 数据库记录 + 应用层精确检索；pgvector；独立向量索引 | 同一语料的召回质量、数据规模变化、更新一致性、延迟、内存与运维成本；与 embedding 选型分开 |
| 任务执行与调度 | 自建持久任务执行器；Celery + Redis + 持久业务状态；Temporal | 崩溃、重复唤醒、过期执行者回写、提交响应丢失及恢复接管；计费去重、部署支持与维护负担。APScheduler 等唤醒工具不能单独证明持久恢复 |
| 媒体资产 | 本地受控资产库；私有对象存储；两者组合（对象存储服务如 TOS/OSS 另行对比） | 候选接口实际支持的上传/取材方式、访问权限与有效期、下载哈希、备份保留、空间和流量账单 |
| 视频和音频处理 | FFmpeg/ffprobe；媒体处理库或服务的等功能组合 | 同输入的编码兼容、音画同步、画质、标识保留、解码、处理时延与成本；生成式增强另验身份漂移 |
| 管理工作台 | Vue + TypeScript；React + TypeScript；Streamlit；必要时评估 Electron/Tauri 壳 | 同一任务、预算、审查、预览及失败恢复流程的可用性；构建、类型契约、浏览器兼容与维护成本；原生能力是否确有需求 |

具体版本、目标操作系统、设备资源、并发和数据量须在该环节测试前记录；不能用框架名称代替持久性验证。没有测试结果前，不以“首期不强制”“规模扩大后再换”提前淘汰其他候选，也不把 SQLite 或 Vue 写成方案默认值。

新工程从 schema 第 1 版、独立配置命名空间和空资产库开始。Base Avatar、参考图、服装背景素材、VoiceAsset、基准音频、测试夹具与阈值标定集均为本项目重新生成或重新取得授权的资产；首次声音创建/注册产生新的音色记录与审批。Mock 从零编写确定性契约模拟，仅生成测试所需的固定响应和带模拟标记的测试媒体；离线负例另行构造，不承担真实人物预览或口播能力。

### 4.2 解耦的含义

Base Avatar 是只读的原始身份资产及版本；outfit、background 分别有自己的描述、参考素材、许可与版本。单次参考图编辑、受保护区域编辑和分层合成是待比较的实现方式，**逻辑独立不要求分别生成三层再硬拼**。采用哪种方式由同身份样本的实测决定。

模型仍可能重绘面部，所以“Base Avatar 原件不变”不代表“生成图脸部像素不变”。每次输出都必须重新检查身份、发型和肤色等不变量。seed 只用于复盘和限定条件下的复现，不能用它证明身份锁定。

确需严格固定人物像素或复用固定背景时，可以评估头部保护 mask 编辑或 BiRefNet 抠图合成，但须独立验证发丝边缘、光照、衣领和颈部衔接。抠图不证明换装能力；重着色、几何领型绘制不能代替所需的真实服装编辑。

### 4.3 身份门禁与许可证

- 待比较许可合格的人脸检测/embedding、发型/肤色/年龄感视觉检查、人工金标复核及其组合；具体实现为 `UNSELECTED`。模型未定前不能写死 InsightFace、ArcFace 预训练权重为生产依赖。
- **ArcFace 是算法/损失范式；具体代码、权重、训练数据及依赖分别有许可。** R02 记录的 InsightFace 预训练模型非商用研究限制，不能以“仅在内部质检”“代码 MIT”或外包一层接口规避；必须取得适用授权或更换具备完整许可证据的实现。
- 人脸 embedding 只覆盖部分身份特征，不能单独证明发型、肤色、性别呈现全部固定，也不能证明不侵犯任何真实人物权益。禁止凭 0.60 等未标定常数自动放行。
- 为新项目独立建立有来源的同人/不同人、换装/换背景、光照/姿态、明显漂移正负例集。门禁阈值从新样本标定；误放率、误拒率及人工一致性记录通过评审后才启用自动放行。
- 无可用合法门禁时，G2 可进入人工复核队列并明确记录；自动质量门禁未解决，不能声称全自动生产质量闭环成立。

许可历史线索：[R02 §2.3、§9—10](../research/02-人物一致性生成.md)、[R06 §2.4](../research/06-决策汇总.md)。GFPGAN/CodeFormer 等重建工具如进入候选，必须单独检验身份漂移、自然度和许可，不能直接启用；不以未授权公众人物脸库开展“撞脸筛查”。

### 5.2 固定声音与表达的技术边界

Voice Asset 至少绑定 provider、模型/快照、地域、voice_id、参考音频哈希、来源/授权、基准音频、参数版本。provider 或 model 变化属于资产兼容性事件；重新注册属于新版本，不能覆盖旧版。seed 可以记录，但不是跨模型保持音色的证明。

表达采用结构化标注：停顿、重音、情绪、语速和读法与正文分离，由确定性编译器映射到已验证的服务能力。不支持的标注应明确报告或进入经批准的有限降级，不能宣称用标点已经实现精确毫秒停顿。内容不应在表达标注阶段被悄悄改写。

最终音频须校验可解码、实际时长、削波、异常静音、缺字/错读、音色与段间连续性。说话人相似度可比较许可合格的 speaker embedding 与盲听方法；不能因为 ASR 库存在就假定其提供声纹能力。具体模型、阈值与盲听样本集尚待确定。已批准音色不可用时停止或等待，不自动换成任意通用声音。

查重阈值须在新建人工标注集上标定，本文不设置可直接放行的初始相似度常数。查重覆盖新系统积累的账号历史与已排期待发布内容；固定栏目名、必要术语可以单独标记，但不能因此豁免开场、论点和例子的重复。

### 7.3 事实核查是证据门禁

事实门禁须能从断言追溯到证据及其支持程度、适用时间与冲突；具体检索、匹配、判定工具为 `UNSELECTED`。候选实现须保留来源、发布时间、采集时间、快照哈希、相关段落和判定依据，不能拿模型自身记忆作为外部证据。

维护的本地知识库、获授权的在线检索及二者组合应按同一断言集比较；涉及价格、模型版本、政策等时效事实，资料过期必须刷新或阻断。断网时可以生产不依赖时效信息的合格内容，不能给“时效性”虚拟高分。

无证据或证据矛盾时删去断言、补充可靠来源或进入复核；**加“据称”“可能”不会自动把无依据结论变成合格事实**。链接 HTTP 200 只说明可访问，不证明内容支持断言；LLM judge、关键词评分也不能替代事实核查。规则评分用于文字风险和重写建议，事实、许可、身份等硬门禁不能被高总分抵消。

此流程由原始需求中的内容正确性、时效性、去重与自动重写目标独立设计。重写次数、费用和策略须有限；保留历史版本，不能通过降低门槛“刷过”验收。

| 封面 | 合格成片抽帧或已批准身份图 + 已授权字体排版；排版工具待对比 | 封面须与成片为同一人物，标题兑现正文；不能通过另造人脸改善样例 | 清晰度、标题、安全区、字体授权、平台实际规格、批量一致性 |
| AI 标识 | 显式画面标识、合规元数据、发布声明的具体实现组合 | 按适用规则覆盖必要方式；自定义 `ai_generated=true` 或单个 `comment` 不证明合规，manifest 不代替媒体标识 | 核对适用标准和平台字段，验证转码后保留/正确重建、播放器可见、声明传递并留证；失败阻断发布 |

字幕必须使用与最终旁白时间轴一致的音频：若在数字人生成后进行剪裁、拼接或变速，对字幕及音画同步做重新验证；改变旁白内容通常要重新驱动对应视频。ASR 用于发现实际说出的内容，对齐用于将经过核对的稿件映射到时间轴，不能把 TTS 漏读的词硬塞进字幕。最终音轨有 BGM 时优先对齐保留的最终旁白母版，再验证其与混音时间轴一致。

响度 `-14 LUFS`、峰值 `-1.5 dBTP`、CRF 20、字幕每行约 14 字等是基于移动端口播清晰度、响度余量与可读性提出的新工程起点，须在新样片上检验，不是已验证的平台强制标准。720P 放大只满足容器尺寸，画质是否达到 G2 必须另验。

外部能力与规则依据：[R05 §1.1—1.6、§3.1—3.3、§9、§11](../research/05-视频后处理发布与合规.md)、[R04 §3.5](../research/04-TTS音色与内容生成质检.md)、[R01 §5.1—5.4](../research/01-产品形态与抖音生态.md)。R01 记录了法规原文，R05 列出未核验的技术细节；据此设置标识硬门禁，但不把任意自定义元数据当合规结论。

## 9. 持久编排、费用与供应商切换

持久编排实现为 `UNSELECTED`，候选见 §3。共同验收要求是保存任务、阶段 attempt、外部 job_id、资产哈希、产物、事件、预算预留和实际账单，并证明重复唤醒、执行者过期和崩溃恢复不会产生未经授权的重复收费。数据库、队列和工作流引擎须在同一故障集上测试。外部调用期间不能长期持有数据库事务；任何框架或消息队列名称都不自动给予外部 API 恰好执行一次的保证。

每个 Adapter 应区分能力声明、成本估算、提交、查询、下载和结果验证。幂等键覆盖人物/场景/声音资产版本、最终音频哈希、provider、model、参数及目标阶段；本地幂等键不会自动让服务商具备幂等能力。

**付费动作默认关闭，单任务、每日、每月额度默认均为 0。** 额度为 0 表示不允许付费，不能解释为无限制。真实生产须得到明确的服务、金额、次数、试验范围和重试授权；本文件候选清单、历史报价及首轮环节选择均不构成授权。提交前原子预留预算，执行后对账；未决费用保持预留，不能提前释放供其他任务消费。

| 情况 | 建议行为 |
|---|---|
| 尚未提交，预算不足/服务未准入/音色不兼容 | 阻断执行并记录原因；不得自动换质量档或另开新音色 |
| 提交后超时、连接中断，是否受理未知 | 进入待对账状态，保存请求指纹与已有 job_id；查询状态/账单或向服务商核对，**不立即重发或跨供应商提交** |
| 只读状态查询遇到可恢复网络错误 | 在有限次数、期限和速率内重试；重试查询与重试生产提交分开统计 |
| 明确失败且服务商确认未受理/未产生待结算任务 | 依用户已批准的次数与预算决定是否新 attempt；默认无额外付费重试 |
| 生成成功但内容不合格 | 保存失败证据；重生成属于新付费动作，必须有剩余额度和明确授权；不降低质量门槛 |
| worker 崩溃/断电 | 按数据库阶段和外部 job_id 恢复查询；不能从头执行整条链 |
| 云服务失效，需要切换 | 仅可选择另行通过身份、音色、质量、许可及成本准入并获授权的服务；保留原 attempt，切换有显式事件。当前没有已经选定的替代服务 |

媒体交付方式须按候选接口实测确定；如果使用临时取材 URL，须验证私有资产签发、拉取、重定向、鉴权和有效期。任务尚未结束或需要对账时不能机械执行“一天删除全部素材”。区分临时公网访问权限与私有原始证据保留周期，日志不得落密钥或可直接访问的签名 URL。

此处保留收费异步服务的副作用与用户预算边界要求，不指定执行器。默认 0 额度、未知提交先对账是新系统约束；任何模型报价、配置示例或候选路线均不授予付费权限。

## 10. 发布技术与能力矩阵

### 10.1 不用某一份调研的推论替代需求

R01 §6 记录创建视频 API 文档和权限要求；R05 §6 记录 SDK/H5 分享能力、主体准入及用户操作规范；R06 将它们收敛为放弃全自动。用户现已选择 V1 先交付 G2、G3 后续单独验收。技术上仍采用更窄结论：**现有证据没有证明本项目账号具备合法无人值守发布能力，G3 当前不能启用；但最终目标仍保留，也不能推断所有主体、应用类别和通道永久不存在服务端发布可能。**

无凭证请求返回鉴权错误，最多作为网关/路由行为线索；不能证明上传、创建、预约或查询对当前账号可用。某个目录未列出接口也不能单独证明全平台不存在该能力。R05 记录的企业注册资本/成立年限等准入要求，只能作为对应能力与当时版本的线索，不能泛化成所有发布通道的共同资质。

### 10.3 G3 放行与状态真实性

准入须同时取得：具体账号与应用的能力开通证据、有效 OAuth/委托授权、允许自动排期与触发的明确依据、AI 声明传递方案，以及经授权的真实端到端投稿与状态回读记录。若现行规则要求逐条人工操作，则该通道只可提供 G2，G3 继续阻塞；不能用一次泛化授权消除规则要求。

状态严格复用《接口契约与数据字典》：V1 发布包 `ready → awaiting_human → reported_published`，人工回填不能转成 `published`；后续 G3 获得准入后使用 `scheduled/submitting → submitted → published/rejected`。`submitted` 可包含平台审核中，上传进度保存在操作事件，不新增同义发布状态。HTTP 200 必须同时验证业务错误码、必要结果字段及外部 ID；不同接口版本按真实契约处理，不能简单“未发现 error_code 就成功”。发布提交结果不明用 `unknown`，只有官方状态响应或验签回调证据才能标为 `published`。

提交响应丢失遵循先查询对账原则。若找不到可靠查询或去重机制，停止自动再次发布，避免同一条视频被重复投递。到点触发与平台审核完成是两件事；系统不能承诺审核时延或保证指定秒数公开可见。

依据：[R01 §6、§9](../research/01-产品形态与抖音生态.md)、[R05 §5—7、§11](../research/05-视频后处理发布与合规.md)、[R06 §2.1、§4](../research/06-决策汇总.md)。

## 11. 成本计算方法与历史价格算例

### 11.1 一次性资产与逐条费用分开

定义：

```text
C_asset = N_base_candidate × P_image
        + N_voice_design × P_voice_design
        + C_voice_register + C_license_or_setup

C_video = C_script + C_retrieval + C_embedding + C_TTS
        + N_new_scene_candidate × P_image
        + C_talking_head + C_ASR + C_storage_egress
        + C_compute + C_publish + C_billable_failed_attempts

C_TTS = billable_characters / 10000 × P_TTS_per_10k
C_talking_head = Σ [round_up(segment_seconds, billing_unit) × P_per_second]
                + N_detect × P_detect + other_provider_fees

C_month = C_asset_created_this_month + Σ C_video + C_fixed_monthly
```

`N_base_candidate` 是一次性定妆/参考图候选总数；已经存储并复用的参考图不应每条视频再计一次生成费。`N_new_scene_candidate` 只统计本条实际新增的场景图候选及被计费重生，复用已合格场景图时为 0。若供应商对输入图片收费，应另计实际输入费，不能混入输出张数。

R06 沿用“每条约 6 张图”的预算假设，必须先区分这 6 张是一次性资产、每条场景候选还是重新计费的参考输入；不能把一次建立的 Base Avatar 及 4 张参考图重复作为每条生成支出。开源、FFmpeg 和本地后处理虽然可能无 API 费，但算力、电费、存储、工程维护并非零成本。

### 11.2 60/75/90 秒算例

以下仅保留旧价例算来展示计算方法，**不是当前报价、已选方案、选型依据、正式采购预算或付费授权**。价格取自既有调研，尚未确认当前产品版本、税费、成功/失败计费、取整规则及账号资源包。不计赠送额度。实际字数、音频时长、计费秒数及请求次数以核验后的计价规则与真实账单为准；不得按此表直接比较候选性价比。

算例假设：正文每秒 4 个汉字；阿里 TTS 每汉字按 2 个计费字符，示例使用 R04 的 CosyVoice Plus 1.5 元/万字符（前提为已完成合法音色注册及兼容验证）；每条新场景图 1 张，按 R02 的 0.50 元/张；数字人价格采用 R03 的火山 1.00 元/秒、阿里 720P 0.90 元/秒、480P 0.50 元/秒。没有分段重叠、失败或取整附加费用时：

| 音频时长 | 示例汉字/计费字符 | TTS | 新场景图 | 火山数字人 | 阿里 720P 数字人 | 阿里 480P 数字人 | 火山路径三项小计 |
|---|---|---|---|---|---|---|---|
| 60 秒 | 240 / 480 | ¥0.072 | ¥0.50 | ¥60.00 | ¥54.00 | ¥30.00 | **¥60.572** |
| 75 秒 | 300 / 600 | ¥0.090 | ¥0.50 | ¥75.00 | ¥67.50 | ¥37.50 | **¥75.590** |
| 90 秒 | 360 / 720 | ¥0.108 | ¥0.50 | ¥90.00 | ¥81.00 | ¥45.00 | **¥90.608** |

三项小计仅含数字人、示例 TTS、新场景图；不包括 LLM、检索、embedding、ASR、detect、输入图费用、存储/下载、云主机、许可、订阅、税费及失败重生成，不能称“全链路总成本”。如果走 Voice Design 兼容的 Qwen TTS 路径，应替换其实际单价和字符规则，不能套用 CosyVoice 音色或价格。

沿用旧调研的纯算术假设：阿里 75 秒示例若切为 5 段、每段约 15 秒且无重叠，720P 数字人费用为 `5 × 15 × 0.90 = 67.50` 元；若每次接缝额外生成 0.5 秒，共 4 处，则按生成总长 77 秒估为 69.30 元。假设每段另做一次 detect，按 R03 旧价 0.004 元/张再加 0.020 元。**这不是当前接口要求分段或 detect 的证据。** 实际限制、分段策略、计费粒度与 detect 能否复用都须重新核验；这里也不视为成片质量已合格。

一次性资产的旧价例算：6 张定妆/参考候选 × 0.50 元 = 3.00 元；一次声音设计按 R04 旧价 0.20 元估算，则**两项算术小计为 3.20 元**。目标 TTS 注册费、迁移授权和其他候选费用尚未确定，另行增加；不能用 3.20 元声称音色跨模型链路已完整开通。

按每条 75 秒、每月 30 天估算：

| 设计产能 | 月条数 | 月成片分钟 | 火山路径三项小计 |
|---|---|---|---|
| 1 条/天 | 30 | 37.5 | ¥2,267.70 |
| 2 条/天 | 60 | 75 | ¥4,535.40 |
| 3 条/天 | 90 | 112.5 | ¥6,803.10 |

上述月小计另加当月新建资产和其他全部费用。若复用同一已合格场景图，分别减去 15/30/45 元的图像生成假设；若每条确实新增 6 个候选，则在“1 张”假设上每条增加 2.50 元。R03 中“1.5 分钟、3 条/天、30 天”应为 **135 分钟/月**，不能沿用原表的 180 分钟。

参考：[R02 §8](../research/02-人物一致性生成.md)、[R03 §7](../research/03-数字人口播选型.md)、[R04 §8](../research/04-TTS音色与内容生成质检.md)、[R06 §1](../research/06-决策汇总.md)。实际端到端延迟、通过率、质量返工率均未知；不以调研单价外推“稳定日产 3 条”或确定 ROI。

## 12. 逐环节决策门禁与 ADR 记录
