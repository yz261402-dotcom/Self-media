## 1. 系统的起点与终点

用户日常输入可以只有：

> 生成一期关于 RAG 的 AI 科普视频。

系统从栏目配置补齐：目标受众、目标时长、已批准主播、已批准音色、服装背景组合、字幕样式、预算、计划发布时间及其时区。若没有完成主播/声音建档，先进入第 2 节，不能临时随机换人。

一次任务的逻辑输入示例，**这是设计示例，不是已经生成的本期内容**：

```json
{
  "主题": "RAG 科普",
  "受众": "刚接触 AI 的普通用户",
  "目标时长秒": 60,
  "主播": "已批准的基础角色版本",
  "声音": "该角色绑定的声音版本",
  "服装背景": "蓝色西装＋AI 教室",
  "发布计划": {"当地时间": "2026-09-22 20:00:00", "时区": "Asia/Shanghai"}
}
```

目标主流程：

```text
主题或自然语言请求
  → 任务参数与历史检索
  → 可信资料包
  → 选题角度、标题、简介、分段口播稿、标签
  → 内容查重与事实/表达质检（不通过则有限重写）
  → 锁定人物变体与声音版本
  → TTS 朗读计划 → 最终旁白音频 → 音频质检
  → 固定人物画面＋旁白 → 真人数字人口播原片
  → 原片质检与时间线确定
  → 字幕时间轴、封面、后处理
  → 成片质检
  → 发布就绪包与发布任务
  → V1 人工投稿/回填；取得官方能力后 V2 自动投稿/查询结果
```

**V1 最终交付：** 1080×1920、9:16、MP4/H.264/AAC 视频，封面、SRT/ASS 字幕、标题/简介/标签、质检报告、来源与模型记录、成本台账、排期任务。人工完成投稿后记录其结果。

**后续自动发布验收的最终结果：** 上述发布包经过已验证的官方 Adapter 上传和投稿，取得平台作品 ID，查询并保存实际发布状态。上传成功、平台受理、审核通过、作品已发布是不同状态。

## 2. 首次准备：角色与声音建档

这一条支线是长期资产初始化，**不是每生成一期就重新做一遍**。

### 2.1 创建基础人物

- **输入：** 人物设定：成年男性/女性、年龄感、五官和发型描述、正面胸像/半身构图、自然肤质、专业亲和的摄影风格。
- **本项目已试：** 百炼 `qwen-image-2.0`，已生成 [测试人物](../../experiments/数字人口播选型/inputs/测试人物.png)，1080×1920。它尚未被批准为正式 Base Avatar。
- **当前选定：** `gpt-image-2`，通过用户专用中转站调用，状态 `SELECTED_BY_USER / PENDING_ACCEPTANCE`；生成接口已取得 B/C 候选，用户已确认人物 B，资产 ID 为 `av_base_b_v1`。原图 941×1672 未达到请求尺寸，参考图编辑仍待实测。旧 `qwen-image-2.0` 输出保留为对照；Seedream 仅保留历史备选记录。[S1][S2][S16]
- **输出：** 基础人物 PNG、人物身份说明、模型/提示词/参数记录、SHA-256、审批记录。后续引用同一不可变角色版本。
- **验收：** 正常人脸与比例、五官/发型完整、无明显绘画/塑料感。重复同一提示词不能作为身份锁定机制。

### 2.2 创建服装与背景变体

- **输入：** 已批准的 Base Avatar 参考图＋指定服装＋指定背景＋保持人脸/发型/肤色/年龄/比例的约束。
- **当前选定：** 同一 `gpt-image-2` 中转渠道的参考图编辑能力，状态 `SELECTED_BY_USER / PENDING_ACCEPTANCE`。中转接口与图像输入方式需实测，不能仅凭模型名称假定编辑能力已开通。Qwen 编辑与 Seedream 留作按需对照。[S2][S3][S16]
- **技术：** 参考图编辑；支持时使用明确保护区域。批准后的变体登记、缓存复用。
- **输出：** 一个固定角色的多个 AvatarVariant，例如西装演播室、休闲上衣教室。每个变体有独立版本与图片摘要。
- **下一步：** 变体通过身份检查后才供数字人口播取用。当前换装/背景一致性尚未实测。

### 2.3 固定声音

- **本项目已试：** `qwen3-tts-flash`＋系统音色 `Cherry`，产生了 9.36 秒真实 WAV；这是临时基线，并非专属声音设计结果。
- **当前选定：** MiniMax Speech 2.8 HD，官方直连，准确请求模型 `speech-2.8-hd`，状态 `SELECTED_BY_USER / PENDING_ACCEPTANCE`。[S16]
- **声音已登记：** 用户已确认音色 3“温暖闺蜜”，固定 `voice_id=Chinese (Mandarin)_Warm_Bestie`，声音档案 ID 为 `voice_minimax_warm_bestie_v1`。基准参数为 speed=1、vol=1、pitch=0、emotion=calm；已保存 32kHz 单声道、15.218844 秒试听。多稿件及生产质量仍待验收；没有沿用 Cherry，也不把换到 MiniMax 写成同音色已迁移。
- **专属声音路线：** 如后续明确需要声音设计/克隆，须核对所选 MiniMax 服务的创建、授权和合成兼容性后单独验收。Qwen 与 Fun-CosyVoice3 保留历史备选，不默认另装或自动调用。[S4][S5]
- **输出：** provider、准确模型/快照、voice_id 或参考音频摘要、注册信息、基准句音频、发音词典、参数与权利来源。
- **限制：** 不同模型的 voice_id 不自动通用。改 TTS 或重建声音需要声音重新验收，不能把跨模型声音不同误当同音色性能对比。

素材创建与每期生产分开缓存。输出资产必须带真实模型/版本、输入摘要和来源，不能用后续同名文件覆盖原有结果。

### 3.1 内容质量与事实错误怎么处理

查重对象分别是正文、主题、论点和例子。embedding 返回“哪些历史内容相近”，不直接决定是否抄袭或事实正确；用标注集确定阈值，并检查同题不同角度的误杀。

事实核查按“断言 → 证据原文 → 来源日期/采集日期 → 支持、矛盾或证据不足”记录。价格、模型能力、版本等时效事实须有当前可靠来源。换一个 LLM 打高分不等于事实核验。资料缺失时补证、删去断言或复核，不能只加“据说”后放行。

目标时长先按已测音色语速估算；TTS 后以真实音频长度为准。超过目标时长则回到稿件压缩，改变稿件会令旧语音、口播、字幕失效。不能只修改任务上的“时长”字段。

### 3.2 TTS 情绪与停顿不是统一 SSML

内部朗读计划可以包含“停顿、重音、情绪、语速”，但各模型支持项不同。Provider 只把支持项编译成真实接口参数/指令，不向不支持的 API 塞任意 SSML。

当前目标 Provider 为 MiniMax 官方 `speech-2.8-hd`。按所选接口实际支持项映射朗读计划，并分别验证中文术语、数字读法、停顿、情绪、固定音色与长文分段衔接。未支持或尚未验证的表达项应明确记录，不能把内部标签存在当作模型已执行；固定 `voice_id` 已确认，表达控制与长稿验收通过后才进入正式批量合成。[S16]

**已试 `qwen3-tts-flash` 不支持指令控制、声音设计或声音复刻。** 它证明了基本 TTS 可调用，未满足全部表达控制要求。[S4] 系统不能把 Cherry 基线的出声成功当作专属声音/情绪能力已通过。

### 3.3 MuseTalk 的自然动作从哪里来

MuseTalk 1.5 已按用户成本决策选为自部署口播路线，质量验收仍为 `PENDING_ACCEPTANCE`。单图模式主要重绘脸部区域，当前样片头部和眼睛基本静止。它能提供唇形驱动，但尚不能满足完整自然主播要求。

一种需要单独验收的组合是：用相同人物图和参考音频通过阿里/火山生成一次合格动作母版 → 固定母版 → 每期由 MuseTalk 用新音频重驱动。它仍是图像＋音频数字人口播路线。母版的动作、初始生成成本、身份变化与重复感都必须计入组合方案。

这段组合描述记录已做实验与待验证方向，不意味着自动调用阿里/火山制作新母版。正式动作来源尚未选定；需要先定义母版规范、成本和长片验收，再安排独立任务。

本项目现有缓存样片采用这一组合，不能列为“独立 MuseTalk 单图”与另外两家直接比。9 秒母版用于 60 秒视频会产生循环/接缝问题，长片未验证之前不能声称已经解决。也可以采集具有适用权利的真人动作素材，但当前项目没有这类已批准素材。

### 3.4 字幕必须绑定最终音轨

尽量保留 TTS 为最终旁白，先确定原片与音轨是否完整对齐。若原片存在漏字/时移，先解决并冻结时间线，再生成字幕；不能给缩短后的音轨直接套原 TTS 时间戳。

字幕可从 TTS 真实时间戳（仅限具体型号验证后）或 ASR 的词句时间戳得到，再与批准稿件核对。显示“RAG”但读为中文/字母时记录显示与发音映射。ASR 猜错术语不能直接改掉原稿；必要时用已验收的强制对齐方案。按字数平均分时间不能通过字幕验收。

### 3.5 后处理的能力边界

FFmpeg 能规范分辨率、帧率、响度与编码，不能凭空恢复真实脸部细节、补回漏读内容或自动纠正错误口型。1080×1920 的画布不等于人脸本身原生高清。

黑帧/首尾静音先定位，再结合语音时间线判断是否允许删除；禁止盲目裁切有声片段。确需剪辑时统一更新视频、音频、字幕与片头偏移，并重新做成片检查。面部增强模型先不默认加入，避免修复导致换脸。

### 4.7 视觉与音视频质量辅助模型

| 项目 | 当前实现方向 | 模型候选/边界 |
|---|---|---|
| 格式、黑帧、静音、音量、帧时间戳 | FFprobe/FFmpeg、NumPy/SciPy | 不需要生成模型；已有部分实验测量，生产门禁未开发 |
| 五官/服装/背景变化、明显视觉伪影 | 关键帧对比与人类复核；评估视觉 LLM 辅助 | `qwen3-vl-plus-2025-12-19` 为待测候选 [S14]，不能当生物识别/精确身份保证 |
| 字幕错读、漏字 | 原稿＋ASR 回识＋人工金标 | 复用 4.6 的 ASR，不另外虚构一套“音频质检大模型” |
| 精确唇音同步 | 音素标注与逐帧评审，未来另选检测器 | 检测模型未选定；当前波形相关只测音轨保持，不能代表嘴型误差 |
| 画面增强 | 首期保留规范化基线 | 暂不默认接 GFPGAN、CodeFormer 或 Real-ESRGAN；若原片不合格，先评估上游与增强对身份的影响 |

自动质量门禁不完整时要如实进入待复核，不能把模型的“看起来不错”变成生产验收。代码和权重许可分别核对，不默认启用有研究用途限制的人脸权重。

## 5. MuseTalk 内部还包含哪些模型

即使业务只调用一个 MuseTalk Provider，算力云环境实际还有以下依赖；用户做自托管技术对比时应把整套算力和许可纳入成本。

| 组件 | 已部署权重/身份 | 作用 |
|---|---|---|
| MuseTalk 1.5 UNet | `models/musetalkV15/unet.pth` | 根据图像特征和音频特征生成脸部区域 |
| VAE | `stabilityai/sd-vae-ft-mse`，本地 `models/sd-vae/` | 脸部图像的潜空间编码/解码；不是文生视频 |
| Whisper tiny | `openai/whisper-tiny`，本地 `models/whisper/` | 该口播链路中提取音频特征；不表示字幕已经实现 |
| DWPose | `dw-ll_ucoco_384.pth` | 预处理中的人体/面部位置线索 |
| BiSeNet 人脸解析 | `79999_iter.pth`＋ResNet18 `resnet18-5c106cde.pth` | 生成脸部区域遮罩与融合所需信息 |
| S3FD | `musetalk/utils/face_detection/detection/sfd/s3fd.pth` | 人脸检测依赖；是否实际走到某分支以执行日志为准 |

上述均已下载并留存摘要，见 [权重清单](../../experiments/MuseTalk部署/MT-001/远端证据/weights-manifest.json)。业务选型首先比较 MuseTalk 整体输出；独立更换 VAE/Whisper/检测器会形成新的实验组合，不能与已测版本混用。

## 6. 非模型技术栈：建议测试的两套组合

现有生产系统还没实现；下面是用于工程选型的明确组合。MuseTalk 的自部署方向已由用户选定，其余前后端、存储和任务框架**不因模型选定而自动成为 SELECTED**。

| 层级 | 单人工作台优先候选 A | 扩展候选 B | 输出/选择依据 |
|---|---|---|---|
| 前端 | Vue 3＋TypeScript＋Vite | React＋TypeScript＋Vite | 输入任务、素材管理、预览、逐项审查；用同工作流比开发/使用成本 |
| API/契约 | Python＋FastAPI＋Pydantic 2 | Python＋Django/DRF | 校验结构、任务查询、鉴权；与模型推理隔离 |
| 任务和资产元数据 | SQLAlchemy 2＋SQLite（本机单写/有限并发） | PostgreSQL＋SQLAlchemy 2 | 持久记录、事务、恢复、备份；实际并发与迁移代价决定 |
| 向量索引 | 小语料用版本化向量＋NumPy 精确检索 | PostgreSQL＋pgvector | embedding 版本/维度隔离；不要早期就强制多个向量服务 |
| 执行和定时 | 数据库持久任务＋独立 Worker；APScheduler 只负责唤醒 | Celery＋Redis＋持久业务状态，复杂工作流再比较 Temporal | 重启恢复、租约、重复触发与未知受理，不把内存定时器当可靠队列 |
| 媒体资产 | 本机不可变文件＋SHA-256，SSH/SFTP 与云 Worker 传输 | 私有 S3 兼容存储/OSS/TOS＋临时授权 URL | 原图/音频/原片/成片留存与引用，数据库不塞视频二进制 |
| GPU 执行 | 用户已选现有 Linux 算力云自部署 MuseTalk；隔离环境已有实测 | 是否封装独立 GPU 容器/Worker 服务仍待工程验证 | 自部署方向 `SELECTED_BY_USER`，服务化、冷热运行/空闲费用和失败恢复仍待验收 |
| 视频/封面 | FFmpeg＋FFprobe＋libass＋Pillow | 需要后再测试其他处理工具 | 编码、字幕、封面、响度与时间线，工具不冒充生成模型 |
| 发布 | PublishAdapter：V1 发布包/手工回填 | 权限验证后的官方抖音 API Adapter | 区分受理/审核/发布，不采用假设存在的网页自动化接口 |

**建议先验证 A 的理由：** 当前单人、本机工作台、一个 GPU 实例，额外常驻服务应有实测收益再加入。若并发、多账号和恢复能力测试不满足，再选择 B 对应组件。框架选择与模型选择分开，不因为某云 API 测试成功就自动选择数据库或前端。

MuseTalk 现有环境是 Python 3.10、PyTorch 2.0.1+cu118、diffusers 0.30.2、transformers 4.39.2、mmcv 2.0.1、mmpose 1.1.0、FFmpeg 4.4.2。此锁定环境不等于整个后端必须采用同一 Python 或依赖版本。[部署详情](../selection/01-数字人口播/04-MuseTalk部署与首测结果.md)

## 7. 模型接口怎么分，替换时才不会重写系统

这是逻辑接口，不是已经存在的生产代码；最终字段以 [核心契约](04-接口契约与数据字典.md) 为准。

| 接口职责 | 输入 | 输出 |
|---|---|---|
| TextProvider | 稿件任务、证据、结构规范 | 结构化内容、原文、真实模型与用量 |
| EmbeddingProvider / RerankProvider | 文本或文本对、模型版本 | 向量/排序结果、维度与版本 |
| ImageProvider | 新建描述或固定参考图＋编辑约束 | 图片资产、来源、参数、实际费用线索 |
| TTSProvider | 朗读计划、兼容的 VoiceAsset | 音频、实际时间信息与模型回执 |
| TalkingHeadProvider | 人物图/母版、音频、输出规格 | 提交结果、可查询任务 ID、原片 |
| TranscriptionProvider | 最终音频、语言与术语提示 | 识别文案、真实时间戳、误差与来源 |
| VisualReviewProvider（可选） | 参考图、关键帧、检查项 | 辅助问题清单；没有最终放行权 |
| PublishAdapter | 已批准发布包、排期、账号能力 | 上传/投稿/发布状态与官方证据 |

配置集中引用模型 ID、endpoint、region、voice_id、资源限额和密钥环境变量名。密钥不写入生成文档与发布包。Provider 的实际能力声明决定是否支持情绪、原生时间戳、参考图编辑等；Mock 始终带模拟标记，不进入真实验收。

模型比较至少保留请求模型/实际回执版本、原始输入哈希、提示词与参数、原始响应、时长、资源、费用、人工评审。第一次单样本可排除不可用候选，不能算总体成功率、P95 或长期产能。

成本分四层记录：首次资产/部署成本；每次模型调用与 GPU 活跃时间；开机空闲/存储/流量；人工处理与失败重做。最终看**每条通过质量验收视频的总成本**。秒级推理费用小，不代表租用全天的账单小。
