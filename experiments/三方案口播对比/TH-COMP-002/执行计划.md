# 同人物三方案口播对比执行计划

**目标：** 同一人物 PNG、同一 9.36 秒 WAV，比较阿里万相、MuseTalk 单图和火山 OmniHuman1.5，交付可本地打开的中文 HTML。

**范围依据：** 用户明确纠正为同人物的三个数字人口播方案，并要求样片、耗时、成本、质量对照表。复用已存在的阿里与 MuseTalk 原片；新增一次火山生成请求。取消新人物生图方向。

**隔离：** 本目录保存新请求与报告；不覆盖 TH-AB-001、MT-001，不访问 demo。当前项目不是 Git 仓库，以独立实验目录隔离。

**成本：** 用户本次生成要求为动作授权，不挪用旧轮 60 元预算。执行器自设 20 元预留限制，只允许一次 720P、原 9.36 秒音频请求，无自动付费重试。文档单价 1 元/秒，仅据此预估约 9.36 元；账户账单、取整规则及失败请求扣费须另外对账。预留并非账单。

- [x] 1. 先测试补测执行器：已有阶段禁止再次提交；异常后仍禁止重复；HTTP 失败不能当成功；原素材哈希严格验证。
- [x] 2. 使用已有官方签名工具和试验账本，下载核对远端素材字节，再单次提交火山接口；受理成功才查任务、下载、测量。
- [x] 3. 读取既有阿里与 MuseTalk 测量证据。新增样片如失败，保留错误及 request_id，不制作第三个假样片。
- [x] 4. 制作 HTML：三栏结果、同输入说明、耗时/估算费用/媒体规格/质量证据表、原音频、人像、完整证据链接。MuseTalk 动作母版仅作补充。
- [x] 5. 运行执行器测试、媒体解码、HTML 本地链接及浏览器桌面/手机检查。

主表采用阿里服务端提交至完成时间和 MuseTalk 进程总耗时，明确计时边界不同。所有成本均标估算或未知，未核对账单不写实际支出。全片人类视听评审保持待评，不凭静帧编造质量分。
