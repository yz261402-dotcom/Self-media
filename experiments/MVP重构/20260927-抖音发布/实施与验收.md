# 抖音浏览器发布首版

用户已确认采用 Playwright 操作抖音创作者中心，先实现单账号单条作品的即时发布。此能力通过网页操作实现，不冒充官方 OpenAPI。

## 实现范围

- FastAPI 发布 API、独立 `app/publishing` Adapter、SQLite 发布任务及浏览器占用记录。
- 专用 Chrome 持久化目录；用户首次扫码登录，程序根据可见页面验证账号。
- 只接收用户已确认的真实交付包；再次校验文件哈希及作品版本。
- 自动上传成片、填写可编辑标题/简介/话题、上传封面，并保留 AI 生成声明。
- 准备完成后展示账号与本次任务快照，用户确认后执行一次发布点击。
- 提交成功、结果未知、待登录、准备失败分别记录。结果未知不自动重试，也不能以取消后重建方式重复发布。
- 首版不包含定时调度、多账号、多平台、平台数据监控。其它平台入口保留开发中。

## 执行分工

1. 后端：先写门禁、幂等、并发确认及重启保护测试，再实现状态机及异步准备/提交。
2. 前端：先写状态与交互测试，再接登录、准备、恢复、确认、取消及状态轮询。
3. 浏览器：先用本地真实 DOM 验证只上传不发布、账号变化、表单变化、验证码、缺封面和重复点击保护，再检查真实网站。
4. 集成：隔离数据库回归、类型检查、构建、真实页面登录与最终验收证据。

## 边界

登录状态不由标记文件、用户自报或页面 URL 推断；无法读取账号时不能发布。专用 profile 仅存本机运行目录，不从用户日常浏览器提取 cookie，不记录密码或令牌。验证码由用户处理。

准备阶段会向抖音上传用户选择的已确认作品，但不会点击最终发布。最终确认同时绑定交付包、账号与文案版本。服务端在点击前持久化提交意图；超时或重启进入待核验，避免重复投稿。

网页选择器属于平台外部依赖：本地 DOM 测试不等于真实账号验收。真实账号尚未扫码前，上传表单不可见；必须如实标记该部分未验收。平台显示“提交成功”也不代表审核通过或公开可见，管理页地址不能作为作品链接。

## 已取得证据

- 真实匿名创作者中心上传地址展示登录介绍页，文件输入框与正文编辑器均不存在；不能只依据地址判断登录完成。
- Python Playwright 1.58.0 已安装，本机 Chrome 可用于测试与专用登录窗口。
- 浏览器 DOM 测试 6 项先红后绿：上传填表不提交、账号/文案变化阻断、单次点击、缺封面、假登录标记、验证码。

以下结果来自已保存的 [发布恢复记录](../20260928-发布恢复/恢复记录.md) 及其证据文件，本次文档收尾未重新运行测试，也不将历史结果作为当前运行状态。

- 真实账号曾完成同一作品的视频上传、标题/简介/话题填写、平台 AI 声明保存，以及 3:4 和 4:3 两张封面在主表单上的应用验收；当时任务进入 `ready_to_confirm`。平台仍提示封面“边框面积过大”，未宣称视觉质量全部通过。
- 最终发布未执行，提交回执、平台审核及公开可见性尚未验收。最终提交仍须用户核对账号、交付包与文案版本后确认。
- 后端重启会使尚未提交的准备状态中断，须显式恢复同一任务并重新核验；历史 `ready_to_confirm` 不能证明当前仍可提交，已经提交或结果未知的任务不得自动重传。
