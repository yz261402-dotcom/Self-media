# Claude 中转客户端兼容核验

## 已确认的事实

用户再次提供的 Airelay URL 和密钥与项目原配置完全相同。模型始终是 `claude-sonnet-5-5`。本机 Claude Code 会话在 10 月 1 日 15:00 成功返回该模型；不能将一条普通 API 的 `Upstream access forbidden` 直接解读为整个中转都不可用。

只使用假 token 和本机 loopback 捕获 Claude Code 的真实请求格式：实际模型会剥离 `[1m]`，使用 Bearer、流式、客户端专有 headers。捕获没有发送远端模型请求，安全摘要在 `production/runtime/cc-local-20261001/captured_safe.json`。

## 切换到灵算

按用户“可以换一个试试”指令，将项目 `.env` 中的 Anthropic URL 和密钥设为新值。没有修改共享密钥清单、Claude Code 全局配置或其他模型线路。密钥通过隐藏输入写入，不打印到日志。

免费 GET 测试确认：Python urllib 默认 UA 被 Cloudflare 1010 拦截；同一请求使用真实项目 UA `AvatarStudio/0.1` 或官方 SDK UA 即可进入 API。新密钥鉴权返回 200，模型列表包含准确的 `claude-sonnet-5-5`。

只发送一次获准的新线路小请求：`/v1/messages`，模型名不变，最多 64 输出 token。返回 HTTP 503，完整错误原文：

> No available accounts: this group only allows Claude Code clients

这把密钥所属分组仅允许 Claude Code 客户端。当前项目直接 API 调用会被拒绝。中转请求 ID：`bacf6003-7620-405d-9a54-299a17144d35`；探针作业 `job_b099a9257c5f`，一次 attempt、预留 1 分，实际费用未知。没有继续重试或运行准备中的两组兼容探针。
