## 2. 项目背景与目标（Why）

### 2.1 背景

单次生成一段视频不能支撑长期运营。账号需要可被观众识别的固定主播、稳定声音、
持续更新且不重复的内容，以及能够恢复失败、核算成本、追溯发布结果的生产流程。
`production` 已存在真实实现。本 PRD 定义 v2.4 目标契约；本轮已同步角色、Skill/MCP 工具边界及内部 Worker 入口；真实合成、字幕和清晰度处理仍待实现/验收，不把边界测试当生产完成。

产品定义：**供项目负责人单人自用的数字人口播工作台，以一条作品贯通人物、稿件、语音和成片。**
内容聚焦 AI 教学、科普、工具介绍、技术趋势与实战技巧，单条围绕一个清晰知识点。

### 2.2 目标

1. 提供真人外观角色库，每个人物选定后冻结身份并绑定默认音色；人物 B＋音色 3 是初始预设。
2. 从提示词/关键词、目标时长和用户提供资料开始，由 DeepSeek 直接生成三个不同角度的候选稿件；quality 反馈仅允许有限改稿，用户选择或编辑并确认。
3. 用户确认人物、稿件和最终 TTS 后，选择 OmniHuman 或 M2 生成口播；业务依赖满足后由 Worker 自动完成字幕、清晰度、封面、打包和登记，交付可预览、可下载的视频、字幕和投稿资料。
4. 七个功能入口完整呈现，页面明确区分可用、开发中和规划中，不将演示壳当作已完成能力。
5. 各阶段保留选择、版本、质量、费用与任务状态；页面关闭后可继续查看，返工只重做受影响产物。
6. 发布、排期回填、运营指标及完整模型选择能力后续逐项建设、独立验收。

### 2.3 非目标与备选取舍

- 首版不做团队协作、多租户、多账号矩阵、无人直播、移动端原生应用与素材交易。
- 首版采用用户逐步确认的生产工作台；全自动无人值守生产和发布保留为后续扩展。
- MVP 必须接入并独立验收 OmniHuman 1.5 音频驱动口播：固定人物图＋已确认最终 TTS＋可编辑表演描述，生成身体动作、表情及口型同步视频。M2 保留低成本本地选用，不能替代 OmniHuman 验收；不承诺任意动作。
- 用户已允许使用视频生成 API；两条口播路线均使用固定人物与已审已确认最终 TTS，纯文生视频不属于当前交付能力。
- 不用卡通、PPT 配音、静态头像或假嘴型替代真人数字人口播；不承诺流量扶持或涨粉收益。

## 3. 目标用户与画像（Users）

### 3.1 主要用户：项目负责人单人自用

- 在 Windows 桌面管理自己的作品，本机提供工作台与资产管理，云数字人 API 承担 OmniHuman 生成，租用算力云承担可选 M2 的重型推理。
- 主要生产 AI 教学、科普、工具、趋势和实战内容；需要亲自比较人物、稿件与声音后确认成片；对无依据的事实或最新信息，按待复核提示提供依据或人工确认。
- 能配置服务与预算，关注单条成本、耗时、返工原因以及任务能否恢复。
- 用户目标为每天 5 条、每条约 60 秒；吞吐与合格产出成本仍须实测，不代表已批准支出。

### 3.2 职责与扩展边界

同一用户承担创作、审核与运营职责。首版不建立团队账号和组织权限；专业智能体的工具权限仍必须受控。
多个角色资产供本人选择，不等同于多用户或多账号运营。未来多人使用需要单独设计数据与密钥隔离。

### 3.3 不服务的场景

冒用真人身份、无授权声音克隆、批量搬运、规避平台限制、以更换人物掩盖身份漂移。
多平台发布与数据监控在首版只呈现入口和规划说明，不形成可用能力承诺。

## 4. 用户故事与场景（User Stories）

- **US-01 角色定版**：作为创作者，我希望用关键词与自由描述生成人物候选并确认身份，
  以便今后作品复用同一人物；也能创建另一个独立身份而不覆盖旧角色。
- **US-02 逐步创作**：作为创作者，我输入“生成一期关于 RAG 的 AI 科普视频”，
  希望比较三个不同切入角度的合格稿件，选择、编辑并确认后再生成语音和视频。
- **US-03 换装换景**：作为创作者，我希望追加服装和场景要求，
  以便改变画面而保留脸型、五官、发型、肤色、年龄感、身体比例和人物身份。
- **US-04 避免重复和错误**：作为审核者，我希望看到与历史稿件的冲突、事实证据与修改建议，
  以便判断新意和准确性，而不是只收到无法解释的分数。
- **US-05 失败续跑**：作为创作者，我希望关闭页面后找回选择、进度和费用，
  以便继续生成并避免超时后重复付费。
- **US-06 下载交付**：作为创作者，我希望下载视频、字幕、封面和投稿文案，
  以便在当前尚无自动发布能力时自行投稿；排期提醒和结果回填留待后续。
- **US-07 自动发布**：作为后续具备权限的运营者，我希望按平台已验证能力发布并读取回执，
  以便减少人工操作；能力未实现或未授权时入口仍可查看但不能提交。
- **US-08 声音确认**：作为创作者，我希望先试听短句，再合成全文并确认，
  以便更换不满意的声音时明白哪些结果需要重做、是否再次收费。
- **US-09 表演与费用**：作为创作者，我希望选择日常口播或描述自定义表演，
  以便按效果和成本取舍；提交收费生成前能看到估价、预算与重做收费提示。
- **US-10 完整展示**：作为产品汇报者，我希望看到七个清晰入口和真实实现状态，
  以便讲清当前闭环与后续规划，不展示虚假的发布或运营成绩。

## 5. 功能列表与范围（Scope）

V1 是四项生产功能与一组共用运行保障；前端七个入口按下表顺序全部可进入。

| 顺序与入口 | 对应需求 | 首版交付 |
|---|---|---|
| 1. 人物形象 | F01 基础角色、F02 衣景、F03 默认声音、F07 表演选择 | 真人角色创建、参考图变体与表演方式选择 |
| 2. 口播稿生成 | F04 选题稿件、F05 质量历史 | 三个不同角度的合格候选、编辑与确认 |
| 3. TTS 语音 | F03 音色、F06 TTS | 音色短句试听、全文合成、质检与用户确认，两条口播路线共用最终音频 |
| 4. 视频合成 | F07 口播、F08 后期、F09 字幕封面、F10 交付 | OmniHuman 音频驱动口播 MVP、预览与下载；M2 保留本地选用 |
| 5. 发布 | F10 后续排期回填、F12 平台发布 | 规划/开发状态页，未实现操作禁用 |
| 6. 指标监控 | F13 运营指标 | 规划/开发状态页，数据空状态 |
| 7. 领域模型选择 | F14 模型配置 | 规划/开发状态页；通用模型编辑后置 |

- **P0 共用保障**：F11 作品版本、任务、预算与恢复，及 F14 基础服务配置、预检和错误反馈。
  基础配置是首版必需能力，可通过服务端配置管理，不等于完整模型选择页已完成。
- **P1 后续增量**：排期提醒、人工回填、发布接口、指标接入、完整模型编辑；各自独立验收。
  计划覆盖抖音、B站、快手、小红书、微信视频号，平台之间不默认能力相同。
- **P2 后续扩展**：团队协作、多账号与移动端。
- 不能用 Mock、静态头像加音频、假接口、假数据或网页模拟代替真实生产与平台验收。

## 6. 详细功能描述（Functional Requirements）

### F01 基础角色创建与身份管理

**触发**：用户新建人物，或从人物库选择已定版角色进入作品。

**输入**：性别、成年年龄感、外貌、发型、气质等可选关键词，以及自由描述、人设简介和来源说明。
提示词由本次选择组成，可预览；不把所有用户写死为同一外貌。

**流程**：生成真人候选 → 检查五官、皮肤与人体结构 → 用户选择 →
保存定妆照与至少 4 张经审核参考图 → 冻结身份版本 → 关联默认音色。

**输出**：角色身份、名称、人设、定妆照、参考集、校验信息、来源与审核记录。
构图为正面或轻微侧面、胸像或半身、完整清晰脸部；自然、亲和、专业，不自称真实专家。

**边界**：未定版不能进入正式生产；文件丢失或损坏阻断；新建人物不得覆盖旧身份。
人物 B＋音色 3 为本项目已选初始预设，不是唯一允许的人物，也不代表参考集和变体已验收。
作品绑定明确人物版本；禁止以占位图定版，不读取失败项目资产。

### F02 服装、背景与角色变体

**触发**：用户选择或描述服装、背景，或采用已有合格组合。

**输入**：已冻结人物参考图、固定身份描述、独立的服装/背景关键词及自由追加要求。
用户可编辑衣景要求；改变脸型、五官、年龄等身份要求应引导新建人物，不能覆盖现有人物。

**流程**：选择已审核变体，或基于原人物参考图编辑衣景 → 人物一致性与画面审核 →
用户确认 → 保存同一人物下的新变体。固定提示词只能辅助一致性，不能代替参考图和审核。

**输出**：关联同一 Base Avatar 的主播画面、生成要求、输入参考、变体版本与审核证据。
初次验收至少覆盖 2 套服装 × 3 类背景，共 6 个组合。
背景分类可表达演播室、教室、科技场景、新闻演播室、AI 实验室。

**边界**：不得随机重造人物；脸型、五官、发型、肤色、年龄感及身体比例变化须拒收。
缺合格组合时暂停或由用户明确选择已有组合，不能静默换脸或换景。

### F03 固定音色资产

**触发**：用户选择主播默认声音，或显式为新音频版本更换声音。

**输入**：当前服务可用音色、声音偏好、短句基准文本；声音克隆仅允许具有完整授权的材料。

**流程**：浏览音色选项 → 用同一短句试听 → 审核普通话、术语与表达 → 确认并绑定角色默认声音。
音色和情绪分别选择，只展示当前服务确实支持的能力；合成试听若收费，纳入预算与费用提示。

**输出**：音色身份与版本、基准音频、支持表现力范围、服务绑定及权利记录。

**边界**：人物 B 初始默认音色为音色 3；用户可显式创建新声音版本，旧作品仍绑定原版本。
不同模型的音色标识不能默认通用；服务失效或升级先回归试听，不得静默换备用声音。
同一次生产内未经确认的声音变化阻断下游。
两条口播路线共用已选音色生成的最终 TTS；视频模型须保持该音轨，不自行改词或换声。

### F04 选题、标题、文案与口播稿

**触发**：用户在作品中输入提示词并点击生成。

**输入**：提示词/选题、关键词、文案类型、受众、目标时长、用户提供资料以及已保存的已核资料引用。默认约 60 秒，可配置 45～90 秒，最终以实际音频时长为准。

**流程**：content 将输入整理为 DeepSeek 请求 → 直接生成三个角度不同的候选 → quality 检查 → 向用户展示候选、问题和待复核标记 → 用户选择或编辑并确认。content 不联网、不搜索、不爬取，不调用来源抓取工具。

**输出**：三个 `ScriptVersion`，每份包含标题、简介、标签、开头、分段正文、表演提示和资料说明；候选差异应来自角度、结构或例子，而不是换词重复。保存用户最终选择和确认版本。

**边界**：没有用户提供或系统已有已核资料时，涉及事实、时效、数字、案例或产品能力的断言标 `待复核`，请求用户依据或人工确认；不能声称模型自审已验证事实，不能假造 URL。候选不足三个时说明缺额，不用不合格稿凑数；标题承诺必须在正文兑现。

### F05 内容质量检测、历史库与重写

**触发**：每次生成、编辑或有限改稿后。

**输入**：当前稿件、同账号历史内容、尚未发布的已通过稿件、用户提供资料、规则版本。

**流程**：quality 先调用 M01 的本地 `search_content_history` 查重，再检查主题/观点差异、用户资料一致性、逻辑、错别字、口语、开头吸引力和完整性；对无依据事实和最新信息标记待复核，形成通过、有限改稿或人工确认决定。历史为空记录“冷启动”，不能声称长期不重复。

**输出**：逐维度报告、命中历史片段、资料引用状态、问题位置、修改建议和最终决定。质量审核贯穿每个阶段和最终成片，结论必须引用可定位证据。

**边界**：M01 只查本地历史，不提供 `search_sources`/`fetch_source`；不能把联网取证或模型自评当作本版本能力。每个候选初稿后 quality 反馈最多触发 3 次自动改稿，补足候选同时受任务调用次数与预算上限约束；不通过换稿重置计数。每轮保存稿件和报告；改写不能把无依据断言变成已验证事实。用户编辑形成新版本并重新审核；无充分依据时进入待复核。

### F06 表达标记与 TTS

**触发**：用户已确认合格稿件和试听音色，点击生成全文音频。

**输入**：确认的分段稿、音色版本、停顿/语气/重音/情绪/语速要求、术语发音词表。

**流程**：生成受约束表达标记 → 检查能力 → 合成语音 → 检查漏读、错读、长静音、削波和时长 →
生成真实时间信息 → 用户试听并确认，或选择新声音生成新版本。

**输出**：可播放音频、实际时长、最终朗读文本、时间信息、发音/音色报告和用户确认记录。
RAG、LLM、API 等术语须读法一致，标记不能被朗读。

**边界**：不支持的情绪明确提示；时长越界优先修稿而非无限加速。
缺时间戳时以音频重新对齐，不按字数平均分配；用户未确认的音频不能投入最终口播。
重新合成保留旧版本并展示费用；只有新音频被采用才使对应口播与字幕失效，不修改旧交付包。
两条路线都必须使用质检通过且用户确认的同一最终 TTS，不能用视频模型自行生成的另一声音代替。

### F07 真人数字人口播

**触发**：用户在人物页设置表演要求，在视频合成页确认人物、最终 TTS、路线和适用预算后点击合成。

**输入**：已审固定人物图、已审且用户确认的最终 TTS、可编辑表情/动作描述、路线与预算。
选择 M2 时另需经许可且已审查的动作参考；单条作品绑定同一人物、稿件和声音版本。

**流程**：核验输入及能力 → 展示时长/分辨率/片段数/估价和重做风险 → 预算内提交 →
保存原片 → 核对输入音轨保持、人物、嘴型、表情、身体动作与接缝 → 触发 studio-media Worker → 用户预览。字幕对齐、后期和封面由 Worker 按依赖自动执行，最终成片仍由 quality 复核。

**输出**：面对镜头进行口播的真人数字主播视频；保留固定人物、最终音频、表演要求与真实任务关联。
身体活动程度与自然度必须实测，不能把生成成功视为手势、身份和唇形均已通过。

**路线要求**：

- MVP 必须接入并独立验收 OmniHuman 1.5：固定人物图＋最终 TTS＋可编辑表演描述，直接生成身体/表情/口型视频。不经过 LivePortrait，不重复调用 MuseTalk。
- 目标是改善身体僵硬；仅开放已验证的动作/参数，不承诺任意动作或每次 prompt 都被准确执行。历史样片不能证明当前人物 B、复杂手势和约 60 秒能力已通过。
- M2 保留低成本本地选用：LivePortrait 将获准动作迁移到人物形成底片，经审查后与最终 MiniMax 音频一起交 MuseTalk；两阶段分别保存证据。M2 成功不能代替 OmniHuman 的 MVP 验收。
- 当前核验依据的 OmniHuman 音频限制为严格小于 60 秒、建议不超过 15 秒；表演描述不超过 300 字符，720p/1080p 需复核当前账户能力。约 60 秒作品必须按同一已确认音轨的句子边界分段并验收接续，禁止通过加速或截字绕过限制。
- Grok 图生视频排除当前 MVP，仅保留只读历史调研；不以其自行产生的声音替代固定音色音频驱动。

**边界**：缺固定人物或最终确认音频不能提交；纯文字随机人物、静态头像加音频、假嘴型均不合格。
超时先查询原任务，禁止盲重试或静默切换收费模型。生成不满意仍可能收费，返工受适用预算限制。
输出音轨须核对原 TTS，口型另行检查；音轨相同不能证明嘴型或身体动作合格。

**页面归属与顺序**：人物页准备资产和可编辑表演要求。第 3 页完成 TTS、质检与用户确认后，
第 4 页才发起音频驱动口播。两条路线分别校验依赖；更换稿件或声音使受影响音频/口播/字幕失效，
只改动作或衣景时可复用未变的已确认音频；只改字幕样式仅重渲染和重审。

**成本口径**：OmniHuman 按用户确认 1 元/生成秒估算：60 秒 60 元、5 条/日 300 元、30 天 9000 元，仅视频生成费；取整/最低消费与失败扣费待账单核验，报价不等于具体预算授权。
Grok 的 0.38 元/秒不适用于本路线。生成、分段取整、失败返工、TTS、图片/文本、存储后期分别记账；
M2 按实际 GPU 与合成用量记账。选模型和修改规格不构成新的付费试验授权。

### F08 视频后处理与视频质检

**触发**：真实口播原片和 quality 原片审核通过后，由业务依赖自动触发。

**输入**：已审原片、确认的最终 TTS、输出规格、字幕/封面设置。

**流程**：`studio-media` Worker 探测并检查黑帧/空白 → 按依赖调用内部字幕对齐、FFmpeg＋libass、FFprobe 和清晰度处理 → 响度与 AI 标识检查 → 生成候选成片并登记产物。总控不编写剪辑方案，字幕/渲染/检测实现不暴露为 MCP。

**输出**：9:16、1080×1920、MP4、H.264、AAC（建议恒定 30 fps），保留原片、时间线、参数和父链。片头默认关闭，启用时不得挤占开头核心表达。

**边界**：放大不等于真实细节达标；脸部漂移、黑帧、嘴部伪影或音画断裂进入拒收/待复核；增强不得重画五官。只改字幕样式时仅重触发 Worker 渲染、FFprobe 和最终 quality，不重新生成声音或口播原片。

### F09 自动字幕与封面

**触发**：Worker 获得最终 TTS、实际音频和合格原片后。

**输入**：实际音频、最终朗读文本、字幕风格、重点词、标题和合格视频帧。

**流程**：Worker 按语义分句与实际音频对齐 → 应用裁剪/片头偏移 → 排版并突出重点词 → 输出可编辑字幕和带字幕视频 → 从同一人物成片选封面。`align_subtitles`、`render_video` 等内部步骤不作为 MCP 能力。

**输出**：可编辑字幕文件、时间轴、带字幕视频、同一人物封面和预览。默认每行不超过 14 个中文字符、最多两行；长术语按视觉宽度校验，不拆坏含义。

**边界**：不能按字数伪造时间轴；时间戳越界/重叠须修复或拒收；字幕不得被平台控件遮挡；编辑文案后必须使旧字幕失效并触发新版本。

### F10 发布就绪包、排期与结果管理（分期）

**触发**：Worker 产出视频、字幕、封面和检测报告且最终 quality 通过后。

**输入**：成片、封面、标题、简介、话题、字幕、AI 声明、产物版本和质量记录。

**流程**：确定性 Worker 登记 manifest 和父链 → `studio-core` 冻结当前交付版本 → 提供预览和下载；M05 交付 MCP 删除，包登记由代码完成。V1 到此结束，排期、回填和自动发布后置。

**输出**：视频、封面、投稿文案、字幕、清单、校验信息与审核摘要。可下载不代表已上传、已审核或已发布。

**边界**：缺资料、quality 拒收、身份异常或 AI 声明缺失不得标记 ready；改片/改文案生成新版本，旧包保留但标为非当前。

**后续排期/回填规则**：时间以 Asia/Shanghai 显示并保留时区；到期只表示应处理。人工回填标记“人工报告已发布”，取得平台证据才能显示“平台已确认发布”。休眠错过排期显示逾期，默认不集中补发；允许取消和改期，不能伪造成功回执。

### F11 全流程编排、预算与可恢复性

**触发**：用户提交、确认、恢复或取消阶段任务；定时排产属于后续增量。

**输入**：作品、确认的稿件/人物/声音版本、表演要求、服务配置和预算。

**流程**：预检 → 预算预留 → supervisor 分派 4 个专家 → 按依赖并行和逐阶段 quality 审核 → Worker 自动触发字幕/后期/封面/包登记 → 异常分类 → 恢复/重试/人工处理。总控不编写后期方案，也不代替 Worker。

**输出**：作品、候选与选择、版本依赖、真实阶段、耗时、费用、服务、质量证据和异常原因。无真实百分比时只显示阶段，不伪造进度。

**边界**：Mock 不得进入生产发布任务；无预算上限不得付费；未知受理先查询原任务；恢复核对输入、版本、产物和远端状态；取消后停止新提交并记录已受理费用。刷新或关闭页面后仍可恢复查看，迟到旧结果不能覆盖新版本。

**协作要求**：

- 仅设置 `supervisor`、`content`、`quality`、`avatar`、`audio`，即 1 个总控和 4 个专家；不设 editor。
- 用户确认稿件后，audio 与 avatar 可并行准备；口播完成后由 Worker 依据依赖自动做字幕、后期、封面和打包。
- quality 在稿件、TTS、原片、Worker 产物和最终成片各阶段审核；不能因某个 Agent 或 Worker 报成功跳过门禁。
- 保留 S01-S06、S08 七个业务 Skill；M01-M04 工具按角色白名单调用，M01 仅 quality 的本地查重；不设 M05。
- MCP 目标边界：M01 本地历史查重（仅 quality 的 `search_content_history`）、M02 角色与记忆、M03 媒体生产、M04 媒体检测与审核；不提供 `search_sources`、`fetch_source`、`align_subtitles`、`render_video`，也不设 M05 交付 MCP。字幕对齐、FFmpeg＋libass、FFprobe、清晰度、封面和包登记由 `studio-media` Worker 内部执行，业务状态仍由 `studio-core` 写入。
- 固定人设、音色、历史内容和经验按版本与来源保存；经验经审核才进入记忆。

### F12 官方自动发布（后续条件范围）

**触发**：经验证的账号和通道已启用，任务到达排期且满足授权要求。

**输入**：F10 冻结就绪包、目标平台/账号授权、逐平台已核实能力、计划时间、AI 声明字段。

**流程**：检查授权及能力 → 上传/设置平台支持字段 → 创建投稿 → 追踪审核与可见性 →
记录真实发布结果；不支持的步骤转人工并停止宣称全自动。

**输出**：平台任务/作品标识、受理状态、审核/公开状态、实际时间、错误与重试记录。

**边界**：官方不支持的字段不得静默丢弃；账号授权不等于应用权限已开通；
上传成功不等于创建成功，创建受理不等于审核通过；
超时未知先核对远端结果；不得以不稳定网页模拟或虚构 URL 补足接口。
定时行为须符合平台规则，不能把本地定时器当成无人值守权限证明。
抖音、B站、快手、小红书、微信视频号各自验证；不支持的平台、字段或动作显示限制和可用的人工方式。

### F13 运营指标监控（后续范围）

**触发**：用户进入指标监控页；后续由已验证的数据通道更新已发布作品的指标。

**输入**：平台、账号授权、可核验作品标识、指标能力与统计时间。

**流程**：V1 展示用途、实际规划/开发状态与空状态；后续按平台权限读取或导入数据并注明来源。

**输出**：可获得的播放量、完播率、点赞量、收藏量及统计窗口、采集时间、来源和更新状态。

**边界**：不能假设各平台都开放完播率，也不预设自动爬取为通用接口；V1 content 不联网。
未授权、未接入、不可获取与真实零值明确区分，不造假看板；允许后续导入后台数据但须保留来源。
重复采集与指标回撤须有记录，指标含义不同的平台不能直接混合比较。

### F14 领域模型选择与基础配置（分期）

**触发**：用户进入模型选择页，或在首次使用时配置并检查所需服务。

**输入**：已支持服务的地址、密钥、模型名称及能力配置；后续页面支持文本、音频、生图和已接入视频路线。

**流程**：V1 由受控服务端配置完成必要接入 → 检查凭据和当前步骤所需能力 →
生成失败时明确提示原因；完整可编辑模型选择页后续开放。

**输出**：脱敏的服务配置状态、检查结果、支持能力与具体错误，当前实际调用模型可追溯。

**边界**：密钥由服务端保存，不在浏览器直接调用中暴露，不写进作品或日志。
地址＋密钥＋模型名不能承诺任意供应商兼容；只允许已接入接口与经验证能力。
密钥错误、余额不足、模型不存在、能力不支持和网络故障给出不同提示；缺配置在付费前阻断。
连接检查可能收费时先明确费用并纳入预算；不能以列表可见冒称真实生成已通过。

## 7. 非功能需求（NFR）

以下数值是拟定验收目标，尚未取得新系统实测成绩；测法见 [验收方案](06-验收标准与测试方案.md)。

- **NFR-01 身份与声音**：资产定版后，生产任务只使用已批准版本；
  6 个变体和真实视频抽帧均需通过身份审核。阈值尚未标定时必须人工复核。
- **NFR-02 音视频**：原始口播音视频时长差目标 ≤250 ms；字幕抽样偏移 P95 ≤200 ms；
  响度目标 -14 LUFS±1 LU，真峰值 ≤-1.5 dBTP。包装后的整体时间线另行核对。
- **NFR-03 可观察性**：任务创建响应目标 P95≤2 秒，任务状态查询 P95≤1 秒，
  环境为本机 1 个运行任务、10 个同时查询；远端生成耗时单独记录，不承诺固定 SLA。
- **NFR-04 排期与恢复**：重启后 60 秒内识别未完成任务，未知远端受理不重复提交；
  浏览器刷新不丢失已保存候选、选择和阶段状态。后续启用排期时，应用运行期间到点 60 秒内进入应处理状态。
- **NFR-05 安全**：密钥统一管理并脱敏；不写入文案、就绪包或常规日志；
  只传输服务需要的资产，临时外链到期失效，拒绝越权访问和任意文件路径。
- **NFR-06 标识与权利**：可见 AI 标识、适用的隐式标识和平台声明是发行检查项；
  任意自定义文件元数据不自动等于符合监管/平台标准。保留素材和声音权利证据。
- **NFR-07 数据**：稿件历史与最终审核记录持续保存用于查重；原始大媒体建议保存 30 天，
  最终成片/清单建议保存 180 天，资产与发布回执长期保存。清理周期可配且不能删掉在用依赖。
  初期每日备份；启用生产前完成一次隔离恢复演练。
- **NFR-08 成本**：每条任务可查累计消耗；预算检查必须覆盖并发、重试与未知受理；
  所有付费测试须预先确定次数和金额，文档评审本身不构成支付授权。
- **NFR-09 使用体验**：简体中文，支持键盘操作；错误信息给出失败环节与下一步，
  不把 Provider 类名、堆栈或服务商内部状态直接作为用户提示。
- **NFR-10 独立新建**：仅提供新工程、公开依赖与获准配置的环境能够从空数据库启动；
  人物、声音、内容历史和测试数据均由新系统建立；运行、构建和验收不得读取失败项目目录。

## 8. UI 与交互说明（Interaction）

### 8.1 主要页面

主导航固定为：**人物形象 → 口播稿生成 → TTS 语音 → 视频合成 → 发布 → 指标监控 → 领域模型选择**。
七个入口全部可进入；新建/切换作品、任务记录和基础配置可作为共用区域，不代替上述入口。

1. **人物形象**：人物库、关键词/自由描述、候选定版、参考图换衣换景、表演模板/自定义描述。
2. **口播稿生成**：文案类型与内容、关键词、资料证据、真实进度、三个合格候选、编辑与确认。
3. **TTS 语音**：音色试听、表达选项、全文合成进度与确认；两条视频路线均使用已确认的最终 TTS。
4. **视频合成**：已选人物/稿件/音频摘要、本地/API 路线、估价与预算、字幕/增强设置、预览与下载。
5. **发布**：展示五个平台目标、后续能力与真实开发状态；未实现的连接、发布、排期操作禁用。
6. **指标监控**：展示计划指标及“未接入”空状态；未实现的数据获取操作禁用，不显示假数字。
7. **领域模型选择**：说明后续可配置的模型类别及真实状态；通用配置表单未实现时禁用。
   MVP 必需服务仍通过基础配置管理，并向用户提供脱敏配置状态与错误反馈。

### 8.2 关键交互

- 每条作品沿用默认人物与声音，也可明确选择其他版本；角色、候选、稿件、声音和成片彼此可追溯。
- 稿件选择、音频采用和最终合成是显式用户操作；页面跳转不是自动批准生成或预算的依据。
- 生成过程显示真实阶段；未知百分比用阶段状态或不定进度，不做匀速假进度。
- 刷新或离开页面不丢任务；回到作品可继续查看。排队等待算力与模型失败分开显示。
- 失败提示包含环节、原因和下一步；“继续查询”与“重新付费生成”分开，支持定位问题片段。
- 重新生成前展示预计费用、预算、可能再次收费；本地故障不自动切到收费 API。
- 上游修改展示受影响的下游产物，再生成新版本；仅改字幕样式不重跑语音与口播。
- 未开始的功能标“规划中”，正在开发的才标“开发中”；可用、实验可用与已验收状态不能混淆。

## 9. 验收标准（Given / When / Then）

### AC-F01：真人基础身份

**Given** 系统尚未激活角色；**When** 完成候选生成和负责人定版；
**Then** 保存 1 张定妆照、至少 4 张参考图、身份与音色绑定及来源记录，
人物呈真人外观且没有明显五官、皮肤、头发与人体比例错误；不能以占位图通过。

### AC-F02：换装换景身份不变

**Given** 已冻结角色；**When** 生成并检查 2 套服装 × 3 类背景的 6 个组合；
**Then** 全部关联同一身份，脸型、五官、发型、年龄感和肤色保持一致；
注入另一人物负例时必须拒收，未审核组合不得进入生产。

### AC-F03：长期声音一致

**Given** 冻结音色与基准句；**When** 连续生产 3 条不同内容并模拟主服务不可用；
**Then** 合格输出声音一致，故障任务暂停，不得自动换成未经审核的声音。

### AC-F04：指定选题输出完整

**Given** 用户输入 RAG 科普需求和时长；**When** 生成稿件；
**Then** 选题、标题、简介、标签、分段稿和资料说明齐全，正文解释 RAG 的检索与生成及其适用边界（内容主题，不触发联网检索），
标题与正文一致；重写后仍讲 RAG，不捏造来源或具体产品能力。
输出三个不同角度合格候选，用户可编辑并重新审核后确认；不足三个时说明缺额，不以不合格稿凑数。

### AC-F05：质量检测与重写

**Given** 历史库含同义改写稿、同题不同角度稿以及无依据断言样本；**When** 新稿质检；
**Then** 报告区分文本、主题和观点重复，错误/无证据断言不得通过，
最多自动改稿 3 次后进入待复核；M01 查重不可用不能报“无重复”，没有用户依据的事实不能报“已核实”。

### AC-F06：自然语音与表达标记

**Given** 稿件含 RAG、API、重音与停顿；**When** 用已定版音色合成；
**Then** 术语读法正确、无标记读出、无漏字，实际时长落在配置范围内，音频可播放；
可先试听短句再全文生成，用户未确认前不投入最终口播，更换声音生成可追溯新版本。

### AC-F07：真实音频驱动数字人口播

**Given** 已审固定人物、已确认最终 TTS、可编辑表演描述和适用预算；**When** OmniHuman 生成；
**Then** 保存真实任务、原片与输入音频关联，输出人物稳定、音轨保持、嘴型同步，身体/表情自然度按实测签收；
不另调用 LivePortrait/MuseTalk。约 60 秒按句子分段并复核全片接缝，不能用短片外推。
M2 单独按已审 LivePortrait 底片＋确认 TTS → MuseTalk 验收；不得以 M2 成功代替 OmniHuman MVP 验收。

### AC-F08：成片规格与保真

**Given** 真实口播源视频；**When** 后处理结束；
**Then** 成片为 1080×1920、9:16、MP4/H.264/AAC、恒定帧率，
身份未被增强改变、音画同步和响度达标、异常黑帧未掩盖在“成功”结果里。

### AC-F09：字幕和封面

**Given** 已确定最终声音与片头/裁剪；**When** 生成字幕及封面；
**Then** 字幕覆盖实际朗读且抽样偏移 P95≤200 ms，无越界遮挡，重点词正常突出，
可编辑字幕随包输出，封面为同一人物且与标题一致。

### AC-F10：V1 下载交付与后续排期区分

**Given** 合格成片与完整资料；**When** 用户预览并下载；
**Then** 获得视频、字幕、封面、文案及版本清单，未发布状态真实，不要求先完成排期或人工回填。

**Given** 后续已实现排期与回填；**When** 到期并由用户填入投稿结果；
**Then** 人工报告与平台确认区分，取消、逾期可识别，不能把本地到期记为平台成功。

### AC-F11：预算、恢复与隔离

**Given** 同一任务被重复触发、远端已受理但响应超时、或预算不足；
**When** 重启/重试；**Then** 不盲目新建付费任务，预算不足阻断；
旧产物输入版本不匹配时只重新执行受影响环节，Mock 不得进入生产发布队列。
关闭或刷新浏览器后恢复真实任务；不伪造进度百分比；生成重试和原任务查询区分。

**Given** 已审核稿件、独立制作任务及共享表演说明；**When** 多个专业角色协作或在中途重启；
**Then** 独立任务可并行，缺前置产物的任务不能提前执行，输出绑定同一有效版本；工作规范、工具权限和经审核的长期记忆按职责生效，冲突写入不覆盖正式记录。测试细项见验收方案 AC-AG 组。

### AC-F12：真实自动发布（独立于 V1）

**Given** 已验证的合法发布通道与账号能力；**When** 合格任务到计划时间；
**Then** 按平台允许方式投稿并获取可核验回执、审核/公开结果，
未知结果不重复发布；V1 人工包或 Mock 回执不能作为本项证据。

### AC-F13：监控入口与数据可信

**Given** V1 尚未接入运营数据；**When** 用户进入指标监控；
**Then** 页面可访问并显示真实规划状态和数据空状态，未实现操作禁用，不展示虚构或以零代替未知的数据。
后续接入只显示有来源的指标及统计时间，不支持的指标有明确说明。

### AC-F14：配置与服务错误

**Given** 已支持模型配置有误或缺少能力；**When** 检查或尝试相应生成；
**Then** 明确区分凭据、模型、余额、能力和连接问题，不暴露密钥、不改用其他收费模型；
V1 有基本配置与错误反馈，完整模型编辑页的规划状态不影响正常已配置服务使用。

### AC-UI：单用户七入口与版本选择

**Given** 单用户工作台启动；**When** 依次进入七个功能页面并切换同一作品；
**Then** 入口顺序与第 8 章一致，前三个确认结果被视频合成复用，后三页可进入并诚实展示状态。
人物 B＋音色 3 是初始预设，创建其他人物不覆盖它；修改字幕样式不触发重新配音。

### AC-E2E：RAG 贯通验收

**Given** 真实 Provider、已定版角色和音色、足够且已授权预算、历史内容与证据；
**When** 输入“生成一期关于 RAG 的 AI 科普视频”并选择合格稿件、人物与声音，确认音频和生成预算；
**Then** 按确认顺序贯通 F04/F05→F02/F03→F06→F07→F08/F09→F10，
保留完整资产链、质量报告、实际消耗和下载就绪包；无需先完成平台发布、排期提醒或人工回填。
只有 F12 额外通过后，才可宣称原始目标中的“真实定时自动发布”完成。

## 10. 优先级与 MVP（Priority）

- **P0 首版**：四项真实生产功能、七入口完整呈现，以及共用作品/版本/任务/预算/配置保障。
  固定人物、三稿选择、最终 TTS 审核确认、OmniHuman 音频驱动口播与费用确认，最终预览和下载；OmniHuman 主路线未通过不能宣称 MVP 完成。
- **P0 实施顺序**：先验证协作分工、交接、持久恢复，再接入真实素材与服务；
  短片实验不能替代正式动作素材、衣景变体、约 60 秒成片与日产目标的验收。
- **P1 后续增量**：排期提醒与人工回填、逐平台发布与指标接入、完整模型选择页。
- **P2**：团队协作、多账号和移动端，另行确认范围。

MVP 要验证：人物是否能长期一致；三个候选是否有不同价值；用户能否试听、确认并控制返工；
真实生产成本、时间与质量是否支持日更。预算、事实核查、Mock 隔离和 AI 标识不能为演示删去。

## 11. 度量指标（Metrics）

北极星指标：**每周经真实视听质检通过、人物和声音一致的可发布作品数**。
不把 Mock、重复稿、仅包装成功的劣质视频计入。

- 试运营目标：20 次有预算的真实任务中，至少 18 次在预算内形成合格就绪包；
  每次失败计入分母，用户主动取消单列，不静默剔除。
- 身份异常漏放、已知事实错误漏放、Mock 混入和重复投稿：目标均为 0，出现即暂停放行。
- 平均/分位生产时长、单条实际费用、重写率、质检拒收率按阶段记录，不承诺未经测量的收益。
- 后续启用排期后统计到点可处理率：应用在线期间目标 100%；休眠、权限阻断和远端故障分别计数。
- 后续人工投稿回填率与人工耗时单列，不能算自动发布率。
- 真实自动发布成功率仅在 F12 启用后统计，并区分受理、过审、公开、删除/撤回。
- 首版质量/成本/产能指标来自生产任务，仍须记录；前端“指标监控”指后续平台运营数据。
  后续只记录可获得的播放、完播、点赞、收藏等实际指标，不设置未经验证的“必爆”目标。
- 日看异常与费用；周看质量和产能；每累计 50 条或切换模型时复核质量标定。

## 13. 风险、对策与开放问题（Risks / Decisions）

### 13.1 风险登记

| 风险 | 影响 | 控制与退出条件 |
|---|---|---|
| 参考图生成仍可能换脸 | 最高，破坏核心人设 | 参考集冻结、逐变体审核、负例测试；不过则不批量生产 |
| 声音模型更新或音色不兼容 | 高，长期声音漂移 | 绑定模型版本、基准句回归、迁移试听后才启用 |
| 动作素材不足或长片质量不满足 | 高，无法生成完整自然口播 | 短片回归后验证约 60 秒内容、动作覆盖和接缝，再测日产 5 条 |
| 自定义表演不遵循且重复收费 | 高，成本与预期失控 | 明示动作能力、估价和预算；人工确认路线，不保证任意动作，保留失败证据 |
| 发布或运营数据权限不满足 | 高，后续功能不可用 | V1 交付下载包；平台能力逐个验证，不编造接口或数据 |
| 无用户依据的事实/时效判断 | 高，内容错误 | content 标记待复核；请求用户依据或人工确认，不能声称模型自审验证 |
| 付费请求重复/失控 | 高，预算消耗 | 预算预留、受理查询、未知状态隔离、封顶重试 |
| 模型许可与隐式标识误用 | 高，无法投产 | 核查具体权重/服务条款和目标格式，不以库许可证代替 |

### 13.2 开放问题及关闭时点

- **OQ-01 人物与声音偏好（已关闭）**：用户选择约 22 岁、专业温柔的成年女性方向，已确认人物 B＋音色 3；参考集、变体和长片质量仍按验收要求完成，不能把偏好已选等同质量通过。
- **OQ-02 付费预算**：单条/每日/月度额度和首次真实测试总额，由负责人在首次付费前确定。
  当前默认不自动支出；文档中的价格不构成授权。
- **OQ-03 Provider 可用性**：具体模型 ID、权限、时长、分辨率与音色兼容由开发负责人在 G1 验证。
- **OQ-04 身份检测许可与标定**：采用哪个可商用检测器，由开发负责人在 G1 前核验；
  未通过时保留人工门禁，不能用无权使用的模型或未标定分数自动放行。
- **OQ-05 标识字段**：适用标准、供应商保留要求和平台声明入口，由投产负责人在 G2 前核对。
- **OQ-06 自动发布条件**：主体、应用权限、可用 API/SDK、预设发布交互要求，由负责人在 G3 前确认。

### 13.3 已关闭决策

- **DEC-01**：V1 四项真实生产与下载交付；排期、回填、自动发布及平台指标后续逐项验收。
  本次单用户工作台范围取代此前将排期回填纳入 V1 的范围。
- **DEC-02**：固定真人身份与经确认声音，禁止占位人物；用户最新允许可选视频生成 API，
  两条口播路线均使用固定人物图/底片＋已确认最终 TTS，早期一刀切禁令不再适用。纯文生视频不是本轮交付能力。
- **DEC-03**：Mock 用于开发联调，与真实产能验收严格分开；来自用户 Provider 要求及验收边界。
- **DEC-04**：用户明确指定整个项目从零重做，失败项目不借鉴；
  不保留旧接口兼容义务，不导入旧人物/声音/素材/数据库/配置，不复用旧测试或 Mock 实现。
  调研仅采纳有独立来源的厂商与平台证据，涉及失败项目的代码结论不进入新设计。

- **DEC-05**：用户要求按环节比较并实测；用户明确指定的模型和框架可登记为已选，接口能力及生产质量分别待验收。最新技术决定见 02、03、09，不由文档建议直接转为已验证的生产默认值。
- **DEC-06**：采用总控与四类专业智能体协作；content 依据提示词直接写稿，quality 查内部历史并做质量审核，avatar/audio 负责人物和声音；后期由确定性代码 Worker 执行。独立任务可并行，质量贯穿各阶段，工作规范、工具能力和记忆分别管理。框架落地详见技术方案。
- **DEC-07**：人物 B＋音色 3 是已确认初始预设，允许新建其他独立身份；目标每天 5 条、每条约 60 秒待验收。
- **DEC-08**：单用户自用；七入口固定呈现，人物、稿件、最终 TTS 与路线由用户确认；后三项显示真实开发状态。
- **DEC-09**：MVP 必须接入并独立验收 OmniHuman 1.5，以固定人物图＋最终 TTS 生成身体/表情/口型；M2 保留选用，Grok 排除当前 MVP。按用户确认 1 元/生成秒估算并确认具体预算，不自动重试或切换。
- **DEC-10**：服务端基础配置和错误反馈随 MVP 完成；通用模型选择页后置，不承诺任意接口兼容。

## 14. 里程碑与交付节奏（Milestones）
