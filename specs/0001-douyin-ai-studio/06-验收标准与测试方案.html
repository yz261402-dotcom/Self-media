1. 验收对象与不可替代的证据

验收对象是能够持续生产同一位写实虚拟主播内容的系统。固定真人外观的 Base Avatar 与 Outfit、Background 在资产身份和业务接口上解耦；换装、换背景不能重新随机换人。视觉实现可以采用参考图约束的完整画面生成，不要求把三张图片机械拼接。音色必须固定且版本可追溯。

V1 完整链路为：创建作品、选人物 → 总控委派策划按提示词/关键词/可选用户资料直接生成三种角度候选稿＋PerformancePlan → 三层去重和内容审核 → 用户选稿/编辑重审 → 音色试听选择、全文 TTS 与人物准备 → 音频审核和用户确认 → 用户选择 M2 或 OmniHuman 1.5、确认适用预算 → 该路线口播与质量审核 → 代码 Postprocess Worker 合成、清晰度处理、字幕、封面及 AI 标识 → 成片质量审核与内部打包 → 用户预览、下载合格包。单 GPU 重型作业排队，目标每天 5 条、每条约 60 秒；两条路线分别报告适用时长、质量和成本。

PerformancePlan 的每段统一绑定 segment_id/text/emotion/pace/emphasis/motion。表达意图不代表模型已经准确实现；动作参考迁移保持人物 B，不能用“按文本描述了手势”代替真实模型输出。质量审核智能体必须引用用户资料中的断言证据、内部查重结果、音频/影像指标和 timecode，最终放行由代码层硬门禁控制。策划与审核均不网上搜索或抓取；资料可空，生成能力不能以联网为前提。关键事实或时效断言缺依据时进入 review、补充用户资料或删改后重审；LLM 自审不是事实核验。

以下是不可被综合评分覆盖的硬拒绝条件：

  • 未经选择或能力验证就调用视频模型；以无固定人物参考/无已选音频的随机文生视频，或 SVG/CSS 人形、卡通、静图加音频、RMS 形变嘴和贴片嘴冒充真实数字人口播。用户本次已允许视频生成 API，OmniHuman 1.5 路线本身不构成拒绝条件。
  • 主播身份漂移、擅自换声音、存在未解决的事实矛盾、关键事实无证据、重复内容未处理、Mock 结果混入生产。
  • 最终视频规格不符合 9:16、1080×1920、MP4、H.264、AAC、30 fps CFR；最终音频综合响度不在 -14 LUFS ±1 内，或 true peak 高于 -1.5 dBTP。
  • 字幕漏句、错序、时间轴与最终成片不对应；必需的 AI 标识缺失或被后处理覆盖。
  • 未授权费用、提交结果未知时盲目重提、把草稿包或人工回填伪记为官方发布成功。

除上述已明确的产品规格外，本文的样本规模、时延、相似度、同步误差、保留期和费用上限均为建议工程基线，未经本项目实测标定，也不是平台保证。执行前须冻结 acceptance_profile 版本、测量工具和阈值；不得看到失败结果后临时降低门槛。商业许可待确认的检测模型不得直接成为生产门禁，选型和例外处理见技术选型。

2. 三层验收与结论规则

验收层级与 PRD 里程碑按以下关系对应，二者不能混用：

  • L0 = G0→G1 期间的 Mock 开发验证：G0 是文档/开发基线，L0 验证契约与编排，不算真实能力。
  • G1 是 L1 的真实核心能力子集：身份/声音定版、六个变体与真实短口播样片证明路线可行，不能据此宣称完整 L1。
  • 完整 L1 = G2：七入口、用户选择、提示词生成 RAG 主题内容的真实生产、OmniHuman 音频驱动约 60 秒分段链路、媒体门禁、预览/下载包、配置错误反馈及恢复/备份通过。排期/回填和实际投稿不阻塞首版；未验参数禁用，OmniHuman 主链路未过不能仅以 M2 通过宣称 MVP 完成。
  • L2 = G3 条件验收：获得适用官方权限及发布授权后，独立验证官方真实发布；实际执行模式决定能否宣称自动发布。

适用范围必须冻结：V1 必验 OmniHuman 音频驱动真实闭环、约 60 秒分段及身体/身份/音轨/嘴型质量；M2 按实际开放范围单独验收，不能替代。后续提醒、回填、发布与指标读取单独列 NOT_RUN/BLOCKED，不计入 V1 未完成项，也不得混报为已交付。

L0：Mock 结构与契约

验证请求/响应契约、DeepAgents 委派和并行汇合、角色 Skill/工具权限、状态转换、持久检查点、记忆隔离、版本失效、费用拦截和故障恢复。使用全新隔离目录、空数据库、确定性模型替身、显式 Mock Provider 和新建合成夹具，禁止访问真实计费服务、远程 GPU 或发布接口。所有模拟数据须标明来源，不从失败 Demo 导入或改造。框架离线成功不能证明 DeepSeek 真实工具调用兼容。

L0 产物必须携带运行模式与来源标记，界面和报告显示“Mock / 结构测试”。即使有可播放 MP4，L0 也不能证明写实形象、音色、事实正确、真实口型或官方发布。L0 通过不等于 L1 通过。

L1：真实生产全链路与发布就绪包

使用获准的真实 Provider、冻结的 Base Avatar/VoiceAsset、真实内容与证据、真实媒体处理链，完成全部 V1 必需用例。输出可人工发布的完整就绪包，并保留从选题到每项产物的证据链。

L1 的成功语义是“真实生产验收通过、就绪包已生成”。它不表示作品已经出现在抖音。人工上传后的记录只可标记为人工确认来源，不升级为 L2。

L2：官方真实发布

前置条件是已核验的主体/应用资格、目标账号授权、适用权限和该权限允许的实际发布方式。按当时官方能力完成真实上传、发布与状态核验，记录官方作品标识、可核验状态和回执。仅有路由存在、HTTP 200、上传成功、SDK 拉起、草稿包、Webhook 2xx 或人工回填均不算 L2。

L2 不属于本轮 V1 完成条件。未取得权限时标记“阻塞：官方权限”，不能标记“通过”，也不能以此否定已通过的 L1。若官方能力要求用户确认，必须如实验收为“官方渠道人工确认发布”；只有权限与规范确实允许、并验证了无人值守提交，才能宣称“真实自动发布”。

结果记录

每个验收 ID 记录 PASS / FAIL / BLOCKED / NOT_RUN、层级、样本 ID、输入/输出哈希、执行版本、实测值、阈值版本、证据路径、评审人和时间。NOT_RUN、BLOCKED 不折算成通过率；硬门禁失败不能被均分抵消。阶段状态字段以契约为准，验收报告额外保存证据层级和来源。

3. 全新项目的验收起点

本规范从用户“整个项目从零重做”的决定出发。目标工程路径为 production/src/avatar_studio/，运行数据按 production/runtime/ 隔离；已有 production/backend 骨架本轮同步最小角色/工具边界及内部 Worker 入口；缺媒体或真实处理能力时显式 blocked/not_run，不产出假媒体或空壳交付包。离线回归不等于本版系统验收通过。当前全部系统验收用例均为 NOT_RUN。本项目 AV-001 已选人物 B/音色 3、EXP-001 已生成 15.20 秒 M2 真实样片，均保留为资产和选型证据；新工程须受控登记来源、摘要和版本，不继承生产通过结论，也不重复生成已选人物或声音。

失败 Demo 不作为正例、反例、技术设计依据或质量金标；其源码、模块、测试、数据库、头像、声音、历史样本、图片、视频、日志和旧验收报告均不复制、不导入、不链接、不读取。不通过修改包名、包装接口或复制形变代码将其纳入新工程。独立选型的通用依赖须从受信来源重新取得并记录版本和许可。

所有模块都必须全新交付，并用本文规定的证据单独验收：

  1. 身份与变体：受控登记本项目已选人物 B 与权属记录，补齐参考集、服装/背景变体和批准流程，通过 AC-AV。
  2. 内容与证据：在隔离新运行区建立内容、可选用户资料与内部查重索引，实现提示词直接生成、逐断言风险审核、主题/观点/文本三层去重，通过 AC-CT。
  3. 固定声音与真实口播：登记音色 3 VoiceAsset，真实 MiniMax TTS 经质检且用户确认后，分别供 OmniHuman 和可选 M2 消费。OmniHuman 必须验证当前人物 B、输入音轨保持、身体动作、嘴型及约 60 秒分段；M2 不替代其结论。历史 TH-COMP-003 为 9.36 秒输入、9.48 秒原片；24 kHz 单声道最佳偏移 0 ms、Pearson 0.99996223 仅支持该样本音轨保持，不证明嘴型、当前人物 B 或身体自然度。
  4. 媒体与交付：按目标边界实现代码 Postprocess Worker 的合成、清晰度处理、完整字幕、封面、AI 标识和内部发布就绪包，通过 AC-MEDIA、AC-PUB 的 V1 用例。V1 提供预览和下载；后续才接提醒/回填，G3 在取得适用权限和具体发布授权后验收官方发布。
  5. 工作台与运行支撑：全新实现任务状态、成本账本、异步对账、幂等、调度、可观测性、备份恢复和工作台，通过 AC-OPS、AC-NFR。
  6. 测试与证据体系：全新编写合同测试、故障夹具和模拟 Provider；全部身份、声音、稿件、媒体、数据库与样本清单在新项目中建立。静图、错音、错时、形变嘴等负例由新项目测试工具基于本次获准输入独立构造，保留制作过程和来源，不使用失败项目的素材或代码。

4.1 评估方法

按“冻结范围与样本 → 离线正反例 → 获准真实生成 → 逐环节测量与盲评 → 失败返工/重审 → 汇总并签收”执行。文档评审和样本规模建议不构成模型调用、收费或发布授权。

  1. 先冻结口径：负责人登记 acceptance_profile 版本、范围/路线、样本 ID、输入摘要、模型/配置、工具版本、阈值、时间窗口及授权预算。默认人物 B＋音色 3，也允许用户明确选择其他已批准身份/声音；所有判断均对照本作品所选版本。路线对比尽量复用相同稿件、人物、最终音频与规格，分别记录本地硬件/云规格，不合并为一个成功率。
  2. 再准备样本：内容用至少 10 个主题 × 3 稿，覆盖仅提示词无资料、有用户资料、新题、旧题新角度、重复和有冲突资料；E02/E03/E06 逐稿评，三稿两两比较共 3 对。去重三层各用至少 50 对保留样本，每层重复/非重复各 25 对；样本可复用，但必须按层独立标注与统计，不能共用一个混淆矩阵。人物用至少 3 组关键词/自由描述、每个拟开放身份的 2 套服装 × 3 类背景共 6 个 AV-POS 变体，另建换人/卡通/身份冲突/哈希篡改 AV-NEG。真实生成失败也保留。
  3. 按能力配媒体样本：TTS 至少 10 段，覆盖术语/数字/长短句/停顿/重音/拟开放情绪，另测 3 条全文及短句试听。OmniHuman MVP 至少 3 条独立真实口播，包含约 60 秒分段样本；可选 M2 按开放范围独立验证。另建静图、贴片嘴、错音素、±400 ms 偏移的 TH-NEG。云路线不因样本未执行而退出 MVP，只有选择/预算门禁通过不能替代媒体质量。
  4. 谁来测、怎样测：工程测量由执行者用结构校验、审计日志、FFprobe/FFmpeg 和时间轴标注完成，审核者复核原始证据。文案至少 3 人、媒体至少 2 人独立盲评，随机顺序并隐藏模型/候选标签。1–5 分为：1 不可用、2 需大改、3 有明显问题、4 符合目标、5 明显优秀；4 分须有分项依据。文案逐稿取中位数，媒体两人每项均达标；分歧标出片段，由第三人复核。评审人数不足只记初评，不能代替正式通过。

  • When：下一任务检索历史，或稿件改版、模型/索引升级。
  • Then：Mock 历史不混入真实内容库；真实已用主题/观点/文本按状态可追溯，失败断言亦可防止复活。向量对应正文哈希及模型版本，索引失败或版本不兼容显式阻塞，不返回“无重复”的假结果。

AC-CT-10 质量分数与人工相关性（L1）

  • Given：冻结的 30–50 篇分层稿件、至少 3 位盲评者及清晰量表。
  • When：比较自动质量分与人工对“能理解、有收获、适合口播”的评分。
  • Then：报告相关性、评审一致性与分布；未达冻结基线时分数仅作预警，不承担自动放行。事实、重复、授权等硬门禁始终独立，不能通过修改权重覆盖。

5.3 固定音色与语音：AC-TTS

AC-TTS-01 音色资产冻结（L0 + L1）

  • Given：在新项目中登记并批准的 VoiceAsset、参考音频哈希、Provider/model/voice ID、参数和权属记录；标准预设音色使用本项目选择、官方使用权及基准合成证据，创建/克隆音色则另提供对应创建/注册证据。
  • When：连续生成 3 条不同稿件，另用 10 段详细样本覆盖长度、语速、情绪，并重启服务。
  • Then：每段实际使用的音色资产与版本一致，变化只在获准表达范围内；逐段声纹检测与盲听支持同一主播。固定 seed 只记为参数，不单独算音色一致证据。

AC-TTS-02 发音、表达与完整性（L1）

  • Given：含多音字、数字、英文缩写、AI 术语、停顿/重音/语速/情绪标记的金标稿。
  • When：确定性编译表达标记并真实合成。
  • Then：标记不被读出，关键术语正确、语句不漏读重读、停顿自然、情绪不致人格漂移；不支持的控制能力在调用前报告，不假装已生效。保存编译输入、输出参数、音频和人工逐项听检记录。

AC-TTS-03 固定音色失败不得静默替换（L0 + L1）

  • Given：主音色不存在、被删除、限流、单句失败或返回空音频。
  • When：生产任务继续到语音阶段。
  • Then：显式阻塞/失败并保留已完成片段；不得自动换备用声音、混入 Mock 或拼接其他人音色。获准切换 Provider 仍须证明同一音色资产，生成新记录并重验；PoC 不自动发起替代计费调用。

AC-TTS-04 字词时间戳与对齐回退（L0 + L1）

  • Given：分别有原生字词时间戳、无时间戳、错误时间戳的真实音频结果。
  • When：构建字幕时序。
  • Then：原生时间戳必须校验；不可用时走可验证的强制对齐/ASR 并与冻结稿件校正，记录对齐来源。只有平均分配时长或未验证逐句时长时不得宣称字词对齐已完成；失败则阻塞就绪包。

5.4 真实数字人口播：AC-TH

AC-TH-01 真实视频级 Provider（L0 + L1）

  • Given：冻结人物 B/已审同身份变体、PerformancePlan 和已审且用户确认的音色 3 最终音频（M2 另需合法动作参考），Provider 能力和费用授权满足任务。
  • When：用户选择 M2 时迁移动作、审核底片后提交 MuseTalk；选择 OmniHuman 1.5 时以已审人物图＋已确认音频＋可选表演提示直接提交；两者均先校验路线、能力和预算，再查询/登记结果。
  • Then：两路线输出音轨须与已确认 TTS 对照，检查错字/漏句/额外句及换声；音轨保持不替代唇形审核。M2 两阶段各保存实际模型、输入/输出哈希、作业 ID、状态时间线、耗时和成本；人物始终是作品选定身份，不把动作参考人物当输出。OmniHuman 1.5 则记录已审人物图、最终音频、表演提示、单阶段/分段真实回执与原片，不要求底片或重复 MuseTalk。无随机人物/程序形变冒充、无自动回退 M1/M3 或收费云接口；只有权重路径或类名不算推理证据。L0 测结构，L1 必须有真实任务结果。

AC-TH-02 多音素唇形同步（L1）

  • Given：多音素短片与对应音频/文字金标。
  • When：按正常速度观看全片，并逐帧/慢放抽查闭唇、唇齿、展唇、圆唇、停顿与语速转换。
  • Then：口型与音素和时间对应，无持续错位、牙齿漂移、嘴部矩形遮罩或周期性同一嘴型；报告对齐误差、失败帧与人工结论。嘴动了、像素变了、RMS 高相关都不能单独通过。

AC-TH-03 错配音频与伪口播负例（L0 + L1）

  • Given：TH-NEG，特别是音量包络相近但音素不同的错配音轨，以及前后偏移 400 ms 的音轨。
  • When：用同一验收检测和盲评流程处理正负样本。
  • Then：静图、形变嘴、音素不符和明显偏移必须拒绝，不因音量相关或分辨率正确而通过。保留每个正负样本的原始分数与结论，证明门禁确实能区分。

AC-TH-04 表情、身体动作与真人构图（L1）

  • Given：自然解释、提问、强调、停顿的真实口播段落。
  • When：评审整片及首中末/极值姿态关键帧。
  • Then：眨眼、眉眼和头部动作自然，具有真实三维姿态/非刚性面部变化；不能仅以整张图平移、缩放或局部贴图满足。人物具有合理颈肩/身体构图，无裁到下巴的悬浮头像、僵直长段、抽搐和边缘穿帮。OmniHuman 逐项核肩臂、身体及所需手势自然度和已支持指令遵循，2人逐项建议≥4/5；严重肢体伪影、持续遮脸/出框必须为0。要求手势时输入构图须容纳手臂和手，不适合的胸像先调整经审构图；无手势要求不强迫动作或把有意停顿判废，不承诺任意动作。完整约 60 秒样本须检查重复感和动作接缝；EXP-001 约 9.13 秒参考循环不能直接定为长期生产母版或通过长片验收。

AC-TH-05 分段约束与接续（L0 + L1，采用分段 Provider 时必测）

  • Given：服务时长上限已由新项目接入时的当前能力证据确认，稿件需分段；围绕所选 Provider 的实际时长上限新建边界前后样本。
  • When：按语义/停顿切段、逐段驱动并拼接。
  • Then：OmniHuman 当前音频规范严格小于60秒、建议≤15秒，prompt≤300字符，720p/1080p按账户复核；提交前拒绝超限片段，按同一确认TTS句子边界切片，不加速/截字，每段身份/音色一致，边界不漏字重字、断音、跳脸或重复帧，字幕和音频偏移统一；记录所有子任务和汇总成本。未采用该路线可记有理由的“不适用”，不能代表该 Provider 已验收。

AC-TH-06 异步失败与下载校验（L0 + L1）

  • Given：任务失败/超时、返回未知状态、结果 URL 过期、下载中断或媒体哈希损坏。
  • When：恢复或继续任务。
  • Then：按原外部任务 ID 查询并验证文件完整性，区分运行中、远端失败和本地未知；不会把空文件、HTML 错误页或过期链接当视频，也不会静默落回形变嘴。不能确定是否提交成功时遵循 AC-OPS-02。

5.5 媒体、字幕和 AI 标识：AC-MEDIA

AC-MEDIA-01 最终编码规格（L0 + L1）

  • Given：包括片头片尾、字幕、AI 标识的最终交付视频。
  • When：对最终文件执行 ffprobe、完整解码和时间戳检查。
  • Then：MP4、9:16、1080×1920、H.264、AAC、30 fps CFR，建议 yuv420p、AAC-LC/48 kHz、faststart；逐帧时间戳支持 CFR，而非仅比较标称/平均帧率。无缺流、损坏、异常旋转或非方形像素失真。原始分辨率与放大处理记录透明，不能把放大当原生细节提升。

AC-MEDIA-02 最终响度与音画完整（L1）

  • Given：后处理和片头片尾拼接全部完成的最终文件。
  • When：运行两遍响度标准化并独立测量最终 AAC 音轨，同时检查裁剪与同步。
  • Then：综合响度 -14 LUFS ±1、true peak ≤ -1.5 dBTP；保存测量日志，不以滤镜配置替代实测。无削波、音节截断、不明静音；有声正文完整保留，时长和同步满足冻结基线。

AC-MEDIA-03 黑帧、静止、清晰度与水印（L1）

  • Given：真实成片及黑帧、冻结、模糊、矩形嘴和非预期服务商水印负例。
  • When：代码 Worker 执行已配置的清晰度处理并保留原片/参数/前后对照，质量 Agent 对原片和成片分别完整解码、检测并组织人工复核告警片段。
  • Then：正文无异常黑帧/冻结/嘴部贴片，脸部可辨清楚；非预期水印不进入就绪包，处理方式为获得合适授权或服务档位，不删除/遮盖应保留的法定 AI 标识或来源标识。建议阈值和误报均记录。普通缩放不等于真实细节增强；超分模型未选未验时不得宣称已增强，增强引入身份漂移或伪影须拒收/回退后重审。

AC-MEDIA-04 完整字幕时间轴（L0 + L1）

  • Given：冻结正文、TTS 时间戳/对齐结果及裁剪、片头片尾、分段拼接编辑表。
  • When：代码 Postprocess Worker 在输入门禁通过后直接执行 ASR/对齐和 FFmpeg/libass，生成烧录字幕与可导出字幕文件；不加载后期业务 Skill 或调用字幕/渲染 MCP。
  • Then：同一编辑时间轴驱动最终视频与字幕；所有有声正文不漏句、不重叠错序，起止时间在最终视频范围内，末句不截断。给出正文覆盖比对、时间单调性检查和同步抽检；字幕不能仍停留在 TTS 原始时间轴。

AC-MEDIA-05 字幕与封面可读性（L1）

  • Given：长术语、数字、中文/英文混排和较亮/较暗背景样本。
  • When：以竖屏手机尺寸叠加平台常见 UI 安全区预览。
  • Then：字幕不截断、不遮嘴或关键人物区域，重点词高亮不改变内容，封面有有效画面且标题与稿件一致；字号/换行/安全区满足冻结参数，输出封面 1080×1920。平台 UI 布局以执行时复核记录为准。

AC-MEDIA-06 显式与隐式 AI 标识正反对照（L0 + L1）

  • Given：完整标识样本，以及仅末尾闪现、被裁掉、元数据缺失、manifest 声称有但文件没有的负例。
  • When：最终封装后逐段检测可见标识、读取实际元数据并核对 manifest。
  • Then：首帧起至末帧均有清晰可见的项目要求 AI 生成标识；元数据与 manifest 一致且符合已冻结的适用规则；所有缺失/冲突样本被拦截。自定义 comment 字段只能证明写入过信息，不能独立宣称已满足标准化隐式标识规范；未知规范格式须先关闭待核验项。

5.6 发布就绪包与官方发布：AC-PUB

AC-PUB-01 完整发布就绪包（L0 + L1）

  • Given：全部内容、身份、音色、媒体和标识硬门禁通过的任务。
  • When：最终成片质量门禁通过后，代码 Postprocess Worker 调用内部打包服务导出就绪包，不经交付 MCP 或后期 Agent。
  • Then：包内含最终视频、封面、标题/简介/标签、完整字幕文件、AI 声明说明、manifest、质量报告与证据索引；manifest 记录相对路径、SHA-256、媒体规格/时长、版本、实际 Provider 与运行模式、资产/音色引用、事实/去重报告、标识及成本摘要。逐文件可校验、可离线阅读，不依赖失效的临时 URL。

AC-PUB-02 发布状态不夸大（L0 + L1；交接/回填为后续增量）

  • Given：V1 导出成功与下载操作；后续交接/回填开放后另测 Webhook 2xx 和人工上传后的回填链接。
  • When：更新系统状态和界面文案。
  • Then：V1 只记录包就绪和下载，不触发提醒/投稿。后续分别记录交接受理、人工确认来源；没有官方核验回执不能变成官方已发布。人工回填只写 reported_published，保留操作者/时间/链接和 manual 证据来源，不计入 L2 自动发布成功率。

AC-PUB-03 包完整性与门禁不可绕过（L0 + L1）

  • Given：缺封面、字幕漏句、媒体哈希被改、AI 标识缺失、内容门禁失败或含 Mock 的包。
  • When：导出、排期或准备发布。
  • Then：失败并明确指出缺项，不能因为存在 MP4 或 ready_to_upload 字段就放行；修改视频/文案/字幕后必须使旧验收签名失效并重新检查受影响环节。

AC-PUB-04 官方权限与能力探测（L0 + L2）

  • Given：已脱敏记录的目标账号、应用、权限、有效期及官方允许的发布方式。
  • When：计划或触发真实发布。
  • Then：实际权限覆盖目标操作；无权限、过期或不适用时阻塞且不循环提交。未取得权限的 L0 只验证错误契约；SDK/H5 仅拉起编辑器不等于已发布。

AC-PUB-05 双错误码与真实失败（L0 + L2）

  • Given：HTTP 错误、顶层/嵌套 error_code、err_no、无作品 ID、业务拒绝和合法成功响应夹具。
  • When：适配器解析上传/创建/查询结果。
  • Then：仅识别到合法业务成功并取得必要标识才进入下一状态；权限、配额、审核拒绝不误报成功、不盲重试，原始脱敏响应可追溯。真实环境至少保存一次合法成功和可安全验证的权限/参数失败；不得为测故障制造违规发布。

AC-PUB-06 官方发布与结果核验（L2）

  • Given：真实权限可用、内容已获发布授权、包仍通过校验、平台 AI 声明可设置。
  • When：通过获准官方通道完成上传、必要人工确认或获准自动创建，再查询作品状态。
  • Then：记录官方作品 ID、目标账号一致性、提交/审核/发布状态、发布时间、可核验 URL 和回执；等待审核不算已发布，作品被拒或不可核验不得通过。报告明确实际模式，导出包和人工回填不可代替本用例。

AC-PUB-07 平台 AI 声明对照（L0 + L2）

  • Given：文件层显式/隐式标识完整，平台侧有声明要求；另有未设置声明的负例。
  • When：进入官方发布确认并核对平台实际结果。
  • Then：声明操作/字段与真实作品状态可核验，负例在提交前被阻止；文件中的 AI 元数据不能替代平台声明。入口、字段与规范按执行时官方证据确认，不将平台入口、字段或规范格式永久写死。

5.7 费用、异步、恢复与调度：AC-OPS

AC-OPS-01 费用授权与原子预算预留（L0 + L1）

  • Given：单次、单任务、当日、当月和本轮 PoC 总上限，含各 Provider、计费单位、税费/存储/传输等已知费用。
  • When：提交前估算并有多个任务同时竞争剩余额度。
  • Then：先原子预留预算，超限/价格未知/授权缺失即不提交；实际费用回写并对账。失败和取消不能在未确认账单前释放可能已发生的成本。估算不是账单，未知实际费用保留为待对账。

AC-OPS-02 一次提交与未知结果处理（L0 + L1）

  • Given：同一幂等键的任务在请求发送后连接断开或进程崩溃，不知远端是否受理。
  • When：重启、用户再次点击或网络恢复。
  • Then：先按已有任务 ID/幂等键/Provider 查询能力对账；查询确认前不再次计费提交。不能核实时进入人工处理。PoC 每个获准样本最多一次实际提交，不自动切 Provider、不自动重抽；只读查询/下载重试与提交重试分开计数。

AC-OPS-03 异步超时与有限轮询（L0 + L1）

  • Given：远端长时间运行、限流、暂时网络故障和业务永久失败。
  • When：按冻结轮询间隔/最大等待时间执行，建议起始间隔 10–15 秒、总等待 30 分钟。
  • Then：退避和总时限有效，业务拒绝不重试；本地超时记为待对账而不推断远端取消/免费。任务可通过原 ID 恢复查询，费用预留与审计记录不丢失。

AC-OPS-04 分阶段重启恢复（L0 + L1）

  • Given：在提交前、受理后未记账、下载中、媒体处理后未提交状态、包写入中分别中断。
  • When：恢复同一逻辑任务。
  • Then：只执行未确认完成的安全阶段，不重复计费/发布；通过输入版本与产物哈希检查有效性，损坏/半写文件不得因“存在”跳过。状态、错误与费用记录可重建，无混用旧稿新音频。

AC-OPS-05 业务幂等与并发（L0 + L1；发布部分 L2）

  • Given：相同身份/音频/Provider/参数哈希请求、重复点击、重复回调与并行调度。
  • When：同时执行多次。
  • Then：同一有效任务最多一个外部生成提交和一个允许的发布动作，新系统自身已有且通过相应验收的合格结果可复用；参数或输入变化产生新任务版本。重复/乱序回调不能倒退终态，幂等键与 Provider task ID 入库可查。

AC-OPS-06 时区、到期和错过执行（后续增量 L0 + L1；真实发布另按 L2）

  • Given：明确 Asia/Shanghai 时区、UTC 持久化时刻、本机改为其他时区，包含跨日和暂停恢复的排期。
  • When：触发计划、服务重启、重复 tick，或切到不支持相同 cron 语义的调度后端。
  • Then：在正确本地时刻执行一次，不提前消费未来队列；错过任务默认提示逾期、不集中补发、不自动改期；经明确批准的其他处理策略必须冻结并留痕。调度后端能力不足须拒绝配置，不静默忽略日期/星期/秒。V1 不启用排期；后续人工提醒只推进就绪包交接及人工待办，不能无权限自动发布。

AC-OPS-07 Provider 模式隔离与依赖失效（L0 + L1）

  • Given：内容、内部历史查重、TTS、口播任一阶段为 Mock，或真实 Provider 未配置/不可用。
  • When：请求生产输出或查看任务结果。
  • Then：Mock 只能留在测试空间，实际来源逐阶段可查；缺依赖、能力不足或降级建议对用户可见。只有用户明确批准、同等级且重新通过相关验收的替代方案可进入生产，绝不静默降级。

AC-OPS-08 存储访问与证据安全（L0 + L1）

  • Given：云 Provider 需读取人物图与音频，任务含临时签名 URL。
  • When：上传、生成、完成/失败与日志导出。
  • Then：只上传必要文件，访问期限覆盖任务但有上限，过期/拒绝访问明确报错；日志不泄露签名/令牌，清理可验证；清理不破坏受控本地证据。来源文件和旧验收目录不被覆盖。

AC-OPS-09 端到端可观测性（L0 + L1 + L2）

  • Given：一个任务经历生成、质检、人工处理或失败。
  • When：从用户结果追查任一阶段。
  • Then：能定位 run/job/stage、实际 Provider、输入输出、状态、重试类型、费用、耗时和对应验收 ID；错误不能只显示“done”。L0/L1/L2 结果分别汇总，不能把产物存在率写成生产成功率。

AC-OPS-10 全新项目隔离验收（L0 + L1）

  • Given：临时环境只提供新工程 production/src/avatar_studio/、配套新建测试与启动文件、获准配置及从受信来源独立安装的依赖；production/runtime/ 为新的空运行区，数据库为空，失败 Demo 的目录、包和数据均不可访问。真实服务授权、输入来源与费用范围分别登记。
  • When：从零初始化 schema，新建身份、声音和任务，执行提示词生成、内部历史查重/事实风险质检、TTS、音频驱动口播、代码媒体处理与发布就绪包全链路，并记录导入依赖、文件访问、资产来源、任务事件和产物清单。L0 使用全新 Mock 与合成夹具；L1 在获准范围内另行使用真实 Provider 和新建真实资产执行。
  • Then：启动和链路执行均无 Demo 路径、包、数据库或数据读取，不依赖复制的旧代码、素材、缓存、日志或隐式搜索路径；身份/声音/任务可追溯至新系统创建记录，产物落在新运行区。L0 报告明确“模拟结构与隔离验证”，不能声称生成了合格真实视频；L1 只有同时具备真实生成证据并通过相应质量用例才通过。保存环境依赖清单、空库初始化记录、来源清单、访问审计和逐层结果，任何越界依赖均失败。

5.8 工作台与非功能验收：AC-NFR

AC-NFR-01 工作台性能与关键交互（L0 + L1）

  • Given：记录了 CPU、内存、磁盘和服务版本的本机环境，1 个运行任务和 10 个同时查询客户端。
  • When：采集至少 100 次任务创建/状态查询，并走七入口、选人物、三稿选择、试听确认、路线预算、预览、下载及刷新恢复；后续改期/回填按其开放版本另测。
  • Then：创建 P95≤2 秒、查询 P95≤1 秒；报告实际值和失败数；真实生成耗时另计。键盘可完成核心操作，错误与预算阻断可见，API 不返回密钥。

AC-NFR-02 备份与隔离恢复（L0 + L1）

  • Given：含历史稿件、审核证据、进行中作业、费用预留和发布包的数据库及媒体清单。
  • When：建立一致性备份，并在全新隔离目录恢复和重新启动。
  • Then：任务、摘要、审批、历史查重、媒体引用和预算均可追溯；未知外部受理继续核对而非重提；原目录不覆盖，缺失文件明确阻断；保留恢复报告。

AC-NFR-03 保留期与依赖保护（L0 + L1）

  • Given：超过配置保留期的媒体、仍被运行任务/未知作业引用的媒体、长期身份与发布回执。
  • When：先运行清理预览，再执行批准范围内的清理。
  • Then：只删除到期且无依赖的副本；运行中/未知状态、争议、受控验收证据和在用人物资产不被误删；清理可审计。验收证据至少 90 天的专项规则优先于普通原始媒体 30 天默认值。

AC-NFR-04 试运营质量与反指标（L1）

  • Given：已获得明确额度并完成 20 次真实生产任务，任务集事先登记。
  • When：统计合格就绪包、失败、主动取消、费用和人工干预。
  • Then：至少 18 次在预算内形成合格包；全部失败计入分母；启动后取消仍计入分母并单列，启动前撤销不补抽且不计入20次已启动任务；Mock、重复投稿、已知错误断言漏放和身份异常漏放目标为 0。样本未完成只报告实际数量，不将首次样片推算成达标。

5.9 DeepAgents、统一表演与记忆：AC-AG

本组正式逐 ID 验收仍为 NOT_RUN；本轮只完成角色/工具权限、单一三稿工作项、Worker 缺依赖/未实现阻断及恢复防假成功的离线行为回归。L0 使用真实框架版本和确定性模型替身，L1 在具体授权后使用真实 DeepSeek/媒体 Provider；两层证据分别保存。

AC-AG-01 主框架、角色委派与真实模型兼容（L0 + L1）

  • Given：锁定的 DeepAgents 版本、总控和 content/quality/avatar/audio 四类 subagents、模型适配与结构化输出 schema。
  • When：先离线执行委派/工具调用/错误传播/返回校验，再在授权范围内以真实 DeepSeek 验证同样调用路径。
  • Then：总控按职责委派，工作项可追踪到角色、模型/Skill 版本和结果；不支持工具调用、非法参数或结构化返回失败明确阻断。真实调用须保存脱敏模型回执，不能以离线替身成功、文字回复正常或框架已安装宣称 DeepSeek 兼容通过。

AC-AG-02 工作项、结果与版本化 Skill（L0 + L1）

  • Given：合法及缺字段的 AgentWorkItem/AgentResult，包含任务、角色、输入摘要、依赖、schema、Skill 版本和工具权限策略；另有角色错误/Skill 摘要不匹配样本，以及将代码后期伪装为 Agent 结果的负例。
  • When：委派、恢复或登记 subagent 结果。
  • Then：只加载该角色批准的 S01～S06、S08 共 7 项 Skill 中的适用版本，S07 字幕与剪辑撤出且不复用编号；代码后期只记 executor_kind=worker、worker_kind=postprocess 的 StageExecution，不创建后期 AgentWorkItem/AgentResult。Agent 结果必须匹配工作项输入、输出 schema 和资产证据。缺失/过期引用、未经执行的“已完成”、角色越权或不匹配版本被拒绝；Skill 文本不能自行扩大工具权限、预算或改变固定人设。

AC-AG-03 PerformancePlan 单一分段来源（L0 + L1）

  • Given：绑定 ScriptVersion 的 PerformancePlan，分段包含 segment_id/text/emotion/pace/emphasis/motion；另有正文切片不符、分段 ID 重复、旧版本和不支持表达控制的负例。
  • When：声音/数字人 Agent 与代码 Postprocess Worker 分别读取同一冻结计划，代码从实际音频建立时间轴。
  • Then：正文、分段和表达引用一致，编译结果记录支持/近似/不支持项；不支持控制在调用前可见，不能伪称按文本精确生成动作。最终时间取自实际音频及有效对齐，不取目标时长或均分估算；文本/版本错误负例在媒体提交前拒绝。

AC-AG-04 并行汇合与单 GPU 互斥（L0 + L1）

  • Given：稿件和计划已冻结，配音和人物变体/动作准备可并行，代码可准备版式配置；设置音频未审、底片未审、分支引用旧稿和 GPU 被占用的负例。
  • When：DeepAgents 派发角色分支，Worker 调度已选路线作业；依赖满足后代码自动执行字幕对齐与后期合成，记录实际开始/结束和输入版本。
  • Then：StageExecution/AgentWorkItem 保留各分支进度，单一显示 stage 不覆盖其他结果；计划冻结前不生产，最终音频决定时长，底片与音频均批准才可 MuseTalk。字幕对齐等待最终音频确认，合成等待原片质量通过，打包等待成片质量通过；这些节点没有后期 Agent/MCP 调用。每个 GPU 最多一个有效重型作业，排队不误报失败，未确认结束的 UNKNOWN 作业不释放冲突资源；并行日志证明 Agent 并行和 GPU 串行分别成立。

AC-AG-05 质量证据与代码门禁不可绕过（L0 + L1）

  • Given：事实、音频、视频报告和有效证据；另有 Agent 输出“全部通过”却无引用、虚构数值、错误 timecode、硬失败被高分覆盖的样本。
  • When：质量审核智能体分别审核内容、最终音频、路线原片与后期成片并返回 QualityDecision，再尝试推进 TTS、口播、代码后期或发布包。
  • Then：每项建议绑定当前对象摘要、规则版本及真实报告；文本问题定位 claim/segment，媒体问题定位 asset 和毫秒区间。缺失指标只能待审/未运行，确定性硬失败继续阻断；模型、人工和工具均不能直接清除门禁或写入批准状态，篡改证据负例必须拒绝。

AC-AG-06 返工与下游失效（L0 + L1）

  • Given：已审稿件、计划、音频、动作底片、口播、字幕与发布包，分别准备改正文、改声音表达、改动作参考和改剪辑的修订。
  • When：创建新版本并尝试复用旧产物/审批或恢复旧检查点。
  • Then：按依赖图使受影响后代和批准失效，保留原文件与历史结论；正文变化不能使用旧音频，音频变化不能用旧嘴型/字幕，动作变化不能用旧成片，剪辑变化不能用旧时间线/包。没有依赖变化且摘要相同的批准资产可复用；旧版本并行回写不得污染当前任务。

AC-AG-07 四层记忆与并发审核合并（L0 + L1）

  • Given：两个任务的独立检查点、只读人设资产、历史内容索引、待审 MemoryCandidate，含相互冲突、无来源、过期规则和提示注入候选。
  • When：并行 Agent 写入各自命名空间、申请经验合并并在下一任务检索。
  • Then：隔离写不覆盖其他任务或固定人设；共享经验经来源/适用版本核验和 ReviewDecision 后以期望版本合并，冲突需复核，不是最后写入者覆盖。未审、被拒或过期经验不用于自动决策；记忆不能替代事实证据、来源权利或预算授权。模型/索引版本变更须显式复验，外部指令不改变权限。

AC-AG-08 检查点恢复与 UNKNOWN 对账（L0 + L1）

  • Given：委派后、工具发送后回执前、Provider 已受理但本地未记结果、结果登记后检查点未更新等中断；其中作业受理与费用可能未知。
  • When：重启进程并从持久检查点恢复同一工作项。
  • Then：先读取业务账本、ProviderRun、预算和资产摘要，使用原幂等键查询/核对；UNKNOWN 不自动重新 submit，不让聊天记录覆盖真实状态。重放工具返回原结果，费用预留不丢失，过期 Worker 被拒绝；不能核实时阻断人工处理。保存进程重启和查询证据，内存内续跑不算持久恢复通过。

AC-AG-09 MCP 工具边界与最小权限（L0 + L1）

  • Given：角色 allowlist、任务/mode 命名空间、输入资产和预算策略；另有任意 URL/路径、直接 shell、越角色工具、跨任务资产、提权预算及来源文档恶意指令的负例。
  • When：Agent 经受限 MCP 调用内部历史/记忆、媒体生成、检测审核工具，调用已批准的本机纯函数普通工具，或试图越权请求网上搜索/抓取、字幕/渲染/打包与直接外部副作用；另测代码后期由依赖图调度。
  • Then：Agent 外部能力仅按受控通道进入 Provider→Worker；M01 内部历史仅 quality 可用，M02 角色记忆、M03 媒体生成、M04 检测审核按角色授权，M05 及后期工具不暴露。代码 Postprocess Worker 直接执行内部服务，不绕 MCP；副作用前完成 schema、来源、版本、许可、预算与幂等校验。本机纯函数允许直接适配，但入口和结果仍按相同业务门禁核验，不能因此扩大文件/任务权限或包装未授权外部副作用。全部越权负例被拒绝；查询和登记也限制作用域。工具错误不被包装成成功，日志脱敏并保留工具/工作项及适用 ProviderRun 关联。

AC-AG-10 每天五条与约 60 秒联合生产（L1）

  • Given：前置真实模型、动作参考、许可证和质量用例通过；固定人物 B/音色 3，为一天 5 条不同稿件分别登记约 60 秒目标及总预算。
  • When：按真实排产运行 DeepAgents 四类专职角色的受限工具/Provider 链路，以及依赖驱动的代码 Postprocess Worker 合成与内部打包链路，期间覆盖一次可控恢复并汇总人工投入。
  • Then：分别记录每条实际时长、身份/口型/自然度、字幕/标识、包、角色证据与成本；必须 5 条均通过本次冻结门槛才报告该批达标。单 GPU 排队与实际占机时间、加载/空闲/失败费用透明，未完成或失败样本不得替换后沿用原结论；短片线性外推和 20 次试运营指标不能相互代替。全批只产生 V1 包，未经授权不发布。

AC-UI-03 三稿审核、选择和编辑重审（L0 + L1）

  • Given：一个主题及历史内容库；正例具备三个不同角度，负例只有两稿合格或三稿实为同义改写。
  • When：生成、逐稿审核、有限补写，用户浏览并选择或编辑，再提交旧候选版本的选择请求。
  • Then：只允许采用合格稿；正常返回三个不同角度，不足明确告知且不凑数、不自动代选。编辑创建新版本并重审；过期决定返回冲突，未选择处于 waiting_selection。质量审批不能替代选择。
  • 证据：候选/历史快照、质量报告、版本化选择、补写次数及请求响应。

AC-UI-04 试听、全文确认与音色返工（L0 + L1）

  • Given：已选稿件、至少两个受支持的候选音色和同一句试听文本。
  • When：在全文音频未生成/未确认时尝试对口型，再播放样音、选声、生成全文、试听确认并进入第 4 步视频合成；最后换声重合成。
  • Then：音频未就绪时不提交口型作业，人物页面不执行最终对口型；区分样音和全文，新增付费合成受预算约束；只有合格且用户确认的全文音频可进视频生成。换声保留旧音频和费用，已依赖旧音频的口型/字幕/成片失效，不覆盖历史或混用时间轴。
  • 证据：样音/全文媒体、音色作用域、用户选择与音频确认、失效事件和费用。

AC-UI-05 显式路线选择、估价和预算拦截（L0 + L1）

  • Given：默认且 MVP 必交付 OmniHuman 1.5、可选 M2；用户已给出视频费率 1 元/生成秒，另设取整/失败扣费待核、超预算、受理未知和重做情形。
  • When：选择路线、分辨率、时长与描述，查看估价并确认预算后提交；再注入 M2 失败和云请求超时。
  • Then：未选路线/未确认适用预算不得新增收费任务；M2 不自动切云。云路线以人物图＋最终 TTS＋可选描述生成原片，不要求底片或再跑 MuseTalk。动作要求须与人物构图匹配：要求手势时检查手臂/手可见并能活动，生成后核肩臂/身体/手势自然度和指令遵循，按E12≥4/5建议基线及严重伪影/持续遮脸出框为0硬门禁；无手势要求不强迫动作。不承诺任意动作，未验规格禁用；重生成提示可能再收费，未知结果先核对。估价、预留与实际费用分开，超额停止新提交，不反复确认已批准范围。
  • 证据：路线选择与输入摘要、估价依据、预算事务、远端任务与请求次数、原片和用量。

AC-UI-06 真实进度与页面恢复（L0 + L1）

  • Given：排队、内部查重、生成、审核、待选择、代码后期、失败和已完成任务；Provider 无真实百分比。
  • When：切换页面、刷新、关闭浏览器并重新进入，再在后端重启后查询作品。
  • Then：显示真实阶段/已等待时间，无编造百分比或提前 100%；浏览器关闭不取消后台已提交任务。恢复相同作品候选、选择、进度和错误原因，恢复不会重复收费；旧版本晚到不覆盖新选择。
  • 证据：前后截图、持久事件、选择摘要、恢复记录和外部提交计数。

AC-UI-07 局部修改与最小返工（L0 + L1）

  • Given：已有合格人物、已选稿件/音频和成片。
  • When：分别只改字幕样式、只换衣景、修改正文。
  • Then：样式改动只重新渲染及复验后期；衣景改动可复用未变音频；正文变化使音频、嘴型、字幕和成片的相关批准失效。保留旧版本与账本，不一律从头生成；重新采用和收费依照新版本决定。
  • 证据：依赖图、前后哈希、实际作业列表、调用次数和费用差异。

AC-UI-08 基础模型配置和脱敏报错（L0 + L1）

  • Given：已适配供应商和未配置、认证失败、额度不足、模型不存在、能力不支持、网络异常等响应夹具。
  • When：通过受控基础配置加载凭据并检查连接，尝试把任意 URL/Key/型号当通用协议使用。
  • Then：基础配置可供前四功能使用，错误类别和处理建议可见但不泄露密钥；检查产生费用时同样受预算约束。配置齐全不等于可调用，未适配能力拒绝；完整通用设置页仍按后续状态显示。框架/工作台不能直接读取或展示生产密钥。
  • 证据：配置摘要、错误响应、界面截图、脱敏日志和能力检查结果。

6. “RAG 检索增强生成”主题的真实端到端验收脚本

本节是 AC-AG/AC-CT/AC-TTS/AC-TH/AC-MEDIA/AC-PUB/AC-OPS 的联合用例。RAG 仅为科普主题，生产流程按提示词直接生成，不要求网上检索或抓取。目标约 60 秒，允许窗口在执行前冻结，具体字数由真实语速决定，不为了达到字数补空话。本轮没有执行此脚本。

  1. 冻结输入：选择“RAG 为什么还可能答错”，固定人物 B/已审变体、音色 3、OmniHuman 1.5、已核能力/价格、目标约 60 秒、DeepAgents/Skill/规则、预算与历史快照。记录授权号并新建 L1 运行目录。M2 如另测再绑定获准动作参考。
  2. 冻结用户资料：本条事实型验收由用户提供获准的 RAG 原始论文/官方说明/技术文档摘录；保存提交时间、资料版本、正文和片段哈希，不由 Agent 上网获取。另测仅提示词可正常生成的样本；其关键断言无依据时必须 review，不能借生成成功取得事实通过。
  3. 建立断言清单：至少覆盖“检索为生成提供外部上下文”“检索结果可能缺失、过期或不相关”“RAG 不保证回答必然正确”。每条均要由实际证据支持；如证据不足，先调整稿件而不预设其已通过。
  4. 加入事实负对照：把“RAG 可以彻底消除所有幻觉”及一个虚构提升百分比送入同一门禁，预期拒绝；保留拒绝报告。正例中不得偷换为相同错误断言的弱措辞版本。
  5. 生成并选择内容：策划按用户提示词、关键词和可选资料直接输出三种不同角度的候选，各有标题、简介、正文、标签和表演意图；分别审核事实、重复和表达。用户选择一稿，编辑后重新审核；选择绑定该稿件版本及摘要，再冻结计划。
  6. 执行三层去重：在新项目测试空间新建历史集，含一篇同题同角度、一篇同义改写及一篇同题不同角度，并保留来源与标注。输出主题、观点、文本三个独立结果；重复候选须变更实际内容并重新验收，不能改标题了事。
  7. 并行准备与真实 TTS：声音导演使用冻结计划与音色 3 合成并检查“RAG”、数字和术语读音，保存完整音频与参数；代码 Worker 在最终音频确认后登记有效对齐；数字人导演同时准备人物变体/动作参考，代码读取用户字幕/版式配置。短句试听选择与全文音频分别保存；音频质检及用户确认后固定实际时长，各分支引用同一版本。未经用户选择擅自换声或混入 Mock 即失败。
  8. MVP 路线真实口播：用户显式选择 OmniHuman 1.5 并确认适用预算；将同一已确认最终 TTS 按句子切片，每段严格小于 60 秒，当前建议不超过 15 秒，实际按账户已核能力执行。人物 B＋音频切片＋可编辑表演描述直接生成原片，不调用 LivePortrait/MuseTalk。记录每段实际回执、输入输出、费用与音频全局偏移；全片分别核输入音轨保持、唇形、身体/表情、身份和接缝。约 60 秒不能直接超限提交或通过加速截字绕过；多音素/错音轨负例另验门禁。
  9. 代码处理与字幕：原片经质量 Agent 审核通过后，Postprocess Worker 直接执行 FFmpeg 合成、清晰度处理、裁剪、规格统一、ASR/对齐、libass 字幕烧录和封面、两遍响度和最终封装；编辑时间轴统一映射，保留原片及处理对照，成片再次交质量 Agent 审核。ASR/对齐与超分按已验能力执行，普通缩放不计真实增强。用最终文件核对分辨率、CFR、编码、响度、true peak、完整正文及字幕同步。
  10. 核验标识：逐段观看首帧至末帧可见 AI 标识，读取真实文件隐式标识并与 manifest 对照；包中给出平台 AI 声明的待操作事项。
  11. 导出并校验包：成片门禁通过后由内部打包服务生成 AC-PUB-01 的全部文件，校验哈希与跨文件引用。系统只记录发布就绪，不发起本轮未授权的官方发布。
  12. 回查与签收：从最终包可反查每个断言来源、三个查重报告、计划/角色/Skill 版本、资产/音色、适用 MCP/ProviderRun、代码 Worker 执行记录、费用与失败负例；验证检查点恢复和旧版本失效后，人工完整观看和盲听签收。有证据的经验仅作为 MemoryCandidate 提交审核合并。任一步缺证据即记失败或未执行，不能只凭 Agent 回复或命令退出成功签收。

M2 保留独立同人物/最终 TTS 对照：获准动作参考经 LivePortrait 迁移为已审底片后，交 MuseTalk 对口型。其通过不替代 OmniHuman MVP；每条路线未验规格不开放。OmniHuman 旧 9.48 秒样片不能外推当前人物 B、复杂手势或约 60 秒质量。

通过结论应写为：“运行 <run_id> 完成 RAG 主题的 L1 真实生产与发布就绪包验收；L2 未执行/受权限阻塞。”只有独立执行 AC-PUB-04～07 后，才能追加相应官方发布结论。

7. 真实服务 PoC 的费用授权与一次提交纪律

OmniHuman 按用户确认 1 元/生成秒（100 分/秒） 估算：60 秒 60 元、5 条/日 300 元、30 天 9000 元，仅视频生成费用；price_source=user_confirmed_rate、billing_verified=false。实际账单、取整/最低消费与失败扣费仍待核验；TTS、文本图片、存储后期和返工另计。报价不构成具体付费任务授权，Grok 的 0.38 元/秒不适用于本路线。

本规范不构成付费授权。默认新增付费调用额度为 0；免费额度也须纳入账号、样本和调用范围确认，不能假设失败重提不会扣费。下列金额仅为可提交给用户审批的建议封顶值，以接入时实际价格重新估算：

  • 身份/变体 PoC：建议总额不超过 ¥20，最多 6 个明确变体，每个变体一次提交；不足以覆盖实际价格则缩减样本或重新申请，不自动超支。
  • 固定音色 PoC：建议总额不超过 ¥10，标准预设音色仅登记选择/使用权并限定逐段试听合成清单，不要求创建/克隆/注册；如另有获准的声音创建任务，其次数与合成次数分别列出，每个样本一次提交。
  • 真实多音素口播 PoC：建议单 Provider、1 条 10–15 秒、总额不超过 ¥30，含所需 TTS/存储费用；不得收到低质结果后自行重复抽取。
  • RAG 主题真实生产 PoC：建议 1 条约 60 秒、全链路总额不超过 ¥120；OmniHuman 每个分段样本最多按批准清单提交一次，LLM/内部查重基础设施/TTS/图片/代码后期分别限额（有实际费用时）。M2 另测时 LivePortrait/MuseTalk 每阶段同样按单次纪律。此金额是待批准的试验封顶建议，不是供应商固定套餐或已获授权。
  • L1 多样本验收：在上述 PoC 证明路线可行后单独授权，建议 3 条真实成片合计不超过 ¥360；仅新系统自身已验收的合格样本可按第 4 节复用。此上限不与其他批次自动合并，金额不足不降低验收门槛。

每次只申请下一批具体可审阅的调用，不能一次授权无限重试。轮询/下载可以在既定上限内有限重试；任何新增计费 submit、切换 Provider、改变稿件再次合成、补足样本均需在已明确授权清单之内，否则重新批准。系统的故障恢复策略不得覆盖此项 PoC 纪律。
