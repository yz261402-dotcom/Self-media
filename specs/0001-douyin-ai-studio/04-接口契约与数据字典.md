# 核心契约与数据字典

**当前基线（2026-09-23）：** 用户已选 DeepAgents 主框架，由总控协调策划文案、质量审核、数字人导演、声音导演四类 subagents。决策模型为 DeepSeek 官方 `deepseek-flash`（V4.1 Flash）；媒体采用 MiniMax 官方 `speech-2.8-hd`、GPT 专用中转 `gpt-image-2`。人物 B `av_base_b_v1` 与音色 3 `Chinese (Mandarin)_Warm_Bestie` 为首个默认预设，允许创建、核验并显式选择其他人物和声音；每条作品锁定其选定版本。MVP 必交付口播路线为 OmniHuman 1.5：固定人物图＋已审且用户确认的最终 MiniMax TTS＋可编辑表演描述，直接输出身体/表情/口型视频，不经过 LivePortrait/MuseTalk。M2（LivePortrait→MuseTalk）保留低成本本地选用，不能替代 OmniHuman 验收；Grok 仅留只读历史调研。准确接口与能力由接入证据约束。见 [接入决策](09-模型选型决策与接入方案.md)。本轮已同步 production 骨架的角色/工具注册与代码 Worker 门禁；真实后期、模型链路和生产验收尚未完成，模型选择与验收分开记录。

版本：v2.4 单用户工作台 / DeepAgents Draft；日期：2026-09-23。本文规定 `avatar_studio` 的目标数据与接口，角色与工具边界已做最小同步，不表示全部契约已实现或云服务已在本轮调用。本文是尚未冻结的业务契约草案，可随实测发现的能力边界修订；字段以必要、可验证为原则；状态枚举以本文为唯一来源，其他文档不得另建同义枚举。FastAPI、PostgreSQL＋pgvector、APScheduler 属于建议试验组合，尚未因此定为生产依赖；前端、影像 QA、字幕 ASR/对齐、超分与 embedding 模型仍待选。

当前代码 Worker 仅持久登记执行边界与阻断原因（复用 media_jobs 存储），缺少已审媒体或真实后期能力时返回 blocked/not_run，不生成伪造媒体或交付包；下文描述目标实现。

策划文案按用户提示词、关键词和可选用户资料直接生成三稿；质量审核保留内部历史查重与事实风险审核，两者均不进行网上搜索或抓取。视频合成、清晰度处理、字幕、封面和打包由代码 Postprocess Worker 执行，原片与成片仍由质量 Agent 审核。

本版以作品为根管理人物、三稿候选、试听、音频与视频版本，新增独立的用户选择、生成路线与费用确认契约。七个功能入口始终可进入：人物形象、口播稿生成、TTS 语音、视频合成、发布、指标监控、领域模型选择；前四项为真实 MVP，后三项展示真实规划/开发状态，基础连接配置属于 MVP。业务状态由确定性代码提交，Agent 只能提出计划、调用获准工具并返回结构化结果。

首阶段交付用户逐步确认的生产闭环、成片预览与可下载发布就绪包（G2），不要求排期提醒、人工回填或实际投稿。提醒/回填在后续交付，按平台取得官方权限后的自动发布和指标读取分别验收（G3）。人工报告、上传成功、创建请求受理都不能替代平台确认发布。

契约依据为原始需求、已确认的 V1 范围及待评审的 [03 总体技术方案](03-总体技术方案.md) 的新模块边界。外部事实只取 [口播厂商能力](../research/03-数字人口播选型.md)、[TTS 能力与条款](../research/04-TTS音色与内容生成质检.md)、[平台发布规则](../research/05-视频后处理发布与合规.md) 中可独立追溯的证据；型号、价格、路由、时长与权限仍须接入时核实。**demo 以及调研中的 demo 现状、复用、改造或既有测试结论均排除，不作为契约依据。**

先验证离线最小编排、权限和恢复，再按 [技术选型与实测流程](07-技术选型与实测流程.md) 验证尚未确认的能力。Provider 的厂商字段、上限和响应映射只有经过当前文档核验与真实调用后才能冻结。

## 1. 公共约定

- API 前缀 `/api/v1`；JSON 使用 `snake_case`、UTF-8。业务 ID 为服务端生成的不透明字符串，不能拼接为磁盘路径。
- 所有时间使用含时区 RFC 3339，存储统一 UTC；排期额外保留 IANA 时区，默认 `Asia/Shanghai`。时长与时间轴统一为非负整数毫秒，区间采用 `[start_ms, end_ms)`。
- 金额使用人民币分整数 `*_fen`，不使用浮点货币；提交前估价向上取整。其他币种必须先经版本化汇率折算，不能直接相加。
- `schema_version` 从新系统第 `1` 版开始；只承诺本系统后续版本按明确契约升级，版本号相同不代表兼容任何外部或旧项目 schema。请求未知字段拒绝，响应允许客户端忽略新增字段。
- 文本先统一换行为 LF、Unicode NFC，再计算 SHA-256。字符位置为规范化文本的 Unicode 码点偏移，不是 UTF-8 字节数或 UTF-16 长度。
- `sha256` 为文件原始字节的 64 位小写十六进制摘要。`asset_id` 是稳定引用；签名 URL 是短期传输凭据，不是资产 ID，不写进业务事件或日志。
- `mode` 值为 `mock | integration | production`，由运行环境决定，请求不能越级切换。每个任务、资产、Provider 任务和发布包均携带该值。
- 成功响应必须包含经校验的业务结果；HTTP 200、空错误码、`success=true` 均不能单独证明成功。普通写接口返回 200/201，异步受理返回 202；冲突 409、校验失败 422、能力不支持 422、权限失败 403。

### 1.1 全新资产来源约束与零兼容保证

- 项目暂定名为 `avatar_studio`；实际语言、目录与包结构待工程栈选型，当前不据此创建生产包。新 schema 初始化空数据库，配置及 `AVATAR_STUDIO_` 凭据引用由新项目建立；启动不搜索旧配置、路径或数据库，不提供旧包别名、旧字段映射、旧数据导入或旧任务恢复接口。
- Base Avatar、参考图、服装/背景素材、预设音色选择或声音创建/注册记录、基准音频、成片及证据均须有新项目的来源链。允许本项目新生成、独立选择并核验使用权的预设音色，或为本项目独立取得授权的新材料；禁止读取旧数据库、导入旧头像/声音 ID/音频/视频/审批结果，即使补写新 ID 或复制文件也不改变来源。
- 根资产须绑定新建 SourceRecord 和可核验摘要；派生资产须保留 `parent_asset_ids` 并可追溯全部根资产。创建身份/声音、提交任务、登记派生媒体和生成发布包时均校验来源；来源缺失或属于排除范围返回 `ASSET_SOURCE_FORBIDDEN`，人工审批不能豁免。
- `VoiceAsset` 可从本项目首次预设音色选择及基准合成建立，也可来自有证据的声音创建/注册及基准验证。音色 3 为已选标准预设音色，登记须保存官方作用域、使用条款、选择记录和本项目基准合成证据，不要求额外克隆或注册。跨供应商注册使用的参考音频同样必须来自上述合法新来源；不接受只提供未经本项目建立来源证据的 `remote_voice_id`。
- Mock 由新写的确定性契约模拟器生成固定响应与带模拟标记的测试素材；离线负例和测试夹具全部独立新建。身份、声音、语义和视频质量阈值依据新标定集产生，不接受历史夹具或经验阈值直接放行。几何嘴型实现不作为 Mock、预览或负例生成器。
- 仅允许新系统内部有来源证据的 `integration` 资产经显式审批新登记为生产资产；保持原始记录与模式追溯，不能直接改 `mode`。模拟资产及其后代不得进入生产。
- 本项目 AV-001 的人物 B、音色 3 与 EXP-001 的 M2 样片属于新项目证据，不属于被排除项目。新工程可按已核验来源、摘要与选择记录受控登记这些资产；登记不继承生产质量通过结论，也不要求再次生成已选人物或声音。旧阿里实验片仅为动作参考，不可登记为人物 B 的正式动作母版。

## 2. 权威枚举与状态规则

### 2.1 PipelineStage：处理到哪一步

枚举保留：`topic | script | content_review | avatar_variant | tts | talking_head | postprocess | video_review | publish_package`。这是业务阶段视图，不要求每一项串行执行。

- `topic`：整理用户提示词、关键词及可选资料；`script`：直接生成三种角度的结构化口播稿与表达标记；`content_review`：内部历史查重与事实风险等内容门禁。
- `avatar_variant`：选择或创建已批准的同身份服装/背景变体，收集可编辑动作描述、素材与路线能力；此时不提交正式 OmniHuman 口播或最终口型。各子工作由 AgentWorkItem 区分。`tts`：两路线共用音色试听、声音选择、全文合成、质检及用户确认的最终音频。
- `talking_head`：`OMNIHUMAN_1_5` 以已审固定人物图＋已确认最终 TTS＋可编辑表演描述直接生成身体/表情/口型；不运行 LivePortrait/MuseTalk。`M2` 以已审 LivePortrait 底片＋同一最终 TTS 调用 MuseTalk。`postprocess`：代码 Worker 执行裁剪、FFmpeg 合成、清晰度处理、规格统一、字幕、封面和标识；各子任务等待所需已审输入，最终合成等待该路线合格原片与真实时间线。
- `video_review`：成片技术检测与人工观感检查；`publish_package`：冻结发布材料与 manifest。

三个不同角度候选稿各自审核后，用户选稿并冻结版本。MiniMax 配音与人物/动作准备可并行；代码可提前校验用户选定的字幕和版式配置。
两路线都必须已选人物、稿件、音色、最终 TTS 和路线，且对应质量门禁及预算满足后才提交正式口播。
OmniHuman 输入固定人物图＋最终音频＋表演描述；M2 先以 LivePortrait 生成已审底片，再结合最终音频对口型。
人物页不提前运行最终嘴型；第 3 页确认最终 TTS，第 4 页按路由生成。Postprocess Worker 可在音频确认后并行对齐字幕，原片经质量 Agent 审核后再核视频及剪辑偏移，成片仍须质量 Agent 审核和代码门禁通过。
单 GPU 重型作业串行排队；独立 OmniHuman 云任务可与本地作业并行，但需分别核输入版本及预算。

资产首次创建属于前置资产流程，不冒充某期视频已经完成。`stage` 为界面显示的主要阶段：从尚未完成且正在执行、待审或阻塞的阶段中按上述枚举顺序选择最早一项；尚未启动时显示下一可执行阶段，全部结束时显示最后阶段。实际并行进度读取 `active_stage_execution_ids`；不能把 `stage` 填成 `running`、`failed` 或 `published`。

### 2.2 TaskState：本期生产任务处于什么状态

`queued | running | waiting_provider | waiting_review | waiting_selection | retry_wait | succeeded | failed | cancelled | blocked`。

合法主路径：`queued → running → waiting_provider/running → waiting_review/waiting_selection/running → succeeded`；实际按工作图在这些非终态间流转。

- Provider 外部任务未结束用 `waiting_provider`；等待人工质量判断用 `waiting_review`；等待用户选稿、选人物/音色、确认全文音频或确认路线用 `waiting_selection`。选择不能替代质量审批；预算授权不足仍为 `blocked`。
- 明确可重试的临时错误：`running/waiting_provider → retry_wait → queued`；记录 `next_run_at` 与剩余次数。
- 预算、许可证、权限、能力缺失或外部提交结果不明用 `blocked`。条件解决后经可审计的 resume 回到 `queued`，不能自动清除阻断原因。
- 不可恢复错误或重试耗尽用 `failed`。生产成功只表示所有生产门禁及发布包完成，`succeeded` 不表示抖音已发布。
- `cancelled` 只表示停止推进；已提交云任务必须继续核对、下载必要证据并结算，不能因此宣称未计费。
- `succeeded/failed/cancelled` 是本次执行终态；再次生产创建新执行 ID 并引用 `previous_task_id`，不得修改旧证据。

`StageExecution.state`、`AgentWorkItem.state` 复用 TaskState。聚合按确定顺序执行：已接受取消后停止新调度并显示 `cancelled`；必需节点不可恢复失败为 `failed`；硬阻断为 `blocked`；所有必需节点、选择及发布包门禁完成才为 `succeeded`；否则有可执行工作为 `running`。无可执行工作时依次检查待质量审批 `waiting_review`、待用户选择 `waiting_selection`、已提交未结束作业 `waiting_provider`、延期重试 `retry_wait`，最后为 `queued`。显示状态不隐藏其他并行分支：返回 `active_stage_execution_ids`、`pending_selection_ids` 和全部阻断/待审原因。取消/失败后已提交作业继续对账，不能据聚合状态删除远端任务或释放未知费用。阶段成功必须有输出摘要、对应选择和门禁结果，不以文件存在或 Agent 回复“完成”替代。

### 2.3 PublishState：独立的发布状态

`pending | ready | awaiting_human | reported_published | scheduled | submitting | submitted | published | rejected | failed | blocked | unknown | cancelled`。

- V1：`pending → ready`，表示包已就绪且可下载；下载不是已发布，也不自动转 `awaiting_human`。后续启用人工交接/回填能力后，才允许 `ready → awaiting_human → reported_published`；人工报告保存 URL、操作者、时间和证据，显示“人工报告已发布”。
- V2：能力和授权实证通过后，`ready → scheduled/submitting → submitted → published/rejected`。`scheduled` 必须有有效排期授权和 Adapter 的定时能力；V1 不启用排期；后续人工提醒也不进入 `scheduled`。
- `submitted` 表示官方受理且有远端 ID；只有明确的官方状态响应或验签回调能转 `published`，保存该响应证据。人工回填不能直接执行此转换。
- 提交超时、连接断开或无法确认副作用时进入 `unknown`；先查远端和既有回执，禁止自动重新创建作品。核对后可转 `submitted/published/rejected`；确认未受理后才允许新的提交尝试。
- `reported_published` 若以后取得对应作品的官方证明，可转 `published`，同时保留原人工报告。无官方查询能力不强行核验成功。
- `blocked` 表示缺授权/能力/标识/有效材料；`failed` 为已明确失败且无不明副作用；`rejected` 为平台审核拒绝；`cancelled` 只取消尚未执行的计划，不等于删除远端作品。

发布与生产失败互不覆盖。例如生产 `succeeded`、包及发布记录 `ready` 是合法 G2 结果，Publication 本身也可尚未创建。

### 2.4 其他小枚举

- `ApprovalState`：`pending | approved | rejected | revoked`。批准总是绑定对象版本与内容摘要。
- `CheckOutcome`：`pass | fail | review | not_run`。`not_run` 不能按通过计。
- `ProviderJobState`：`prepared | submitting | queued | running | succeeded | failed | cancelled | unknown`。
- `ClaimVerdict`：`supported | refuted | unverified`，不把“未发现问题”当作 `supported`。
- `EvidenceOrigin`：`automatic | human | provider`；人工结论和机器结果分开保存。
- `AgentRole`：`supervisor | content | quality | avatar | audio`，依次对应总控智能体、策划文案智能体、质量审核智能体、数字人导演智能体、声音导演智能体；后四项为 subagent 角色。`postprocess` 是代码执行阶段，不属于 AgentRole。
- `ExecutorKind`：`agent | worker`，区分 Agent 阶段和代码任务；代码后期阶段使用 `executor_kind=worker`、`worker_kind=postprocess`，不伪造 Agent 角色或模型结果。
- `MemoryCandidateState`：`proposed | approved | rejected | superseded`；只有审核合并后的 `approved` 版本可供跨任务检索。
- `GenerationRoute`：`M2 | OMNIHUMAN_1_5`；MVP 默认且必交付 OmniHuman 1.5，M2 保留本地选用。首次合成与路线变更须用户选择，默认值不是费用授权。`GROK_IMAGINE_VIDEO_1_5` 仅允许只读历史，不接受新建任务、恢复提交或自动映射为其他路线。

- `SelectionState`：`pending | selected | superseded | cancelled`；过期输入或选项版本变化使原请求 `superseded`，不能复用旧决定。
- `FeatureState`：`planned | developing | available | blocked`，与运行能力分开；只有已实现、已验证能力才 `available`。占位页不得伪造生产数据、进度或连接成功。

## 3. 核心实体

以下为技术中立的逻辑实体；具体数据库、表布局、文档字段与索引由存储选型结果决定。除不可变内容外，实体均有 `id`、`created_at`、`updated_at`、用于乐观锁的 `version`；更新使用期望版本。

### 3.0 作品、偏好与用户选择

**Work**：`id`、`name`、`brief`（文案类型、用户提示词、受众、关键词、目标时长、可选 `provided_source_ids`）、`current_task_id`、`current_selection_refs`、`version`。用户未提供资料时 `provided_source_ids=[]` 合法，生成不以在线检索为前提；关键事实审核仍须有独立依据。这是单用户作品的根；任务、候选、资产和导出包均通过 `work_id` 归属，首次人物库创建可以暂不绑定作品。更新只切换当前指针，旧执行和费用证据保留。一个 Work 可有多次 Task；候选和重生成不能覆盖旧版本。

**SelectionRequest**：`work_id`（人物/声音库独立选择时可空）、`task_id`（资产库独立选择时可空）、`kind`（`avatar/script/voice/audio/route`）、`input_digest`、`options[]`（对象 ID、版本、摘要和质量状态）、`required`、`state`。`script` 目标是 3 个经审核且角度不同的候选；不足 3 个明确显示不足并在预算内返工，不能伪造合格候选，也不能自动代选。

**SelectionDecision**：`selection_request_id`、`selected_ref`（对象 ID、版本、摘要）、`expected_work_version`（无作品时为空，并校验所选资产版本）、`actor_id`、`decided_at`、`decision_digest`。选择须引用仍有效且通过该环节门禁的对象；陈旧选项返回 409。同一请求只接收一次有效决定，改变主意新建请求/版本并计算依赖失效。用户点击“采用”只表达偏好，不能代替 QualityReport、ReviewDecision 或费用授权。两路线均在生成前选择 VoiceAsset 及其全文 TTS，不能用视频模型自行生成的声音替换该音频。

**GenerationIntent**：`work_id`（可空）、`purpose`（`identity/variant/performance`）、`keyword_values`、`free_text`、`compiled_prompt_asset_id`、`compiler_version`、`identity_id`（后两种必需）、`identity_digest`、`capability_report_id`。首次人物提示词由关键词与自由描述构成；衣景编辑组合冻结身份锚点、实际参考图和用户追加衣景要求，身份冲突词提交前提示/拒绝。表演提示词保持用户可编辑；记录支持、近似和未验证项，不把自然语言等同于可执行动作。高级提示词预览只展示用户输入和本次生成描述，不暴露系统指令或凭据。

**ProgressSnapshot**：`work_id`、`task_id`、`stage_execution_id`、`state`、`phase`、`percent`（未知为 null）、`source`（`provider/measured/indeterminate`）、`completed_units/total_units`（可空）、`updated_at`。百分比只来自 Provider 可靠进度或可测量工作量；排队、质检、等待用户与超时用真实阶段和等待时间展示，不按计时器伪造线性进度。SSE/增量事件断线后按 seq 恢复。

### 3.1 身份与声音资产

**AvatarIdentity**

- `id`、`name`：固定主播；“真人 Base Avatar”指写实成年虚拟人物，不表示采用真实自然人的肖像。
- `hero_asset_id`、`reference_asset_ids`、`identity_prompt`、`identity_digest`：冻结的主参考图、参考集、身份锚定描述及摘要。脸型、五官、发型、肤色、年龄与性别不随单期配置改变。
- `source_record_id`：生成来源、模型版本、提示词/seed、使用权证据。seed 仅用于复盘，不能证明身份一致。
- `approval_state`、`approval_id`：身份质量与来源批准；`selection_decision_id`：用户采用记录，二者分开。`default_voice_asset_id` 可保存该人物默认声音版本。批准后不可覆盖 hero 文件；换身份创建新 identity，旧期视频继续引用旧资产。人物 B 是初始默认，不是全局唯一白名单。

**AvatarVariant**

- `identity_id`、`image_asset_id`、`outfit`、`background`：服装与背景选择，只描述本次可变部分。
- `reference_digest`、`provider_run_id`、`generation_spec_digest`：能追溯到冻结身份和生成参数。
- `identity_report_id`、`approval_state`、`approval_id`：须先过身份门禁再可生产。无许可清晰的人脸模型时，以人工对照审批代替自动打分；不得填写虚构相似度。

**VoiceAsset**

- `provider`、`model`、`region`、`remote_voice_id`：完整音色作用域；四者作为组合解释，不能仅凭字符串 ID 复用。
- `reference_audio_asset_id`、`synthesis_profile`、`profile_digest`：冻结试听音频和基础参数；不支持 seed 的服务不得写“已固定 seed”。
- `source_record_id`、`approval_state`、`approval_id`：预设音色选择与使用权，或声音创建/注册的来源证据，以及盲听/基准句评审。声音更换创建新版本。
- 新模型/供应商必须创建独立 VoiceAsset 并重新验收；Qwen Voice Design 输出 ID 能否供某 CosyVoice 型号使用是待实证能力，默认不允许。允许用有权使用的参考音频重新建音色，但不承诺完全相同。

**SourceRecord** 只保留 `source_type`（本项目生成 / 本项目预设音色选择 / 为本项目新取得授权 / 本项目独立测试素材）、`provider/model/version`（适用时）、`provider_run_id`（真实生成、基准合成或注册时）、`prompt_asset_id`（适用时）、`seed`（可空）、`rights_evidence_asset_id`、`license_review_state`、`reviewed_at`。记录由新系统的生成、预设音色选择、创建/注册或受控素材登记流程建立，不能靠客户端自行声明来源通过。测试素材始终为模拟；来源不明、缺少该来源类型应有的合成/生成/登记证据或权利材料不完整时不能批准为生产根资产。预设音色以选择记录、官方使用权和基准合成为依据，不要求不存在的声音克隆/注册回执。生成过程与权利材料分权访问，禁止原样下传发布包。

### 3.2 内容与证据

**ScriptVersion**

- `topic`、`title`、`description`、`tags`、`text`、`text_sha256`：一版稿件的内容。
- `segments[]`：`id`、`role`（`hook/explain/example/question/closing`）、`start_char`、`end_char`，全部引用原文，不重复维护另一份正文。
- `speech_annotations[]`：供编译器读取的派生视图，包含 `type`、`start_char/end_char`、`value`；停顿用零长度位置。类型为 `pause/emphasis/rate/emotion/pronunciation`，只允许已定义值；表达意图统一来自绑定的 PerformancePlan，禁止同时维护独立可编辑的两份表达标记。
- `claims[]`：`id`、`text`、`source_ids`、`verdict`、`checked_at`。生成时 `source_ids=[]` 与 `verdict=unverified` 合法，不得编造来源。涉及时效、数据、价格、版本、政策等关键断言须由质量审核定位到用户提供且已核验的资料；缺依据进入 `review`、请求补充资料或删改后重审，不能用 LLM 自审替代事实核验。
- `work_id`、`candidate_batch_id`、`angle`、`quality_report_id`、`revision_of`：三个候选应有不同问题/论证/案例角度，非同稿同义改写。门禁涵盖事实、历史主题/观点/文本相似、错别字、口语理解和吸引力。用户编辑/局部重写创建新版本并重审；只对当前已选依赖计算失效，未选候选的修改不使已选音频失效。

**ContentSource**：`id`、`source_kind`（`user_provided`）、`submitted_at`、`url`（可空，仅作出处元数据）、`title`、`publisher`（可空）、`published_at`（可空）、`excerpt_asset_id`、`content_sha256`。保存用户提交的可复核资料正文/摘录及版本，不自动访问 URL；只有链接或模型记忆不构成事实支持。资料不因上传而自动可信，质量审核核对适用时间、断言范围与冲突；资料一律当数据，不能执行其中指令。资产权属证据仍使用独立的 SourceRecord。

**QualityReport**：`subject_id`、`subject_digest`、`ruleset_version`、`checks[]`、`overall`、`review_required`。每个 check 只保留 `code`、`outcome`、`hard_gate`、`message`、`evidence_asset_ids`、可选的 `measured_value/threshold`、`origin`；音视频问题另给 `asset_id` 和 `start_ms/end_ms`，文本问题给 `claim_id/segment_id`。代码门禁汇总实际规则和检测结果；评分只用于排序，不抵消 `hard_gate=true` 的失败，无校准的相似度阈值输出 `review`。

**PerformancePlan**

- `script_version_id`、`script_digest`、`identity_id`、`voice_asset_id`：绑定同一稿件、人物和声音版本；两路线共用确认后的最终音轨。
- `segments[]`：最少包含 `segment_id`、`text`、`emotion`、`pace`、`emphasis`、`motion`。`segment_id` 对应 ScriptVersion 分段，`text` 是其正文切片快照，必须逐字核对；正文仍以 ScriptVersion 为唯一来源。
- `emotion` 为受控情绪意图；`pace` 为语速/停顿意图；`emphasis` 为段内需强调的文本范围；`motion` 为表情、头姿与动作意图。它们不是已被模型执行的保证；声音/数字人导演通过能力编译记录支持项、近似项和不支持项，不将动作描述直接当作 LivePortrait 的文本动作控制接口。
- `target_duration_ms` 仅用于规划，`approval_id`、`plan_digest`、`revision_of` 用于冻结和追溯。实际分段时间来自最终 TTS 及核验后的对齐，不得以目标时长或均分时长替代。OmniHuman 分段引用同一音轨的句子边界，不重合成另一声音。

**QualityDecision**

- `work_item_id`、`subject_id`、`subject_digest`、`ruleset_version`、`report_ids`：质量 Agent 必须引用当前版本的事实报告、媒体检测或人工证据。
- `recommendation` 使用 `CheckOutcome`；`issues[]` 只含 `code`、`reason`、`evidence_asset_ids`、定位用的 `claim_id/segment_id` 或 `asset_id/start_ms/end_ms`，以及 `rework_target`。
- `model_run_id`、`decision_digest`：记录判断来源；未知事实或缺指标只能建议 `review/not_run`。该对象不是批准令牌，不能写 `ApprovalState`、清除代码硬失败或替代 ReviewDecision。

### 3.3 任务、阶段与媒体

**Task**：`id`、`work_id`、`mode`、`stage`、`state`、`topic`、`identity_id`、`voice_asset_id`、`script_version_id`、`performance_plan_id`、`audio_asset_id`（未选时可空；正式口播前必须已审且用户确认）、`route`、`route_selection_id`、`input_snapshot_digest`、`active_stage_execution_ids`、`pending_selection_ids`、`config_snapshot_id`、`budget_policy_id`、`cost_confirmation_id`、`next_run_at`、`block_reason`、`last_error`、`previous_task_id`（可空）。本次输入一旦冻结不原地替换；选择变化创建新执行并保留旧结果。发布进度通过可空 `publication_id` 获取，不混入 TaskState。

**StageExecution**：`task_id`、`stage`、`executor_kind`、`worker_kind`（Agent 阶段为空；代码后期/打包为 `postprocess`）、`attempt`、`input_digest`、`state`、`output_asset_ids`、`quality_report_ids`、`provider_run_ids`、`started_at/finished_at`、`lease_owner/lease_until/fencing_token`。同一阶段与输入摘要只能有一个有效执行；过期 worker 的写入凭 fencing_token 拒绝。`postprocess/publish_package` 使用 `executor_kind=worker`，记录代码/工具/配置版本、输入输出摘要与执行日志，由内部执行服务登记；不创建后期 AgentWorkItem/AgentResult，不要求 Skill 或 model_run_id。

**MediaAsset**：`id`、`mode`、`kind`（`image/audio/video/subtitle/cover/manifest/evidence`）、`storage_key`、`sha256`、`bytes`、`mime_type`、`duration_ms`（适用时）、`width/height`（适用时）、`source_record_id`（根资产必需，派生资产可由父链追溯）、`parent_asset_ids`、`producer`、`simulated`、`validation_report_id`。`producer` 包含 Provider、模型/版本、请求 ID，确定性本地处理记录工具与版本；Mock 资产及其所有后代均 `simulated=true`。所有根来源须符合 §1.1，复制文件、改变 mode 或重新编码均不能消除来源限制。

**ReviewDecision**：`subject_id`、`subject_digest`、`decision`（`approve/reject`）、`actor_id`、`reason`、`evidence_asset_ids`、`created_at`。人工可以处理 `review` 项，不能豁免模拟素材、缺失标识、来源摘要不符等确定性硬门禁。撤销审批增加新记录，不覆盖旧记录。

### 3.4 Agent 工作、记忆与版本绑定

**AgentWorkItem**：`task_id`、`stage_execution_id`、`role`、`objective`、`depends_on_ids`、`input_refs`、`input_digest`、`output_schema_version`、`skill_refs`、`tool_policy_id`、`namespace`、`checkpoint_ref`（可空）、`budget_policy_id`、`state`。`role` 只接受 AgentRole；`input_refs` 引用对象 ID＋版本＋摘要；`skill_refs` 绑定角色所需 Skill 的 ID＋版本＋摘要；`state` 复用 TaskState。Skill 清单保留 S01～S06、S08 共 7 项，S07 字幕与剪辑撤出清单且不复用编号。权限由服务端按角色、任务和运行模式授予，不能让 Agent 自填 allowlist 或提高额度。

**AgentResult**：`work_item_id`、`input_digest`、`state`、`output_refs`、`evidence_asset_ids`、`quality_decision_ids`、`provider_run_ids`、`model_run_id`、`error`（可空）、`result_digest`。结果须通过输出 schema、对象摘要、依赖版本及工具审计核验；subagent 不能仅返回长文本就把工作标记为 `succeeded`。中间失败、阻断和重试通过既有状态机处理。

**MemoryCandidate**：`task_id`、`work_item_id`、`scope`（`role/project`）、`namespace`、`content_asset_id`、`content_digest`、`evidence_refs`、`applicability`、`supersedes_id`（可空）、`state`、`review_decision_id`（待审可空）。`applicability` 至少绑定适用模型/规则/Skill 版本；事实结论有来源和有效时间。候选、错误案例与已批准经验分开检索，经验不能替代事实来源、资产批准或预算授权。

记忆分四层：任务检查点保存恢复所需工作图与引用；不可变人设/声音资产通过 ID 只读加载；历史内容库仅由质量角色用于主题/观点/文本查重，不是在线资料检索；经验库只接收有证据并经审核合并的 MemoryCandidate。每个工作项写入 `mode/task_id/work_item_id` 隔离命名空间；共享写入使用期望版本和审核合并，不让并行 Agent 覆盖公共文件。持久化实现待离线试验选定，框架检查点不替代 ProviderRun、预算账本或媒体证据。

版本失效按路由和实际依赖图计算并留事件：修改已选稿件或声音表达，使对应 PerformancePlan、最终 TTS 及其口播/字幕/后期后代失效；未选候选变化不影响当前生产。改人物/衣景/动作要求使对应 OmniHuman 原片或 M2 底片/口型后代失效，未变的已确认 TTS 可复用。切换路线重新核验人物、同一最终 TTS 与该路线能力/预算。只改剪辑重算时间线、字幕和包；只改字幕样式复用原片和已校准时间轴，仅重渲染并重审。约 60 秒分段返工只重做受影响片段并复核接缝，不能换音轨或覆盖旧记录。

模型/Skill/规则更新按兼容性复验。失效停止当前生产使用，保留原结果、费用和历史批准，不删除失败证据。

### 3.5 外部任务、预算与发布

**ProviderRun**：`work_id`、`task_id`（独立资产/试听可空）、`stage`、`provider_account_id`、`route`（非口播可空）、`provider`、`model`、`capability_snapshot_id`、`request_digest`、`idempotency_key`、`state`、`remote_job_id`（未取得时可空）、`request_trace_id`、`poll_after`、`deadline_at`、`result_asset_ids`、`cost_reservation_id`、`last_error`。未知远端任务仍保留占用/预算，不因 worker 重启创建替代计费任务。

**BudgetPolicy**：`provider_model_allowlist`、`per_task_limit_fen`、`daily_limit_fen`、`monthly_limit_fen`、`max_billable_submissions`、`allow_failover`、`valid_until`、`authorization_evidence_id`。默认额度与可计费次数均为 0；不得将 0 解释为无限制。

**CostReservation**：`work_id`（独立资产可空）、`task_id`（独立资产/试听可空）、`provider_run_id`、`budget_policy_id`、`reserved_fen`、`actual_fen`（未知时为空）、`state`（`reserved/settled/released/disputed`）、`price_snapshot_id`、`billing_evidence_id`。`actual_fen=0` 只用于确认零费用，不能表示未知。预算按已花费加未结算预留校验，日界使用配置时区；重试和备用供应商也占预算。

**PriceSnapshot**：`provider_account_id`、`provider/model`、`region`、`billing_unit`、`unit_price`、`currency`、`fx_version`（非人民币必需）、`rounding_rule`、`effective_at/expires_at`、`evidence_asset_id`、`price_source`、`billing_verified`。账户套餐、分辨率、时长取整、附加费和最低消费影响估价时必须记录；不能沿用历史单价当当前报价。

OmniHuman 使用用户确认 1 元/生成秒（100 分/秒）记录价格快照，`price_source=user_confirmed_rate`、`billing_verified=false`。60 秒估算 60 元、5 条/日 300 元、30 天 9000 元，仅视频生成费。当前账户取整、最低消费、失败扣费及账单待核验；报价不等于具体预算授权，Grok 的 0.38 元/秒不能移用。最终成片秒数不等于全部计费生成秒数；分段取整、失败返工、MiniMax、文本/图片、存储后期分别记账，M2 GPU 只按实际使用计入。未知费用保留待对账。

**CostConfirmation**：`work_id`（可空）、`task_id`（可空）、`operation`、`route`（适用时）、`request_digest`、`price_snapshot_id`、`estimated_fen`、`ceiling_fen`、`budget_policy_id`、`max_billable_submissions`、`accepted_risks`、`actor_id`、`confirmed_at`、`valid_until`。确认画面展示模型、片段数、生成总秒数、分辨率、估价、预算与“效果不满意仍可能收费、重生成可能再次收费”。金额/输入/路线变化须在已确认清单与预算内，否则重新确认。选择 OmniHuman 不自动授权付费，只有关联有效预算和具体调用清单的费用确认才允许提交；不允许失败静默切换或盲重试。

**ProviderAccountConfig**：`id`、`adapter_kind`、`provider`、`base_url`、`model`、`secret_ref`、`config_digest`、`validation_state`（`unverified/usable/invalid`）、`checked_at`、`error_code`。MVP 仅提供已适配 Provider 的基础配置和连接检查；可编辑 URL/模型名不代表任意协议兼容。明文密钥只通过专用设置请求写入服务端受控存储，响应只返回掩码/是否已设置；URL 和协议由适配器安全校验。验证分别报告身份认证、模型访问和所需能力，不用一次文本响应证明图像编辑/TTS 可用；会扣费的探测也须先估价确认。

**PublishPackage**：`work_id`、`task_id`、`mode`、`video_asset_id`、`cover_asset_id`、`subtitle_asset_id`、`title`、`description`、`tags`、`ai_label`、`manifest_asset_id`、`package_digest`、`quality_report_ids`、`review_decision_ids`。任何文案/成片/封面修改都生成新 package，旧审批不继承。

**Publication**：`package_id`、`account_binding_id`（未绑定账号时可空）、`adapter`、`state`、`idempotency_key`、`scheduled_at`（可空）、`authorization_id`（V2 必需）、`remote_item_id`、`official_evidence_asset_id`、`manual_report`（`url/actor_id/reported_at/ai_declaration_confirmed/evidence_asset_ids`）、`last_error`。`reported_published` 可以有 URL 但无 official evidence；`published` 必须有官方证据。

**PublicationPlan**：`publication_id`、`planned_at`、`timezone`、`state`（`pending/due/overdue/completed/cancelled`）、`completed_at`。该实体为后续人工投稿提醒保留，V1 不开放；启用后不改变 PublishState 为 scheduled；已上线应用到点置 due，休眠错过置 overdue，禁止集中自动补发。生产排产用独立 `ProductionSchedule` 保存规则、下一次触发和 `schedule_id + planned_fire_at` 唯一键。

## 4. Provider 契约

### 4.1 能力声明必须先于调用

`capabilities()` 返回 `provider`、`model`、`verified_at`、`evidence_id`、`supported_modes`、`operations`、`constraints`。每个 capability 的状态为 `unverified/supported/unsupported`；只有 `supported` 可被生产调度采用。能力证据绑定账号、地域、模型版本，有过期时间；服务升级后重新验证。

- 图像：是否支持参考图输入、最大参考数、允许分辨率。
- TTS：可用 VoiceAsset 作用域、字/词级时间戳、可用表达控制、音频格式和最大文本长度。
- 动作迁移：批准的 source image＋动作参考，LivePortrait 模型/权重/许可证、参考时长、帧率、裁剪和循环策略。约 9.13 秒循环只属 EXP-001 实验条件，不自动成为生产能力。
- `TalkingHeadProvider`：按 route 声明 `image_audio_to_video`（OmniHuman）或 `video_audio_to_video`（M2/MuseTalk）；均消费已确认最终 TTS。OmniHuman 声明参考图、音频格式/长度、表演提示、分辨率、异步查询/取消/幂等的当前账户能力；不把模型可见或历史短片等同当前人物/动作/长片通过。
- 当前 OmniHuman 核验依据：音频严格小于 60 秒、建议不超过 15 秒，prompt 不超过 300 字符；720p/1080p、最大输入及具体账户权限须复核。约 60 秒以同一最终音轨按句子分段，不允许加速或截字绕过限制。不承诺任意动作。
- `GROK_IMAGINE_VIDEO_1_5` 不属于当前可调度能力；历史调研记录保留只读，不映射为 OmniHuman 或恢复提交。

- 发布：`prepare_package`、`official_submit`、`official_status`、`scheduled_submit`、`ai_declaration`、`requires_human_confirm`。存在接口地址不等于任何能力为 `supported`。

不支持必需参数时返回 `CAPABILITY_UNSUPPORTED`；禁止静默忽略必需情绪/动作、改人物或声音、降级为形变嘴巴、改用未验证的视频生成路线；未验证能力不能调度。允许的近似表达必须在编译结果明确列出并经该音色的能力配置批准。

### 4.2 异步媒体 Provider

口播请求按路线校验实际前置，不增加第二套声音生成：

- `TalkingHeadRequest` 公共字段：`route`、`person_asset_id`、`identity_digest`、最终 `audio_asset_id`、`audio_digest`、`voice_asset_id`、`script_version_id`、`performance_plan_id`、可编辑 `performance_prompt`、`segment_id`、`audio_start_ms/audio_end_ms`、`output_spec` 与输入摘要。台词与时间范围须属于已审且用户确认的同一 TTS；外部下载引用由受控资产解析。
- `OMNIHUMAN_1_5`：固定人物图＋相应最终音频切片＋受支持的可编辑表演描述，直接生成带身体/表情/口型的原片，不要求底片，不调用 LivePortrait/MuseTalk。`TalkingHeadResult` 含 `video_asset_id`、`provider_run_id`、实际时长、音轨保持/身份/嘴型/动作报告、输出摘要与费用。
- `M2`：另需已批准 `motion_video_asset_id` 及摘要。LivePortrait 使用人物与许可动作参考生成底片，审核后与最终 TTS 交 MuseTalk；两阶段分别保存 ProviderRun、输入输出、作业和费用。

约 60 秒 OmniHuman 请求按同一最终音轨的语义/句子边界切片，每段严格低于当前已验证上限；保存音频全局偏移和片段顺序，不重新生成声音，不加速截字。字幕可提前基于确认 TTS 对齐，拼接后再映射实际视频前导/剪辑时间。检查原片音轨保持是独立门禁，不能用高波形相关代替嘴型、身份或身体质量。

火山原生协议为 `visual.volcengineapi.com`，HMAC AK/SK 签名，`region=cn-north-1`、`service=cv`；POST `Action=CVSubmitTask/CVGetResult`、`Version=2022-08-31`，`req_key=jimeng_realman_avatar_picture_omni_v15`。密钥只由服务端引用。本版 Adapter 目标接入尚未验收，本轮不据文档修改推定已有骨架已同步；历史成功仅证明该历史账户/输入可调用，重新接入仍须核当前权限、规格与价格。

### 4.3 音频、表达与字幕时间轴

**VoicePreview**：`work_id`（可空）、`voice_asset_id`、`sample_text_digest`、`synthesis_profile_digest`、`audio_asset_id`、`provider_run_id`（复用缓存可引用原运行）、`cost_reservation_id`。音色列表可播放来源清楚的预设样例；要比较声音必须使用同一短句。短句试听不能当正文音频，缓存仅按声音/模型/参数/文本摘要精确命中。用户选音色后合成全文；全文质检与用户试听采用分别记录，更换音色重新合成并保留旧费用。

`TTSResult`：`audio_asset_id`、`voice_asset_id`、`script_version_id`、`performance_plan_id`、`duration_ms`、`spoken_text_mapping`、`timing_source`（未完成对齐时为空；完成后为 `provider/forced_alignment/asr_alignment/mock`）、`words[]`（未完成时可空，不算字幕已完成）。word 含 `segment_id/start_char/end_char/start_ms/end_ms`，时间均相对于对应的 **实际音频文件起点**。分句合成必须先加分句在整段音频中的偏移再汇总；字级能力需在具体模型和音色上验证。

TTS 合成与音频确认不要求已完成字幕对齐；原生字词时间戳由代码核验，没有可靠时间戳时由 Postprocess Worker 补齐并登记新的对齐产物版本，不能原地伪填或均分时间。两路线均消费同一 `TTSResult`。字幕由代码 Postprocess Worker 在最终音频确认后并行执行 ASR/对齐；云视频生成后复核输入音轨保持与视频前导，不重新选用另一原生声音。

表达编译器不得改变字幕原文。发音替换将原文范围映射到朗读字符串，例如 `RAG` 与供应商所需读法；合成后时间戳必须映回原文范围。标记范围越界、未知标记、剥离标记后正文变化均拒绝。句长均分只能用于 mock，生产不得以按字数均摊伪装时间戳；无原生时间戳时用 ASR/强制对齐并核对术语，无法可靠对齐则待审。

`EditTimeline`：`source_audio_asset_id`、`source_video_asset_id`、`segment_sources[]`（分段时保存每段视频/实际音轨与全局偏移）、`provider_lead_ms`、`clips[]`、`final_duration_ms`。`provider_lead_ms` 是原始口播视频相对输入音频多出的前导时长，必须测量/核对，不能默认靠改字幕掩盖口型偏移。每段先核对实际视频对输入 TTS 的偏移，再按编辑表与音频全局偏移汇总；历史样本 0 ms 不能推定未来全部任务为 0。

每个 clip 含 `source_start_ms`、`source_end_ms`、`target_start_ms`；source 指原始口播视频时间轴。V1 只允许速度 1 倍和非重叠顺序剪辑。音频某时刻先映射为 `source_video_ms = audio_ms + provider_lead_ms`，再映射为 `final_ms = target_start_ms + source_video_ms - source_start_ms`。字幕区间先与 clip 求交，跨剪点则拆分；被删除区间不能产生负时间戳。片头/片尾占目标时间轴，未对应口播的区间不显示原文字幕。

```json
{
  "schema_version": 1,
  "source_audio_asset_id": "audio_001",
  "source_video_asset_id": "raw_video_001",
  "provider_lead_ms": 0,
  "clips": [
    {"source_start_ms": 400, "source_end_ms": 11800, "target_start_ms": 1000}
  ],
  "final_duration_ms": 12900,
  "example_word": {"text": "你好", "audio_start_ms": 500, "audio_end_ms": 900, "final_start_ms": 1100, "final_end_ms": 1500}
}
```

Postprocess Worker 直接调用 FFmpeg/libass 完成统一时间轴、合成、字幕烧录、封面及标识；待选 ASR/对齐、超分模型通过能力与质量验收后才能启用。普通缩放只统一输出尺寸，不等于真实细节增强；清晰度处理保留原片、参数及前后对照，质量 Agent 复核身份与伪影。最终门禁通过后由内部打包服务生成交付包，不由模型规划命令或绕道 MCP。

此例裁去前 400 ms 和尾部，加入 1000 ms 片头与 500 ms 片尾。若云端因时长限制分段，另存每段输入音频范围与输出剪辑映射；不得简单 concat 重叠的音频，必须验证无重复字、漏字和段间口型跳变。默认按句无重叠切分，确需上下文重叠时先裁掉重复区再生成映射。

## 5. 应用 API 最小集

### 5.1 DeepAgents、MCP 与执行权限

Agent 获准的外部或跨进程能力调用链为 `DeepAgents / subagent → 受限 MCP 工具 → Provider 适配器 → Worker`。本机确定性纯函数可适配为普通工具，无需为每次计算经过 MCP；其入口和结果同样执行角色/任务作用域、输入版本、schema 与业务门禁校验，不能借普通工具访问未授权文件、改变审批或绕过外部提交/预算台账。角色 Skill 是版本化操作规范，不授予系统权限；MCP 工具不实现另一套调度或状态机。总控只能委派任务、查询状态和汇总结果，不能直接运行任意 shell、任意访问文件、直连供应商或改预算/审批/固定人设。

内部最小工具面为 `submit_work(work_item_id, operation, input_refs, idempotency_key)`、`query_work(work_item_id/provider_run_id)`、`register_result(work_item_id, result_refs, evidence_refs)`。角色按 allowlist 获得所需内部历史/记忆、媒体生成与检测审核操作；任务、模式、命名空间、输入版本、费用上限及许可均在服务端再次校验。`register_result` 只登记受控结果，不能替 Agent 填入不存在的检测分数或强制放行。

保留两个 MCP 服务的部署建议，但仅承载 M01 内部内容历史（仅 quality）、M02 角色记忆、M03 媒体生成和 M04 检测审核；无网上搜索/抓取、字幕对齐、视频渲染或打包入口。删除 M05 交付 MCP，打包由内部服务执行。Postprocess Worker 由依赖图在输入和门禁满足后自动调度，直接运行代码/模型适配器，不进入 Agent 的 MCP 工具面；仍执行相同的输入摘要、租约、幂等、预算及版本失效校验。

提交前持久化意图和预算，Worker 按资源队列执行；同一 GPU 同时只有一个有效重型作业租约。MCP 超时不证明底层未执行，先查询已记录 ProviderRun；`unknown`（界面可显示 UNKNOWN）期间禁止自动重发。即使 DeepAgents 恢复后重复调用工具，幂等层也必须返回原结果。检查点恢复首先对账现有工作项、ProviderRun 和预算，不从模型聊天记录猜测远端状态。

### 5.2 面向工作台的接口

以下接口仅是开发契约。所有写接口须验证操作者；高风险发布/预算操作另核对授权范围。业务接口不得接受本地任意路径、明文 key 或未经登记的外部媒体 URL；专用配置写入接口是密钥输入的唯一例外，不回显、不写日志。单用户也需限制本机/受信访问，不能因无多人角色就公开凭据接口。

- `GET /api/v1/capabilities`：返回已验证能力与阻断原因，不返回凭据。
- `GET /api/v1/features`：七个固定功能入口的 `feature_id/title/feature_state/reason/available_actions`；占位页可打开，未实现动作禁止调用，指标缺数显示 unavailable/null 而非 0。
- `POST /api/v1/works`、`GET /api/v1/works`、`GET /api/v1/works/{id}`：建立/读取作品与当前选择、版本、结果和任务历史；刷新后从持久记录恢复。
- `POST /api/v1/selections/{id}/decisions`：提交绑定摘要和期望作品版本的用户选择；不是质量批准接口。
- `GET /api/v1/voices`、`POST /api/v1/voice-previews`：读取当前 Provider 确实可用的音色及短句试听，新增计费试听也需预算。
- `GET /api/v1/provider-configs`、`PUT /api/v1/provider-configs/{id}`、`POST /api/v1/provider-configs/{id}/validate`：MVP 支持已接入适配器的基础配置、脱敏读取与受控验证；通用模型自由接入页面后期开放。
- `POST /api/v1/cost-estimates`、`POST /api/v1/cost-confirmations`：读取账户价格估算并记录确切请求/路线的预算确认，不替代 BudgetPolicy 原子校验。
- `POST /api/v1/avatar-identities`、`GET /api/v1/avatar-identities/{id}`：建立候选身份/读冻结资产；没有覆盖已批准 hero 的接口。
- `POST /api/v1/avatar-identities/{id}/variants`：提交服装/背景变体生成任务。
- `POST /api/v1/voice-assets`、`GET /api/v1/voice-assets/{id}`：登记 MiniMax 等作用域明确的候选音色；生产需审批。
- `POST /api/v1/tasks`：提交 `work_id`、输入版本、路线和已授权预算策略；创建或继续该作品一次生产执行，返回 `task_id/state/stage/pending_selection_ids`。内容/试听阶段不要求下游音频或路线决定已存在；route 可先记默认 OMNIHUMAN_1_5，route_selection_id 在合成前可空，默认值不代表用户已确认。只对当前将执行阶段校验必需选择，进入 talking_head 时两路线均核已审人物/已选稿/已确认最终 TTS/路线/预算；M2 另核已审动作底片。
- `GET /api/v1/tasks/{id}`、`GET /api/v1/tasks/{id}/events?after_seq=...`：状态与增量事件。
- `GET /api/v1/tasks/{id}/work-items`：读取角色、依赖、结构化结果和阻断证据；不返回完整提示词或密钥。
- `GET /api/v1/tasks/{id}/performance-plan`：读取绑定稿件的当前表演计划；改动通过版本化修订接口提交并重新审核。
- `POST /api/v1/tasks/{id}/performance-plan-revisions`：新建计划版本，按依赖失效受影响产物；不能修改已批准快照。
- `POST /api/v1/tasks/{id}/cancel`、`POST /api/v1/tasks/{id}/resume`：停止推进/解决阻断后恢复；不得清除未知外部副作用。
- `POST /api/v1/tasks/{id}/script-revisions`：保存修订稿，创建新的执行输入并失效下游缓存。
- `POST /api/v1/works/{id}/scripts`：触发三稿生成，可带 `materials`（参考资料，字符串或 `{text, source}` 列表）。资料写进 `WorkBrief.materials`，是断言判定的**唯一**依据来源；哈希与加入时间由服务端复算写入，调用方填的值一律覆盖。留空合法，此时生成侧不得写需要外部依据的事实断言。
- `POST /api/v1/works/{id}/script-repairs`：让**模型**定向重写某一稿。请求 `{script_id, request_id?}`；有效返工创建新候选 ID，`parent_id` 指向原稿，并重新审核当前三稿。仅当三稿全部通过审核时返回完整 `ScriptVersion`；否则只返回 `{id, parent_id, ready_to_present: false}`，不得提前返回正文或分镜。页面随后读取 `GET /api/v1/works/{id}/scripts` 的当前批次投影。
  注：上述两个 works 路径与本节既有 `tasks` 路径的写法不一致，属历史遗留，以代码实现的 `works` 路径为准，待统一。
- `POST /api/v1/reviews`：对精确对象摘要提交 approve/reject；过期摘要返回 409。
- `GET /api/v1/publish-packages/{id}`、`GET /api/v1/publish-packages/{id}/download`：查看、下载经验证的发布材料。
- `POST /api/v1/publications`：V1 可由包建立只处于 ready 的记录，实际发布入口仍是占位。
- `POST /api/v1/publications/{id}/plan`、`PATCH /api/v1/publications/{id}/plan`：后续阶段才启用，设置/改期/取消人工投稿提醒，返回 PublicationPlan；不调用平台。
- `POST /api/v1/publications/{id}/manual-report`：后续阶段才启用，记录作品 URL、操作者和证据，写 `reported_published`。
- V2 才启用 `POST /api/v1/publications/{id}/submit`、`POST /api/v1/publications/{id}/schedule`、`GET /api/v1/publications/{id}/status`。
- `POST /api/v1/provider-callbacks/{provider}`：默认关闭；只在提供商具备验签能力并完成防重放验证后开放，原始请求体校验签名，不能复用普通登录接口放行。

所有创建/提交/人工回填接口接受 `Idempotency-Key`。同 key 同规范化请求返回原结果；同 key 不同请求返回 409。重放不得生成新预算预留或远端请求。

## 6. 事件与发布包

事件与业务状态在同一事务提交，事件为追加记录。每个聚合的 `seq` 单调递增，消费者按 `event_id` 去重；outbox 投递是至少一次，不能承诺跨外部服务 exactly-once。

事件名：`task.created`、`stage.started`、`provider.submission_unknown`、`provider.completed`、`quality.review_required`、`review.decided`、`stage.completed`、`package.ready`、`publication.manual_reported`、`publication.submitted`、`publication.confirmed`、`cost.settled`、`task.blocked`；新增 `work.created`、`selection.requested`、`selection.decided`、`selection.superseded`、`cost.confirmed`、`progress.updated`、`agent.work_assigned`、`agent.result_registered`、`performance_plan.frozen`、`artifact.invalidated`、`memory.candidate_proposed`、`memory.candidate_reviewed`。新事件仍复用同一追加审计与去重机制。

```json
{
  "schema_version": 1,
  "event_id": "evt_001",
  "aggregate_type": "task",
  "aggregate_id": "task_001",
  "seq": 7,
  "type": "quality.review_required",
  "occurred_at": "2026-09-21T03:15:00Z",
  "trace_id": "trace_001",
  "payload": {
    "stage": "avatar_variant",
    "state": "waiting_review",
    "subject_id": "variant_001",
    "quality_report_id": "qr_001",
    "reason_code": "LICENSE_REVIEW_REQUIRED"
  }
}
```

内部打包服务在最终质量门禁通过后由代码触发。发布包目录至少包含 `video.mp4`、`cover.jpg`、`subtitles.srt`、`title.txt`、`description.txt`、`tags.txt`、`ai_label.txt`、`manifest.json`。字幕同时烧录成片并提供文本文件；包不是“已发布证明”。

包内另附可离线阅读的 `quality-summary.json` 和脱敏 `evidence-index.json`，提供必要质量/事实/查重结论与费用摘要，敏感原始证据仍在受控库中；不能仅给出无法离线解释的内部 ID。

manifest 必需字段：`schema_version/package_id/work_id/task_id/mode/simulated`、每个交付文件的路径/摘要/大小、成片规格、所选 route、选择决定摘要、实际 Provider 与身份/音色版本、事实/去重报告和费用摘要、AI 显式/隐式标识检查结果、平台声明待办、`quality_report_ids`、`review_decision_ids`、`created_at`。仅包含相对文件名，不包含密钥、对象存储签名 URL、内部文件绝对路径或上游完整提示词。以确定性清单计算 package_digest，manifest 中不包含自身摘要；清单摘要存 DB，避免循环自哈希。

AI 隐式标识的具体字段与封装方式由上线前确认的规范版本决定；任意 `comment=AI-generated` 不能单独算规范通过。标准未核对时对应 check 为 `review/not_run`，不得宣称合规已经验收。

## 7. 契约验证清单

- Work、SelectionRequest/SelectionDecision、GenerationIntent、ProgressSnapshot、CostConfirmation、AgentWorkItem/AgentResult、PerformancePlan、QualityDecision、MemoryCandidate 的最少字段、版本与摘要可验证；无依据的 Agent“通过”不能改变代码硬门禁。
- DeepAgents 的任务检查点可恢复；稿件未选/未审不得合成正文 TTS，两路线最终 TTS 未选/未审不得口播，M2 底片未审不得对口型；并行分支按版本汇合、重型 GPU 作业互斥；MCP 重放不重复计费，未知结果先对账。
- 后期阶段为 `executor_kind=worker`、`worker_kind=postprocess`，没有后期 Agent 角色或结果；禁止为代码合成、字幕和打包重新引入业务 Skill/MCP。
- 用户资料可空，生成不触发联网；关键事实缺依据转 `review`，LLM 自审和只有 URL 的资料不能将断言判为 supported。
- 角色 Skill 与工具权限隔离，公共记忆审核合并；并行任务不能覆盖人设、历史事实或其他任务的检查点，返工按依赖使旧审批失效。
- 枚举、JSON Schema、字符偏移、时间戳、金额和状态转移拒绝非法值；每个样例需可解析。
- 空环境只使用新工程即可初始化；无旧包导入、旧库访问、旧配置探测或兼容入口。用独立新建的无来源/来源不符样本验证拒绝规则，不读取旧素材制作夹具。
- 身份、VoiceAsset、根媒体及派生媒体必须追溯新 SourceRecord；测试素材复制、改 mode、转码或伪填新 ID 后仍被拒绝进入生产。阈值须关联新标定集和规则版本。
- G0 是文档基线；Mock 跑通只计 G0→G1 期间的开发检查。真人身份与声音定版、真实图像驱动样片另计 G1，稳定生产与发布包计 G2，官方授权自动发布另计 G3。
- 同幂等键重放、并发提交、过期 lease 写入、worker 重启、下载半文件、URL 到期、提交丢响应、重复回调均有故障用例。
- 测试音色跨作用域误用被拒绝、未批准变体被拒绝、模拟素材在 production 被拒绝、V1 仅包 ready；后续人工回填只得到 `reported_published`。
- 裁剪/片头/分段/发音替换之后，字幕时间戳单调且落在成片范围，字幕原文与批准稿一致；不能用放宽时长阈值掩盖时间轴错误。
- 发布未知结果阻止重复创建；业务错误和缺失远端 ID 不能成功；上传成功与官方发布确认分别建证据。
