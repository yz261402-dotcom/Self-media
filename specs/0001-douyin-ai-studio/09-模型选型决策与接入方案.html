模型选型决策与接入方案

v2.4 · 评审版7 个章节Markdown 原文

版本：v2.4 · 2026-09-23。本文维护准确模型、渠道、权限、已有证据和待测能力；总体流程见 总体技术方案，逐步输入输出见 流程速查，Agent/Skills/MCP/记忆设计见 Agent 编排方案。

本次恢复 OmniHuman 1.5 音频驱动数字人路线，纳入 MVP 必交付；M2 保留为低成本本地可选路线。 两路都使用固定人物和已质检、经用户确认的最终 MiniMax TTS。OmniHuman 根据人物图、最终音频和可编辑表演提示生成身体动作、表情与口型，不再接 LivePortrait/MuseTalk。身体运动改善是本轮重点，当前人物 B、动作遵循与长片质量仍待验。本轮没有新增收费生成、GPU 推理或发布。

production 已存在真实实现；本文是 v2.4 目标接入契约，本轮同步角色/工具边界及代码后期入口，不证明真实 Provider 或全链路已验收。

2. DeepSeek 与 DeepAgents 接入

2.1 接口、版本与权限

  • 官方服务根：https://api.deepseek.com；首条拟验证路径为 POST /chat/completions，独立 Bearer 凭据。

  • 请求 ID：deepseek-flash；记录期望版本 DeepSeek-V4.1-Flash。不要将用户口述的 deepseek-v4.1-flash 当作 API model ID。

  • 本项目尚无真实 DeepSeek 调用、账号模型权限或费用证据。接口依据来自 官方文本与语音核验；目录、账号及返回模型仍须在授权试验中核对。

  • 保存请求型号、响应型号、响应 ID、system_fingerprint（若返回）、时间、用量、提示词版本、工具调用及原始输出。别名映射可能变化，不能将其表述为永久冻结的模型快照。

DeepAgents 是主框架；LangGraph 是其底层运行机制。DeepSeek 拟作为总控与四个专职智能体的语言推理和工具决策模型，适配包与版本需通过试验确定。官方工具调用说明、框架子 Agent 示例或 SDK 安装成功，都不能代替本项目 Python＋DeepSeek 的实际兼容证据。

2.3 结构化输出与待测能力

文本 JSON 先采用官方已核的 response_format={"type":"json_object"}，再由业务 schema 检查字段、类型、分段与引用；不能假定支持 OpenAI 式 json_schema 或把工具调用 strict Beta 作为已通过能力。空结果、输出截断、字段缺失和无效引用必须拒收。

真实接入需分别验证：单次工具往返、子任务分派、允许的并行调用及汇总、结构化输出、上下文隔离、有限修正、人工暂停恢复、已登记收费结果的复用。框架并行调度与模型能正确发出/消费工具调用是不同测试项，均需证据。

质量审核不能假定 deepseek-flash 已具备本项目所需的视频视觉或音频识别能力。人物身份、嘴型、自然表情、音色与音画同步必须引用画面或音频时间码、适用检测工具、原始产物及人工判断。尚未选定的视觉/音频审核模型按实际缺口另行验证。

content 的最小输入字段为 prompt、keywords、target_duration_seconds、audience、user_materials。输出 3 个 ScriptVersion，每个包含标题、简介、标签、开头、分段正文、表演提示和资料引用说明；资料引用只能指向用户提供或系统已有已核资料，不生成虚假 URL。

quality 可以检查稿件内部逻辑、用户资料一致性、重复和表达质量。对没有用户依据的事实、时效、数字、案例或产品能力，必须写 待复核 并请求用户依据或人工确认；不得把 DeepSeek 自审、改写或自评分描述成事实核查完成。候选不足 3 个或有限改稿达到上限时如实报告，不降低门槛凑数。

2.4 Skills 与 MCP 白名单

  • 业务 Skill 保留 S01-S06、S08 共 7 个；删除 S07 字幕与剪辑，不重编号。
  • M01 本地内容查重：只提供 search_content_history，调用者仅为 quality；不提供 search_sources、fetch_source。
  • M02 角色与记忆：角色、声音、偏好、历史经验的受控读写；正式状态和预算仍由 studio-core 事务写入。
  • M03 媒体生产：Provider/Worker 作业提交、查询、取消（若受支持）和产物读取；不提供字幕渲染或交付决策。
  • M04 媒体检测与审核：媒体完整性、规格和检测报告登记/读取；删除 align_subtitles、render_video。
  • M05 交付 MCP：移除。

字幕对齐、FFmpeg＋libass、FFprobe、清晰度处理、封面生成和 manifest/包登记由 studio-media 代码 Worker 在依赖满足后自动触发，不进入 MCP 工具列表。quality 仍审核 Worker 产物；总控只等待和汇总。

3. GPT Image 2 专用中转

3.1 渠道与现有证据

  • 服务根：https://airelay.dog.airelay.buzz；请求模型固定 gpt-image-2。

  • 只读核验：GET /v1/models 返回 HTTP 200，目录包含该 ID；该记录本身的生成次数为 0。

  • AV-001 后续已有两张可解码 PNG，用户选定人物 B。实际生成响应未包含模型字段，上游权重身份未独立核实。

  • B 的请求尺寸为 1152×2048，实际原图为 941×1672；保留原始字节，不把后处理 1080×1920 输出记为原生生图尺寸达标。

3.2 接入边界与待验事项

生成与参考图编辑是两个能力：生成路径已有样本；/v1/images/edits 的实际协议、参考图输入、身份保持、尺寸和计费尚未验收。若中转采用其他真实协议，应单独记录协议适配，不静默换模型或把未经验证的官方参数直接视为中转支持。

配置分开记录 provider=openai_compatible_relay、requested_model=gpt-image-2、base_url、protocol 与凭据引用。保存提示词、参考图哈希、原始响应、实际图片尺寸、模型字段（若返回）和用量。图片响应可以是 Base64，不假定必有永久 URL。

首次人物创建接受关键词和自由描述，保存生成提示与来源，由用户选定人物版本。换装或换背景必须引用当前作品已批准人物（初始预设为人物 B），输出经身份复核后登记新变体；重复文本提示词不能替代参考图。现有服装与背景仍在同一张图内，尚未实现可独立替换的图层或其他视角资产。

既有官方资料给出的 Image 2 自定义尺寸要求宽高可被 16 整除；1152×2048 是待核验的 9:16 请求尺寸，1080×1920 是最终视频尺寸。实际中转尺寸能力以响应为准。用户指定 gpt-image-2，不自行改用 gpt-image-2-2026-04-21 快照。

4. MiniMax Speech 2.8 HD 与音色 3

4.1 固定参数与渠道

  • 官方同步接口：POST https://api.minimax.cn/v1/t2a_v2；准确模型 speech-2.8-hd，不改为 Turbo。

  • 初始预设音色：Chinese (Mandarin)_Warm_Bestie；声音档案 voice_minimax_warm_bestie_v1。

  • 已选样音基础参数：speed=1.0、vol=1.0、pitch=0、emotion=calm、language_boost=Chinese。

  • 已有试听：WAV、32000 Hz、单声道，约 15.22 秒，真实成功证据见 人物与音色定版。

同一官方服务的其他文档域名不能视为均已测通；超时后不自动换域名重新提交。旧 Qwen 的 Cherry 不是 MiniMax 音色 ID。声音创建、设计或克隆属于独立接口与资产流程，本方案不假定已注册专属或独占声音。

4.2 表达、音频与字幕待验

音色库先提供同一短句试听，区分已缓存样音与需要付费的新合成。用户选声后，声音导演以已审且已选稿件生成朗读计划，按已核协议编译停顿和情绪参数，不发送任意 SSML。固定声音不意味着每句话只能采用同一种情绪；改变情绪、语速等应在验证范围内，并记录实际参数及试听结果。

待验包括 RAG/API 等缩写、数字、多音字、停顿、情绪、跨段连续性和首尾完整性。emotion=calm 有试听证据，其他情绪不能沿用它的通过结论；官方声明 Speech 2.8 不支持 whisper，不能因通用枚举中出现就启用。

同时检查 HTTP 状态、base_resp.status_code、数据非空、完整解码、实际时长、采样率和声道。保留原始音频与为 MuseTalk 转换的派生版本；转换必须记录参数、来源和哈希。短期下载 URL 不作为永久资产。

官方文档的 subtitle_type=word 与部分响应字段说明存在粒度差异，实际词级时间戳尚未验收。保存字幕 JSON 后核实字段、单位与最终音轨；Worker 后期改变时间轴时通过内部代码重新对齐。MuseTalk 内部的 Whisper 音频特征模型不因此成为字幕转写方案。

计费保存 usage_characters 和实际账单；计费字符不等于汉字数。单样音费用不直接外推约 60 秒、多稿件和返工后的生产单价。

5. 口播路线：音频驱动云端与本地路线

5.1～5.4 保存 M2 的已验版本、权重和边界；这些不是 OmniHuman 必经依赖。5.5 定义 OmniHuman 的图＋最终音频接口及身体动作验收。

5.1 固定版本与已验范围

LivePortrait 独立环境位于 /root/autodl-tmp/avatar-motion/EXP-001，源码 commit 9b294b3d0536135442ea73cb01e6cb3ca7029dd3；MuseTalk 环境位于 /root/autodl-tmp/avatar-musetalk/MT-001，源码 commit 0a89dec45a0192b824e3cf4daf96c239440c5ed8。保留隔离环境、权重、日志和原件，后续使用新运行目录及缓存版本。

M2 的输入绑定人物/变体版本、动作参考版本及哈希、声音版本、最终音频哈希、模型与参数版本。LivePortrait 以人物 B 为 source，仅从动作参考迁移运动；MuseTalk 再以 B 的动作底片与最终音频生成嘴型。它们不负责根据稿件语义自动生成完整手势或全身表演。

EXP-001 实测 已有 15.20 秒 M2 原片。首次两阶段作业共 235.177 秒：LivePortrait 53.505 秒，MuseTalk 181.672 秒；GPU 作业费估算 0.103217 元，不含安装、下载、空闲、素材及动作参考成本，不是账单或生产单价。

约 9.13 秒的历史阿里片只作为实验动作参考，循环至样片时长，未被批准为正式长期母版。真实约 60 秒输出仍需检查循环接缝、头颈与肩膀、身份、嘴型及整体自然度。每天 5 条产能未验证，日开机 2 小时只是预算情景。

5.4 运行与缓存边界

一台 GPU 的重型推理先串行调度，LivePortrait 输出就绪后才进入对应 MuseTalk 阶段。content、audio、avatar 可并行准备文案、朗读计划和人物素材；版式由代码配置提供，不能因此忽略最终音频时长与成片依赖。

人物、服装、背景、动作参考、裁剪或遮罩改变时新建缓存版本；缓存复用需校验输入哈希与版本。提交失败或结果未知先查作业与产物，不通过重启编排盲目重新生成。

M1 单图 MuseTalk 仅作基准，M3 SadTalker 仅作历史对照。M2 失败进入修正或人工处理，不自动回退到其他路线。旧比较结果和失败证据不因定版而修改。

5.5 OmniHuman 1.5：固定人物＋最终音频驱动

本轮选择与用途： 用 OmniHuman 解决本地样片身体基本不动的问题，同时保留固定人物、已选音色及已批准的口播内容。已审人物/衣景图片＋已质检且用户确认的最终 MiniMax TTS＋可编辑动作/表情提示 → OmniHuman 1.5 → 数字人口播原片 → quality 原片审核、确定性 Worker 字幕/后期和 quality 终审。声音先由 MiniMax 确定，视频模型据其驱动表演；不把稿件交给视频模型重新生成另一套声音，也不默认再跑 LivePortrait 或 MuseTalk。

真实接口与历史接通证据：

  • 服务根 https://visual.volcengineapi.com，提交和查询均为 POST；Action=CVSubmitTask / CVGetResult、Version=2022-08-31，HMAC-SHA256 AK/SK 签名，Region cn-north-1，Service cv，不是普通 Bearer API。

  • 业务 req_key=jimeng_realman_avatar_picture_omni_v15；生成必填 image_url 和 audio_url，可选 prompt、seed、output_resolution、pe_fast_mode。业务层传受控资产 ID、版本和摘要，Provider 转为有有效期且可读取的媒体 URL。

  • 提交成功的 data.task_id 只说明受理；查询使用原 task_id，综合业务 code、data.status、非空 video_url 和文件解码判断成功。done 单独不代表成功。URL 有限期，及时保全返回原件、响应和费用证据。

  • 2026-09-21 接口核验 的约束是音频严格小于 60 秒，建议 15 秒以内；prompt 保守限 300 字符；分辨率选项 720/1080，实际像素需测量。以上按原核验日期保留，正式新提交前核对当前账户规格与配额，不把建议 15 秒写成 1～15 秒的硬限制。

  • 约 60 秒作品先按同一最终 TTS 的句子边界拆分，保存音频范围、每段任务与统一时间线，验收音色、人物、身体动作和衔接。不得提交超限整段、截掉文字或靠加速音频蒙混通过；若有重叠上下文，应裁除重复区域再映射字幕。

已有证据能说明什么： TH-COMP-003 历史实测 已生成 9.48 秒原片，输入音频 9.36 秒、画面 704×1248、25fps。将输入/输出音轨统一解码为 24kHz 单声道后，最佳对齐偏移 0ms、重叠区 Pearson 相关系数 0.99996223；这支持该短样本保持输入音轨。它不是当前人物 B 的结果，不证明全片嘴型同步、身体动作、任意手势或分钟长片达标。完整生产质量仍待验收。

人物与身体动作的优先验证： 使用人物 B 和音色 3 的真实输入，先比较自然讲解、轻微抬手/摊手等可审动作；按需采用同身份、手臂可见的半身参考图，不能借扩大构图重新换脸。检查身体确有自然运动、动作与讲稿节奏是否协调、是否遮脸或出框、肢体/手指是否异常、人物与衣景是否保持；同时核查音轨内容/音色/时序和嘴型。不得仅凭接口属于数字人类别就承诺表现自然或任意动作可控。失败定位到相应片段，原件与成本保留。

费用与提交边界： 用户已确认 OmniHuman 1 元/生成秒（100 分/秒），按此费率做当前预算估算：60 秒生成量约 60 元，每天 5 条约 300 元，30 天约 9,000 元，仅为无返工的视频生成费。Grok 的 0.38 元/秒不适用于本路线。计费取整、最低粒度、不同规格/辅助检测费用和实际账单尚待核实；所有重做、分段重复生成按真实计费量累加。另记 MiniMax、文本/图片、后期/存储等费用；OmniHuman 不含必需 LivePortrait/MuseTalk 推理。费率确认不是实际任务预算授权，超时受理未知先对账，不盲目重新提交。

MVP 验收： OmniHuman 图＋最终音频驱动、身体运动、音轨保持、身份与口型、长片衔接必须在首版打通并单独验收；不能以已有 M2 样片替代，不能推为后续扩展。M2 保留低成本本地选项，仍按自身门禁和成本说明供用户显式选择。任一路线失败都不自动换人、换声或跨模型回退。Grok 已退出当前路线清单，旧模型目录查询不构成后续生成授权。

7. 剩余验收与资料索引

按 技术验证流程 先完成 DeepAgents 模拟编排，再验证真实 DeepSeek 兼容，补齐 OmniHuman 身体动作、输入音轨保持、人物/口型、分段长片和批量证据；图片编辑、TTS 和 M2 按各自门禁验证。ASR/对齐、embedding/重排、身份/声音检测仍待选；工程组合的建议状态见 剩余选型矩阵。
