技术验证与定版流程

v2.4 · 评审版6 个章节Markdown 原文

版本：v2.4 · 2026-09-23。DeepAgents 主框架已选；人物 B、MiniMax 音色 3 为初始预设。OmniHuman 1.5 音频驱动为 MVP 必接入且独立验收路线，M2 保留低成本本地选用；Grok 排除当前 MVP，仅保留只读历史调研。两路线共用已审且用户确认的最终 TTS。首版七入口、前四项真实生产闭环；本文规定下一轮完整验证；本轮已同步 production 角色/工具注册与内部 Worker 门禁并完成离线行为回归，缺媒体/缺能力会阻断，真实后期与模型链路未验收。决定见 技术决策，精确接口与证据见 模型接入。

1. 先验证什么

验证顺序为：

  1. 工作台契约与 DeepAgents 模拟编排：作品/候选版本、用户选择与质量审批分离、七入口与后三项真实占位、任务分派、并行、恢复、去重及收费路线门禁。
  2. 真实 DeepSeek 兼容：官方 deepseek-flash 的工具调用、结构化输出、子任务分派与汇总；真实调用另需明确预算。
  3. 生产质量与剩余模型：固定人物、MiniMax 最终音频、OmniHuman 身体/表情/口型和审核工具，形成约 60 秒分段成片，再测每天 5 条。OmniHuman 必须在 MVP 验证；M2 成功不替代云路线验收。

架构测试采用受控输入和假工具，不产生图像、TTS、文本模型或 GPU 推理费用；不能用它证明真实模型效果或生产兼容性。既有成功样片继续作为证据，无需为文档改版重复生成。

3. 第一阶段：DeepAgents 无付费编排验证

3.1 范围与环境

使用隔离实验目录，固定 DeepAgents 及适配依赖版本。总控智能体分派四个专职智能体：策划文案、质量审核、数字人导演、声音导演；模型输出与外部工具返回由可控模拟输入提供。策划按用户提示词、关键词和可选资料直接生成三稿，质量角色仅查内部历史并审核事实风险，两者均无网上搜索/抓取。后期改由依赖驱动的代码 Postprocess Worker 自动执行合成、清晰度处理、字幕和内部打包，原片及成片由质量 Agent 审核。应实际运行目标框架的被测机制；仅运行自写的顺序函数不能宣称 DeepAgents 验证通过。

Python＋FastAPI、PostgreSQL＋SQLAlchemy/pgvector、持久 Worker＋APScheduler 是建议试验组合，尚未选定或验收。框架实验只接入验证所需组件，不以前端工作台全部建成作为前提；不需要向量检索的用例也不强制启用 pgvector。

3.2 必测行为

checkpoint 保存执行状态；长期 Store 保存审核后的跨任务知识；业务数据库保存任务、产物及费用事实。这些用途需要明确映射，不因框架有存储接口就推定持久性、一致性和“恰好执行一次”已经解决。

额外核验：角色仅 supervisor/content/quality/avatar/audio，Skill 仅 S01～S06、S08 共 7 项（S07 撤出且不复用编号）；保留两个 MCP 服务建议，范围缩至 M01 内部历史（仅 quality）、M02 角色记忆、M03 媒体生成、M04 检测审核，M05 撤销。代码后期/打包用 StageExecution.executor_kind=worker、worker_kind=postprocess，不创建后期 AgentResult。未选稿不能全文合成、最终音频未审/未确认不能口播、Agent 不得伪造 SelectionDecision、过期选择返回冲突、不足三稿不得凑数；刷新恢复 waiting_selection。OmniHuman 不依赖 LivePortrait/MuseTalk，失败不能自动换模型/新计费重试；未知结果先查询对账。前端不得伪造进度、连接或平台数据。

第一阶段交付版本清单、输入用例、事件与调用记录、持久化快照、恢复对比、失败证据和结论。任何未覆盖机制列为待验，不用“流程走通”概括全部通过。

4. 第二阶段：真实 DeepSeek 接入兼容

在新实验目录中，按明确调用次数、token 上限和金额上限执行；本次文档整理不构成真实调用授权。请求模型继续为官方 deepseek-flash，目标版本 DeepSeek-V4.1-Flash，不用别的模型替代兼容性验证。

按小范围顺序验证：

  1. 核对官方渠道、账号模型权限、请求/响应模型字段与版本映射，保留脱敏回执和用量。
  2. 执行一次有边界的工具往返：模型发出工具调用、工具返回、模型正确消费结果；工具参数由业务层校验。
  3. 验证 JSON 输出、业务 schema、引用完整性；覆盖空输出、截断和非法字段，不能以“能解析 JSON”代替业务合格。
  4. 在目标 Python DeepAgents 适配器上执行子任务分派、允许的并行分支与汇总，检查工具名称、调用 ID、消息顺序和上下文隔离。其他语言的官方示例不能代替本项目证据。
  5. 验证拒收后的有限修正、人工中断与继续，以及真实调用结果登记后恢复时不会重复收费。需要故障注入的情形优先使用第一阶段模拟工具，不为制造失败反复请求收费服务。
  6. 分别使用仅提示词、提示词加关键词、提示词加用户资料生成三稿，验证输入遵循、三种角度、中文口语和约 60 秒可朗读性；质量角色对照内部历史查重，核用户资料的适用时间、支持范围与冲突。关键事实缺依据须 review/补充用户资料或删改重审，LLM 自审不能充当事实核验；全过程不搜索或抓取网页。

并行子任务是模型调用与框架调度共同完成的能力；接口宣称支持工具调用不等于这个组合已经兼容。JSON 模式和严格结构化 schema 也不是同一能力，适配器只能使用该服务实际支持且已验证的协议。

DeepSeek 在质量审核中可以分析文本、用户资料引用与内部工具报告，模型判断不等于事实已被核验。画面身份、嘴型、自然动作、音色和音画同步需要媒体证据、适用检测工具及人工视听；不能假定文本模型能直接看懂成片或听出音色异常。

5. 第三阶段：模型缺口与生产质量

复用固定人物 B 与 MiniMax 音色 3，围绕 OmniHuman 音频驱动 MVP 按 模型接入方案 推进：

  • 图片：引用人物 B 做服装/背景编辑，核实实际编辑协议、尺寸、身份稳定及用量。保留原图 941×1672 的事实，不以放大后的成片规格覆盖原始证据。
  • 声音：用固定 voice_id 验证多稿件、英文术语、数字、多音字、停顿、情绪、首尾完整性和字幕时间戳。
  • OmniHuman 1.5 MVP：火山视觉接口 visual.volcengineapi.com，AK/SK HMAC，cn-north-1/cv，POST CVSubmitTask/CVGetResult、Version=2022-08-31、req_key=jimeng_realman_avatar_picture_omni_v15。输入人物 B＋已确认最终 MiniMax TTS＋可编辑表演描述直接生成口播，不用 LivePortrait/MuseTalk。当前规范音频严格小于 60 秒、建议不超过 15 秒，prompt 不超过 300 字符；当前账户权限、720p/1080p 和实际限制须复核。约 60 秒按同一音轨句子切片，保存全局偏移，禁止加速/截字。先测短片，再测全片接缝；身份、身体/手部、描述遵循、输入音轨保持和嘴型分别审核，不承诺任意动作。
  • M2 本地可选：保留 EXP-001 的 15.20 秒原片及费用；开放时核动作参考时长/来源许可、模型权重许可、循环接缝、头颈肩膀和音轨。LivePortrait 动作迁移不等于任意语义动作；合格底片与同一已确认 TTS 交 MuseTalk，两阶段记录齐全。M2 不能替代 OmniHuman 的 MVP 验收。
  • 审核与代码后期：选择并验证尚未定版的 ASR/对齐、超分、视觉及声音辅助模型；Postprocess Worker 对已确认音轨执行字幕 ASR/对齐，在原片审核通过后直接用 FFmpeg/libass 完成时间轴映射、视频合成、清晰度处理、字幕、封面和封装，成片审核通过再内部打包。普通缩放不等于真实增强，保留原片/处理参数/前后对照并核身份和伪影。质量 Agent 分别审核原片与成片，检测误报漏报与人工基准对照，不增加后期 Skill/MCP。
  • 批量交付：最后执行每天 5 条、每条约 60 秒的目标批次，记录每条合格与否、返工、总等待和占机时间、总费用、人工投入及发布包完整性。

历史 TH-COMP-003 的输入为 9.36 秒，原片为 9.48 秒；24 kHz 单声道对照最佳偏移 0 ms、Pearson 0.99996223，支持该样本音轨保持。人物不是当前 B，这不是嘴型质量、身体动作或分钟长片验收；新工程仍需独立真实证据。Grok 调研仅归档，不提交新任务。

单条不合格时保留原始输出，按限次策略修正；预算不足或结果未知时停止相应生成。没有生成合格结果，就报告未通过，不静默换人物、音色、模型或口播路线。

V1 终点为七入口真实呈现、用户逐步选择、OmniHuman 以固定人物及确认 TTS 实际生成的合格约 60 秒成片预览与下载包；M2 按开放范围独立验收。OmniHuman 未过不得只禁用云路线再用 M2 宣称 MVP 完成；未测参数/动作继续禁用并单列。发布、提醒回填和平台指标后续单独验收。

OmniHuman 价格按用户确认 1 元/生成秒（100 分/秒）估算，price_source=user_confirmed_rate、billing_verified=false：60 秒 60 元、5 条/日 300 元、30 天 9000 元，仅视频生成费。取整/最低消费/失败扣费待账单核验，TTS、文本图片、存储后期和返工另计；Grok 0.38 元/秒不移用。报价与文档修改不授权本轮付费提交。

6. 实验冻结与决策回填

统一使用 06的评估方法与指标。对照固定提示词、可选用户资料/内部历史快照、人物/音色和非被测模型；Skill改版仅换该Skill，代码后期比较仅换对应代码/参数或已验模型，调度比较仅换并行方式。E20 角色分母仅含总控及四类专职 AgentWorkItem，代码 Worker 归已有媒体、恢复和交付指标，不增设指标。人工盲评顺序随机并保留胜/平/负与失败；质量智能体必须对独立金标报告漏放、误拒和待复核率。逐片采样和分位数、成本分母、20次稳定性与日产5条的定义不在本文另设一套。

每次真实试验开始前记录：目的、样本、输入文件及 SHA-256、固定资产版本、模型/协议/参数、执行环境、预算和次数上限、预先确定的验收标准。采用新的运行 ID 与输出目录，保留旧原件及失败记录。

执行后记录：原始响应和产物、请求或作业 ID、实际耗时、费用用量、技术检查、逐项质量结论与复核人、未覆盖范围。费用未知写待对账，预留金额不等于实际扣款。

付费提交每个已授权样本只执行规定次数；轮询不算重新生成，超时不代表未受理。先核对任务账本与供应商状态，不能自动重发、换渠道或恢复历史已用额度。

通过的技术只在证据覆盖范围内定版，回填 技术决策、总体技术方案、模型接入方案 和非敏感配置。模型、适配器、权重、参数或关键资产发生变化，安排相应回归验证。

历史试验与原账本见 数字人口播首轮实测、MuseTalk 首测、人物与音色定版、M2 实测。历史预算只属于原实验，不延续成下一阶段的可用授权。
