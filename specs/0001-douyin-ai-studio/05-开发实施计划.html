v2.4 · 评审版6 个章节Markdown 原文

版本：v2.4 单用户工作台计划 · 2026-09-23。本文是 v2.4 后续实施计划；本轮已在 production 骨架同步四类专职角色/工具注册、单一三稿工作项和代码 Worker 阻断边界，清单未勾选表示完整目标交付与验收尚未完成。文档更新、框架选型或现有实验样片不能代替目标实现。

当前路线：先验证 DeepAgents 离线最小编排与恢复，再逐步接入真实生产能力。 用户已选 DeepAgents 主框架；总控智能体协调策划文案、质量审核、数字人导演、声音导演四类 subagents。角色 ID 统一为 supervisor/content/quality/avatar/audio。DeepSeek 官方 deepseek-flash（V4.1 Flash）承担决策，但与 DeepAgents 的工具调用、结构化返回和恢复兼容性尚未实测。

媒体 MVP 必交付 OmniHuman 1.5 音频驱动路线：GPT 专用中转 gpt-image-2 的固定人物图＋MiniMax 官方 speech-2.8-hd 已审且用户确认的最终 TTS＋可编辑表演描述，直接生成身体/表情/口型视频，不经过 LivePortrait/MuseTalk。M2（LivePortrait→MuseTalk）保留低成本本地选用，不替代 OmniHuman MVP 验收。人物 B av_base_b_v1 与音色 3 Chinese (Mandarin)_Warm_Bestie 是初始预设，作品锁定其选择版本。目标每天 5 条、每条约 60 秒；历史非当前人物 B 的 9.48 秒 OmniHuman 原片不证明身体动作、身份、嘴型及长片已通过。Grok 排除当前 MVP，仅留只读历史。

V1 是单用户、以作品为中心的工作台：七个入口全部展示，顺序为人物形象、口播稿生成、TTS 语音、视频合成、发布、指标监控、领域模型选择。前四项完成真实流程和用户逐步确认，最终下载视频、字幕与投稿文案等交付包；后三项展示准确的规划状态，禁用未实现操作，不填假数据。基础服务端模型配置、连接检查及错误提示属于 MVP；任意模型配置、到期提醒、人工回填、多平台发布和指标接入均为后续增量。FastAPI、PostgreSQL＋pgvector 是建议试验组合，APScheduler 只在后续排期需求启动时验证；本版持久化、MCP、角色 Skill、记忆与代码后期边界仍待实施验证，前端、影像 QA、字幕 ASR/对齐、超分和 embedding 模型继续选型。

输入：PRD、总体技术方案、契约、验收、模型接入。架构阅读入口：DeepAgents 多智能体架构。本版替换原先“所有 T01～T13 暂停”的旧草案；按下述依赖逐项验证，未选基础组件在对应任务内先试验再定版。

1. 实施边界与门槛

  1. 本次修订文档并同步 production 的角色/工具注册与内部 Worker 门禁，运行离线回归，不发起付费或 GPU 作业、不发布。下面路径和验证项是完整目标交付约定；当前 Worker 对缺媒体/缺能力记录 blocked/not_run，真实后期与模型链路未完成验收。
  2. demo/ 原位保留并完全排除，不读取、借鉴、复制、迁移或用作测试材料。新建工程、依赖、配置、数据库、测试与运行区，不提供旧系统兼容接口。
  3. 人物 B、音色 3 和 EXP-001 来自本项目独立选型，按来源、摘要与审批受控登记为初始预设；不能因工程从空库启动而强制重生人物/声音。新人物与新音色建立独立版本，不覆盖已有作品绑定；用户选择不等于质量通过证明。
  4. 所有 Agent 结果经结构校验；Agent 获准的外部/跨进程能力通过受限 MCP 和 Provider/Worker 执行。代码 Postprocess Worker 在依赖通过后自动执行字幕、合成、清晰度处理和内部打包，不经过业务 Skill/MCP。本机确定性纯函数可用普通工具直接适配，但同样受角色、任务、版本与业务门禁约束。预算、来源、许可、身份、事实、发布等硬门禁在代码层，Agent 和人工评审均不能绕过确定性硬失败。
  5. 每个任务先写行为测试并观察预期失败，再做最小实现、关联验证和差异审查。L0 只验证结构与恢复，真实生产单独按 L1 验收。
  6. 新增真实调用须有服务、样本、次数、金额和新输出目录授权；默认预算与提交次数为 0。收费生成前展示路线、模型、时长、分辨率、预计费用及预算，并说明效果不满意重做也可能收费；预留后才提交。结果未知先查询/核对，不自动重发或因 M2 失败静默切到收费模型。用户选用 OmniHuman 路线不等于已授权本轮实际调用。
  7. 当前文档不建立版本库、提交或清理旧目录；实现开始时采用已确认的版本管理方式，只提交任务范围内文件。

2.1 评估实现要求

评估规范唯一来源为 06第4章。T00/T01落地评估样本与指标记录契约、首次/修正后结果、运行版本及模拟标记；T02记录工具副作用计数、恢复、预算、记忆作用域与冲突；T03～T08实现各角色和媒体检测的指标采集、盲评证据与金标校准；T12汇总成本、约60秒真实质量、20次试运营与日产5条，输出中文HTML及机器可读JSON/CSV。

测试前冻结样本、阈值版本、对照因素和预算；缺测值用null并记录NOT_RUN，不以目标填实测，不创建伪造评分。E指标是测量项，AC仍为验收用例；本节不新增任务编号或擅自触发收费评估。

3. 依赖、并行与退出条件

执行顺序：T00＋T01 最小契约骨架 → T02 持久化与执行边界 → 各角色及媒体模块 → T11 部署恢复 → T12 V1 联合验收。T03/T04 可并行；T06 内容与 T07 代码后期模块开发可并行；T05 的 MuseTalk 汇合依赖已审人物动态底片和已确认最终音频，OmniHuman 1.5 路线依赖有效参考图、最终音频、显式路线选择与预算。T09 依赖视频门禁。T10 在 T01 契约明确后先做前端选型实测，再实现七入口和选择状态骨架，不能先建设完整 UI 再补选型依据。

每期运行顺序为：创建 Work、选人物/衣景/表演要求 → 三候选稿各自审核 → 用户选稿/编辑重审 → MiniMax 短句试听选声 → 全文合成、质检、用户确认最终 TTS → 选择 OmniHuman 或 M2 并确认适用预算 → 口播及审核 → 后期、字幕、预览下载。人物/声音准备可并行；代码 Worker 在最终 TTS 确认后可并行对齐字幕，原片经质量 Agent 审核后执行合成并复核视频/剪辑偏移，成片再次交质量 Agent 审核。M2 等待已审底片及确认音频，OmniHuman 等待已审人物图与同一确认音频。质量通过不替用户选择，单 GPU 重型作业排队。

  • G0 文档基线：需求、模型路线、角色、契约和验收一致。
  • L0 开发验证：T00～T02 优先覆盖编排、工具权限、持久恢复、预算与 UNKNOWN；不证明 DeepSeek 或媒体真实效果。
  • G1 真实核心能力：人物、声音和 OmniHuman 真实短片按门禁验收，当前人物 B 的身体动作、嘴型与输入音轨保持分别有证据；M2 开放范围独立核验。OmniHuman 未过不能以 M2 通过替代。
  • G2 / 完整 L1：T06～T12 的七入口展示、三稿选择/编辑重审、音频试听确认、提示词生成 RAG 主题口播及代码合成、下载包、恢复和配置报错通过；不用页面存在或旧实验片冒充真实联通。
  • G3 / L2：T13 后续发布与指标能力按平台分批实施，适用官方权限和具体发布授权齐备后独立验收；提醒/回填、完整模型设置也按后续增量验收。

现有 15.20 秒 EXP-001 M2 样片不证明 60 秒、每天 5 条或稳定生产通过。约 9.13 秒循环仅作实验动作参考；默认 InsightFace 权重商用许可或替代方案须在生产商用前关闭。

4. 实施清单

T00 DeepAgents 离线最小编排与恢复

拟交付：agents/{supervisor,roles,results}.py、角色 Skill 清单、tests/integration/test_agent_orchestration.py、tests/integration/test_agent_checkpoint_recovery.py。本项与 T01 的最少 schema 同批实现，其余功能不作前置。

  • 固定 DeepAgents 版本与实际接口，用确定性模型替身和无网络工具构造总控及四类 subagents；先验证角色分工、结构化结果、依赖关系、任务隔离和并行汇合的失败测试。
  • 验证同一 PerformancePlan 的 segment_id/text/emotion/pace/emphasis/motion 在声音/数字人分支及代码时间轴输入中一致；稿件未审核、用户尚未选择或依赖版本不同即拒绝推进。
  • 模拟三稿审核后进入 waiting_selection，页面退出/进程重启后保留候选；真实用户 SelectionDecision 才恢复相应分支，Agent 伪造选择或拿质量通过替代选择必须失败。
  • 在委派后、工具受理后、结果登记前中断并恢复，确保检查点关联原工作项；重复工具调用命中原幂等结果。
  • 验证模型输出恶意工具名、越权路径、伪造批准或编造指标都不能突破工具和代码门禁。
  • 记录持久检查点、并行更新和恢复的真实框架行为；内存内恢复不算进程重启持久恢复。PostgreSQL 等持久方案待 T02 验证。
  • 后续有具体授权时，另验 DeepSeek 的工具调用、多步调用、参数结构、错误传播和恢复；离线替身成功不代表模型接入成功。

退出：AC-AG-01、02、03、04、05、08 的 L0 相关项有离线证据；框架版本、未测真实能力及待关闭问题明确。

T01 工程隔离、契约与配置

拟交付：依赖锁、非敏感配置、contracts/、tests/contract/test_configuration.py、tests/contract/test_agent_contracts.py。

  • 先测非法枚举/未知字段、预算 0、mode 越级、敏感输出及排除目录探测；新环境仅装独立声明依赖。
  • 实现 Work、SelectionRequest/SelectionDecision、AgentWorkItem、AgentResult、PerformancePlan、QualityDecision、MemoryCandidate 与原业务契约；人工选择独立于 ReviewDecision，身份、声音、模型、Skill 和规则绑定版本/摘要。
  • 按 04 冻结 work_id、route=M2|OMNIHUMAN_1_5、route_selection_id、pending_selection_ids、input_snapshot_digest；绑定作品而非依赖页面间手动上传。
  • 为已支持供应商提供服务端配置与受控连接检查；区分未配置、认证失败、额度不足、模型不存在、能力不支持和网络故障。密钥不返回前端、不写日志；URL/Key/model 文本齐全不等于模型可用。
  • StageExecution 区分 executor_kind=agent|worker，后期和打包使用 worker_kind=postprocess，不生成后期 AgentWorkItem/AgentResult。状态按 StageExecution/AgentWorkItem 聚合；单个 stage 只供显示，不能丢失并行分支。
  • 固定 supervisor/content/quality/avatar/audio 角色 ID 和 S01～S06、S08 共 7 项 Skill 版本清单；S07 字幕与剪辑撤出且不复用编号，校验缺失/不匹配即阻断；通过测试后记录契约版本。

退出：AC-OPS-10 的隔离前提与 AC-AG-02/03 的结构约束成立；没有误发真实请求的启动路径。

T02 持久任务、MCP、预算与记忆

拟交付：storage/、pipeline/、mcp/、memory/；测试 test_task_recovery.py、test_provider_jobs.py、test_mcp_permissions.py、test_memory_isolation.py。

  • 先测租约竞争、过期 Worker 回写、并发预留、提交丢响应、检查点与业务账本不一致、取消后仍需结算。
  • 试验 PostgreSQL 持久状态/检查点及 pgvector 历史索引；只在恢复、事务与并发证据满足后定版，不能因列入建议组合就宣称已部署。APScheduler 排期适配留到 T13 后续提醒/发布增量。
  • 实现 Agent 获准能力的受限 MCP 工具：两个服务仅承载 M01 内部历史（仅 quality）、M02 角色记忆、M03 媒体生成、M04 检测审核；撤掉在线搜索/抓取和字幕/渲染/打包工具及 M05。代码后期/打包由依赖图调度内部 Worker，生成类 Provider→Worker 保持受控执行通道；持久意图、幂等键和预算先于副作用。本机纯函数普通工具使用同一权限和业务门禁，不得包装外部副作用来绕过台账。
  • 结果 unknown 先对账，不能创建替代计费任务；单 GPU 重型作业互斥，过期作业未核实结束前不释放资源给冲突任务。
  • 任务检查点、人设资产、历史内容、经验候选分层；分支只写隔离命名空间，共享经验须审核并用期望版本合并。
  • 保存作品、候选集、人工选择、资产绑定、待选请求与进度事件；刷新和重启后能恢复同一作品，不依赖浏览器内存。
  • 修改稿件/声音/动作/剪辑时按依赖失效下游产物及审批，保留原始结果；仅改字幕样式只重新渲染，改正文则更新音频、嘴型与字幕。重启后重新核对引用与摘要，旧候选迟到不能改写当前选择。

退出：AC-OPS-01～05、07～10 及 AC-AG-04～09 的相关 L0 用例通过；没有用检查点代替账本或从聊天内容推断真实状态。

T03 人物库、人物候选与衣景动作资产

拟交付：avatar/、图像参考 Provider、数字人导演 Skill；测试 test_avatar_assets.py、test_identity_gate.py。

  • 先测冻结身份不可覆盖、换脸候选拒收、旧审核摘要失效、Mock 后代拒绝及动作参考误作人物 B 原片。
  • 受控登记已选人物 B 原图及来源证据，保持 av_base_b_v1 作为初始预设；首次新建人物允许性别、年龄、外貌、气质等关键词与自由描述生成候选，由用户选定后建立新的基础资产。
  • 使用 GPT gpt-image-2 专用中转验证同参考图编辑；衣景变体继承选定人物的身份描述并允许追加服装/背景关键词，必须绑定参考图和身份检查，不能靠写死提示词宣称不换脸。
  • 在具体授权范围内补齐参考集与 6 个服装/背景组合并单独审核，未经验证的编辑接口不标已支持。
  • 人物页面收集动作/表情描述和模板选择；M2 将 motion 意图映射到获准动作参考和受支持参数。OmniHuman 1.5 自由描述留到 T05 与最终 TTS 一起提交；首阶段不提前重复生成嘴型视频，不承诺任意动作执行。
  • 核验动作参考权利与 InsightFace 权重商用许可，准备时长适合的动作资产；EXP-001 的短循环不直接转长期母版。

退出：AC-AV-01～04；固定资产选择不等于变体、动作或生产质量通过。

T04 音色试听、音频确认与统一表达编译

拟交付：tts/、MiniMax Provider、声音导演 Skill；测试 test_voice_scope.py、test_expression_compiler.py。

  • 先测 voice 作用域、表达范围越界、标签误读、缺字/重字、不支持情绪、未知结果及失败换音色。
  • 按本项目预设音色选择、官方作用域/使用权及基准合成证据登记音色 3 voice_minimax_warm_bestie_v1 和 Chinese (Mandarin)_Warm_Bestie 为初始预设；其他受支持音色经明确选择后创建独立绑定，不覆盖旧作品。
  • 使用同一短句提供音色试听，区分已缓存试听与需费用的新合成；用户选定后生成全文。试听片不能被误作最终音频；不满意重新选择或重新合成须保留旧版本、费用及适用预算。
  • 从冻结 PerformancePlan 编译 MiniMax 参数及朗读映射，保留原文、朗读表达、实际支持/近似/不支持控制，不维护另一份可编辑分段稿。
  • 合成全文并审核术语、音色、完整性与时序，用户试听确认后才成为本次作品的最终音频；实际音频确定时长，对齐模型仍须选型和标定。
  • 按授权执行不同稿件真实样本；基准参数和变化范围有版本，失败不切声音或静默重试。

退出：AC-TTS-01～04 与 AC-AG-03；真实试听与字词对齐证据齐备。

T05 OmniHuman 音频驱动 MVP、可选 M2 与 GPU Worker

拟交付：digital_human/、LivePortrait/MuseTalk/OmniHuman 1.5 Provider、Worker 资源队列；测试 test_talking_head.py、test_m2_dependencies.py、test_route_selection.py、test_gpu_queue.py。

  • 先测未选路线、未确认音频、未审人物/动态底片、版本错配、无视频轨、超时未知、GPU 重入和假成功输出的拒绝行为；纯文生视频不能冒充固定人物参考图＋音频的口播主流程。
  • LivePortrait 以当前作品绑定人物原图/已审变体＋动作参考生成动态底片；与最终音频核对时长后审查，保持人物身份。
  • 动态底片与音频门禁均通过才提交 MuseTalk 1.5；两阶段各有 ProviderRun、模型参数、输出哈希与费用记录。
  • MVP 必须接入 OMNIHUMAN_1_5：有效固定人物图＋已确认最终 TTS＋可编辑表演 prompt，直接生成原片；不经过 LivePortrait/MuseTalk。当前规范音频严格小于 60 秒、建议不超过 15 秒，prompt 不超过 300 字符；720p/1080p 与账户能力重新核验。约 60 秒按同一音轨句子分段，保存全局时间偏移，禁止加速截字。
  • 按用户确认 OmniHuman 1 元/生成秒展示估价：60 秒 60 元、5 条/日 300 元、30 天 9000 元，仅视频生成费用。保留取整/最低消费/失败扣费待账单核验；TTS、文本图片、存储后期及返工另计。费用确认绑定调用清单和预算，用户报价不是本轮付费授权。
  • Agent 可并行准备工作，GPU 重型模型作业串行；失败保留，不自动回退 M1、M3 或其他云口播，不因超时盲目重提 OmniHuman 1.5。
  • 在独立授权目录执行短片、60 秒和动作接缝验证，完整检查身份、口型、表情与颈肩；不为通过重抽付费样本。

退出：AC-TH-01～06、AC-AG-04/08 和 AC-UI-05；OmniHuman 必须在 MVP 接入并独立通过长片/身体/身份/音轨/嘴型验收。M2 单独验收；未验证参数禁用，历史短片不能直接充当系统约 60 秒能力证据。

T06 提示词生成三稿、内部查重与事实风险审核

拟交付：content/、内部历史查重适配、策划文案/质量审核 Skill；测试 test_content_gates.py、test_rewrite_limits.py、test_performance_plan.py。

  • 构造独立语料测仅提示词无资料、有用户资料、同义重复、同题不同角度、旧价格、资料不支持、资料指令注入和指定题目被擅改；确认生成与审核不调用网上搜索/抓取。
  • 接收文案类型、主题、自由提示词、页面关键词和可选用户资料，直接由模型生成三个不同切入角度的口播候选；不联网找资料或爬取文章，不能只做同一稿改写。
  • 实现 DeepSeek 结构化稿件与 PerformancePlan，工具调用兼容性另有真实证据；记录提示词、输入资料与稿件版本；资料可空，关键事实缺依据时标为 unverified，不能编造引用。
  • 由质量角色建立主题、观点、文本三层内部历史查重与并行主题预留；embedding/重排选型与阈值标定完成前不伪报无重复。
  • 质量审核智能体逐稿检查事实/时效、相似性、错别字、通俗性和吸引力并引用断言证据，返回 QualityDecision；无依据的时效/关键事实转 review、请求用户补充依据或删改重审，LLM 自审不算事实核验；少于三个合格候选时展示实际结果和原因。
  • 合格候选进入用户选择；用户可编辑/局部重写，修改后创建新版本并重审。通过审核和用户选择均满足才冻结正文及 PerformancePlan，不让 Agent 代选或为凑三个强行放行。
  • 初稿后最多 3 次重写且受授权预算约束；每次改稿新版本、重审并失效后代，无新策略或超限即待处理。

退出：AC-CT-01～10、AC-AG-03/05/06/09；事实硬门禁不能被评分覆盖。

T07 代码后期 Worker、字幕、清晰度与统一时间线

拟交付：video/ 代码 Postprocess Worker、ASR/对齐适配器；测试 test_media_timeline.py、test_video_format.py。

  • 先测依赖未通过不得执行、重复调度不重复产物登记、Worker 失败/恢复、裁剪、片头偏移、分段拼接、字幕越界、正文漏字、音频变更后沿用旧时序。
  • 移除后期子 Agent；Worker 读取固定模板和用户配置，在最终 TTS 审核且确认后执行 ASR/对齐，合成等待质量 Agent 审核原片通过，不依赖模型生成剪辑命令或 Skill/MCP 调用。
  • 用同一时间轴映射驱动音频、视频和字幕，代码直接调用 FFmpeg/libass 合成、烧录字幕、生成封面/标识并导出；执行 1080×1920/H.264/AAC/30 fps CFR、两遍响度和清晰度处理。普通缩放不等于真实增强；超分模型待选，启用前须验证许可、身份保持和前后画质，失败保留原片并阻断交付。
  • 用 ffprobe、完整解码、响度测量与人工视听核验；ASR/对齐、超分和影像 QA 模型未选前不假设已有能力，成片由质量 Agent 再审，代码门禁通过后才可打包。

退出：AC-MEDIA-01～06、AC-AG-03/06；合成夹具只证明处理逻辑。

T08 质量门禁、人工复核与追溯

拟交付：quality/、质量审核 Skill、评审 API；测试 test_video_gates.py、test_review_binding.py、test_quality_decisions.py。

  • 基于本项目获准素材独立建立错音、换脸、静图、贴片、漏标识与伪指标负例。
  • 质量审核智能体只能引用事实/音频/影像检测报告、片段和 timecode；没有看过的帧或未执行指标不能编造。
  • 把确定性硬门禁与 Agent 观感建议分开；待选检测模型未标定时进入人工复核，不能自动放行或点按钮豁免硬失败。
  • 评审绑定对象版本和摘要；返工后的报告、批准与发布包重新核验，历史失败原件保留。

退出：AC-AV/CT/TTS/TH/MEDIA 对应质量项及 AC-AG-05/06；RMS 相关不替代嘴型同步。

T09 V1 发布就绪包与下载

拟交付：publish/package.py 与下载接口；测试 test_publish_package.py、test_publication_states.py。

  • 先测缺文件/标识、Mock、过期审批、导出完成误写 published 和下载摘要错误。
  • 由 Postprocess Worker 调用内部打包服务，在最终质量门禁通过后产出含哈希、质量摘要、来源清单的视频/封面/字幕/文案完整包，不新增业务 Skill/MCP；预览与下载引用同一有效版本。
  • V1 只登记就绪和下载，不调平台、不创建排期提醒；人工回填、计划队列留到 T13。

退出：AC-PUB-01～03 的 V1 适用项、AC-UI-01/06；下载不代表发布。

T10 七入口工作台与用户确认

拟交付：契约 API、经同流程对比选定的前端；测试 test_api.py、test_work_selections.py 和浏览器关键流程。

  • 先测作品版本冲突、幂等、非法路径、越权、未选择越阶段、预算不足以及旧结果晚到。
  • 用同一七入口/三稿比较/试听/预览流程对比 Vue 3 与 React，记录构建、交互和维护证据后再冻结依赖；不凭习惯宣布选型完成。
  • 固定导航为人物形象、口播稿生成、TTS 语音、视频合成、发布、指标监控、领域模型选择。七页均可进入；后三页展示实际规划/开发状态，禁用未实现按钮，无假账号和指标。
  • 人物支持关键词/自由输入、参考图衣景变体和用户选择；稿件显示三个不同角度的合格候选、编辑重审、缺额说明；音色先短句试听，再全文合成与确认。
  • 第 4 步“视频合成”才发起对口型。最终 TTS 尚未合格并被用户确认时禁止提交；人物页仅收集表演设置，不提前生成嘴型。M2 与 OmniHuman 1.5 的实际前置条件分别校验。
  • 合成前显示已选路线、模型、时长/分辨率、估价、预算和重做收费风险；只按显式选择调用，不静默转云收费。
  • 显示真实阶段、等待时间、费用与错误原因；无实际百分比时只显示阶段，清楚区分 Mock、技术完成和质量通过。刷新从同一 Work 恢复选择和进度，密钥不回显。
  • 在本地 HTTP 下核验创建作品到下载的成功、拒收、待选、预算拦截和恢复路径，并锁定选型后的构建/浏览器测试命令。

退出：AC-NFR-01、AC-UI-01～08 和接口契约；页面可点击不等于真实链路通过。

T11 空环境部署、备份与恢复

拟交付：预检/初始化/备份/恢复脚本；测试 test_clean_install.py、test_backup_restore.py。

  • 隔离环境仅提供新工程、明确依赖和配置，从空数据库开始，不探测旧路径或残留素材。
  • 受控登记已选资产的来源与摘要；缺文件、缺许可或审批未完成明确阻断，不能靠本机文件存在自动放行。
  • 备份恢复同时覆盖业务账本、DeepAgents 检查点、Skill 版本、人设/媒体引用、历史索引版本和审核后的经验。
  • 恢复在新目录进行；未知外部作业先核对、预算预留不丢失、失效产物不重新变有效，原目录不覆盖。

退出：AC-OPS-10、AC-NFR-02/03、AC-AG-07/08；空环境 L0 不代替真实生产验收。

T12 RAG 主题真实生产与每日 5 条验收

拟交付：test_rag_pipeline.py、受控验收入口、新 runtime/acceptance/<run_id>/ 证据目录。

  • 冻结人物 B、音色 3、PerformancePlan、Skill/模型/规则、历史快照、动作参考、许可证与授权预算。
  • 离线回归通过后按具体授权执行提示词直接生成 RAG 主题口播的真实约 60 秒流程（RAG 是科普主题，不是在线检索链路），保留角色委派、适用工具调用、代码后期执行记录、各项产物和指标。
  • 从最终包按所选路由反查稿件/计划、来源、历史命中、最终 TTS、OmniHuman 真实任务或 LivePortrait/MuseTalk 两阶段、字幕和审批；故障恢复不重复计费。
  • 执行全片视听、媒体规格和证据检查；不合格保留原结果与费用，未获授权不重抽。
  • 按06指标字典输出逐样本成绩、原始分子/分母、逐片时间误差、独立盲评、漏放/误拒及人工介入、合格成本和未测项；同输入比较一次只改一个因素。
  • 另按授权验证每天 5 条的排产、单 GPU 队列、合格率、占机时间、空闲与总费用；20 次试运营成绩单列，不用一日或一条样片替代。

退出：06 第 6 节联合验收、全部 V1 必需用例、AC-AG-10；七入口/选择/下载有浏览器证据。未测的增强规格及后续功能单列，L2 独立。

T13 后续排期、平台发布、指标和通用模型配置

拟交付：提醒/回填、逐平台发布与指标 Adapter、已适配模型设置页面；测试 test_publication_plan.py、test_publish_reconciliation.py、test_platform_metrics.py、test_model_settings.py。各增量分批开放，不作为 V1 前置。

  • 先实现提醒/回填并测时区、逾期和人工来源状态；实际投稿须另有具体授权。

  • 分别核验抖音、B站、快手、小红书、微信视频号的发布与数据权限；先测权限不足、空作品 ID、业务拒绝、提交 UNKNOWN、重复/乱序回调和定时语义。

  • 核验账号主体、应用权限、官方允许的实际发布方式、AI 声明能力及具体发布授权，再实现获准通道。

  • 只有明确允许且实际验证无人值守提交才验收自动发布；需要人工确认则如实记录。

  • 按授权真实投稿一次，保存受理、审核、公开与恢复证据；未知结果不重复创建作品。

  • 指标保存平台、账号/作品、指标定义、时间窗、获取时间和来源；完播率等不可获取时显示不可获取，不填 0，允许经授权导入后台数据。

  • 模型设置只开放已适配协议，安全保存凭据、按能力检查并反馈错误；URL/Key/模型名不能绕过 Adapter。

退出：AC-PUB-04～07、AC-OPS-05/06 与 PRD AC-F12～14；逐增量记录能力和通过范围，G3 阻断不重写 V1 历史。

5. 真实调用记录与费用

每批调用记录目标、准确模型/账号、样本和输入摘要、每阶段子限额、总额、最多提交次数、有效期、授权人、新 run 目录和验收 ID。默认不授权，单次试验授权不扩大为生产预算。

M2 两阶段、OmniHuman 1.5 云生成、DeepSeek 决策/改稿、MiniMax 试听/全文与图片生成/编辑分别列调用清单；重试、返工、模型加载、GPU 空闲、存储和传输计入适用成本。已估算费用与实际账单分开，未知费用保留待对账。轮询/下载在已授权边界内有限重试，未知 submit 仅查询核对；不自动重发或跨供应商回退。

  • 持久检查点、任务/预算账本、四层记忆、并发隔离与审核合并，以及未知作业对账和备份恢复证据。
  • 人物 B、音色 3、变体与动作参考的来源、权利、摘要和审批记录。
  • 提示词生成的真实 RAG 主题成片与完整发布包、60 秒质量和每天 5 条实测，未测能力与风险单列。
