官方文本与语音接口核验

2026-09-21 核验记录6 个章节Markdown 原文

核验日期：2026-09-21。调用渠道：各家官方 API 直连。范围：DeepSeek V4.1 Flash 与 MiniMax Speech 2.8 HD 的公开官方文档。

本轮仅检索和读取文档，没有读取项目密钥、调用模型、创建音色或产生模型推理费用。以下属于文档核验，账户权限、接口连通性、实际音质、延迟与计费均尚未实测。

1. 已确认的名称与配置

  • 用户选择的文本模型版本为 DeepSeek-V4.1-Flash。官方当前要求请求 model="deepseek-flash"，不能直接把用户写的 deepseek-v4.1-flash 当作已验证的 API ID。这是官方版本到调用名的映射，不是更换用户选择的模型。
  • 用户选择的语音模型为 MiniMax Speech 2.8 HD。官方请求 ID 为 speech-2.8-hd，不是 minmax-speech-2.8 HD。
  • 两者都是官方云 API；用户本地或算力云自部署的是 MuseTalk 数字人口播模块。本次没有选择自托管上述文本或语音模型。

建议配置名称如下。变量名是项目建议，API 地址与请求 ID 来自官方文档；不包含真实凭据。

DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_EXPECTED_MODEL_VERSION=DeepSeek-V4.1-Flash

MINIMAX_API_KEY=
MINIMAX_BASE_URL=https://api.minimax.cn
MINIMAX_TTS_MODEL=speech-2.8-hd
MINIMAX_VOICE_ID=

MINIMAX_VOICE_ID 需要试听并确认后固定，当前不填入随机示例音色，也不继承旧实验 Qwen / Cherry 的音色标识。不同厂商的音色 ID 不通用。

2. DeepSeek 官方接口与版本映射

2.1 接口

  • Base URL：https://api.deepseek.com。
  • 请求：POST /chat/completions。
  • 认证：Authorization: Bearer <DEEPSEEK_API_KEY>。
  • 请求格式：Content-Type: application/json，兼容 OpenAI Chat Completions。
  • 账户模型列表：GET /models。本轮未发送带凭据的请求。
  • 本项目先采用 Chat Completions 的文本 JSON 输出路径；官方也列出 Responses API，但不因此增加第二套业务调用协议。

官方首页原文摘录：Your First API Call

Use deepseek-flash as the model name. The legacy names deepseek-v4-flash and deepseek-v4-flash-vision-exp are still accepted, but the corresponding models have been retired, their requests are served by the DeepSeek-V4.1-Flash model and billed at the Flash price.

官方价格与能力页：Models & Pricing

MODEL: deepseek-flash；MODEL VERSION: DeepSeek-V4.1-Flash；Json Output: ✓；Tool Calls: ✓。

因此生产配置使用 deepseek-flash，同时在每次调用记录中保存请求 ID、请求的 model、响应 model、system_fingerprint（若返回）、用量和核验时的官方版本映射。该调用名是官方别名，不等于永久固定版本快照；后续若官方映射变化，应重新做回归对比，不宣称它能永久锁定 V4.1。

2.2 JSON 输出与质量边界

官方 JSON Output 要求：

  1. 设置 response_format={"type":"json_object"}。
  2. system 或 user 提示词包含 json，并给出所需 JSON 示例。
  3. 设置足够的 max_tokens，防止输出截断。
  4. 需要处理偶发空内容。

最小请求形状如下，仅供接口设计，不是已执行的请求：

{
  "model": "deepseek-flash",
  "messages": [
    {
      "role": "system",
      "content": "请根据已提供的资料输出 json 对象，字段为 title、description、tags、segments、claims。不得编造资料引用。"
    },
    {
      "role": "user",
      "content": "生成一期面向初学者的 RAG 科普口播稿，目标 60 秒。资料包和历史查重结果由业务层提供。"
    }
  ],
  "response_format": {"type": "json_object"},
  "thinking": {"type": "disabled"},
  "stream": false,
  "max_tokens": 4096
}

这里关闭 thinking 是用于首个接口测试的可调整参数，不代表用户已经选定最终推理强度。生成稿件与内容评估是否启用 thinking，应通过同输入测试决定并分别记录耗时和 tokens。

JSON Output 只处理 JSON 格式；业务层仍须用 Pydantic 或 JSON Schema 检查字段、类型、长度、分段和引用。出现空结果、finish_reason=length、缺少字段或不合法引用时，不能进入 TTS。事实判断需要检索资料与引用核对，模型自检不能作为唯一证据。

官方 Chat Completions API 的 response_format.type 当前列出 text、json_object；不要假定这里支持 OpenAI 的 json_schema 形式。该页另有工具调用 strict 的 Beta 能力，这与普通 JSON 输出不同，不作为首版必需依赖。

2.3 官方页面不一致的处理

同日获取的 Chat Completions 参数页仍列出旧 ID deepseek-v4-flash、deepseek-v4-pro、deepseek-v4-flash-vision-exp；首页和价格页已明确说明 Flash 升级映射。采用首页和价格页一致给出的 deepseek-flash，在首次账户连通性验证时保存 /models 与实际响应证据，不用旧参数页否定用户要求的 V4.1。

thinking_mode 指南抓取结果还含 deepseek-chat、deepseek-reasoner 及旧的输出上限描述。不要将这些旧示例参数上限复制成 V4.1 的当前限制；版本能力与额度以当前模型页和账户实际接口验证为准。

3. MiniMax 官方接口与固定音色

3.1 同步 HTTP 作为一分钟口播的首个接入路径

官方 同步语音合成 HTTP 当前 OpenAPI 列出：

servers: https://api.minimax.cn
POST /v1/t2a_v2
Authorization: Bearer <MINIMAX_API_KEY>
Content-Type: application/json
model: speech-2.8-hd

同一页还公布备用接口 https://api-bj.minimaxi.com/v1/t2a_v2。官方其他页面（例如音色列表、异步接口）仍出现 https://api.minimaxi.com。因此项目对地址保留配置项，首轮按同步接口文档的 https://api.minimax.cn 验证；不能把不同页面的域名混用后宣称全部已经测通，也不在超时后自动换地址重发计费任务。

本项目一分钟口播无需为了长度使用异步接口：同步文档给出文本长度小于 10,000 字符，超过 3,000 字符建议流式。最终长度限制、超时和重试策略仍需通过真实稿件测试。

3.2 固定声音需要固定什么

  • voice_setting.voice_id：支持系统、复刻、文生音色。长期保存审核通过的具体 ID。
  • 同时锁定模型 ID、基础语速、音调、声音效果配置及样音 SHA256；仅把每句需要的停顿和情绪作为朗读计划。
  • speed：范围 [0.5, 2]，默认 1.0。
  • vol：范围 (0, 10]，默认 1.0。
  • pitch：范围 [-12, 12]，默认 0。
  • voice_modify 会改变音高、强度、音色等，应随 VoiceAsset 版本记录；首版不随机混音或调整音色。

官方 查询可用音色 ID 原文：

该 API 支持查询当前账号下可调用的全部音色 ID（voice_id）。

该页面列出 POST https://api.minimaxi.com/v1/get_voice，请求可以使用 {"voice_type":"system"}。官方返回示例包含 Chinese (Mandarin)_News_Anchor 等，但这里只证明文档列有该音色，不替用户选择声音，也未证明本账户已可调用。voice_name 是显示名，不能替代 voice_id。

3.3 停顿、情绪与发音

同步接口文档原文：

在文本中增加 <#x#> 标记，x 为停顿时长（单位：秒），范围 [0.01, 99.99]，最多保留两位小数。文本间隔时间需设置在两个可以语音发音的文本之间，不可连续使用多个停顿标记。

例如 TTS 文本可以写成 你可能不知道。<#0.35#>RAG 会先查资料，再生成回答。，字幕展示文本须去掉控制标记。

emotion 文档支持 happy、sad、angry、fearful、disgusted、surprised、calm，并可由模型按文本自动匹配。文档的额外枚举还包括 fluent、whisper，但说明对版本有限制，其中明确写出 Speech 2.8 不支持 whisper；fluent 也不应只凭枚举就认定 2.8 可用。首版采用明确支持的七项或不传 emotion，再用真实样音验证表现。

Speech 2.8 支持 (laughs)、(chuckle)、(breath)、(sighs) 等语气词标签。它们是声音事件，不等于任意 SSML 标签或逐字重音协议。行内拼音 / IPA 以及 pronunciation_dict.tone 可用于 RAG、API 等术语读法；术语替换规则要保存版本，且需要试听验证。

3.4 音频、字幕时间戳与返回处理

  • stream=false 时，output_format 支持 hex 或 url；URL 有效期为 24 小时，不能直接当永久资产地址。
  • stream=true 仅返回 hex；本项目先测非流式，便于保存完整音频与时间戳。
  • 音频请求格式枚举包含 mp3、pcm、flac、wav 等；建议先请求单声道无损音频，再由 FFmpeg 统一为 MuseTalk 实际需要的 PCM WAV。该路径尚未实测。
  • subtitle_enable=true 开启字幕。subtitle_type 文档列出 sentence（句级）、word（词级）、word_streaming（仅流式）。优先验证 word，为重点词高亮提供时间戳。
  • 返回包含 data.audio、data.subtitle_file、trace_id、extra_info 与 base_resp。必须同时检查 HTTP 状态、base_resp.status_code==0、data 非空、音频完整解码及实际时长；HTTP 200 本身不等于合成成功。
  • extra_info 包含 audio_length（毫秒）、采样率、声道、音频大小、usage_characters 等，用于验收和成本台账。

字幕文档存在一处不一致：请求支持 subtitle_type=word，但响应 subtitle_file 的字段说明仍写“精确到句（不超过 50 字），单位为毫秒，格式为 json”。因此，词级时间戳是官方声明支持、待实际响应核验的能力，不能据此删除字幕对齐的后备接口。

接入时需要下载并保留原始字幕 JSON，确认字段和单位，再转换为内部时间轴、SRT / ASS。若只有句级时间戳，可生成句级字幕；逐词高亮需要另行对齐。后处理改变首尾时长、切片或拼接后，必须更新字幕时间轴。这里不新增或擅自选定 ASR / 对齐模型。

3.5 初始测试请求形状

以下只是模板，不会在文档生成时执行，<审核通过的固定音色ID> 必须由已确认的 VoiceAsset 提供。

{
  "model": "speech-2.8-hd",
  "text": "你可能不知道。<#0.35#>检索增强生成，会先查资料，再生成回答。",
  "stream": false,
  "voice_setting": {
    "voice_id": "<审核通过的固定音色ID>",
    "speed": 1.0,
    "vol": 1.0,
    "pitch": 0
  },
  "audio_setting": {
    "sample_rate": 32000,
    "format": "wav",
    "channel": 1
  },
  "language_boost": "Chinese",
  "subtitle_enable": true,
  "subtitle_type": "word",
  "output_format": "hex"
}

4. 费用口径

官方 MiniMax 按量计费 本次读取显示 Speech 2.8 HD 同步和异步均为 3.5 元 / 万计费字符。原文说明：

1 个汉字算 2 个字符，英文字母、希腊字母、标点符号、特殊符号、空格、回车等算 1 个字符。

不能把“一万汉字”直接当“一万计费字符”。粗略例子：一分钟若有 250 个汉字，仅汉字部分为 500 个计费字符，对应 0.175 元；实际还要计入标点、控制文本等，以 usage_characters 与账单核对。该例没有证明 250 字必然读满一分钟，也没有包含返工、音色设计或复刻费用。

官方 DeepSeek 价格页本次读取为美元报价，并按输入缓存命中、未命中、输出 tokens 及峰谷时段分别计价。成本记录应存输入 / 输出 tokens、缓存分类、调用时间、币种、价格核验日期和实际账单；不能将美元数字直接当人民币。当前没有账户用量证据，也不承诺单位成片文本成本。

5. 接入验收清单

  1. 使用新模型各完成独立的、小规模真实接口测试；不复用或改写以前 Qwen / 阿里 / 火山实测的成功结论。
  2. DeepSeek 检查请求 ID 与版本映射、JSON 格式、结构字段、引用真实性、60 秒稿件长度、重复率和用量。
  3. MiniMax 先确认固定 voice_id，再检查普通话、英文术语、数字、停顿、情绪、首尾完整性、字幕 JSON 粒度和计费字符。
  4. 将合格 MiniMax 音频作为唯一音频输入接入已部署 MuseTalk，保留原始音频、归一化音频、字幕和 SHA256。单个模块成功不等于全链路合格。
  5. 最终记录 5 条一分钟稿件的总耗时、失败次数、返工次数及合格产出成本，之后才能替换现有基于短样片的成本假设。
