阿里云百炼 / 万相 S2V 候选核验

2026-09-21 核验记录10 个章节Markdown 原文

核验日期：2026-09-21（Asia/Shanghai）。

核验方式：使用 agent-reach 的 Exa 搜索与网页提取读取阿里云帮助中心第一方文档，并用 Jina Reader 再次读取 S2V 视频生成 API 页面核对接口域名与参数。以下是官网资料核验，尚未实际调用检测或视频生成接口。未登录账户、未读取密钥、未开通服务、未上传素材、未下载模型或示例视频，未发生本次生成测试费用。搜索引擎返回的页面发布日期不作为本次核验日期，也不据此保证官网所有示例已经同步更新。

1. 候选身份与当前可确认范围

候选是阿里云百炼托管的 wan2.2-s2v，辅助检测模型为 wan2.2-s2v-detect。图片与人声音频输入、输出人物说话 / 唱歌 / 表演视频，支持真人肖像、半身、全身和卡通人物。[S1][S2][S3]

其公开约束可以覆盖约 15 秒同图同音频试片：图像宽和高各为 400～7000 像素，音频 WAV / MP3、文件小于 15M、时长严格小于 20 秒。是否能达到本项目所需的口型、面部稳定性、动作自然度和身份一致性，仍须生成原片后评估；官方演示和描述不能替代本项目样本实测。

2. 接入地域、鉴权与开通

  • 地域：S2V API 和检测 API 均明确“仅适用于华北 2（北京）地域，且必须使用该地域的 API Key”。视频模型总览也限定其服务部署范围为中国内地，静态数据存储位于北京，推理计算资源位于中国内地。[S1][S2][S4]
  • 凭证：HTTP Header 为 Authorization: Bearer <百炼通用 API Key>，不是要求阿里云 AccessKey ID / AccessKey Secret 签名，也不是 Coding Plan 的 sk-sp-… 专属 Key。文档通常使用 DASHSCOPE_API_KEY 环境变量名，但变量名本身不构成权限。[S1][S2][S6]
  • 业务空间：当前 S2V API 参考要求以真实 WorkspaceId 填入域名。API Key 与所选北京业务空间应匹配；子业务空间需已授权这两个标准模型。[S1][S2][S6]
  • 开通：百炼按地域开通。官方 FAQ 说明由主账号切换目标地域、阅读并同意服务协议完成开通；若提示未实名认证，应先实名认证。这是文档流程，本次未代用户操作。[S8]
  • 权限：获取 / 创建 API Key 需主账号，或具备管理员 / API-Key 页面权限的子账号。默认业务空间 Key 可调用标准模型；子业务空间只能调用已获授权模型。若使用 RAM 用户首次开通模型调用功能，官方 RAM 文档要求 AliyunBailianFullAccess；这不代表每个持 Key 的运行进程都必须拥有该管理权限。[S6][S9]
  • 仍未知：用户账户是否已开通北京百炼、具体 WorkspaceId、Key 是否有效、IP 白名单与模型权限、实际免费额度 / 优惠 / 账户余额。上述账户事实不能由公开文档推断。

3. 前置图片检测

当前 API 参考列出的同步检测接口：[S2]

POST https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/services/aigc/image2video/face-detect
Authorization: Bearer <API_KEY>
Content-Type: application/json

{
  "model": "wan2.2-s2v-detect",
  "input": {
    "image_url": "<公网可访问的同一张图片URL>"
  }
}

官方总览的流程是先检测，check_pass=true 后再生成。检测检查清晰度、单人、正面等要求。生成 API 的已列入参不包含检测任务 ID、检测令牌或坐标；因此可以确认它是官方流程中的前置校验，但仅凭现有文档不能确认服务端会强制校验“该图此前调用过 detect”，也不能宣称跳过检测一定可行。[S1][S2][S3]

检测通过的文档响应形态：

{
  "output": {
    "check_pass": true,
    "humanoid": true
  },
  "usage": {
    "image_count": 1
  },
  "request_id": "<请求ID>"
}

检测不通过的文档响应形态：

{
  "output": {
    "check_pass": false,
    "code": "",
    "message": ""
  },
  "usage": {
    "image_count": 1
  },
  "request_id": "<请求ID>"
}

check_pass 是是否通过，humanoid 是是否检测到人像；未通过示例没有 humanoid，且 code / message 是空字符串，不能要求每次响应都带完整诊断字段，也不能将 humanoid=true 单独当作检测通过。上面是依据官网整理的结构示例，不是本项目的实际响应。[S2]

4. 输入的硬限制与未公开项

图片：[S1][S2]

  • 一张人物图片，格式为 JPG、JPEG、PNG、BMP 或 WEBP。
  • 宽和高分别落在 [400, 7000] 像素范围。
  • 提供公网可访问的 HTTP / HTTPS URL；官方链接到临时文件上传说明。不能把本地文件路径直接填入 image_url。
  • 人物可为肖像、半身、全身或卡通；检测页与总览要求清晰、单人、正面。
  • 未知：独立的图片文件字节上限、固定宽高比范围、面部最小像素、允许头部角度、检测的数值阈值。已读 S2V 专用文档未明确列出，不把其他万相模型规则迁移过来。

音频：[S1]

  • 格式为 WAV 或 MP3，公网 HTTP / HTTPS URL。
  • 原文为“文件<15M，时长＜20s”。M 未进一步明确十进制或二进制单位；15 秒试片无需贴近该上限。
  • 要求清晰、响亮的人声，去除环境噪音、背景音乐等干扰。A/B 应使用同一份已冻结的干净音频。
  • 生成视频时长随输入音频时长一致。S2V API 明确“须小于 20 秒”；模型总览写“不超过20s”，存在边界措辞差异，实测按较严格的 <20s，不能把 20.000 秒视为已确认可用。
  • 未知：最短音频时长、采样率 / 位深 / 声道硬限制、音频边界裁切与静音处理、具体编码子类型。不使用其他视频模型的音频限制补全。

5. 生成与查询的契约

以当前 S2V 专用 API 参考为请求模板：[S1]

POST https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/services/aigc/image2video/video-synthesis
Authorization: Bearer <API_KEY>
Content-Type: application/json
X-DashScope-Async: enable

{
  "model": "wan2.2-s2v",
  "input": {
    "image_url": "<与检测一致的图片URL>",
    "audio_url": "<已冻结的约15秒音频URL>"
  },
  "parameters": {
    "resolution": "720P"
  }
}

model、input.image_url、input.audio_url 为必选。parameters.resolution 可选 480P / 720P，默认 480P。S2V 专用 API 参数表未列 prompt、seed、独立 duration 或 style，不据总览中的旧示例增加未核实参数。

提交成功只表示创建了异步任务，不代表生成完成。响应必要定位字段：

{
  "output": {
    "task_id": "<任务ID>",
    "task_status": "PENDING"
  },
  "request_id": "<提交请求ID>"
}

官网该示例在 output 后漏了逗号，此处按字段表修正为合法 JSON。这是文档整理，未声称观察到真实响应。

查询：

GET https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/tasks/{task_id}
Authorization: Bearer <API_KEY>

可返回状态为 PENDING、RUNNING、SUCCEEDED、FAILED、UNKNOWN、CANCELED。官方建议约 15 秒轮询一次，并给出约 5～10 分钟生成耗时作为说明；这是参考描述，不是本次延迟结果或 SLA。查询默认 QPS 为 20。任务状态 / 结果与生成视频 URL 均须在 24 小时内及时保存；超时可能返回 UNKNOWN。[S1]

成功查询的关键结构：

{
  "output": {
    "task_id": "<任务ID>",
    "task_status": "SUCCEEDED",
    "submit_time": "<提交时间>",
    "scheduled_time": "<开始执行时间>",
    "end_time": "<结束时间>",
    "results": {
      "video_url": "<24小时有效的结果URL>"
    }
  },
  "usage": {
    "duration": 18.13,
    "size": "512*640",
    "fps": 16,
    "video_count": 1,
    "SR": 480
  },
  "request_id": "<查询请求ID>"
}

上述 usage 数值来自官网 480P 示例，不代表拟测的 15 秒 / 720P 成片；最终应保存真实响应。S2V HTTP 字段表和成功 JSON 中的视频地址为 output.results.video_url。Jina 读取到的同页 Python SDK 示例却打印 rsp.output.video_url，不能据 SDK 示例推断 HTTP 字段路径。[S1]

失败查询的关键结构：

{
  "output": {
    "task_id": "<任务ID>",
    "task_status": "FAILED",
    "submit_time": "<提交时间>",
    "scheduled_time": "<开始执行时间>",
    "end_time": "<结束时间>",
    "code": "InvalidURL",
    "message": "Required URL is missing or invalid, please check the request URL."
  },
  "request_id": "<查询请求ID>"
}

这同样是官网失败示例的结构摘录。提交阶段的非 2xx 错误、连接超时与任务已创建但客户端未收到响应，应作为不同情况留存；不能把所有失败都归入异步 FAILED，更不能在无法确认是否已创建任务时自动重新提交。S2V 专页没有完整列举提交阶段的全部错误 JSON，具体字段集合留待真实响应核实。

6. 输出规格与音频保留

  • 档位为 480P、720P；API 说明会尽量保持输入图片宽高比，将总像素数调整到相应档位附近。因此 720P 不代表所有结果固定为 1280×720，竖图也不能预先承诺固定 720×1280；应以 usage.size 与成片探测值为准。[S1]
  • 模型总览明确：480P 为 16 fps，720P 为 30 fps，均是 MP4 / H.264，且属于有声视频。[S4]
  • 已确认输入音频驱动口型、表情与动作，视频时长跟随音频。[S1][S4]
  • 未确认源音频无损保留：已读资料没有承诺输出音轨与输入文件逐字节 / 逐采样相同，也没有明确说明是否重编码、调采样率、调响度、改变起止静音或生成伴音。不能将“有声视频”写成“原音频原样保留”。15 秒测试需探测音轨并听辨，对齐波形 / 语句边界，区分有损重编码与内容变化。
  • 口型误差、音画偏移、面部漂移、眨眼自然度、手部与背景稳定性、运动幅度、失败率及真实耗时：全部尚未实测。

7. 价格、扣费与并发

官网当前北京原价：[S1][S2][S5]

  • wan2.2-s2v-detect：0.004 元 / 张。请求成功即计费，即使 check_pass=false；请求失败不计费。
  • wan2.2-s2v 480P：0.5 元 / 成功输出视频秒。
  • wan2.2-s2v 720P：0.9 元 / 成功输出视频秒。
  • 生成输入不计费，按成功生成的输出秒数计费。模型调用失败或处理错误不产生生成费，也不消耗新人免费额度。
  • 官方新人免费额度：检测 200 张、视频 100 秒，价格页写有效期为百炼开通后 90 天。是否仍可用依用户账户而定，不能提前把测试费用记为零。
  • 视频即使观感不合格，只要任务成功生成，仍按成功输出计费。检测不通过的正常响应也收费；不要把“验收失败”与“服务端调用失败”混淆。
  • 最小计费 / 取整未知：专用 API 的 usage.duration 是 Float，示例含 18.13 秒；价格页公式为视频单价乘输出时长。本次未找到 S2V 专属的最小计费时长、秒数向上取整、金额舍入或最小收费金额规定。不能自行补为“每秒向上取整”或“最低 5 秒”。

仅用于直接生成费用估算的公式（未扣免费额度或折扣）：

直接模型费 = 0.004 × 成功完成检测的图片张数
           + 0.5 × 成功输出的480P视频计费秒数
           + 0.9 × 成功输出的720P视频计费秒数

例如同一图一次检测通过、成功输出恰好 15.00 秒且只生成一条：480P 原价估算为 0.004 + 15 × 0.5 = 7.504 元；720P 为 0.004 + 15 × 0.9 = 13.504 元。这是单次条件式估算，不是已授权额度或完整测试总预算；不包含另一候选、TTS、素材生成、存储 / 流量、额外重试，最终以账单及 usage.duration 为准。

限流：[S1][S2][S7]

  • S2V 提交接口 5 RPS，同时处理中任务数为 1。
  • Detect 为 5 RPS，文档称“同步接口无限制”（同时处理中数量栏）；并不意味着请求频率无限。
  • 主账号下 RAM 子账号、业务空间和 API Key 合并计算模型调用限流；不能通过多建 Key 假定获得更多并发。
  • 本次未核实用户账户的定制提额。标准并发 1 意味着单账户多片测试需要顺序观察执行，不能将 5 RPS 当成 5 条并行渲染。

8. 官方文档差异与实测处理

  1. 域名不一致：S2V / Detect 专页使用 https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com，总览生成示例仍使用 https://dashscope.aliyuncs.com。本次 Exa 与 Jina 均读到前者，故试验模板以专用 API 参考为准；后者是否仍兼容不在本次只读核验范围。[S1][S2][S3]
  2. style 未列入专页参数表：总览示例有 style: speech，专页仅列 resolution。初次对照试片不将该未明确参数作为必要控制项，其受支持状态未知。[S1][S3]
  3. 地域提示残留：总览在声明仅北京后，又在任务查询样例提示新加坡地址；视频模型总览与两份专用 API 均只支持北京。不能据通用示例认定该模型可在新加坡调用。[S1][S2][S3][S4]
  4. 20 秒边界：专页 <20s，模型总览“不超过20s”。选择约 15 秒样本可避开差异；长音频需要切段，跨段身份 / 动作接续质量属于另一项未完成测试。[S1][S4]
  5. HTTP / SDK 字段差异及 JSON 漏逗号：按 HTTP 参数表与 JSON 示例组织解析，保留原始响应，遇到实际字段不一致先记录和停止，不制造成功结果。[S1]

这些差异不直接证明服务不可用，但降低了仅凭官网即可完成接入验收的可信度。当前结论仍是待实测候选，不据此决定主选或备选。

9. 15 秒同图同音频 A/B 的阿里侧输入与证据要求

这是准备清单，并非本次已经执行：

  1. 冻结同一张图片和同一条约 15 秒干净人声音频，记录 SHA-256、尺寸 / 编码 / 时长；核实两家都可接受后再上传。若需要压缩或改采样，保留源文件及同一份共同输入，不给单方单独优化内容。
  2. 确认北京服务、WorkspaceId、对应 API Key 与两模型权限；通过安全配置读取凭证，不将值写入报告。由用户单独授权本轮付费额度与调用次数。
  3. 阿里侧一次 detect。只有 check_pass=true 才提交生成；检测未通过时记录失败原因，不能无授权地换图循环检测。
  4. 先约定 480P 或 720P 档位，并披露与另一候选实际输出分辨率 / fps 的差异。仅提交一次、不自动重试；通过同一个任务 ID 查询状态。合理轮询不等于重复生成。
  5. 保存脱敏请求、HTTP 状态、检测响应、提交响应、每次查询响应、request_id、task_id、各阶段耗时与 usage；成功后在链接到期前保存原始 MP4。
  6. 对原片进行音画时长、尺寸 / fps、音轨、可播放性、口型与身份 / 背景稳定性检查。后处理不得覆盖原片，也不能用换音轨后的版本证明服务自身原音频保留。
  7. 同时记录账单或可查询用量，区分官方标价估算、免费抵扣与实际扣费。只有成片和证据齐备后才进入候选比较，未生成或失败如实标记。
