0. 结论速览

编号 决策点 推荐 理由 置信度
A1 4GB 显存能否本地跑高质量人物一致性 不能。本地仅保留 SD1.5 级草稿/兜底能力 官方 README 实测门槛：PhotoMaker 最低 11GB、PuLID-FLUX 16GB（demo 12GB）；SDXL/Flux 系在本机 4GB 上不可用。现有 SD1.5 流程已被验证「放大到 1080×1920 后脸部崩坏」 高
A2 主生成通道 云端图像 API（参考图驱动范式） 2025-2026 的云模型已把「参考图[最多 9 张] + 文字指令」做成原生能力，天然满足「换装换背景不改人」，无需自建多模型 pipeline 高
A3 首选云模型（质量档） Gemini 3 Pro Image（Nano Banana Pro） 与 阿里百炼 wan2.7-image-pro 双通道 Nano Banana Pro：1K–2K 出图 $0.134/张、4K $0.24/张 [实测 官方价格页]；wan2.7-image-pro 官方明示「多图参考（最多 9 张输入图片）」「角色一致性多图生成」、文生图最高 4096×4096，0.50 元/张 [实测 官方文档] 高
A4 成本档备选 阿里 z-image-turbo（0.1 元/张，写实人像定位） 或 wan2.7-image（0.20 元/张） 官方文档明示 z-image-turbo 「生成速度快 10 倍，价格约为 1/5」「写实人像和产品照片」 中（画质需自测）
A5 三段解耦（Base+Outfit+Background） 资产化 + 参考图数组 + 提示词模板，而非三段分别生成再拼 拼接（人体 inpaint/抠图合成）会引入颈部接缝、发丝边缘、光照不一致三类瑕疵；云模型一次生成可绕过 高
A6 seed 固定是否足够锁定身份 不够。seed 只保证「同模型同版本同 prompt」可复现 换装换背景必然改 prompt；云 API 模型热更新会让 seed 漂移。seed 是复现性手段，不是身份锁定手段 高
A7 真正的身份锁定手段 参考图条件 + ArcFace 人脸指纹门禁 每张图生成后用 InsightFace/ArcFace 提 embedding，与 Base Avatar 基线比余弦相似度，低于阈值拒收重生成 高
A8 本地人脸指纹/抠图的许可证风险 自建人脸指纹链路只能用于内部质检，不可用于可商用训练 insightface 官方 README 原文：模型「available for non-commercial research purposes only」[实测]；InstantID 官方 README 亦声明「Our released checkpoints are also for research purposes only」[实测] 高（但注意：生成结果的商用性取决于云服务条款，不取决于本地质检脚本）
A9 换装/换背景实现路径 首选「分层生成」而非「重绘人体」：背景独立生成 → 人物（云 API 按 outfit 提示词生成）→ 抠图合成；仅在必须保留精确姿态时才用 inpaint 躯干重绘 抠图合成不改人脸像素 = 零身份漂移；inpaint 需严格保护头部区域 mask，工程脆弱 中高
A10 抠图模型选型 BiRefNet（MIT） 为主，rembg（MIT）作为封装壳；优先用 matting 专用权重 BiRefNet 有 portrait / general matting 专用权重，官方 README 注明可在 1024×1024 下 17 FPS、3.45GB 显存（RTX 4090, fp16）[实测]；rembg README 明示老模型（u2net/silueta）发丝边缘需要 -a 才平滑 [实测] 中高
A11 人脸修复（CodeFormer/GFPGAN）要不要用 默认不用。它是身份漂移的来源，不是身份保持的工具 CodeFormer 为 S-Lab License 1.0「non-commercial purpose」[实测]；且人脸修复按先验「美化」五官形态，会改变下游唇形驱动依赖的嘴部几何 中高
A12 1080×1920 放大链路 直接按目标分辨率云端生成，不做「先小后放大」 云 API 已支持 2K/4K 出图；Real-ESRGAN/GFPGAN 会在放大时「重绘」细节，对嘴部几何是灾难 高
A13 本地还能保留什么 编排调度 + 质检（人脸相似度）+ 抠图合成 + 背景拼接 这几步都是小模型或 CPU 可跑，且不产生身份漂移 高
A14 单张成图成本量级 0.1–0.5 元/张（国产云）／$0.03–$0.24/张（海外云） 见 §8 成本表；均为官方页采集，落地前需复核 中高

1. 需求拆解：身份锁定的技术定义

1.1 必须锁死（不可随机变）

维度 具体含义 校验方式（建议）
脸型与五官 颅骨轮廓、眉眼鼻唇比例、双眼间距、脸宽比 ArcFace embedding 余弦相似度 ≥ 阈值
发型 长度、卷直、发际线形态、分发方向 视觉人工抽检 + 可选 CLIP/DINO 特征距离

性别呈现 不可漂移 视觉抽检 / 分类器

维度 可变量

1.3 「三段解耦」的可落地定义

Base Avatar（身份层，只读资产）
  ├─ avatar_hero.png        定妆照（2K，正脸/胸像）
  ├─ avatar_ref_1..4.png    多角度/多光照参考图（用于多图参考输入）
  └─ avatar_face.npy        ArcFace embedding 基线（建议 3~5 张取均值 + 类内方差）
Outfit（服装层，可替换词条/参考图）
  └─ outfits.yaml           { name, prompt_cn, prompt_en, ref_image?(可选) }
Background（背景层，可替换词条/参考图）
  └─ backgrounds.yaml       { name, prompt_cn, prompt_en, ref_image?(可选) }

生成 = f(avatar_ref[], outfit, background, camera, seed)  → 单次云 API 调用

核心原则：身份层只读、永不重绘。 任何会「重新画脸」的环节（inpaint 面部、face restore、超分重绘）都是身份漂移风险源。

1.4 下游唇形驱动的硬约束（写给 03 的接口约定）

  • 构图：胸像或半身，正脸或 ≤15° 偏转；嘴部区域无遮挡（无手、无麦克风、无围巾遮挡嘴）。
  • 分辨率：正脸区域像素高度需足够支撑逐帧嘴部形变；建议人脸在成图中占比不要过小（生成阶段先按 2K 出图，再裁/缩到 1080×1920）。
  • 生成的图不要经过任何「重绘型」放大（见 §7）。

3.2 裁决

  • 能跑：SD1.5 文本出图（质量不达标）、人脸指纹质检、抠图、图层合成、小幅度放大。
  • 不能跑：一切能满足「身份高保真 + 高分辨率」的生成方案（SDXL/Flux/Qwen 全系列）。
  • 结论：本机角色 = 编排调度引擎 + 质检门禁 + 后处理合成；生成环节外包给云 API。这与用户「愿意为云 API 付费换取质量，本地只做编排调度」的决策一致，无需更换硬件即可开工。

5.3 背景生成

  • 背景与人物同一次生成（P1 路径）：性价比最高。
  • 需要长期复用的固定背景（如固定演播厅）：先生成一张 2K 背景底图 → 归档 → 后续用 P3 合成，保证背景 100% 稳定。
  • 背景无需人物一致性校验，可放心用最便宜的通道（z-image-turbo 0.1 元/张）。

6. 身份一致性校验工程手段

6.1 seed 固定够不够？—— 不够，原因有三

  1. 语义冲突：seed 的可复现性建立在「同模型 + 同版本 + 同 prompt + 同参数」之上。而本项目的核心动作恰恰是改 prompt（换装换背景），此时 seed 已经失去锁定意义。
  2. 服务端不可控：云 API 的模型会热更新（阿里文档中同一模型 ID 存在多个日期快照，如 qwen-image-2.0-pro-2026-03-03 / -2026-04-22 / -2026-06-22 即可见其版本演进模式）[实测]；本地模型换量化/换依赖同样漂移。
  3. 它管的是「随机噪声」而不是「身份」：seed 固定能让同一 prompt 输出稳定，但不能阻止模型在不同 prompt 下把鼻子换个形状。

正确姿势：seed 只是故障复盘用的日志字段；身份锁定靠「参考图条件 + 指纹门禁」。

6.2 人脸指纹（FaceID embedding）校验链路

候选图 → 人脸检测（RetinaFace/SCRFD）
      → 关键点对齐（5 点仿射，统一到 112×112）
      → ArcFace 提 512-d embedding
      → L2 归一化后与 Avatar 基线做余弦相似度
      → 阈值判定 → 通过 / 拒收重生成

基线建立：对 Base Avatar 的 3–5 张参考图各提 embedding，计算两两余弦，取

  • 中心向量 c = mean(e_i)（归一化）
  • 类内最小相似度 s_min（作为「同一人」的经验下界）
  • 类内平均相似度 s_avg

阈值设计（工程建议，需用自有数据校准，标 [待核验]）

相似度（余弦） 判定 动作
≥ 0.60 强一致 直接放行（推荐作为上线初始硬阈值）
0.50 – 0.60 一致 放行但记录；连续出现则收紧
0.40 – 0.50 灰区 人工抽检；批量场景自动重生成（换 seed）
< 0.40 判定为不同人 拒收 + 重生成；同一素材连续 3 次拒收则报警（提示词/参考图有问题）

阈值不是通用常数，取决于人脸模型版本（buffalo_l / antelopev2 / 其他）、图像分辨率、姿态与遮挡。上线前必须用你自己的 Avatar 图跑一遍类内/类间分布，取类内 P1 与类间 P99 之间的分位点作阈值。 另注：阈值校准用的 ArcFace 模型（InsightFace）为非商用许可 —— 用于内部质检不对外分发权重通常可控，但若未来把质检能力做成对外产品 / 用于训练可商用模型，必须替换为许可干净的模型（如自训或 Apache-2.0 的替代方案）。[待核验：法务意见]

6.3 多层门禁（推荐流水线）

层级 检查项 实现 失败动作
L0 人脸可检出、正脸度、人脸像素高度 人脸检测器 直接丢弃（构图不合格，不必算指纹）
L1 身份 embedding 相似度 ArcFace 重生成（换 seed / 微调提示词）
L2 发型/肤色粗校验 面部区域色直方图 + 人工抽检 人工复核
L3 嘴部可用性（下游唇形驱动前置） 嘴部关键点可见性 + 是否遮挡 重生成
L4 内容合规 云服务内容审核（阿里文档明示 prompt 会过审、违规返回 DataInspectionFailed）+ 抖音 AI 生成标识 丢弃 / 补标识

6.4 「换装换背景不改人」的可落地工程手段（按优先级）

  1. 参考图条件 + 全身重生成（P1）：成本最低、效果最好；配合 L1 门禁兜底。
  2. 面部区域保留式 inpaint（P2）：若必须复用某张已通过门禁的图，用 mask 只重绘「躯干 + 背景」，mask 以羽化边缘覆盖颈线以下，头部与发际线以上完全保护。这是像素级零漂移方案，代价是姿态被锁死。
  3. 分层合成（P3）：人物层不变 + 背景层更换，用 BiRefNet 抠图 → 合成；对「同一张人物图换 N 个背景」的批量场景效率最高。
  4. 禁止：对未来要用的图做人脸修复（CodeFormer/GFPGAN）、禁用带人脸先验的放大链路。

生成阶段 直接生成 2K 级竖屏（如 1024×1536 或 1536×2048，或 2048×2048 后裁 9:16），wan2.7-image-pro 可到 4096×4096 云 API 已原生支持，不需要「先小后放大」
构图 半身胸像（胸线以上）为主，正脸或 ≤15° 微侧 下游唇形驱动需要清晰稳定的嘴部几何；半身也为换装留出领口/肩部信息
人脸占比 人脸高度建议占画幅高度 1/4 以上（[待核验]，需按 03 的嘴部驱动要求定稿） 人脸过小则驱动后嘴部形变细节不足
背景 优先纯色/极简或强分离背景 便于抠图与分层合成
安全带 面部上方、下颚下方各留出余量，避免裁切到发顶/下巴 后续裁切与嘴部对齐容错

7.2 放大链路对比

手段 是否改变人脸 质量 速度 适用
Lanczos / 双三次插值 ❌ 不改（纯插值） 锐度低、细节不加，但绝对安全 毫秒 ✅ 小倍率（1.5× 以内）缩放首选
Real-ESRGAN（BSD-3） ⚠️ 会「重绘」纹理，人脸细节可能被改写 高（有幻觉细节） 十秒级 ⚠️ 仅用于背景/无人物区域；README 自带 --face_enhance 会接 GFPGAN = 换脸风险
ncnn-vulkan 版 Real-ESRGAN 同上，且 README 原文提示分块处理会引入块间不一致 中高 快（CPU/iGPU 可跑） ⚠️ 同上
云超分（云厂商的超分/画质增强） ⚠️ 需确认是否带人脸先验 高 秒级 ⚠️ 落地前需做「放大前后 embedding 相似度」回归测试
不放大，直接生成高分 ❌ 不改 最高 与生成同 ✅✅ 首选

结论：把分辨率需求前置到生成阶段；放大只做 Lanczos 小倍率缩放。若确需超分，必须做「超分前后人脸 embedding 相似度」回归测试，相似度下降超阈值即禁用该链路。
