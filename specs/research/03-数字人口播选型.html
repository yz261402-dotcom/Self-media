L5 零成本保底 本地 MuseTalk（fp16） 唯一官方声明可在 RTX 3050 Ti 4GB 上运行的方案（8 秒视频约 5 分钟）；MIT 可商用；但只重绘嘴部区域（256），需自行合成上屏 高（README 原文实测）

1. 需求拆解：什么是「合格的口播视频」

1.1 技术定义（本项目的验收对象）

输入：固定虚拟主播资产（单张人物图 / 一段基础视频 / 已训练分身 ID）+ TTS 音频（wav/mp3）。 输出：MP4，人物面对镜头口播，具备：

  1. 口型与音频音素对齐（唇形同步，Lip Sync）；
  2. 面部表情有起伏（眨眼、眉毛、嘴角，非贴图）；
  3. 头部有轻微自然运动（点头/微转，幅度可控）；
  4. 画面为半身/全身真人级写实质感（有脖子、肩膀、身体，不是被裁到下巴的头像）；
  5. 无矩形遮罩/几何色块等程序化伪影。

1.2 现有 demo 的差距（来自现状实测描述）

当前成片：静态头像（裁到下巴）贴上屏 + 下半屏几何色块 + 矩形嘴部遮罩。该形态实质是「图片+程序化嘴形形变」，不属于数字人口播，无法通过 1.1 的第 1/2/3/4/5 条。本调研的目标就是给出能真正解决第 1~5 条的接入方案。

2.2 「训练数字人分身」vs「单图驱动」（纯 AI 虚拟人适用性）

维度 训练分身（Video/Replica Avatar） 单图驱动（Photo/Image + Audio） Prompt 生成分身
代表服务 HeyGen（avatar-from-video）、Tavus（2 分钟真人视频训练，$65/$40 每条）、D-ID Express Avatar、腾讯数智人（摄影棚录制/3 分钟视频训练）、Synthesia 个人形象（Express-1 加项 $1,000/年） 火山 OmniHuman、阿里 wan2.2-s2v、D-ID talks、HeyGen avatar-from-photo HeyGen avatar-from-prompt（Avatar V/IV/III 引擎）

对纯 AI 虚拟人可行性 低：多数平台要求真人授权/同意书与人脸核验，AI 生成人脸大概率被拒或在审核环节卡住 高：只要求图片合规 高（HeyGen 官方明示支持）
主要坑 授权视频必须真人录制；形象被平台绑定（迁移成本高） 上下限由单张图质量决定（见 02 文档）；长视频偶发漂移 形象可控性弱，需多轮抽卡，风格受引擎限制

结论：本项目（全 AI 生成虚拟人）走「单图驱动为主 + prompt 分身（HeyGen）为辅」；「训练分身」仅在用户未来引入真人出镜/IP 授权时才启用。另注意：Tavus 的 replica 训练把「2 分钟真人视频」写死在产品设计里，与本项目路线冲突，只保留其视频生成 API 作为海外备选。

2.3 关键结论（对选型有直接影响）

  1. 可编程性：国内「即梦AI 数字人」「阿里 wan2.2-s2v」「阿里 avatar/灵眸」「腾讯云数智人」「百度数字员工组件开放平台」「魔珐有言」均有 REST API；腾讯智影、出门问问奇妙元以网页产品为主，未发现公开 API（智影本机不可达，待核验）。
  2. 「人物资产+音频」形态：火山 OmniHuman 与阿里 wan2.2-s2v 是标准「单图+音频」；sync.so/D-ID clips 是「视频+音频」；D-ID talks 是「图+文本/音频」；Synthesia/有言是「文本/PPT」驱动（与本项目『自己出 TTS 音频』的耦合度较低）。
  3. 价格量级（每分钟成片）：阿里 480P 30 元 < 阿里 720P 54 元 < 火山 60 元；海外 sync.so lipsync-1.9 约 $1.5/分钟（≈10 元）最低，但需要基础视频且大陆网络+外币卡。
  4. 【重要坑】阿里 wan2.2-s2v 单条音频必须 <20 秒（官方原文：超过 20 秒任务报错；需切分音频分段生成再拼接）。火山未见到该限制说明 [待核验]，但按「秒数计费」推测时长上限在几分钟级，落地前必须试跑确认。
  5. 水印：Synthesia「测试模式」、D-ID Trial/Lite、sync.so Hobbyist 档、HeyGen 免费档均有水印；生产必须落在付费去水印档位。
  6. 大陆可用性：国内四家（火山/阿里/腾讯/百度）均大陆直连+人民币；海外四家（HeyGen/D-ID/Synthesia/Tavus/sync.so）均需科学网络+外币卡，在自动化管线里属于「低可靠支线」，只做备选。

5. Adapter 接入设计（针对现有代码的改造）

5.1 现有抽象的问题（src/douyin_auto/digital_human/lipsync.py）

  • 接口签名 apply_mouth(person: Image, mouth_box, level) -> Image 是「逐帧改造静态图」的管道，本质只能支撑 deform 类伪方案；无法承载「API 合成整段视频」的异步任务模型（提交→轮询→下载）。
  • MuseTalkLipSync/Wav2LipLipSync/ApiLipSync 均直接继承 DeformLipSync，属于空壳；available() 只查目录/环境变量，不构成真实实现。
  • 结论：不要在这套接口上继续打补丁，新增独立的视频级抽象，把 lipsync.py 收缩为「本地渲染/离线预览」模块。

5.2 新接口（建议落在 src/douyin_auto/digital_human/talking_head.py）

from dataclasses import dataclass, field
from pathlib import Path

    emotion: Optional[str] = None    # happy/serious/...（不支持的 provider 忽略）
    aspect: str = "9:16"

@dataclass
class TalkingHeadJob:

    provider: str
    status: Literal["queued", "running", "success", "failed", "timeout"]
    video_url: Optional[str] = None
    error: Optional[str] = None
    est_cost_cny: float = 0.0
    actual_seconds: float = 0.0

@dataclass
class CostPolicy:
    daily_limit_cny: float = 200.0
    per_video_limit_cny: float = 120.0

class TalkingHeadProvider(ABC):
    name: str = "base"

    max_concurrency: int = 1

    def estimate_cost_cny(self, audio_seconds: float) -> float: ...

    @abstractmethod

    @abstractmethod
    def download(self, job: TalkingHeadJob, dest: Path) -> Path: ...

    def generate(self, asset, audio_path, *, idempotency_key, policy: CostPolicy) -> Path:
        # 成本熔断 -> 幂等查表 -> submit -> poll -> download -> 记录实际费用
        ...

  1. VolcengineOmniHumanProvider：visual.volcengineapi.com，Action=CVSubmitTask（req_key=jimeng_realman_avatar_picture_omni_v2，body: image_url,audio_url）→ Action=CVGetResult 轮询；Region cn-north-1、Service cv、AK/SK 签名（建议用官方 volcengine Python SDK 做签名，避免手写 HMAC 出错）。

  3. SyncSoProvider：POST /v2/generate（video+audio）→ GET /v2/generate/{id}；支持 webhook。
  4. （可选）HeyGenProvider：POST /v3/avatars（一次性建分身，asset_id 持久化）→ POST /v3/videos。

5.4 幂等与重试

  • 幂等键：sha256(person_asset_hash + audio_sha256 + provider + params)；提交前查库命中直接复用结果（防止重试重复计费——这是按秒计费的核心防线）。
  • 重试：网络类（超时/5xx/连接重置）指数退避 3 次（5s/20s/60s + jitter）；业务类（音频过长、图片无人物、moderation 拒绝、额度不足）不重试，直接换 provider 或标记 FAILED。
  • 并发：火山数字人快速模式并发=1，必须本地串行队列（max_concurrency 配置化）；同步/海外服务按其档位（sync.so 1/3/6/15）。

5.5 成本熔断

  • 提交前 estimate_cost_cny = audio_seconds × unit_price，与 per_video_limit_cny、daily_limit_cny 比较，超限直接拒绝并降级（写审计日志）。
  • 记录实际计费秒数（产出视频秒数），日终对账：实际 vs 估算偏差 >20% 告警（防止报价口径变化）。
  • 默认阈值建议：单条 ≤120 元、每日 ≤200 元（可配置）。

5.6 资产托管（公网 URL 要求）

火山与阿里都要求 image_url/audio_url 公网可访问 → 管线需集成对象存储（阿里 OSS / 火山 TOS / 任意 S3 兼容），策略：

  1. 上传时设对象 TTL（1 天自动删除）；
  2. 只上传「生成所需最小集」（人物图、TTS 音频）；
  3. 任务成功后立即删除（含副本），生成日志中不落音频/图片的公网 URL 明文（防隐私泄露）。

6. 质量验收指标（可自动化检测）

目标：给下游质检模块（quality/checker.py）提供可落地、可自动判定的数字人专项检查。建议实现为 quality/digital_human_checks.py，输入「成片 mp4 + 原始音频 + 人物资产图」。

# 指标 方法 通过阈值（建议） 目的
Q1 音画时长一致性 ffprobe 秒数对比 |video_dur − audio_dur| ≤ 0.25s 抓「视频比音频短/长」的合成故障
Q2 口型-音频相关性 逐帧嘴部开合度（人脸关键点上下唇距离）与音频 RMS 包络的皮尔逊相关 r ≥ 0.5（近景口播）；< 0.2 判不合格 廉价高效的「嘴在动且跟着音频动」代理指标
Q3 面部运动幅度 连续帧关键点位移均值 / 头部 pose 方差 位移均值落在 [0.3, 3.0] px 区间；pose 变化 > 0 且 < 大幅抖动 抓「静止贴图」（当前 demo 的病）与「抽搐抖动」两类废片
Q4 静止帧检测 连续 N 帧（>1s）面部区域像素差 < 阈值 不允许 >1s 完全静止（除刻意停顿） 静态贴图判废

Q6 身份一致性 ArcFace 人脸嵌入与人物资产图的余弦相似度（抽样 5 帧） ≥ 0.6 抓「越生成越不像」
Q7 画面质量 人脸裁剪分辨率 ≥512px；拉普拉斯清晰度方差 ≥ 阈值；黑帧比例 <1% 按分发分辨率设阈值 防止糊片/黑帧

R1 服务不可用/限流 火山并发=1；云服务故障、账号欠费（火山欠费 2 小时停服、24 小时释放资源，[实测条款]） 多 Provider 降级链 + 本地保底 + 余额监控告警
R2 涨价/计费口径变化 按秒计费，官方文档也写「以控制台实际接入为准」[原文] 成本熔断 + 日终对账 + 单价配置化
R3 接口/版本变更 HeyGen v2→v3 已迁移（文档以 v3 为准）；阿里 <20s 限制是一次浏览才发现 Adapter 隔离 + 版本号写进配置 + 契约测试
R4 时长/分辨率上限 阿里单条 <20s（原文）；火山时长上限文档未明示 [待核验] 分段+拼接实现进 Adapter；上线前实测边界
R5 水印 HeyGen 免费档/D-ID Trial/Lite/Synthesia 测试模式/sync.so Hobbyist 有水印 只用付费去水印档；Q8 质检兜底
R6 开源许可 Wav2Lip 开源版禁止商用（原文）；EchoMimic 限学术；Duix 有商用阈值 商用白名单：MuseTalk(MIT)、SadTalker(Apache-2.0)、Duix(带条件)
R7 肖像/形象授权 全 AI 生成虚拟人也要防「撞脸」真实人物；训练分身（Tavus/HeyGen video-avatar）需真人授权书 形象生成侧做相似度筛查（02 文档）；优先 prompt/单图路线
R8 深度合成合规 《互联网信息服务深度合成管理规定》要求对 AI 生成内容标识；抖音平台要求 AI 内容声明 显式标识（角标/文案）+ 隐式标识（元数据）；发布模块统一注入
R9 大陆访问海外服务 网络波动、支付失败、账号风控 海外仅作备选；API Key/账单专人管理
R10 数据隐私 公网 URL 托管音频/图片 对象存储 TTL + 用后即删（见 5.6）
R11 4GB 本地保底产能 MuseTalk 1 分钟≈35 分钟，日更多条时排队 保底档限流（1 条/天）；或后续升级硬件
R12 「AI 虚拟人注册审核」 各平台对 AI 分身训练的人脸审核政策趋严，AI 人脸可能被拒 优先单图驱动；HeyGen 用 prompt avatar 路线并保留生成记录
