## 1. 需求拆解：身份锁定的技术定义

### 1.1 必须锁死（不可随机变）

| 维度 | 具体含义 | 校验方式（建议） |
|---|---|---|
| 脸型与五官 | 颅骨轮廓、眉眼鼻唇比例、双眼间距、脸宽比 | ArcFace embedding 余弦相似度 ≥ 阈值 |
| 发型 | 长度、卷直、发际线形态、分发方向 | 视觉人工抽检 + 可选 CLIP/DINO 特征距离 |
| 肤色与肤色质感 | 色相/明度/饱和度区间、肤质 | 面部区域色度直方图距离 |
| 年龄感 | 「同一人跨年份」漂移不可超一年龄档 | 视觉抽检 |
| 性别呈现 | 不可漂移 | 视觉抽检 / 分类器 |

### 1.2 允许变化

| 维度 | 可变量 |
|---|---|
| 服装 | 演播室正装 / 教师装 / 科技感外套 / 新闻主播装 / 实验室白大褂 |
| 背景 | 演播室 / 教室 / 科技感 / 新闻演播台 / 实验室 |
| 姿态 | 限「口播可用姿态」：正脸或 3/4 侧脸、双肩可见、无遮挡 |
| 光照与色调 | 允许，但不得因此改变肤色认知 |
| 表情 | 允许张嘴（下游唇形驱动需要），但嘴部不得形变 |

### 1.3 「三段解耦」的可落地定义

```
Base Avatar（身份层，只读资产）
  ├─ avatar_hero.png        定妆照（2K，正脸/胸像）
  ├─ avatar_ref_1..4.png    多角度/多光照参考图（用于多图参考输入）
  └─ avatar_face.npy        ArcFace embedding 基线（建议 3~5 张取均值 + 类内方差）
Outfit（服装层，可替换词条/参考图）
  └─ outfits.yaml           { name, prompt_cn, prompt_en, ref_image?(可选) }
Background（背景层，可替换词条/参考图）
  └─ backgrounds.yaml       { name, prompt_cn, prompt_en, ref_image?(可选) }

生成 = f(avatar_ref[], outfit, background, camera, seed)  → 单次云 API 调用
```

**核心原则：身份层只读、永不重绘。** 任何会「重新画脸」的环节（inpaint 面部、face restore、超分重绘）都是身份漂移风险源。

### 1.4 下游唇形驱动的硬约束（写给 03 的接口约定）

- 构图：胸像或半身，**正脸或 ≤15° 偏转**；嘴部区域无遮挡（无手、无麦克风、无围巾遮挡嘴）。
- 分辨率：正脸区域像素高度需足够支撑逐帧嘴部形变；建议人脸在成图中占比不要过小（生成阶段先按 2K 出图，再裁/缩到 1080×1920）。
- 生成的图**不要经过任何「重绘型」放大**（见 §7）。

## 3. 4GB 显存可行性裁决（正面回答）

**结论：本机（RTX 3050 Ti Laptop, 4GB）无法本地生成满足抖音 1080×1920 口播质量的人物一致性图像。本地定位应下调为「编排 + 质检 + 合成」，生成走云 API。**

### 3.2 裁决

- **能跑**：SD1.5 文本出图（质量不达标）、人脸指纹质检、抠图、图层合成、小幅度放大。
- **不能跑**：一切能满足「身份高保真 + 高分辨率」的生成方案（SDXL/Flux/Qwen 全系列）。
- **结论**：本机角色 = **编排调度引擎 + 质检门禁 + 后处理合成**；生成环节外包给云 API。这与用户「愿意为云 API 付费换取质量，本地只做编排调度」的决策一致，**无需更换硬件即可开工**。

## 4. 推荐技术路线

### 4.1 主路线：云 API「参考图驱动」单次生成（推荐）

```
[离线一次性] 铸造 Base Avatar
  1) 用云 API 文生图，反复迭代出「定妆照」（正脸、胸像、干净背景）
  2) 生成 4 张变体参考图：正脸 / 3-4 侧 / 微笑露齿（供唇形驱动）+ 上半身
  3) 本地算 ArcFace embedding 基线（3~5 张取均值 + 记录类内最小余弦）
  4) 资产落盘（avatar_hero.png / avatar_ref_*.png / avatar_face.npz）

[日常] 每条视频按 outfit × background 组合生成
  5) prompt 模板 + 参考图数组 → 云 API 单次调用 → 2K 竖屏图
  6) 本地质检：人脸检测 → 对齐 → embedding → 余弦相似度 ≥ 阈值？
       是 → 通过；否 → 换 seed / 调整提示词重生成（最多 N 次）
  7) （可选）抠图 + 背景合成（若需背景与人物严格分层）
  8) 交付 1080×1920 PNG（直接缩放，不重绘）
```

**推荐模型排序**（按「身份一致性 + 换装换背景能力 + 成本」综合）：

| 顺位 | 模型 | 单张成本 `[实测]` | 选择理由 |
|---|---|---|---|
| 主 1 | **Gemini 3 Pro Image（Nano Banana Pro）** | $0.134（1K–2K） | 当前世代质量档，参考图驱动的身份一致性是强项 |
| 主 2 | **阿里 wan2.7-image-pro** | 0.50 元/张 | 官方明示「多图参考最多 9 张 + 角色一致性多图生成」，国内直连、有中文文档与发票 |
| 备 1 | 阿里 z-image-turbo | 0.1 元/张 | 写实人像定位、成本 1/5，用于草稿与大批量试错 |
| 备 2 | Nano Banana 2 / 2 Lite | $0.067 / $0.0336 | 同族降本 |
| 备 3 | fal.ai Seedream V4 / Flux Kontext Pro | $0.03 / $0.04 | 海外聚合，价格低 |

> 双通道（国内 + 海外）并行的意义：规避单一供应商的模型热更新导致身份漂移、以及可用性/合规风险。

### 4.2 备路线：本地 SD1.5 兜底

仅在云 API 不可用时使用，**用于内部草稿与提示词调试，不用于终稿**。参数建议（沿用现有 demo 基线并加固）：

- 分辨率：512×768，不要尝试超过 640×960。
- `seed`：固定 seed 仅用于「同提示词反复出图比对」，不作为身份锁定手段。
- 若必须本地出终稿：**不要在 512 图上升采样到 1080×1920**（这是当前崩坏的直接原因）。改为：512 出图 → 只保留人脸区域 → 由云 API 以该脸为参考重绘整图。

### 4.3 参数级建议（云 API 侧）

| 参数 | 建议 | 说明 |
|---|---|---|
| 参考图数量 | 2–4 张（正脸必选 + 3/4 侧 + 露齿微笑） | wan2.7-image-pro 上限 9 张；张数过多会稀释指令遵循 |
| 参考图分辨率 | 1024–2048，人脸占比 ≥ 30% | 过低导致身份信息损失 |
| 输出尺寸 | 竖屏：优先 9:16（如 928×1664 / 1024×1536 / 2048×2048 后裁） | Qwen 系支持 928×1664；GPT-Image 推荐 1024×1536 |
| `seed` | **记录但不要依赖**；每张成功图都记录 seed + prompt + 模型版本号 | 用于故障复盘，不用于身份锁定 |
| `n`（候选数） | ≥ 2（同请求多候选，本地挑相似度最高的一张） | 单位成本不变或线性增加，但**一次调用内的一致性更好** |
| 提示词结构 | `[身份锚定句] + [服装] + [背景] + [构图/镜头] + [画质]` | 身份锚定句写死，只替换中段两段 |
| 身份锚定句示例 | 「保持参考图中人物的五官、脸型、发型、肤色、年龄与性别完全一致，不要改变或美化面部」 | 中英各存一份 |
| 构图锚定 | 「正面半身胸像，双眼平视镜头，嘴部无遮挡，肩部完整入画」 | 为下游唇形驱动预留 |

**提示词模板（可直接落地）**

```yaml
identity_lock: >
  严格保持参考图中人物的面部身份：脸型、五官比例、眼型、鼻型、唇形、发型与发色、
  肤色、年龄感、性别呈现完全一致，不得美化、不得换脸、不得改变脸型。
outfit:  "穿着{outfit_name}，{outfit_detail}"
background: "背景为{background_name}，{background_detail}"
composition: >
  竖构图半身胸像，人物居中，正面/微侧脸，双眼平视镜头，嘴部清晰无遮挡，
  肩部完整入画，与背景分离清晰，柔和均匀的正面光
quality: "写实摄影质感，皮肤纹理自然，1080×1920 竖屏构图，高清"
negative: "换脸, 变形, 多手多指, 遮挡嘴部, 侧头过大, 逆光黑脸, 低分辨率, 水印"
```

### 4.4 为什么**不**选「三段分别生成再拼」

| 拼接法 | 问题 |
|---|---|
| 背景 A + 人物 B + 抠图合成 | 三处瑕疵：颈部/发丝合成边缘、光照方向不一致（背景光源与人物受光不匹配）、色温/景深不匹配 |
| 人体 inpaint 换装 | 需要精确保护头部 mask（发际线、耳后、颈部），mask 边缘处理不当会出现「脸贴在别人身体上」的割裂感 |
| 人脸修复保人 | CodeFormer/GFPGAN 会按网络先验「重建」五官，**主动引入身份漂移**，与目标相反 |

云 API 单次生成把「人物 + 服装 + 背景」放在同一次去噪过程中联合求解，光照与色温自洽，这是当前性价比最高的做法。

## 5. 换装 / 换背景解耦实现

### 5.1 三条技术路径对比

| 路径 | 做法 | 身份保持 | 换装自由度 | 工程复杂度 | 推荐度 |
|---|---|---|---|---|---|
| **P1 参考图整体重生成** | 参考图（人物）× 提示词（新服装/新背景）→ 一次出图 | 高（取决于模型） | 高 | 低 | ⭐⭐⭐⭐⭐ 主推 |
| **P2 局部 inpaint** | 原图 + mask（覆盖躯干与背景，头部与手部保护）→ 重绘 | 最高（脸部像素可不变） | 中（姿态被锁死，服装与人体轮廓强耦合） | 中高（mask 需逐张调） | ⭐⭐⭐ 备选 |
| **P3 分层合成** | 人物层（云 API 生成，绿幕或纯色背景）→ 抠图 → 与独立背景合成 | 最高（人物层整层复用） | 高 | 中（需要边缘质量过关） | ⭐⭐⭐⭐ 需要严格分层时用 |

**典型组合**：`P1 出图 → 若需换背景再叠加 P3 抠图合成`。

### 5.2 P3 的抠图与边缘质量对比（发丝边缘是决胜点）

| 手段 | 发丝边缘表现 | 速度 | 显存 | License | 结论 |
|---|---|---|---|---|---|
| **绿幕 / 色度键（chroma key）** | 对纯色幕布快且干净，但**对 AI 生成图不可靠**：生成的「绿幕」很难保证均匀无色溢，且发丝半透明像素与幕布色混合时易出现绿边 | 极快（ffmpeg 内置） | 0 | 取决于工具 | ❌ 不作为主手段 |
| **rembg + 老模型（u2net/u2netp/silueta）** | README 原文：这些模型「tend to produce firmer, blockier edges」，发丝场景需加 `-a` alpha matting（慢） | 中 | 低 | MIT（模型许可另计） | ⚠️ 可用但要加 matting |
| **rembg + 新模型（birefnet-* / bria-rmbg / isnet-general-use）** | README 原文：新模型「already [handle] the *soft* pixels along an edge — hair, fur, fabric, motion blur」 | 中 | 低 | MIT（封装） | ✅ 推荐入口 |
| **BiRefNet（native，含 matting 专用权重）** | 官方提供 `BiRefNet-matting` / `BiRefNet_HR-matting`（2048 训练）与 portrait matting 权重；README 报 1024×1024 下 17 FPS / 3.45GB | 快 | 3.45GB@1024 | **MIT** | ✅✅ 首选 |
| **RMBG-2.0（BRIA）** | 人气最高（HF 621,979 downloads），但为 `license: other` 且 gated | 快 | 中 | ⚠️ 需读全文 | ⚠️ 商用前复核 |
| **BackgroundMattingV2** | 需要额外拍一张「无人物背景板」，AI 生成场景不适用 | —— | 中 | MIT | ❌ 不适用本场景 |
| **vitmatte（rembg `-x` 内置）** | rembg README 明示可配 `base-distinctions-646` 做 trimap-free matting | 中 | 低 | —— | ⚠️ 备选 |

**工程建议**：抠图统一走 `rembg -m birefnet-portrait`（或直接 BiRefNet）→ 输出 RGBA → 用 `-a`（alpha matting）仅在发丝问题明显时开启。AI 生成的人物图建议**主动要求纯色/极简背景**，可显著降低抠图难度。

### 5.3 背景生成

- 背景与人物**同一次生成**（P1 路径）：性价比最高。
- 需要长期复用的固定背景（如固定演播厅）：先生成一张 2K 背景底图 → 归档 → 后续用 P3 合成，保证背景 100% 稳定。
- 背景无需人物一致性校验，可放心用最便宜的通道（z-image-turbo 0.1 元/张）。

## 6. 身份一致性校验工程手段

### 6.1 seed 固定够不够？—— 不够，原因有三

1. **语义冲突**：seed 的可复现性建立在「同模型 + 同版本 + 同 prompt + 同参数」之上。而本项目的核心动作恰恰是**改 prompt（换装换背景）**，此时 seed 已经失去锁定意义。
2. **服务端不可控**：云 API 的模型会热更新（阿里文档中同一模型 ID 存在多个日期快照，如 `qwen-image-2.0-pro-2026-03-03` / `-2026-04-22` / `-2026-06-22` 即可见其版本演进模式）`[实测]`；本地模型换量化/换依赖同样漂移。
3. **它管的是「随机噪声」而不是「身份」**：seed 固定能让同一 prompt 输出稳定，但不能阻止模型在不同 prompt 下把鼻子换个形状。

**正确姿势**：seed 只是**故障复盘用的日志字段**；身份锁定靠「参考图条件 + 指纹门禁」。

### 6.2 人脸指纹（FaceID embedding）校验链路

```
候选图 → 人脸检测（RetinaFace/SCRFD）
      → 关键点对齐（5 点仿射，统一到 112×112）
      → ArcFace 提 512-d embedding
      → L2 归一化后与 Avatar 基线做余弦相似度
      → 阈值判定 → 通过 / 拒收重生成
```

**基线建立**：对 Base Avatar 的 3–5 张参考图各提 embedding，计算两两余弦，取
- 中心向量 `c = mean(e_i)`（归一化）
- 类内最小相似度 `s_min`（作为「同一人」的经验下界）
- 类内平均相似度 `s_avg`

**阈值设计（工程建议，需用自有数据校准，标 `[待核验]`）**

| 相似度（余弦） | 判定 | 动作 |
|---|---|---|
| ≥ 0.60 | 强一致 | 直接放行（推荐作为上线初始硬阈值） |
| 0.50 – 0.60 | 一致 | 放行但记录；连续出现则收紧 |
| 0.40 – 0.50 | 灰区 | 人工抽检；批量场景自动重生成（换 seed） |
| < 0.40 | 判定为不同人 | 拒收 + 重生成；同一素材连续 3 次拒收则报警（提示词/参考图有问题） |

> 阈值不是通用常数，取决于人脸模型版本（buffalo_l / antelopev2 / 其他）、图像分辨率、姿态与遮挡。**上线前必须用你自己的 Avatar 图跑一遍类内/类间分布**，取类内 P1 与类间 P99 之间的分位点作阈值。
> 另注：**阈值校准用的 ArcFace 模型（InsightFace）为非商用许可** —— 用于内部质检不对外分发权重通常可控，但若未来把质检能力做成对外产品 / 用于训练可商用模型，必须替换为许可干净的模型（如自训或 Apache-2.0 的替代方案）。`[待核验：法务意见]`

### 6.3 多层门禁（推荐流水线）

| 层级 | 检查项 | 实现 | 失败动作 |
|---|---|---|---|
| L0 | 人脸可检出、正脸度、人脸像素高度 | 人脸检测器 | 直接丢弃（构图不合格，不必算指纹） |
| L1 | 身份 embedding 相似度 | ArcFace | 重生成（换 seed / 微调提示词） |
| L2 | 发型/肤色粗校验 | 面部区域色直方图 + 人工抽检 | 人工复核 |
| L3 | 嘴部可用性（下游唇形驱动前置） | 嘴部关键点可见性 + 是否遮挡 | 重生成 |
| L4 | 内容合规 | 云服务内容审核（阿里文档明示 prompt 会过审、违规返回 `DataInspectionFailed`）+ 抖音 AI 生成标识 | 丢弃 / 补标识 |

### 6.4 「换装换背景不改人」的可落地工程手段（按优先级）

1. **参考图条件 + 全身重生成**（P1）：成本最低、效果最好；配合 L1 门禁兜底。
2. **面部区域保留式 inpaint**（P2）：若必须复用某张已通过门禁的图，用 mask 只重绘「躯干 + 背景」，mask 以羽化边缘覆盖颈线以下，头部与发际线以上完全保护。**这是像素级零漂移方案**，代价是姿态被锁死。
3. **分层合成**（P3）：人物层不变 + 背景层更换，用 BiRefNet 抠图 → 合成；对「同一张人物图换 N 个背景」的批量场景效率最高。
4. **禁止**：对未来要用的图做人脸修复（CodeFormer/GFPGAN）、禁用带人脸先验的放大链路。

## 7. 输出规格与放大链路

### 7.1 目标与来源规格

| 环节 | 建议规格 | 理由 |
|---|---|---|
| 终稿目标 | 1080×1920（9:16） | 抖音竖屏 |
| 生成阶段 | **直接生成 2K 级竖屏**（如 1024×1536 或 1536×2048，或 2048×2048 后裁 9:16），wan2.7-image-pro 可到 4096×4096 | 云 API 已原生支持，不需要「先小后放大」 |
| 构图 | **半身胸像（胸线以上）为主，正脸或 ≤15° 微侧** | 下游唇形驱动需要清晰稳定的嘴部几何；半身也为换装留出领口/肩部信息 |
| 人脸占比 | 人脸高度建议占画幅高度 1/4 以上（`[待核验]`，需按 03 的嘴部驱动要求定稿） | 人脸过小则驱动后嘴部形变细节不足 |
| 背景 | 优先纯色/极简或强分离背景 | 便于抠图与分层合成 |
| 安全带 | 面部上方、下颚下方各留出余量，避免裁切到发顶/下巴 | 后续裁切与嘴部对齐容错 |

### 7.2 放大链路对比

| 手段 | 是否改变人脸 | 质量 | 速度 | 适用 |
|---|---|---|---|---|
| **Lanczos / 双三次插值** | ❌ 不改（纯插值） | 锐度低、细节不加，但**绝对安全** | 毫秒 | ✅ 小倍率（1.5× 以内）缩放首选 |
| **Real-ESRGAN（BSD-3）** | ⚠️ 会「重绘」纹理，人脸细节可能被改写 | 高（有幻觉细节） | 十秒级 | ⚠️ 仅用于背景/无人物区域；README 自带 `--face_enhance` 会接 GFPGAN = 换脸风险 |
| **ncnn-vulkan 版 Real-ESRGAN** | 同上，且 README 原文提示分块处理会引入**块间不一致** | 中高 | 快（CPU/iGPU 可跑） | ⚠️ 同上 |
| **云超分（云厂商的超分/画质增强）** | ⚠️ 需确认是否带人脸先验 | 高 | 秒级 | ⚠️ 落地前需做「放大前后 embedding 相似度」回归测试 |
| **不放大，直接生成高分** | ❌ 不改 | 最高 | 与生成同 | ✅✅ **首选** |

**结论**：把分辨率需求前置到生成阶段；放大只做 Lanczos 小倍率缩放。若确需超分，必须做「超分前后人脸 embedding 相似度」回归测试，相似度下降超阈值即禁用该链路。
