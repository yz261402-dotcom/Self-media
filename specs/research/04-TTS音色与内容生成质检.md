# 04 TTS音色与内容生成质检调研

> 调研范围：**TTS 固定音色方案** + **口播稿生成** + **内容质检体系** 三件事。
> 明确不覆盖：数字人视频/唇形模型（见 03）、图像生成（见 02）、发布（见 05）。
> 调研日期：**2026-09-21**。文中价格、星数、许可证均为当日采集，标注 `[实测]`（本次会话用工具实际抓取到原文）或 `[待核验]`（未抓到一手页面/口径不清）。
>
> 工具与来源说明（如实披露）：本次会话环境中没有 WebSearch/WebFetch 工具，实际使用的替代路径为
> ① `gh api`（已认证 GitHub CLI）抓仓库元数据与 release/tag；
> ② `curl https://r.jina.ai/<URL>` 抓取官方文档正文（Jina Reader）；
> ③ `curl` 直连官方 `llms.txt` / `*.md` 文档端点；
> ④ Bing HTML 搜索脚本（仅用于兜底定位 URL，结果质量差，未作为结论来源）。
> 凡未拿到一手页面的条目一律写「未核验」，不做推测填充。

## 0. 结论速览

| 编号 | 决策点 | 推荐 | 理由（一句话） | 置信度 |
|:--|:--|:--|:--|:--|
| T1 | 固定音色的主路线 | **阿里云百炼 CosyVoice v3.5 系列（`cosyvoice-v3.5-plus` 主 / `cosyvoice-v3.5-flash` 备）** | 大陆直连、10~20 秒样本零样本复刻、`seed` 可复现 + `instruction` 指令控制 + 字级时间戳 + AIGC 隐性标识，能力组合最全且单价 0.8~1.5 元/万字符 | 高 |
| T2 | 音色资产来源（合规） | **优先「声音设计」生成全新音色（`qwen-voice-design` 0.2 元/音色），而非克隆真人** | 全 AI 虚拟主播本来就要求「非真人声纹」，从源头规避声音权/人格权授权链；克隆真人需 consent + 授权书，且人设绑定真人不可迁移 | 高 |
| T3 | 音色一致性的工程保障 | **固定参考音频 + 固定 seed + 段落级一致性抽检（声纹相似度）+ 落盘音色资产 ID 版本管理** | 一致性不是「选对服务商」就自动成立，零样本克隆每次调用都有随机性，必须工程兜底（§2.3 给方案） | 高 |
| T4 | 第二大备选（跨供应商） | **火山引擎豆包语音「声音复刻 2.0」** | 后付费音色一经合成即固定不可再训练（对固定音色是优点）、价格 2.8 元/万字符起、国内节点稳定 | 中 |
| T5 | 付费出海路线（若做海外分发/更高表现力） | **ElevenLabs `eleven_v3` + IVC（1~2 分钟样本）** | v3 支持 `[excited]` 类 audio tags 的情绪控制，是**唯一被官方文档明确写出**的「标签式情绪语法」；缺点是 $0.10/1k 字符、大陆访问需代理 | 中 |
| T6 | 本地推理（4GB 显存） | **不作为主力；仅保留降级链末端** | 4GB 只能跑极小模型（`k2-fsa/OmniVoice` README 自述在 4 GB Intel Arc A310 上测过 [实测]），其余主流克隆模型显存需求未核验但普遍高于 4GB | 中 |
| T7 | 文本 → 表达标记的实现 | **自定义轻量标记集（`[停:ms]`/`[重]`/`[语速±n%]`/`[情绪:x]`）+ LLM 标注 + 编译器翻译到各家语法** | 不要直接把 SSML 交给 LLM 写（各家语法不通用）；自定义标记 + 确定性编译器，才能做到「换供应商不改稿」 | 高 |
| T8 | 质检体系改革方向 | **把「测不准的维度」移出评分体系**，改为「证据要求 + 引用核验」 | `factuality`/`timeliness` 在无联网检索时测的是措辞而非事实，属于伪指标；给伪指标加权 = 用错的目标函数优化（§6.1 逐项拆解） | 高 |
| T9 | 查重升级 | **字符 3-gram → 语义 embedding 相似度（首选 BGE-M3 自托管，备选百炼 qwen embedding / text-embedding-3）** | 现有 char 3-gram 余弦 + SimHash 取 max，量纲不同、阈值语义混乱，且对同义改写几乎无感 | 高 |
| T10 | 事实核查 | **分层：L1 规则（保留）→ L2 断言抽取 + RAG/联网检索命中核验 → L3 引用可访问性** | 无检索时「事实性」不可测；有检索时它是**唯一**能真测内容正确性的维度，值得单独立项 | 中（L2 依赖检索链路，本 spec 只给接口） |
| T11 | 离线模板生成器的定位 | **只做「管道可用性兜底」，不进生产内容池**；生产必须有 LLM 生成 + 句式骨架化 | 8×6×8×6×6 枚举 ≠ 表达多样性：槽位内句子是**固定字符串**，日更 1 条约 8 天开头重复、选题池（`config/topics.yaml` 60 行 ≈ 10 条 [实测]）先耗尽 | 高 |
| T12 | 质检分数的可信度 | **必须做人工相关性验证（Spearman ρ），不达标就重标定权重** | 14 项加权分现在没有任何「与人会不会划走」的相关性证据；且同一套分做目标函数会诱发 Goodhart 效应 | 高 |
| T13 | 重写闭环 | **策略化分级重写（L1 局部 / L2 换骨架 / L3 换选题 / L4 换类目）+ 强制换策 + 选题熔断 + 保留历史最优版本** | 现在的「3 次重试 + 拼接 issues 文本」会陷入同策略循环，且无法防止越改越差 | 中 |
| T14 | 优先级建议 | **P0 = T2+T3+T7（音色资产一次定音）；P1 = T9+T12；P2 = T10+T13** | 音色是「换不掉」的资产（合同/素材/观众记忆都挂着它），必须先定；质检升级可以灰度上 | 高 |

## 2. 推荐音色方案（主 + 备 + 降级链）

### 2.1 主方案：阿里云百炼 CosyVoice v3.5 + Qwen-TTS 音色资产

**拓扑**：
```
音色资产一次性建立（离线动作，人工参与）
  ├─ 路线 1（推荐）：qwen-voice-design（0.2 元/音色）
  │    用文字描述生成「AI 虚拟主播」音色 → 得到 voice_id → 入库
  │    （如「30 岁女性，亲切、语速偏快、略微沙哑、播音腔不重」）
  └─ 路线 2（备选）：若已有满意的试听音色 → cosyvoice 声音复刻（10~20 秒样本）
       → 得 voice_id
  ↓ 写入 config：tts.provider = bailian_cosyvoice, tts.voice = <voice_id>, tts.seed = <固定值>
每条视频：口播稿（带表达标记） → instruction / speech_rate / hot_fix → 音频 + 字级时间戳
```

**为什么是它**（全部基于实测页面）：
1. **样本成本最低**：10~20 秒，无需训练（相对 ElevenLabs PVC 要 30~180 分钟、微调 3~6 小时）[实测]。
2. **可控参数最全**：`seed`（可复现）、`instruction`（情感/方言/角色）、`speech_rate`/`pitch_rate`/`volume`、`hot_fix`（**拼音注音**，专治 AI 术语读错，如「RAG 检索增强」）、`word_timestamp_enabled`（**字级时间戳**，对字幕/口型对齐直接有用 —— 03 号 spec 会用）。
3. **合规内置**：`enable_aigc_tag`（AIGC 隐性标识写入音频文件）[实测] —— 与 §4 的标识义务直接对应。
4. **价格可忽略**：0.8~1.5 元/万字符（**汉字算 2 字符** → 实际 1.6~3 元/万汉字）→ 单条 450 字视频约 **0.07~0.14 元**。
5. **换供应商不换稿**：把上面的自定义标记编译到各服务语法（§3），未来切火山/ElevenLabs 只改编译器。

**风险**：`cosyvoice-v3-flash` 在新加坡地域不支持复刻音色（需用 `qwen-audio-3.0-tts-flash`）[实测] —— 若未来做海外分发要注意地域/模型组合限制。

### 2.2 备选与降级链

| 层级 | 方案 | 触发条件 | 预期损失 |
|:--|:--|:--|:--|
| **主** | 百炼 `cosyvoice-v3.5-plus` + VoiceDesign 音色 | 默认 | — |
| **备 A** | 百炼 `cosyvoice-v3.5-flash`（同音色家族，快、更便宜） | 主模型限流/成本敏感 | 表现力略降，音色仍在同一家族 |
| **备 B** | 百炼 `qwen-audio-3.0-tts-flash` + 同一 voice_id（跨模型复刻音色复用，火山文档亦称音色槽位可跨模型复用 [实测]） | 主系列故障 | 音色相似度需重新抽检 |
| **备 C** | 火山引擎 豆包声音复刻模型 2.0（独立云厂商，规避单点） | 阿里侧整体不可用 | 音色须重建（**音色 ID 不可跨厂商迁移**），需走一次「音色重建 + 抽检」流程 |
| **备 D** | ElevenLabs IVC + `eleven_v3` | 需要更强情绪标签表现力 / 出海 | 成本 ×5~10，且需代理 |

| **备 F（离线）** | `mock` 共振峰合成 | 完全离线跑通管道 | 不可发布 |

> **对现状的直接批评**：demo 的 `tts.provider: auto` 逻辑是「edge-tts 可用就用 edge-tts」[实测源码 `build_provider`]，且默认音色是通用音色。这意味着**当前 demo 产出的每一条视频里的声音，与任意一个 edge-tts 用户完全相同** —— 这不只是「缺口」，而是「主播人格资产为零」。落地上应把 `auto` 的优先级**反转**：云端 provider 优先，edge-tts 只在显式 `--debug` 时启用。

### 2.3 音色一致性保障工程（跨几十条视频不漂）

零样本克隆的本质是「每次调用都重新编码参考音频 + 采样」，因此**漂移是默认行为，稳定需要工程手段**。建议落成 `tts/voice_lock.py`：

| 手段 | 具体做法 | 为什么有效 | 可验证性 |
|:--|:--|:--|:--|
| 1. 参考音频冻结 | 参考音频（或 VoiceDesign 生成的参考片段）**写入 `voice_assets/` 并记录 SHA256**；任何重训/重建必须升级版本号 | 消除「同一 voice_id 后端被重新计算」的风险 | 哈希可对比 |
| 2. 音色资产 ID 版本化 | `voice_assets/<name>/v1/{ref.wav, meta.json}`，`meta.json` 存 `provider/model/voice_id/seed/创建时间/参考音频 hash` | 出问题时可定位「是哪一版音色漂了」 | 文件级 |
| 3. 固定 seed | 阿里 SDK 支持 `seed`（0–65535，**同参数同 seed 可复现相同结果** [实测原文]）；写入 config 并锁定 | 消除采样随机性 | 复现测试：同输入跑 3 次，比对音频指纹 |
| 4. 生成参数冻结 | `speech_rate`/`pitch_rate`/`volume`/`instruction` 模板化，禁止逐条手改 | 参数变动本身就是「漂移」的主要来源 | 配置 diff |
| 5. 一致性抽检（音频指纹） | 每条视频合成后，抽首句生成 embedding（用 `FunASR`/`SenseVoice` 的 speaker embedding，或 sherpa-onnx 声纹模型），与基准音色的**余弦相似度**入库；低于阈值（建议先按经验 0.75 起，用 30 条样本标定）告警 | 直接量「像不像同一个主播」 | 阈值可用历史分布标定 |
| 6. 参考特征复用 | 若切开源：`Qwen3-TTS` 用 `create_voice_clone_prompt` 一次、后续传 `voice_clone_prompt`；`OmniVoice` 用 `VoiceClonePrompt.load("my_voice.pt")` [实测] | 避免每次重新提取，降低逐次波动 | 代码路径 |
| 7. 长文分段策略 | 长口播按句/段分段合成时，**所有分段共用同一 voice_id + 同一 seed 策略**，段间在静音处拼接并做响度归一（EBU R128） | 分段最容易出现「段与段音色/响度跳变」 | 段间响度差可测 |
| 8. 回归测试 | 固定一句「基准句」（如「你可能不知道，现在一个人可以完成一个团队的工作」），每次切换模型/参数后合成一次，与基准音频比对 | 把漂移检测前置到 CI | 可自动化 |

**验收标准（建议写进 spec）**：连续 30 条视频的说话人相似度分布，**均值 ≥ 阈值、标准差 ≤ 阈值、无单点低于下限**；人工盲听 10 条随机样本，需能识别为「同一个人」（通过率 ≥ 9/10）。

## 3. 文本 → 表达标记的设计

### 3.1 问题定义

需求原文的例子：

> 「你可能不知道——现在，一个人真的可以完成以前一个团队才能完成的工作」

要的是：**破折号处一个明显停顿**、**「现在」轻提**、**「以前一个团队才能完成」加重**，而不是逐字机械念。

### 3.2 设计原则（三条）

1. **不写 SSML**：SSML 是各家方言（ElevenLabs v3 明确不支持 SSML `<break>` [实测]），让 LLM 直接产出 SSML 会绑定供应商、且极易语法错误。
2. **标记与文字分离**：LLM 只做**插入标记**，不改写文字。这样可做**确定性校验**：剥离所有标记后必须与原文逐字一致，不一致直接判标注失败（可自动重试）。
3. **标记集最小化**：只保留「停顿 / 重音 / 语速 / 音量 / 情绪 / 读法」六类，其余交给 TTS 服务自身。

### 3.3 自定义标记语法 v1（建议）

| 标记 | 语义 | 例 |
|:--|:--|:--|
| `[停:N]` | 停顿 N 毫秒（建议 120/250/450/700 四档，禁止超过 1000） | `你可能不知道[停:250]现在` |
| `[重]…[/重]` | 重音（短语级，跨度 ≤ 12 字） | `[重]以前一个团队才能完成[/重]的工作` |
| `[轻]…[/轻]` | 弱化/虚化（用于插入语、口头禅） | `[轻]说白了[/轻]` |
| `[速:N%]…[/速]` | 局部语速变化（-20% ~ +20%，超过 ±20% 音质明显劣化） | `[速:+10%]你猜怎么着[/速]` |
| `[量:N%]…[/量]` | 局部音量（-30% ~ +30%） | `[量:-15%]…[/量]` |
| `[情:xxx]` | **段落级**情绪标记（不是行内），如 `[情:好奇] [情:严肃] [情:兴奋] [情:温和]` | 段首一行 |
| `{拼音}` | 读法纠正（AI 术语、多音字） | `{H T T P}`、`{检索增强}`、`{kǎ nèi jī}` |
| `——` / `…` / `，` | **标点驱动的隐式韵律**（零成本、全供应商通用） | 破折号=迟疑停顿；省略号=拖音；逗号=短停 |

**密度约束（硬性）**：每 100 字 ≤ 6 个标记；连续两个 `[停]` 之间至少 8 个字；同一句内不超过 2 个重音。理由：ElevenLabs 官方文档明确警告**过多 break 类标记会导致不稳定（加速、噪声、artifact）** [实测原文]，这是跨供应商的通用规律。

### 3.4 LLM 标注 prompt 设计（可直接用）

```
系统：你是语音导演，只做「朗读标注」，不改写一个字。
你在口播稿中插入朗读标记，让我按标记合成语音。

可用标记（只用这些，不要发明）：
[停:N]  停顿 N 毫秒，N ∈ {120,250,450,700}
[重]…[/重] 重音短语（≤12字）
[轻]…[/轻] 弱化短语
[速:±N%]…[/速] 语速微调，N ≤ 20
[情:好奇|严肃|兴奋|温和] 段落级情绪，只能出现在段首
{拼音} 读法纠正（仅 AI 术语、缩写、多音字）

硬性约束：
1. 除标记外，输出必须与输入逐字一致（我会做 diff 校验，不一致即失败）。
2. 每 100 字最多 6 个标记。
3. 破折号、省略号、逗号本身已表达韵律，不要在其旁边重复加 [停]。
4. 只给「有表达价值」的地方标注：
   - 钩子句的转折处、反转处
   - 术语第一次出现处（配 {拼音}）
   - 结论句（配 [重]）
   - 段间切换处（配 [停:450] 或 [情:]）
5. 不要给每个句子都加标记，宁少勿多。
6. 输出格式：{"marked": "<带标记全文>", "notes": ["..."], "segments":[{"role":"hook|explain|example|question|closing","text":"..."}]}

用户输入：<口播稿原文>
```

**示例输出**（对应需求原文）：
```
你可能不知道[停:250][速:-10%]现在[/速]，[重]一个人真的可以完成[/重][停:120][重]以前一个团队才能完成[/重]的工作。
```

### 3.5 各服务承载能力对照（编译目标）

| 能力 | 阿里 CosyVoice v3.5 / Qwen-Audio-TTS | 火山 豆包语音 | ElevenLabs v3 | Fish S2 Pro | OpenAI TTS | 自定义标记编译器怎么做 |

| 读法纠正 | ✅ **`hot_fix`**：`pronunciation`（拼音）+ `replace`（文本替换）[实测] | 未核验 | 无（靠 LLM 预规范化 [官方建议]） | 未核验 | 无 | 有 `hot_fix` 就用；没有则做「合成前文本替换 → 合成后字幕回填原文」（**注意：字幕必须用原文，不能用替换后的文本**） |
| 可复现 | ✅ `seed` [实测] | 未核验 | ❌ | 未核验 | ❌ | seed 写入 config 并锁定 |
| 字级时间戳 | ✅ `word_timestamp_enabled`（部分模型/音色）[实测] | 未核验 | ❌（依赖强制对齐） | 未核验 | ❌ | 无原生时用 forced alignment 兜底（见 05/后处理） |

> **实施建议**：把「标注」与「编译」做成两个独立模块 —— `annotate.py`（LLM，产出带标记文本，**供应商无关**）+ `compile.py`（确定性代码，把标记翻译成目标服务参数/文本）。这样换供应商时只改 `compile.py`，历史稿件不必重标。

## 4. 音色资产合规与声音权风险

### 4.1 风险矩阵

| 路线 | 主要法律/平台风险 | 风险等级 | 说明 |
|:--|:--|:--|:--|
| **A. AI 生成全新音色**（VoiceDesign / 声音设计） | ① 需按规定对 AI 生成内容做标识；② 若音色「过于接近某知名主播」，可能落入不正当竞争/混淆 | **低** | 当前最优路线。阿里 `qwen-voice-design`（0.2 元/音色）、Fish `voice-design-1`（$0.01/次）、Qwen3-TTS `VoiceDesign` 均为此类 |
| **B. 克隆真人（本人）** | 需本人授权链（用于商业传播的书面授权）；若该真人日后离职/合作终止，音色资产存在权属争议与迁移问题 | **中** | 适用于「本人就是主播」；合同必须写明「音色模型使用范围与期限」 |
| **C. 克隆真人（非本人 / 网络音频）** | 声音权/人格权（《民法典》对自然人声音的保护参照肖像权规定）、著作权、个人信息（声纹属敏感个人信息）三重风险 | **极高** | **不建议**，收益（好听）远不抵风险（下架/索赔/账号风险） |
| **D. 直接使用厂商预置音色**（如 edge-tts 的公开音色） | 平台/厂商条款可能限制商业使用场景；**且无独占性**——撞声必然 | **中** | edge-tts 属非官方接口，无 SLA，不适合长期商用 |

### 4.2 厂商侧的合规机制（实测到的硬证据）

- **OpenAI**：Custom voices 必须提交 **consent 录音**（必须逐字朗读指定同意话术，且与样本为同一人），样本 ≤30 秒，每组织最多 20 个音色；且使用政策要求**向终端用户明示该声音是 AI 生成** [实测]。→ 说明业界对「克隆」采取的正是「实名同意 + 明示」双保险。
- **ElevenLabs**：提供 IVC / PVC 两级克隆（文档中有独立章节）[实测-导航结构]；官方明确 **「克隆一旦创建无法更改口音/语气」**，且「同一份音频重建，每个克隆也会略有不同」[实测原文]。其「他人声音」的具体验证流程条款本次**未逐条核验**。
- **火山引擎**：存在《火山引擎声音复刻协议》独立协议页与「声音复刻下单及使用指南」[实测-页面存在]；预付费音色可训练 15 次、后付费音色合成后固定不可再训练 [实测]。
- **阿里云百炼**：提供 `enable_aigc_tag`（把 AIGC 隐性标识嵌入 wav/mp3/opus，可设置 `aigc_propagator`/`aigc_propagate_id`）[实测] —— 这是**服务商层面已内建**的标识能力，建议直接启用。

### 4.3 推荐与落地检查清单

**推荐：路线 A（AI 生成音色）作为主路线**，理由：
1. 项目定位就是「全 AI 生成虚拟人」，从源头就不需要真人声纹授权；
2. 音色资产完全归属自己（生成即拥有），不存在「人走了音色没了」的迁移风险；
3. 成本极低（0.2 元/音色或 $0.01/次）；
4. 与「数字人形象也是 AI 生成」在叙事上一致，便于对外统一声明。

**上线前检查清单**：
- [ ] 音色生成后做**相似度排查**：与 3~5 位头部同行/知名主播音色做主观与客观比对，避免「像某人」。
- [ ] 开启服务商 AIGC 标识参数（阿里 `enable_aigc_tag`）。
- [ ] 视频/简介中按要求进行 **AI 生成内容标注**（抖音侧与法规侧的具体要求 **[待核验]**：本次未联网核验最新版《人工智能生成合成内容标识办法》/《互联网信息服务深度合成管理规定》与抖音当前产品要求，落地前请以官方原文核对）。
- [ ] 建立 `voice_assets/<name>/LICENSE_NOTE.md`：记录音色来源（VoiceDesign 描述文本 / 复刻样本来源）、生成日期、服务商条款快照。
- [ ] 若为任何真人克隆：留存书面授权（授权范围含「合成语音」「商业传播」「期限」「可否转授权」）。
- [ ] 保留服务商返回的 `voice_id` 与生成记录，作为「自有资产」的证据链。

## 5. 口播稿生成：去 AI 腔工程手段

### 5.1 先给现有实现的定量诊断

| 现象 | 实测证据 | 后果 |
|:--|:--|:--|
| 组合式模板的**真实多样性远低于组合数** | `LOCAL_TEMPLATES`：hook 8 条、pain 6 条、point 8 条、case 6 条、ending 6 条 [实测源码]；`_fit_length` 另有 8 条固定 filler [实测] | 8×6×8×6×6 = 13,824 种组合，但**每个槽位的句子是固定字符串**。日更 1 条时，**第 9 天开头必然完全重复**（hook 池只有 8 条）；第 7 天结尾重复 |
| 模板不含任何事实 | point/case 全是方法论口号（「先问目标，再选工具」「把任务拆清楚」）[实测] | 内容**无信息增量**，靠模板无法产出「AI 科普」应有的知识价值 |
| 选题池会先耗尽 | `config/topics.yaml` 仅 60 行 ≈ 10 条选题 [实测] | `avoid_recent_topics: 30` 大于池子规模 → `TopicPool.next()` 会走到「全部近期用过」分支 **必然重复选题**（实测源码逻辑：循环一圈后仍返回游标处选题） |
| 查重对模板复用**免疫** | SimHash 汉明相似度 与 字符 3-gram 余弦 **取 max**，阈值 0.72 [实测源码] | 模板句在整篇中占比不足以推高到 0.72，**模板复用不会被判重复** |

**结论**：模板兜底可以保「管道能跑通」，不能保「能长期发」。生产内容必须走 LLM 生成路径，模板仅作为断网兜底并**在产物上打标**（便于事后过滤）。

### 5.2 去 AI 腔的六条工程手段

**① 词表机制（双向）**
- 黑名单（现有 `_WRITTEN_STYLE` 12 词 [实测] 需扩容）：书面连接词（综上所述/由此可见/值得注意的是/与此同时/换言之/众所周知/不可否认）、AI 高频动词（赋能/助力/打造/构建/实现/提升）、空洞形容（极大地/显著地/前所未有地）、绝对化（绝对/永远/100%/万能/彻底解决 [已有 `_ABSOLUTE`]）。
- 黑名单（口播禁忌）：Markdown 符号、括号注释、书名号解释、「大家好」「我是XX」「今天的视频」开头语、自我介绍超过 1 句。
- 白名单（口语连接词，**要求每条至少出现 3 个不同项**）：「你猜怎么着 / 说白了 / 我直接给你 / 注意了 / 说人话就是 / 讲白了 / 记住这一点 / 我给你举个例子 / 别急着 / 说回正题」。
- 落地：词表外置 `config/banned_words.txt`（已有机制 [实测]）+ `config/spoken_style.yaml`（新增白名单与配额）。

**② 句长节奏（可量化）**
- 目标：平均句长 **14~22 字**；**标准差 ≥ 6**（长短交替才有节奏）；单句 ≤ 45 字；**每 3 句内至少 1 句 ≤ 12 字**。
- 纯计算，无需模型：`len(sentence)` 序列的 `mean/std/max/p10`，直接进质量报告（现有 `readability` 只测均值与最长句 [实测]，缺标准差与「短句密度」）。

**③ 句式骨架化（替代成句模板）**
- 把固定句改成**骨架 + 槽位**，例如：
  - 不是「你有没有发现，{topic}这件事，很多人其实都理解错了。」（固定句，会重复）
  - 而是「[提问式钩子] + [反常识断言] + [利益承诺]」的**结构约束**，由 LLM 现场生成句子，并把「最近 20 条用过的钩子句」作为负例注入 prompt（现有 `avoid_hint` 只传最近 30 个标题 [实测]，需扩展为「钩子句 + 结尾句 + 案例句」黑名单）。

**④ 反模板化的生成期约束（prompt 层）**
- 「禁止使用以下已用过的开头句式：…（注入最近 20 条的首句）」
- 「全文不得出现以下词：…（注入黑名单）」
- 「必须包含：1 个具体事实（带来源）/ 1 个具体到可复现的场景例子 / 1 个反直觉结论」——三者至少齐全 2 项。

**⑤ 内容配方（解决「无信息增量」）**
建议强制结构：`钩子（3 秒）→ 误区/痛点 → 2~3 个知识增量点（每点含：原理 + 一个可执行动作）→ 一个具体案例 → 收尾互动`。
「可执行动作」这一项现在完全没有（现有结构含 案例 但无动作 [实测 prompt]），而它恰恰是收藏/完播的关键。

**⑥ 生成后过滤（把 AI 腔检测变成硬门槛）**
- 新增 3 个可计算指标并入 quality：`书面词密度`（每百字命中数）、`口语连接词覆盖数`、`句长标准差`。
- 用 **LLM-as-judge** 做一次「像不像真人在说」的 1~5 分盲评（把稿子与 5 条真人爆款口播稿混在一起打分，去掉身份信息），低于阈值直接打回重写。注意：judge 只作为**重写触发器**，不作为最终评分（避免 §6.4 的 Goodhart 问题）。

### 5.3 选题机制（AI 领域选题库 / 热点 / 系列化 / 防耗尽）

| 层次 | 做法 | 落地要点 |
|:--|:--|:--|
| **L1 稳定选题库** | 从 60 行 10 条扩到 **≥200 条**，按类目组织（基础认知 / 原理 / 工具实操 / 行业事件 / 风险与伦理 / 职业影响 / 应用场景），每条含 `id/title/category/angle/keywords/difficulty` | 目标：**按日更 1 条可支撑 6 个月以上不重复**（200 条 × 复用间隔 ≥ 60 天） |
| **L2 系列化** | 每个类目做成 5~10 集系列（如「RAG 五讲」），用系列编号做追更钩子 | 系列化能显著提高关注转化，且便于批量生产与复用素材 |
| **L3 热点追踪** | 每周一次自动化：抓 arXiv 最新论文标题（`research/arxiv` 技能已有）、Hacker News、国内 AI 媒体 RSS，用 LLM 判断「是否适合本项目受众」→ 生成候选选题 | **热点必须配上「稳定的解释框架」**，否则容易做出「新闻搬运」而非「科普」 |
| **L4 角度生成器** | 同一选题可派生多个角度（是什么 / 为什么 / 怎么用 / 常见误区 / 对比 / 成本 / 风险 / 职业影响 / 历史脉络） | 现有 `angle` 字段已支持 [实测]，但**未被系统性利用**：一个选题 × 9 角度 = 9 条内容，是防耗尽的最低成本手段 |
| **L5 防耗尽熔断** | ① 选题池 < 30 条未使用 → 告警；② 连续 5 条使用同一类目 → 强制切类目；③ `avoid_recent_topics` 必须 < 池规模的 1/3；④ 记录「选题-稿件-质检分-发布表现」，把长期表现差的类目降权 | 这些都是工程规则，不依赖模型 |

## 6. 内容质检体系评估与升级

### 6.1 现有 14 项逐项评价（基于 `quality/checker.py` 逐行实读）

| 维度 | 实现方式（实测） | 评价 | 结论 |
|:--|:--|:--|:--|
| `length` | 落在 320–560 得 100，偏离按 0.45/字扣 | 客观、可测 | ✅ **真有效** |
| `structure` | 首句 ≤45 字 +15；含「第一/首先/记住」等 +20；含「评论/关注/点赞」+20 | 客观但**易被刷**（堆词即得分） | ⚠️ 半有效（需与「信息点数量」结合） |
| `readability` | 平均句长 >34 开始扣、最长句 >60 扣 | 客观、与口播适配强相关 | ✅ **真有效**（建议补「句长标准差」） |
| `density` | `unique_ratio*180` + 词重复率惩罚 | 中文字符的 unique_ratio 区分度低（正常中文文章都落在相近区间） | ⚠️ 半有效（建议换成「信息点/百字」） |
| `speech_fit` | 检测 Markdown、括号、长英文、数字过多、CJK 占比 | 客观、对 TTS 有真实意义 | ✅ **真有效**（且与 §3 标记系统天然配合） |
| `title` | 长度 6–22 分档 + 互动词/感叹号惩罚 | 弱启发式，只能挡明显坏标题 | ⚠️ 半有效 |
| `hook` | 首句 ≤42 字 +15，命中正则（为什么/居然/你有没有/数字…）+30 | 启发式，**容易为了得分而套路化** | ⚠️ 半有效（建议以「前 3 秒是否给出信息承诺」重新定义） |
| `colloquial` | 书面词命中扣 9/个，长句扣 8/个 | 方向正确，与去 AI 腔直接相关 | ✅ 有效（阈值与词表需扩容） |
| `factuality` | **只检测绝对化词、`%` 数字个数、以及「研究表明…数字」缺「根据」** | **这测的是「措辞风险」，不是事实性。** 一段 100% 编造但措辞谦逊的文字可以拿满分；一段真实但有数据的内容反而可能被扣分 | ❌ **伪指标**（见 6.2） |
| `logic` | 结构词 + 因果/转折词对命中 | 关键词计数，测「用了连接词」不测「逻辑成立」 | ⚠️ 半有效 |
| `timeliness` | 提取「20XX 年」：≥2 年前扣 30、1 年前扣 12；**无年份直接给 92 分** | **伪指标**：不写年份=接近满分，「无时效信息」反而被奖励；写「2023 年」讲历史事件也被罚 | ❌ **伪指标** |
| `completeness` | 结构词 + 案例词 + 互动词 | 与 `structure` 高度重叠（同一批标记词被两个维度重复计分） | ⚠️ 半有效（存在**重复计分**） |
| `topic_novelty` | 与历史稿件的**关键词 Jaccard** `1-x` | 关键词集合对同义表述不鲁棒 | ⚠️ 弱 |
| `viewpoint_novelty` | 句级**字符 2-gram 余弦**最大值 `1-x` | 只测字面重叠，同义改写几乎无感 | ⚠️ 弱 |
| （重复度） | `max(SimHash 汉明相似度, 字符 3-gram 余弦)`，阈值 0.72 | **两种量纲不同的相似度取 max，阈值语义混乱**：SimHash 相似度分布集中在高位、3-gram 余弦集中在中低位，同一个 0.72 对二者含义完全不同 | ❌ 需重构（见 6.3） |

**一句话总结**：14 项里真正**客观可测且与目标相关**的约 5 项（length / readability / speech_fit / colloquial / structure 的一半）；**伪指标 2 项**（factuality / timeliness）；**重复计分**至少一处（structure vs completeness）；**相似度实现有量纲缺陷** 1 处。加权平均 72 分阈值因此**不具备可解释性**。

### 6.2 关键结论：无联网检索时，「事实性/时效性」不该出现在评分体系里

- **事实性**：判断一句「现在一个人可以完成以前一个团队的工作」是真是假，需要**外部证据**。规则引擎永远只能判断「措辞像不像在吹牛」。把 1.3 权重的分数给一个测不准的维度，会导致：
  1. 真实但表述直接的稿件被误杀；
  2. 编造但措辞谦逊的稿件被放行（**最危险的失败方向**）。
- **正确做法（把「测不准」换成「可检查」）**：
  - 把 `factuality` 改名为 **`claim_hygiene`（断言卫生）**，只负责：绝对化措辞、无来源精确数字、无法核验的机构名 → 这是**规则能真做的事**；
  - 事实的真假交给**独立的事实核查环节**（6.4），并且该环节**可以判「不通过」但不能「打分」**（避免用零证据打出高分）。

### 6.3 升级一：重复度检测 → 语义相似度

**现状缺陷**：
- 字符 3-gram 余弦：对**同义改写**（「零样本音色克隆」vs「不用训练就能复刻音色」）几乎无感；对**模板复用**（同一固定句）在中长文本里被稀释。
- SimHash：对 300~600 字的短文本区分度低（短文本 SimHash 汉明距离本来就集中在小区间）。
- 两者取 max 且共用一个阈值 → **阈值不可解释**。

**升级方案**：

| 事项 | 建议 |
|:--|:--|
| 主模型 | **BGE-M3**（自托管，中文强，同时输出稠密/稀疏/多向量；可用 CPU 或量化版本跑，规避 4GB 显存）**[待核验：本机可行性未实测]** |
| 备选（云） | 阿里百炼 **qwen embedding 系列**（大陆直连、按量计费、无需自托管）；海外选项 `text-embedding-3-small/large`（需代理） |
| 文本切分 | **段落级 + 句级双粒度**：段落向量查「整体撞题」，句级向量查「金句照搬」 |
| 阈值建议 | 段落相似度 **>0.86** 判「同题同角度」；句级相似度 **>0.92** 判「句子重复」；整体稿件平均相似度 **>0.80** 判「结构雷同」。上述为起始值，**必须用 50 对人工标注样本做 ROC 校准**（见 6.5） |
| 历史库 | SQLite 存**向量 + 原文 hash + 段落序号**；量级小时暴力检索即可（200 篇 × 15 段 = 3000 向量，无需向量库；超过 1 万段再引入 FAISS/pgvector） |
| 保留 SimHash 吗 | 保留，但**降级为「近乎逐字重复」的快速预筛**（低成本先过滤明显抄袭），不再与余弦相似度混合取 max，避免量纲混淆 |
| 降级方案（无 embedding） | 字符 3-gram 余弦（仅在 embedding 不可用时启用），阈值单列，并在报告里标注「降级模式」 |

### 6.4 升级二：事实核查（RAG 检索 + 引用核验）

分三层，L1 现在就有，L2/L3 需新建：

| 层 | 做什么 | 实现 | 失败时的动作 |
|:--|:--|:--|:--|
| **L1 规则** | 绝对化措辞、无来源精确数字、编号/机构名格式检查 | 现有 `_score_factuality` 改名沿用 | 定点改写（不是全篇重写） |
| **L2 断言核验** | ① LLM 抽取「可验证断言」三元组 `(主体, 属性, 值, 时间)`；② 对每个断言做检索（本地知识库 + 联网搜索）；③ 判定：`支持 / 部分支持 / 无证据 / 矛盾` | 检索接口：`agent-reach` 技能里的 Jina Reader + Bing/官方 API；知识库：把权威来源（官方文档、论文）预先落库 | `矛盾` → 拒稿；`无证据` → **降级为弱表述**（去掉数字、加「据称/在部分场景下」）或删除该句 |
| **L3 引用可访问性** | 稿中每个数字/结论若带来源，校验来源链接可访问且内容相关 | HTTP 抓取 + 标题/摘要一致性检查 | 不可访问 → 视为无证据 |

**关键工程建议**：
- **事实核查必须能「拒稿」而不是「扣分」**——一旦发现矛盾断言，无论总分多高都不得发布。
- **核查结果要落库**（`claims` 表：断言 / 证据 URL / 判定 / 核查时间），这样「同一个错误断言」不会在下一版稿子里复活。
- **对 450 字的短视频口播稿，只需核查 1~3 个关键断言**（抽取时限定「含数字、含机构名、含因果结论」的句子），成本可控。

### 6.5 升级三：质检分数与人工评审的相关性验证

这是本次调研里**优先级最高、成本最低、却最容易被跳过**的一步。

**方案**：
1. **采样**：从历史稿件按分数分层抽取 **30~50 篇**（高分/中分/低分各 10~17 篇，含 5 篇已知的劣质样本作为「金标负例」）。
2. **盲评**：3 位评审（可含非专业用户）按 5 点量表打分，维度：① 会不会看完 ② 有没有收获 ③ 像不像真人在说。评审**只看稿件不看分数**。
3. **统计**：计算 `Spearman ρ`（质检总分 vs 人工均分）。判据：
   - ρ ≥ 0.6：分数可用，保留现有权重；
   - 0.4 ≤ ρ < 0.6：可用但需重标定权重（用**秩回归 / 逻辑回归**拟合人工分，替代手工权重 [现有权重是手写的，见 config.yaml]）；
   - ρ < 0.4：**分数不可用于自动放行**，改为「分数只做预警，全部人工过一遍」。
4. **一致性**：计算评审间 `Krippendorff α` / Fleiss κ，α < 0.5 说明评测维度定义不清，先修 rubric 再验分数。
5. **分布诊断**：检查稿件分数的**区分度**（若 80% 稿件落在 78~86 区间，说明分数没有区分能力，即使 ρ 看起来还可以也没有实用价值）。
6. **持续监控**：每 50 条重跑一次，ρ 下降即触发重标定（内容也在变化，锚点会漂）。

### 6.6 补上缺失的维度

| 缺失维度 | 为什么重要 | 建议指标 |
|:--|:--|:--|
| **标题-正文一致性** | 现在 `title` 只测长度，完全没测「标题是否兑现」 | 标题关键词与正文 embedding 相似度；LLM 二分类「标题是否被正文兑现」 |
| **信息承诺（前 3 秒）** | `hook` 只看句式，不看「是否给了继续看的理由」 | 前三句是否出现「具体收益/具体问题/具体数字」 |
| **可执行动作** | 收藏率的核心驱动 | 是否含「一个可以立刻试的动作」 |
| **观点锐度** | 平淡 = 无传播 | 是否含一个可被反驳的明确立场 |
| **违规词/敏感词** | 平台风险 | 平台违规词库（比现有 `banned_words.txt` 更全） |

## 7. 自动重写闭环设计

### 7.1 现状问题（实读源码）

1. `max_rewrite: 3` [config]，重写时把 `report.feedback`（issues 前 5 条，纯文本句子）拼进 prompt [实测源码 `USER_TEMPLATE.feedback`] → LLM 得到的是「综合评分 68.3 低于阈值 72」这类**不可操作**的反馈。
2. 没有任何「已尝试过什么策略」的记忆 → 大概率**同策略循环**（比如三次都在做局部改写）。
3. 没有「保留历史最优」→ 可能出现「第一次 71 分、第二次 69 分」越改越差的死循环。
4. 选题层没有熔断 → 同一个「无解」选题会一直重试到耗尽次数。
5. 模板兜底路径用 `attempt` 参与随机种子 [实测源码] → 能换句式，但**换的是同一批固定句**（见 §5.1）。

### 7.2 建议设计：策略化分级重写

**失败归因 → 策略映射表**

| 失败原因（归因） | 重写级别 | 具体策略 |
|:--|:--|:--|
| 长度偏离 / 句长过长 / 书面腔 | **L1 局部改写** | 保留结构，只改句子：拆长句、替换书面词、补口语连接词；**强制「必须替换的片段清单」** |
| hook 弱 / 结构缺失 / 完整性不足 | **L2 换骨架** | 换切入角度（用 `angle` 列表的下一个）、换开场范式（提问 / 反常识 / 数字 / 场景），**禁止复用上次首句（注入黑名单）** |
| 语义相似度高（撞题/撞观点） | **L2 → L3** | 先换角度；仍高则**换选题**（同类目下一个） |
| 命中禁用词 | L1（**不做整篇重写**） | 定点替换，仅替换命中片段，其他文字冻结 |
| 事实核查「矛盾」 | **人工介入（不自动重写）** | 矛盾断言必须人工确认来源，自动重写有掩盖风险 |
| L3 后仍不通过 | **L4 换类目** | 从选题池切换 category，并把该选题打入冷却（见下） |

**防死循环的四道闸**

1. **强制换策**：记录 `tried_strategies`，每次重写必须使用**未尝试过**的策略；无可用策略则直接进入下一级。
2. **分数不退化**：保留 `best_script`（历史最高分版本）；重写后分数**必须严格更高**才替换，否则丢弃并降级策略。
3. **选题熔断**：同一 `topic_id` 连续 2 次最终不合格 → 写入 `topic_cooldown`（冷却 90 天）+ 记录原因；同类目连续 3 个选题失败 → 该类目进入人工复核。
4. **人工队列兜底**：3 次（可配）后**不降阈值放行**，而是把「选题 + 最高分稿 + 完整质检报告 + 已试策略」写入 `workspace/review_queue/`，等人工处理。**放宽阈值放行劣质内容，是自动化内容生产最常见的质量崩塌路径**（比人工介入更贵）。

**另外三点工程细节**

- **可操作反馈**：给重写模型的 feedback 不应是分数，而应是**结构化 diff 要求**：`{"must_remove": ["...", "..."], "must_add": ["一个可执行动作"], "target_metrics": {"avg_sentence_len": "14-22", "spoken_connectors": ">=3"}}`。
- **回归防护**：重写不得改变选题的核心关键词集合（否则会「跑题式通过质检」）—— 用关键词 Jaccard ≥ 0.6 做硬约束。
- **全链路留痕**：每次 attempt 落库（`rewrite_attempts`：脚本ID / attempt序号 / 策略 / 各维度分 / 总分 / 相似度 / 是否通过），这是后面做「哪条策略最有效」分析的唯一数据源。

## 9. 风险与坑

| # | 风险 | 具体表现 | 对策 |
|:--|:--|:--|:--|
| R1 | **`edge-tts` 依赖是定时炸弹** | 非官方接口、无 SLA、无音色资产；且 `provider: auto` 让它在有网时**一直**被优先使用 [实测源码] | 把云端 provider 提升为主路径；edge 仅在 `--debug` 启用；`auto` 的降级顺序改为 `bailian → azure → edge → mock` |
| R2 | **零样本克隆的调用间漂移** | 每次请求重新编码参考音频 + 采样随机 | §2.3 的 8 条工程手段（固定参考 + seed + 抽检） |
| R3 | **参考音频质量决定音色天花板** | 参考有底噪/混响/口音，克隆必然带上；ElevenLabs 官方亦说明「不能改口音/语气」 [实测] | 参考音频入库前做降噪/静音裁剪/响度归一；一次定音后冻结 |
| R4 | **表达标记过密导致 TTS 崩坏** | ElevenLabs 官方明确警告 break 过多会加速/加噪 [实测] | 标记密度硬约束（≤6/百字）+ 编译器做「密度熔断」 |
| R5 | **音色不可迁移/不可回滚** | 火山后付费音色合成后固定不可改 [实测]；跨厂商 voice_id 不通 | 音色版本化 + 保留 VoiceDesign 描述文本 + 保留参考音频（可重建） |
| R6 | **复刻次数上限** | 火山预付费音色最多训练 15 次；试听音色 7 天未调用会被删除 [实测] | 音色定稿流程化（试听 → 确认 → 正式调用）；避免「试听池被清理」 |
| R7 | **AIGC 标识义务** | 服务商提供隐性标识（阿里 `enable_aigc_tag`），但平台侧通常还要求**显式标注** | 双轨：开隐性标识 + 视频/简介显式标注；具体法规见 §10 待核验项 |
| R8 | **4GB 显存的幻觉** | 网上「X GB 可跑」通常不含 vocoder/参考编码/并发；本机失败模式是 OOM 崩溃 | 本地不承担克隆推理；仅保留有实证的 OmniVoice（4GB Arc 实证）作极端降级 |
| R9 | **查重阈值语义混乱** | SimHash 相似度与 3-gram 余弦分布不同却共用 0.72 [实测源码] | 拆成两套独立阈值 + 分层处理（§6.3） |
| R10 | **模板复用的「查重免疫」** | 固定句占比不足以触发阈值 → 模板稿反复通过质检 | 对「句子级」做重复检测（embedding 句级 >0.92 直接判重） |
| R11 | **伪指标导致「劣币驱逐良币」** | `timeliness` 无年份给 92 分 → 越不写具体信息越安全；`factuality` 惩罚直白表述 | 移出伪指标（§6.1/6.2） |
| R12 | **Goodhart 效应（分数自我强化）** | 用同一套规则分做重写目标函数 → 模型学会堆「第一第二第三」和互动词 | 引入人工盲评做外部锚点；judge 只做触发器不做目标 |
| R13 | **选题池耗尽** | `topics.yaml` 约 10 条 [实测]，`avoid_recent_topics: 30` 大于池规模 → 必然重复 | 扩池 ≥200 条 + 角度生成器（1 选题 × 9 角度）+ 熔断规则 |
| R14 | **合规票据缺失** | 音频无来源记录、无授权证据链 | `voice_assets/<name>/LICENSE_NOTE.md` + 服务商条款快照 |
| R15 | **跨境依赖** | ElevenLabs/OpenAI/Fish/Cartesia 在大陆需代理，稳定性不可控（本次抓取均经代理成功，但**未做长期可用性测试**） | 主链路锁定国内云；海外服务只作「表现力上限」的备选 |
