# 口播写作

用于 `content_route=talking_script` 的初稿和明确发起的定向重写。

## 表达与时长

使用适合朗读的口语短句，以具体观点、例子和自然推进承载信息量。开头可用场景、结论或反常识等方式，不强制提问，不要求固定段落顺序。遵循账号风格及用户目标时长，避免论文腔、空泛排比和标题与正文不符。

正文是纯口播文本，不含 `<#...#>`、`[pause]`、时间轴或情绪控制标记。事实证据单独留在 `claims`，正文不必照抄证据原句。

## 输出契约

初稿仅输出：

```json
{
  "candidates": [
    {
      "slot": 1,
      "angle": "角度名",
      "title": "标题",
      "description": "一句话说明",
      "tags": [],
      "text": "口播正文",
      "claims": []
    }
  ]
}
```

初稿包含 slot 1、2、3 三篇。涉及可核验事实时，`claims` 每项包含 `text/evidence_id/source_quote/position`，按入口规则绑定实际证据；不输出虚构来源。

定向重写只输出指定 slot 的 `text/claims/repair_note`；不改变原角度和标题，不追加未要求重写的候选。`content_route`、时长估计、版本和批次关系由业务层保存，不用伪造审核结论填充写作输出。
