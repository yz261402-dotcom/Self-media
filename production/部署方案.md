# 部署入口与当前实施边界

更新：2026-10-10。本文作为部署文档入口，替代原先基于 SQLite 的旧方案；当前业务存储已使用 PostgreSQL。

## 首次从 GitHub 下载

请按[根 README](../README.md)部署。它包含 Python 3.13、Node 24、锁定依赖、空密钥模板、PostgreSQL Compose、启动／检查／停止、功能接入和备份步骤。命令在完整项目根目录运行，不能只复制 `production`。

## 当前可落地形态

- Windows 10/11 单用户工作台：Vue 开发服务、FastAPI 单实例、本机拼接／字幕 Worker、FFmpeg、可交互 Chrome。
- PostgreSQL 17：推荐用 [compose.yaml](compose.yaml) 运行，数据保存在 named volume；已有或托管 PostgreSQL 也可使用自己的 DSN。
- 媒体文件：`production/backend/runtime`、根目录 `assets`／`content-media`；数据库保存业务状态与文件引用。
- 可选 Linux GPU：LivePortrait、MuseTalk、Qwen3-ASR／ForcedAligner，需接收者准备权重和独立推理环境。
- 外部模型／数据 API：使用接收者自己的账户、精确模型 ID、额度和素材传输配置。

本机服务默认只监听回环地址：前端 `5173`、后端 `8000`、PostgreSQL 宿主端口 `15432`。GPU 隧道常用本地 `18080`，只在用户明确配置后启动。

首次空密钥 Mock 仅验证软件与业务库；真实功能以显式授权 integration 接入。当前 production 还要求供应商成功实测证据，新空库尚不具备完整自动准入闭环；不要把填好密钥或健康检查成功描述为全链路生产验收。

## 生产化与多节点规划

最新完整方案见 [自媒体视频生成部署方案](../specs/汇报/自媒体视频生成-部署方案.md) 或 [HTML 版](../specs/汇报/自媒体视频生成-部署方案.html)。其中服务器配置、GPU 小时和 API 额度均为规划示例；多节点布局不是下载 ZIP 后已经完成的部署。

对外服务前需完成认证、HTTPS、上传与访问限制；先拆内容调度器并补跨进程 owner／租约／心跳恢复，再扩 API 副本。媒体节点需要统一可访问路径；浏览器发布拆机需要远程 Agent。GPU 账本持久化、数据库和媒体恢复、真实生成、字幕和发布仍要分别验收。

Vite 只用于本机开发工作台。正式前端应构建 `dist`，在 Nginx 等静态服务器中配置 `/api`、`/media` 代理；真实发布 Adapter 需要用户可交互的桌面浏览器。
