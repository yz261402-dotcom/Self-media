# 数字人口播工作台部署方案

版本：2026-09-28

本文以当前工程为准，目标是先把单用户工作台稳定部署在一台 Windows 主机上；云端 GPU Worker 作为可选执行节点。当前工程不是多用户 SaaS，也没有登录认证，不能直接把 FastAPI 或 Vite 端口暴露到公网。

## 1. 推荐拓扑

```text
用户浏览器
    |
    | 本机回环地址
    v
Windows 工作台主机
  ├─ Vite 前端       127.0.0.1:5173
  ├─ FastAPI 后端     127.0.0.1:8000
  ├─ SQLite           production/backend/runtime/studio.db
  ├─ 媒体与交付包     production/backend/runtime/{audio,video,deliverables,...}
  ├─ FFmpeg/ffprobe
  └─ 专用 Chrome      抖音发布会话目录
          |
          | SSH 隧道（仅 M2/ASR/字幕需要）
          v
算力云 GPU Worker
  └─ 127.0.0.1:8080 -> 本机 127.0.0.1:18080
```

当前推荐的上线形态是“单用户、单机、仅本机访问”。发布适配器会以 `headless=False` 打开专用 Chrome，因此后端必须运行在用户登录的交互式 Windows 会话中，不能先做成无桌面的 Windows Service。

## 2. 上线边界

- OmniHuman 最终音频必须严格小于 60 秒。`>= 60 秒` 在项目侧直接阻断，不切片、不拼接、不自动改走 M2。
- M2、ASR、字幕依赖 GPU Worker；只发布已有交付包时不需要启动 Worker。
- SQLite 和本机 runtime 是当前事实源，不能同时启动两个后端进程，也不要把同一个工作目录挂给多台主机。
- 当前只支持单账号、单条、即时抖音投稿。最终“确认并发布”仍由用户在专用浏览器中完成。
- 当前后端没有用户认证，8000、5173、18080 都不得配置公网入站访问。

## 3. 主机准备

建议使用一台专用 Windows 10/11 主机，至少预留：

- Python 3.13；
- Node.js（当前环境为 24.x）；
- Google Chrome；
- FFmpeg 与 ffprobe；
- 稳定网络，发布时允许 Chrome 打开抖音创作者中心；
- 媒体盘至少预留 100 GB，按实际产量扩容。

将工程放在不含空格和同步盘的固定目录，例如：

```text
C:\AvatarStudio\production
```

保留以下目录结构，不要把运行数据放进临时目录：

```text
C:\AvatarStudio\production\backend\runtime
C:\AvatarStudio\production\assets
C:\AvatarStudio\production\frontend
```

在 PowerShell 中执行依赖安装：

```powershell
cd C:\AvatarStudio
python -m venv production\backend\.venv
.\production\backend\.venv\Scripts\python.exe -m pip install -r production\backend\requirements.lock.txt
.\production\backend\.venv\Scripts\python.exe -m pip install -r production\backend\requirements-publish.txt
npm --prefix production\frontend ci
npm --prefix production\frontend run typecheck
npm --prefix production\frontend run build
```

确认工具可用：

```powershell
Get-Command node,python,ffmpeg,ffprobe,ssh
Test-Path C:\Program Files\Google\Chrome\Application\chrome.exe
```

若 FFmpeg 不在 PATH，设置服务用户级变量：

```powershell
[Environment]::SetEnvironmentVariable('AVATAR_STUDIO_FFMPEG_BIN', 'C:\ffmpeg\bin', 'User')
```

## 4. 配置与密钥

不要把真实密钥写入前端、文档、压缩包或版本库。生产配置放在 `backend/.env` 或独立的 `AVATAR_STUDIO_SECRETS_FILE`，并只授予运行用户读取权限。

至少核对这些配置：

```ini
AVATAR_STUDIO_MODE=production
AVATAR_STUDIO_ALLOW_PRODUCTION=1
AVATAR_STUDIO_BUDGET_PER_TASK_FEN=<按月度预算设置>
AVATAR_STUDIO_BUDGET_DAILY_FEN=<按日预算设置>
AVATAR_STUDIO_BUDGET_MAX_SUBMISSIONS=<按供应商额度设置>
AVATAR_STUDIO_FFMPEG_BIN=C:\ffmpeg\bin
AVATAR_STUDIO_PUBLISH_ADAPTER=playwright
AVATAR_STUDIO_DOUYIN_BROWSER_CHANNEL=chrome
AVATAR_STUDIO_M2_WORKER_URL=http://127.0.0.1:18080
AVATAR_STUDIO_ASR_WORKER_URL=http://127.0.0.1:18080
```

供应商密钥、M2 token、TOS 凭据和抖音浏览器会话属于秘密资料。`backend/runtime/publish/douyin-profile/` 只能由发布用户访问，备份时必须加密。

第一次正式运行前先确认供应商状态和预算，不要因为配置项存在就认为供应商已经验收。真实付费调用采用单次、有限预算、保留原始响应的方式，失败或超时后先对账，不要猜测性重试。

## 5. 首次启动与本机验收

从项目根目录启动本机服务：

```powershell
cd C:\AvatarStudio
powershell -ExecutionPolicy Bypass -File .\production\start.ps1
```

脚本会复用健康服务，否则启动：

- 前端：`http://127.0.0.1:5173`
- 后端：`http://127.0.0.1:8000`

验收命令：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
(Invoke-WebRequest http://127.0.0.1:5173 -UseBasicParsing).StatusCode
```

必须得到 `ok: true` 和前端 HTTP 200。日志检查：

```powershell
Get-Content .\production\runtime\backend-8000.err.log -Tail 80
Get-Content .\production\runtime\frontend-5173.err.log -Tail 80
```

正式验收顺序：

1. 用 mock 或不计费路径创建一个测试作品，确认五步向导、SQLite 写入和重启恢复。
2. 确认 `ffmpeg`、字幕、封面和 ZIP 交付包能产出，并核对 `manifest.json` 的 SHA256。
3. 用一条已确认的短音频验证 OmniHuman；用 `>= 60 秒` 音频验证门禁只返回阻断且没有供应商调用。
4. 只有在 M2 Worker 恢复后，才验证动作底片、口型和云端字幕。
5. 抖音先执行“打开专用浏览器登录”和“开始准备（不发布）”，核对账号、视频、封面、文案和 AI 声明后，再由用户决定是否最终发布。

## 6. 开机自动恢复

当前发布浏览器需要交互式桌面，因此使用“用户登录时运行”的任务计划，不使用 Session 0 的无桌面服务。

在任务计划程序中创建任务：

- 名称：`AvatarStudio-Local`
- 触发器：指定发布用户登录时
- 选项：仅当用户登录时运行；失败后每 1 分钟重试，最多 3 次
- 程序：`powershell.exe`
- 参数：`-ExecutionPolicy Bypass -File C:\AvatarStudio\production\start.ps1 -NoBrowser`
- 起始目录：`C:\AvatarStudio\production`

任务启动后检查 8000 和 5173。不要在任务计划之外再次手动启动第二个后端；`start.ps1` 的健康复用只适用于同一套工作目录和端口。

## 7. GPU Worker 部署

GPU Worker 单独部署在算力云实例。实例重启后按以下顺序恢复：

已完成[Worker 恢复服务安装](Worker运维说明.md)时，运行本机 `start.ps1` 即可执行安全的 ensure，再验证隧道。服务提供单实例守护和退出后退避恢复；不会结束已有进程或重提作业。该方式兼容没有 systemd 的算力云容器，实例重启后由下一次项目启动触发。以下为未安装恢复服务时的手动流程：

1. 云端确认 8080 没有旧 Worker 占用；若已有任务运行，不要重启。
2. 注入已有 `M2_WORKER_TOKEN`，启动 `start-all-stages.sh`。
3. 云端检查 `http://127.0.0.1:8080/v1/healthz`，必须包含 `align`、`asr`、`lipsync`、`motion` 四阶段。
4. 本机完成一次[长期隧道配置](隧道使用说明.md)，由 `AvatarStudio-GpuTunnel` 登录任务维持本机 18080 到云端 8080 的转发；平时执行 `start.ps1` 自动检查。
5. 本机检查 `http://127.0.0.1:18080/v1/healthz` 后，才在页面启动 M2 或字幕任务。

当前 Worker 作业表在内存中，实例重启会丢失未完成作业；生产操作中必须把实例重启当作维护动作，并先确认没有推理任务。隧道提供专用密钥、固定主机身份、登录自启和断线重连；Worker 提供安全恢复控制入口，现场验收以实际状态与检查记录为准。作业持久化仍需补充；实例开机即自启与项目启动触发恢复是不同语义，如另外部署 systemd，须先确认实例 PID 1 支持它。

## 8. 备份、恢复与回滚

备份分为代码发布包、业务数据库、媒体资产、密钥和发布浏览器会话五类，不要把它们混成一个未经加密的 ZIP。

每日备份至少包含：

```text
production/backend/runtime/studio.db
production/backend/runtime/audio/
production/backend/runtime/video/
production/backend/runtime/deliverables/
production/assets/
```

以下内容单独加密保存，权限只给发布用户：

```text
production/backend/.env
production/backend/runtime/publish/douyin-profile/
AVATAR_STUDIO_SECRETS_FILE 指向的文件
```

备份时先进入维护窗口并确认没有生成、后期或发布任务。SQLite 使用一致性备份，不要在 WAL 写入过程中只复制单个 `studio.db` 文件。每周在另一目录做一次恢复演练：恢复数据库与媒体后启动临时端口，检查作品列表、任务状态、成片播放和下载包。

回滚采用“代码版本与数据备份成对回退”：

1. 停止本机任务计划并确认没有正在执行的外部计费任务。
2. 保留当前日志和未知状态任务证据。
3. 切换到上一份代码发布目录。
4. 仅在数据迁移兼容的前提下恢复对应数据库和媒体备份。
5. 启动临时端口做健康检查和作品读取，再恢复正式端口。

## 9. 监控与日常运维

每天检查：

- `GET http://127.0.0.1:8000/api/v1/health`；
- 磁盘剩余空间，重点是 `backend/runtime`；
- 后端和前端错误日志；
- 是否存在 `waiting_selection`、`unknown` 或长时间 `running` 任务；
- GPU Worker 健康状态和队列；
- 发布任务是否处于待核验状态。

每周执行：

- SQLite 和媒体恢复演练；
- Chrome 专用 profile 是否仍能登录；
- 依赖和 Chrome 更新前做一份完整快照；
- 清理可确认无引用的 scratch、测试和旧日志，不直接删除未知状态任务产物。

## 10. 二期公网/多人部署前置条件

在没有完成以下改造前，不建议把系统放到公网或给多人使用：

1. 后端增加用户认证、角色权限、CSRF 和上传限额。
2. 前端由 Caddy/IIS/Nginx 提供 `dist` 静态文件，反向代理 `/api` 和 `/media`，只开放 443。
3. CORS 改为明确的正式域名白名单，关闭 localhost 正则放行。
4. SQLite 迁移到经过恢复、事务和并发验证的 PostgreSQL；媒体迁移到对象存储并保留哈希校验。
5. 将生成、后期、发布拆成带持久化队列的 Worker；发布浏览器保留单独的交互式执行节点。
6. 为外部供应商调用增加密钥轮换、额度告警、未知状态对账和审计导出。

完成这些改造并通过并发、恢复和安全验收后，才把部署形态升级为多用户服务。

- [ ] `.env`、secrets、抖音 profile 未进入代码发布包。
- [ ] 备份已完成，且在独立目录恢复过一次。
- [ ] OmniHuman `>= 60 秒` 门禁验证没有产生外部调用。
- [ ] M2/ASR Worker 健康检查包含四阶段，或明确本次只做本机/发布。
- [ ] 交付包可以播放、下载，manifest 和质量报告存在。
- [ ] 抖音只做准备上传时，账号和浏览器窗口可见；最终发布由用户确认。
