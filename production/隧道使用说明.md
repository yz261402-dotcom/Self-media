# GPU 隧道：长期配置与日常使用

本机 OpenSSH 将 `127.0.0.1:18080` 转发到算力云 `127.0.0.1:8080`。ASR、对齐、动作和口型共用这条连接。Windows 登录任务维持隧道，网络恢复后自动重连；启动项目时再次检查。

## 日常使用

```powershell
.\production\start.ps1
```

首次安装完成后不再输入 SSH 密码，也不需要为建立隧道进入算力云终端。

```powershell
# 查看后台进程与真实 Worker 健康状态
.\production\scripts\tunnel.ps1 -Action Status

# 立即启动/恢复隧道
.\production\scripts\tunnel.ps1 -Action Start

# 主动停止并禁用登录自启；下次 Start 会重新启用
.\production\scripts\tunnel.ps1 -Action Stop
```

只用文案、发布已有成品或运行隔离验收时，可使用 `start.ps1 -SkipGpuTunnel`。

## 首次安装

需要 Windows OpenSSH Client、项目已有 Python 环境、可用的算力云 SSH 地址。先通过可信渠道确认服务器主机指纹；安装程序只使用用户 `known_hosts` 中已信任的记录，不会自动接受扫描到的任意密钥。

```powershell
# 在本机交互终端中执行，密码由 OpenSSH 直接读取，不写入配置或日志
.\production\backend\.venv\Scripts\python.exe .\production\scripts\setup_tunnel.py --install-key

# 注册当前用户登录任务，并立即启动
.\production\scripts\tunnel.ps1 -Action Install
```

当前配置指向 `connect.weste.seetacloud.com:21170`，用户 `root`。首次密钥安装只向远端 `~/.ssh/authorized_keys` 追加一条专用公钥，保留既有公钥和运行进程。专用密钥禁止 shell/PTY、agent/X11 转发，限制转发目标为 Worker `127.0.0.1:8080`；私钥无交互口令，依靠独立目录 ACL 保护，以支持无人值守重连。

这里的目标限制是 OpenSSH `permitopen`，适用于本地/动态转发。当前程序只使用 `-L`；没有修改实例 sshd 的反向转发策略，因此不能将这条公钥描述为“服务端彻底禁止 `-R`”。如需多人生产环境的进一步隔离，应创建专用远端账号，并对该账号设置 `AllowTcpForwarding local`，避免改变已有 root 连接的权限。

## 文件与进程

- 唯一本机连接配置：`production/runtime/tunnel/config.json`，没有密码和 Worker Token。
- 私钥和固定主机记录：`%USERPROFILE%/.ssh/avatar_studio/`，不在项目中。
- 后台程序：`production/scripts/managed_tunnel.py`，调用系统 `ssh.exe`。
- 状态和轮转日志：`production/runtime/tunnel/`。
- 登录任务：`AvatarStudio-GpuTunnel`，当前用户普通权限，无运行时长上限，允许电池运行。

守护程序使用单实例锁，避免项目启动与 Windows 登录任务竞争。SSH 每 20 秒探活，连续 3 次无响应后退出，按退避间隔重新连接。主机密钥变化或认证拒绝会记录错误，绝不自动关闭身份验证。停止时只清理自己创建的 SSH 子进程。

## 状态含义

`ready` 必须同时满足：托管隧道进程存活、健康接口返回 `state=ok`、Worker 协议版本至少为 2、支持 `align/asr/lipsync/motion` 四个阶段。只监听 18080 不算就绪。

`worker_unavailable` 表示通过当前转发无法得到合格的 Worker 健康响应。云端 Worker 停止、8080 未监听或缺少 ASR 等阶段都可能导致它；重连 SSH 无法启动 Worker。守护程序继续保留连接，不自动杀死或重启 GPU 进程。

`reconnecting` 表示 SSH 已退出，正在等待再次连接；检查网络、算力云实例和 SSH 地址。`port_in_use` 表示 18080 已有其他监听者，程序不会结束它或把它误认为自己的连接。

算力云关机时，隧道只能等待实例恢复，不会购买或自动开启算力。Worker 进程的开机自启属于远端部署，应单独配置；不能从隧道自启推导出 Worker 自启。当前 Worker 作业账本仍在内存中，维护前须查询在途作业，不能把 `pending=0` 当作没有正在运行任务的证明。

项目另提供了 [Worker 恢复服务](Worker运维说明.md)：首次安装后，启动项目时会通过受限控制密钥检查并确保 Worker 存在，守护程序负责进程退出后的安全恢复。

## 更换实例与撤销

先执行 `Stop`。验证新实例 SSH 地址和主机指纹后，备份旧 `config.json`，在本机重新执行带 `--ssh-host`、`--ssh-port`、`--ssh-user` 的首次安装。若旧配置仍存在且目标不同，安装程序会拒绝覆盖，需要人工核对后归档旧配置，再重新准备。不要简单关闭 `StrictHostKeyChecking`。

撤销时停止并删除 `AvatarStudio-GpuTunnel` 任务，在远端 `authorized_keys` 中仅移除注释为 `avatar-studio-tunnel` 且公钥指纹与本机对应的记录。私钥目录是专用目录，可在确认不再使用后归档或删除；不要删除整个 `.ssh` 或其他项目的公钥。

## 验收边界

`Status` 是连接与 Worker 服务检查，不会生成字幕、提交作业或触发模型计费。字幕成功仍须通过现有作品的正常生产流程验证。配置后的现场验收结果记录在 `production/runtime/tunnel/verification.json`（完成现场检查后生成）。
